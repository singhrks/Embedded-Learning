Graphs: grids, topological sort and cycles

Three applications that cover most graph questions asked in interviews: a grid is a graph, dependencies need an ordering, and detecting cycles is what tells you whether one exists.

A grid is a graph

Most grid problems are graph problems that nobody labelled as such. Once the translation is explicit, the algorithms from the previous chapter apply without modification.

   EVERY CELL IS A NODE. Its neighbours are the adjacent
   cells. Nothing else changes — BFS and DFS work unaltered.

     const DIRS = [[-1,0],[1,0],[0,-1],[0,1]];
     for (const [dr, dc] of DIRS) {
         const nr = r + dr, nc = c + dc;
         if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
         ...
     }

   THE STANDARD PROBLEMS:
     COUNT ISLANDS       DFS/BFS from each unvisited land
                         cell; each launch is one island
     FLOOD FILL          same traversal, writing a new value
     ROTTING ORANGES     MULTI-SOURCE BFS — push every
                         initial source before starting, and
                         the level count is the answer
     SHORTEST PATH       BFS, because every step costs 1
     SURROUNDED REGIONS  traverse from the BORDER inwards to
                         find what is NOT enclosed

   MARKING VISITED: either a separate boolean grid, or
   overwrite the cell itself (turning '1' into '0'). The
   second is O(1) space but MUTATES THE INPUT — say which
   you chose.

   MULTI-SOURCE BFS IS THE PATTERN PEOPLE MISS. If several
   starting points spread simultaneously, seed the queue
   with all of them at distance 0. One BFS then computes
   the distance to the NEAREST source for every cell.

Topological sort

Any problem phrased as "this must happen before that" is a topological sort, and the same algorithm that produces the order also detects when no order exists.

   AN ORDERING OF A DIRECTED ACYCLIC GRAPH such that every
   edge u -> v puts u before v. "Do this before that."

   IT EXISTS IF AND ONLY IF THE GRAPH IS ACYCLIC — which is
   why the same algorithm detects cycles.

   ---------------------------------------------------------
   KAHN'S ALGORITHM (BFS on in-degrees) — the one to write

     1. compute in-degree for every node
     2. queue every node with in-degree 0
     3. pop u, append to the order, and for each edge u -> v
        decrement in-degree[v]; if it reaches 0, enqueue v
     4. IF THE ORDER IS SHORTER THAN n, A CYCLE EXISTS

     THAT LAST LINE IS THE CYCLE TEST. Nodes inside a cycle
     never reach in-degree 0, so they are never emitted.

   ---------------------------------------------------------
   DFS ALTERNATIVE

     Postorder DFS, then REVERSE the finishing order.
     Detect cycles with THREE COLOURS:
        0 unvisited   1 IN PROGRESS   2 done
     Meeting a node in state 1 means a BACK EDGE — a cycle.

     TWO COLOURS ARE NOT ENOUGH for a directed graph:
     revisiting a FINISHED node is fine (a diamond), but
     revisiting an IN-PROGRESS one is a cycle. Conflating
     them reports false cycles on any DAG with two paths to
     the same node.

   ---------------------------------------------------------
   CYCLE DETECTION, and the directed/undirected difference

     DIRECTED    three-colour DFS, or Kahn's count
     UNDIRECTED  DFS tracking the PARENT — seeing a visited
                 node that is not your parent is a cycle.
                 (Union-find also works: an edge whose
                 endpoints already share a root closes a
                 cycle — chapter 33.)

     Using the directed method on an undirected graph
     reports a "cycle" for every single edge, because u-v is
     stored as both u->v and v->u.
