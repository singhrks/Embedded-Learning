DP: knapsack and subset problems

A family of problems all reducible to one question: which items do I take, subject to a capacity? The loop order tells you whether each item may be reused, and that single detail decides correctness.

The pattern

Knapsack is the template behind a whole family of "choose a subset subject to a budget" problems. The recurrence is a single either-or choice per item, and everything else is a variation on it.

   THE 0/1 KNAPSACK: n items with weights and values, a
   capacity W, each item taken AT MOST ONCE. Maximise value.

     dp[i][w] = best value using the first i items with
                capacity w

     dp[i][w] = max( dp[i-1][w],                    // skip
                     dp[i-1][w - wt[i]] + val[i] )  // take

   THE SHAPE — "for each item, take it or skip it" — is the
   whole family.

   ---------------------------------------------------------
   THE SPACE OPTIMISATION AND THE LOOP-ORDER RULE

   Each row depends only on the previous row, so one array
   suffices. But the ITERATION DIRECTION now carries meaning:

     0/1 KNAPSACK (each item once):
        for (item of items)
            for (w = W; w >= wt; w--)     // BACKWARDS
                dp[w] = max(dp[w], dp[w - wt] + val);

     UNBOUNDED (unlimited copies):
        for (item of items)
            for (w = wt; w <= W; w++)     // FORWARDS
                dp[w] = max(dp[w], dp[w - wt] + val);

   WHY. Going backwards, dp[w - wt] still holds the PREVIOUS
   row's value — the item has not been used yet at that
   capacity — so it can be taken at most once. Going
   forwards, dp[w - wt] has ALREADY been updated with this
   item, so taking it again is allowed.

   ONE CHARACTER SEPARATES 0/1 FROM UNBOUNDED. If a knapsack
   answer is wrong and the structure looks right, check the
   direction first.

   ---------------------------------------------------------
   THE OTHER LOOP-ORDER RULE: COMBINATIONS VS PERMUTATIONS

   For COUNTING problems the nesting order matters too:

     items OUTSIDE, capacity inside   -> COMBINATIONS
                                         (1+2 and 2+1 count
                                          once)
     capacity OUTSIDE, items inside   -> PERMUTATIONS
                                         (counted separately)

   "Coin change 2" wants combinations; "combination sum IV"
   (badly named) wants permutations. Same table, swapped
   loops.

   ---------------------------------------------------------
   THE FAMILY, all the same table

     subset sum          "can I hit exactly T?"   boolean dp
     partition equal
       subset sum        subset sum with T = total/2
     target sum          assign +/- to each number
     coin change         unbounded, minimise count
     coin change 2       unbounded, count combinations
     last stone weight II minimise |difference| = subset sum
                          near total/2
     ones and zeroes      knapsack with TWO capacities
