The standard library for systems programmers

The C standard library is small, old, and uneven. Some of it is indispensable, some is actively harmful, and much of it disappears entirely in freestanding builds. This chapter is a working engineer's map of what to use, what to avoid, and what you lose in the kernel.

The standard library is smaller than most people assume, and its headers vary enormously in how useful they are to systems work. This is the map, sorted by how often you will actually reach for each.

The mem* functions

The memory functions are the most used in the library and the easiest to misuse — two of them differ only in whether the regions may overlap, and choosing wrongly produces corruption that depends on the addresses involved.

memcpy(dst, src, n)     /* non-overlapping only — restrict (ch. 10) */
memmove(dst, src, n)    /* handles overlap                          */
memset(dst, c, n)       /* c is converted to unsigned char          */
memcmp(a, b, n)         /* byte comparison; NOT for structs (ch. 07)
                           and NOT constant time (ch. 06)           */
memchr(s, c, n)         /* find a byte                              */

/* These are the fastest primitives you have. Modern implementations
   are hand-written SIMD, dispatched by CPU feature at load time.
   Do not write your own copy loop.                                 */

/* The compiler also generates calls to them from ordinary code: */
struct big a = b;            /* may become memcpy */
int arr[1000] = {0};         /* may become memset */
/* Which is why freestanding builds must PROVIDE memcpy/memset even
   if the source never calls them (chapter 20).                  */

/* memset's second argument is an int, converted to unsigned char.
   This does not do what it looks like:                          */
memset(arr, 1, n * sizeof(int));    /* sets every BYTE to 1, giving
                                       0x01010101, not 1           */
/* Only 0 is safe to splat across a multi-byte type. Use a loop
   otherwise, or memset_pattern where available.                 */

printf, and its cost

Formatted output is far more dangerous than it looks: the format string is effectively a small program, and if an attacker controls it, they control a great deal more than the output.

/* The format specifiers that matter, and are commonly wrong */
%d %u %x       int / unsigned / hex
%ld %lu        long
%lld %llu      long long
%zu %zd        size_t / ssize_t          <- not %d, not %lu
%td            ptrdiff_t
%p             void * — you MUST cast:  printf("%p", (void *)ptr)
%s             char * — never a non-literal FORMAT (ch. 06)
%f %e %g       double (float is promoted)
%%             a literal percent

/* fixed-width types need <inttypes.h> */
#include <inttypes.h>
printf("%" PRIu32 " %" PRIx64 "\n", a, b);

/* Field width and precision from arguments */
printf("%*d\n", width, value);
printf("%.*s\n", len, str);        /* print exactly len bytes —
                                      useful for non-terminated data */
printf is enormous

A full printf with floating-point support costs roughly 10–40 KB of flash and needs a sizeable stack frame. On a microcontroller with 64 KB of flash that is unacceptable. Options: -u _printf_float to omit float support in newlib-nano, a minimal reimplementation (tinyprintf, mpaland/printf), or a binary logging scheme that sends a format ID plus arguments and reconstructs the text on the host. The kernel's printk is its own implementation for exactly these reasons — it also cannot use floating point at all.

errno

Error reporting through a global variable has rules that are easy to violate — most importantly about exactly when it is valid to read, which is not simply "after something failed".

#include <errno.h>

/* errno is thread-local (a macro expanding to a per-thread lvalue).
   The rules that people get wrong:                                */

/* 1. It is only meaningful after a function that DOCUMENTS setting
      it, and only when that function reported failure.           */
if (fopen(...) == NULL)
        perror("fopen");            /* correct */

/* 2. A successful call may still CLOBBER errno. Never test errno
      to decide whether something failed.                        */
foo();
if (errno) ...                       /* WRONG */

/* 3. For functions that return a valid value on both success and
      failure (strtol, strtod), you MUST clear errno first:      */
errno = 0;
long v = strtol(s, &end, 10);
if (errno == ERANGE) ...

/* 4. Save it immediately if you do anything else first: */
if (write(...) < 0) {
        int saved = errno;
        cleanup();                   /* may clobber errno */
        return -saved;
}

/* Printing it */
perror("context");                   /* writes "context: message\n" */
fprintf(stderr, "%s\n", strerror(errno));       /* not thread-safe   */
strerror_r(errno, buf, sizeof buf);             /* thread-safe       */

The kernel does not use errno at all: functions return 0 or a negative errno value directly (-EINVAL, -ENOMEM). This is a strictly better design — the error is in the return value, so it cannot be clobbered or forgotten — and it is worth adopting in your own C libraries.

assert, and when to use it

Assertions document what you believe to be true and check it. The critical detail is that they vanish entirely in release builds, which makes putting anything with side effects inside one a real bug.

#include <assert.h>

assert(ptr != NULL);        /* aborts if false; compiled out by NDEBUG */

/* THE RULE: assert on PROGRAMMER errors (invariants that must hold
   if the code is correct). Handle USER and ENVIRONMENT errors with
   real error paths.                                              */

assert(index < ARRAY_SIZE(table));   /* internal invariant — assert */
if (!input_valid(s)) return -EINVAL; /* external input — check      */

/* The classic bug: side effects inside assert */
assert(do_something() == 0);         /* vanishes in release builds! */
int r = do_something();
assert(r == 0);                       /* correct */

/* Give it a message by ANDing a string literal — a widely used trick */
assert(n > 0 && "count must be positive");

/* static_assert costs nothing at runtime and never disappears:  */
static_assert(sizeof(struct hdr) == 8, "header layout");

/* In the kernel: */
BUG_ON(cond);       /* panic — reserve for unrecoverable corruption */
WARN_ON(cond);      /* log a stack trace and CONTINUE — prefer this */
WARN_ON_ONCE(cond);
BUILD_BUG_ON(cond); /* compile time */

Time

C's time facilities are a mixture of genuinely useful and actively broken, with several functions that cannot be used safely in a threaded program at all.

#include <time.h>

/* time_t is seconds since the epoch. On 32-bit systems it overflows
   in 2038 — still a live concern on embedded hardware shipping now.
   Use 64-bit time_t (glibc 2.34+ with _TIME_BITS=64) or your own.  */

/* For MEASURING DURATIONS, never use wall-clock time — it jumps
   backwards with NTP, DST and manual changes.                     */
struct timespec t0, t1;
clock_gettime(CLOCK_MONOTONIC, &t0);
work();
clock_gettime(CLOCK_MONOTONIC, &t1);
double sec = (t1.tv_sec - t0.tv_sec) + (t1.tv_nsec - t0.tv_nsec) / 1e9;

/* Clock choices that matter:
     CLOCK_REALTIME       wall clock; can jump. For timestamps only.
     CLOCK_MONOTONIC      never jumps; may pause in suspend. Durations.
     CLOCK_BOOTTIME       monotonic, includes suspend time.
     CLOCK_PROCESS_CPUTIME_ID   CPU time used, for profiling.       */

/* The C standard's clock() returns CPU time in CLOCKS_PER_SEC
   units and is nearly useless for wall-clock measurement.       */

Signals: async-signal-safety

What you may legally do inside a signal handler is far more restricted than most code assumes — the list of safe functions is short, and almost nothing in the standard library is on it.

/* A signal handler interrupts the program at an arbitrary point,
   possibly in the middle of malloc or printf. Almost nothing is
   safe to call from one.                                        */

/* SAFE inside a handler: a short list, including
     write(), _exit(), signal(), sigaction(), and assignment to a
     volatile sig_atomic_t.

   NOT safe: malloc, free, printf, any stdio, most of libc.      */

static volatile sig_atomic_t got_sigint = 0;

static void handler(int sig) { got_sigint = 1; }   /* that is ALL */

int main(void)
{
        struct sigaction sa = { .sa_handler = handler };
        sigemptyset(&sa.sa_mask);
        sigaction(SIGINT, &sa, NULL);      /* prefer over signal() */

        while (!got_sigint)
                do_work();                  /* the real work happens here */
}

/* The modern alternative on Linux: signalfd() or a self-pipe, which
   turn a signal into a readable file descriptor you can poll —
   removing the async-safety problem entirely.                    */
