Print-based debugging and tracing

The most-used debugging technique in systems programming, and the one most often done badly. A well-designed trace answers questions a debugger cannot — because it does not stop time.

Why printing beats breakpoints

   A DEBUGGER STOPS THE WORLD. That is exactly wrong for:

     · REAL-TIME systems - stop for 200 ms and the motor
       controller has already faulted, the watchdog has
       fired, or the USB host has dropped the device
     · INTERRUPT HANDLERS - a breakpoint in an ISR changes
       the latency you are trying to measure
     · RACES - stopping one thread changes the interleaving,
       and the bug disappears
     · PROTOCOL TIMING - the peer times out while you look
       at a variable
     · PRODUCTION - you cannot attach a debugger to a
       customer's device in the field
     · and ANY BUG THAT TAKES HOURS TO APPEAR - you cannot
       single-step for six hours

   A TRACE RECORDS WHAT HAPPENED AND LETS THE SYSTEM RUN.
   You get the SEQUENCE, which is usually the actual
   question:

     what happened before the failure?
     in what ORDER did these events occur?
     how LONG did that take?
     how many times did that path execute?
     what did the state look like over TIME?

   A DEBUGGER ANSWERS "what is true NOW". A TRACE ANSWERS
   "what happened, and in what order". MOST BUGS ARE
   SEQUENCE BUGS.

   THE OTHER SIDE OF THE TRADE, honestly:
     · a trace only shows what you thought to record
     · you must rebuild and re-run to add a field
     · printing PERTURBS TIMING - the classic heisenbug,
       where adding a printf makes the race disappear
     · and it costs code space and bandwidth

   USE BOTH. A debugger to inspect a stopped state
   (chapter 03); a trace to understand a sequence.

What a good trace line contains

/* BAD - and every codebase is full of these: */
    printf("here\n");
    printf("value = %d\n", x);
    printf("error!\n");

/* Useless in a log with a thousand lines from twelve
   modules, and completely useless six months later.

/* GOOD: */
    [00123.456] [INFO ] [i2c    ] i2c.c:214 xfer addr=0x50
                len=32 -> OK (1.2ms)
    [00123.458] [WARN ] [sensor ] sen.c:88  temp=87.5C
                exceeds limit 85.0C
    [00123.461] [ERROR] [net    ] net.c:512 tx failed
                errno=110 (ETIMEDOUT) retry=3/5

/* THE SEVEN FIELDS THAT EARN THEIR SPACE:

   1. TIMESTAMP. Monotonic, high resolution. THE SINGLE
      MOST VALUABLE FIELD - it gives you ordering and
      duration for free. Use a monotonic clock, never
      wall-clock time, which jumps.

   2. LEVEL. So you can filter without rebuilding.

   3. SUBSYSTEM. So you can filter to one module.

   4. LOCATION. File and line, or the function name.
      __FILE__, __LINE__, __func__ cost nothing to add.

   5. THE OPERATION, named in a way you can grep for.

   6. THE VALUES, with UNITS and in a consistent radix.
      "temp=87.5C" not "temp is high". "addr=0x50" not
      "addr=80".

   7. THE OUTCOME, including the ERROR CODE AND ITS NAME.
      "errno=110 (ETIMEDOUT)" saves the reader a lookup.

/* --- THE PATTERN THAT MAKES IT GREPPABLE --- */
    Log KEY=VALUE pairs, consistently. Then:

      grep 'i2c' log.txt | grep 'ERROR'
      awk '/xfer/ {print $NF}' log.txt | sort | uniq -c

    Structured logging (JSON lines) goes further and is
    worth it on Linux-class systems. On an MCU, consistent
    key=value text is the right level.                    */

The logging layer

/* ------------------------------------------------------
 * log.h - a complete, compile-time-filtered logging layer
 * ------------------------------------------------------ */
#ifndef LOG_H
#define LOG_H

#include <stdint.h>

#define LOG_LEVEL_NONE   0
#define LOG_LEVEL_ERROR  1
#define LOG_LEVEL_WARN   2
#define LOG_LEVEL_INFO   3
#define LOG_LEVEL_DEBUG  4
#define LOG_LEVEL_TRACE  5

/* Per-module override: define LOG_LEVEL before including,
   so one noisy driver can be turned up without drowning in
   everything else. */
#ifndef LOG_LEVEL
#define LOG_LEVEL LOG_LEVEL_INFO
#endif

#ifndef LOG_TAG
#define LOG_TAG "app"
#endif

uint32_t log_time_ms(void);
void log_write(const char *fmt, ...);

/* THE do/while(0) WRAPPER: makes the macro a single
   statement, so `if (x) LOG_INFO(...); else ...` compiles
   correctly (see the C track). */
#define LOG_AT(lvl, tag_str, fmt, ...)                    \
    do {                                                  \
        log_write("[%8lu] [%-5s] [%-7s] %s:%d " fmt "\n", \
                  (unsigned long)log_time_ms(), tag_str,  \
                  LOG_TAG, __FILE__, __LINE__,            \
                  ##__VA_ARGS__);                         \
    } while (0)

/* COMPILED OUT ENTIRELY when the level is too low - the
   string literals do not even reach the binary, which
   matters when flash is 256 KB. */
#if LOG_LEVEL >= LOG_LEVEL_ERROR
#define LOG_ERROR(f, ...) LOG_AT(1,"ERROR",f,##__VA_ARGS__)
#else
#define LOG_ERROR(f, ...) ((void)0)
#endif

#if LOG_LEVEL >= LOG_LEVEL_WARN
#define LOG_WARN(f, ...)  LOG_AT(2,"WARN", f,##__VA_ARGS__)
#else
#define LOG_WARN(f, ...)  ((void)0)
#endif

#if LOG_LEVEL >= LOG_LEVEL_INFO
#define LOG_INFO(f, ...)  LOG_AT(3,"INFO", f,##__VA_ARGS__)
#else
#define LOG_INFO(f, ...)  ((void)0)
#endif

#if LOG_LEVEL >= LOG_LEVEL_DEBUG
#define LOG_DEBUG(f, ...) LOG_AT(4,"DEBUG",f,##__VA_ARGS__)
#else
#define LOG_DEBUG(f, ...) ((void)0)
#endif

#endif /* LOG_H */

/* --- USE --- */
#define LOG_TAG   "i2c"
#define LOG_LEVEL LOG_LEVEL_DEBUG
#include "log.h"

int i2c_xfer(uint8_t addr, const uint8_t *buf, size_t len)
{
    uint32_t t0 = log_time_ms();
    LOG_DEBUG("xfer addr=0x%02X len=%u", addr,
              (unsigned)len);

    int rc = hw_xfer(addr, buf, len);
    if (rc != 0) {
        LOG_ERROR("xfer addr=0x%02X failed rc=%d (%s)",
                  addr, rc, i2c_strerror(rc));
        return rc;
    }
    LOG_DEBUG("xfer addr=0x%02X ok (%lums)", addr,
              (unsigned long)(log_time_ms() - t0));
    return 0;
}

/* --- A HEX DUMP, which you will want constantly --- */
void log_hexdump(const char *label, const void *data,
                 size_t len)
{
    const uint8_t *p = data;
    LOG_DEBUG("%s (%u bytes):", label, (unsigned)len);
    for (size_t i = 0; i < len; i += 16) {
        char line[80];
        int n = snprintf(line, sizeof line, "  %04X: ",
                         (unsigned)i);
        for (size_t j = 0; j < 16 && i + j < len; j++)
            n += snprintf(line + n, sizeof line - n,
                          "%02X ", p[i + j]);
        /* pad, then the ASCII column */
        while (n < 8 + 48)
            line[n++] = ' ';
        for (size_t j = 0; j < 16 && i + j < len; j++) {
            uint8_t c = p[i + j];
            line[n++] = (c >= 32 && c < 127) ? (char)c : '.';
        }
        line[n] = '\0';
        LOG_DEBUG("%s", line);
    }
}
Never log a secret

Keys, passwords, tokens, personal data. A UART pad on the board is accessible to anyone with a soldering iron, and a log file gets emailed to support (cryptography chapter 18). Log a fingerprint — the first four bytes of a hash — if you need to confirm which key is in use. Add a review check for it; this is one of the most common ways a shipped product leaks its own credentials.

When printing is too slow

/* A 115200-BAUD UART CARRIES ~11 KB/S. One 80-character
   line takes 7 MILLISECONDS. In an interrupt handler that
   runs every 100 microseconds, that is not debugging - it
   is a denial of service against your own system.

/* --- 1. RING BUFFER, DEFERRED OUTPUT --- */
    The ISR writes into a RAM buffer and returns. The idle
    loop drains it to the UART.

    static char logbuf[4096];
    static volatile uint32_t head, tail;

    void log_put(const char *s, size_t n) {
        /* single producer here; for multiple producers use
           an atomic head increment (see the OS track) */
        for (size_t i = 0; i < n; i++) {
            uint32_t next = (head + 1) % sizeof logbuf;
            if (next == tail) break;   /* FULL: DROP.
                                          Never block. */
            logbuf[head] = s[i];
            head = next;
        }
    }
    /* AND COUNT THE DROPS. A log that silently discards
       lines will mislead you at the worst moment; print
       "[dropped 412]" when it recovers. */

/* --- 2. BINARY / DEFERRED-FORMAT LOGGING --- */
    Do not format on the device. Log an EVENT ID and raw
    arguments; a host tool formats them using the same
    string table extracted from the ELF.

      · a trace point becomes ~8 bytes instead of 80
      · no snprintf on the target - which is often the
        single largest and slowest function in a small
        firmware image
      · format strings live in the ELF, not in flash

    THIS IS WHAT SEGGER RTT + SystemView, TraceX, Zephyr's
    dictionary logging and the Linux kernel's tracepoints
    all do.

/* --- 3. SEGGER RTT --- */
    Uses the debug probe's memory access to read a RAM ring
    buffer WHILE THE TARGET RUNS. No UART, no pins,
    megabytes per second, and microseconds per call. IF YOU
    HAVE A J-LINK, USE IT - it removes the timing
    perturbation almost entirely.

/* --- 4. ITM / SWO --- */
    ARM Cortex-M's instrumentation trace: write a byte to a
    register, the trace unit streams it out the SWO pin.
    Single-cycle cost.

      ITM_SendChar(c);          /* CMSIS */

    32 stimulus ports, so you can separate channels. Needs
    the SWO pin and a probe that supports it.

/* --- 5. A GPIO PIN AND A SCOPE --- */
    THE FASTEST INSTRUMENTATION THAT EXISTS, and frequently
    the best:

      GPIOA->BSRR = PIN;      /* one store */
      do_the_thing();
      GPIOA->BSRR = PIN << 16;

    A few nanoseconds. Put a scope or logic analyser on it
    and you get EXACT timing, jitter, and the relationship
    to other signals - things no software trace can give
    you. Toggle a different pin in each ISR and you can SEE
    your system's scheduling.

    THIS IS THE TECHNIQUE THAT SEPARATES EMBEDDED DEBUGGING
    FROM APPLICATION DEBUGGING. Use it.

/* --- 6. TRACE BUFFER IN NON-VOLATILE MEMORY --- */
    For crashes: a small circular buffer in a RAM region
    excluded from initialisation, or in flash. After a
    watchdog reset, dump the last events that preceded it.
    Combined with a reset-reason register, this is how you
    debug field failures you cannot reproduce.          */

Tracing on Linux and Windows

/* --- LINUX KERNEL --- */
    printk(KERN_INFO "mydrv: probe %s\n", dev_name(dev));
    dev_info(dev, "probe ok\n");        /* PREFERRED -
                                           includes the
                                           device name */
    dev_err(dev, "failed: %d\n", ret);
    dev_dbg(dev, "reg=0x%08x\n", val);  /* dynamic debug */

    /* enable dev_dbg at runtime, no rebuild: */
    # echo 'module mydrv +p' > \
        /sys/kernel/debug/dynamic_debug/control
    # echo 'file mydrv.c line 100-200 +p' > \
        /sys/kernel/debug/dynamic_debug/control

    /* TRACEPOINTS - near-zero cost when disabled */
    # cd /sys/kernel/tracing
    # echo 1 > events/irq/enable
    # cat trace_pipe

    /* trace_printk() for temporary work: goes to the ftrace
       ring buffer instead of the console, so it is
       thousands of times cheaper than printk. Remove it
       before you submit anything. */

    /* AND THE BIG ONES, covered in chapter 04:
       ftrace, perf, eBPF/bpftrace, LTTng. */

/* --- WINDOWS KERNEL --- */
    DbgPrintEx(DPFLTR_IHVDRIVER_ID, DPFLTR_INFO_LEVEL,
               "mydrv: probe\n");

    /* WPP SOFTWARE TRACING is the production answer: */
    DoTraceMessage(TRACE_LEVEL_INFORMATION,
                   "xfer addr=%!HEXDUMP! len=%d", ...);

    · formatted OFF the device by a trace consumer
    · negligible runtime cost
    · always compiled in, enabled at runtime
    · integrated with ETW (Event Tracing for Windows), so
      it correlates with the rest of the system

    Chapter 05 covers the tooling.

/* --- THE COMMON PRINCIPLE ACROSS ALL THREE PLATFORMS --- */
    THE BEST TRACING SYSTEMS ARE ALWAYS COMPILED IN,
    NEGLIGIBLE WHEN DISABLED, AND ENABLED AT RUNTIME.

    A debug build you have to install to diagnose a problem
    is not available when you need it - the problem is
    happening on a production unit, now. Design so that the
    instrumentation is already there and only needs turning
    on.                                                   */

How it shows up

SymptomCause
Adding a printf makes the bug vanishTiming perturbation — use RTT, ITM or a GPIO
System misses deadlines with logging onBlocking UART writes — defer to a ring buffer
Log stops partway through a failureBuffer full and dropping, or the crash beat the drain
Log lines interleaved and corruptedMultiple producers with no locking or atomic head
Cannot tell what order events occurred inNo timestamps, or wall-clock time that jumped
Flash full after adding loggingFormat strings — use deferred-format or dictionary logging
Cannot reproduce in a debug buildThe bug is timing-dependent — trace instead
Field unit fails, no informationNo persistent trace buffer across reset
Credentials found in a support logSecrets logged — log a fingerprint instead
Log too noisy to readNo per-module levels or subsystem tags
