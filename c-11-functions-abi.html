Functions, calling conventions and varargs

A function call is a contract between two pieces of code that may have been compiled separately. This chapter covers what C guarantees about that contract, what the ABI adds, and why varargs is the least safe thing in the language.

C is pass-by-value, always

There are no exceptions

Every argument is copied into the function. The function receives a private copy and cannot modify the caller's object. "Pass by reference" in C is a convention: you pass a copy of a pointer, and the function modifies what that pointer designates.

void bad_swap(int a, int b) { int t = a; a = b; b = t; }
/* modifies copies; the caller sees nothing */

void good_swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }
good_swap(&x, &y);
/* the POINTERS are still passed by value — but they point at the
   caller's objects, so writing through them is visible.        */

/* This is also why you need a pointer-to-pointer to change a
   caller's pointer (chapter 04):                              */
void alloc(char **out) { *out = malloc(100); }

/* And why passing a large struct by value is a real cost: */
void f(struct big s);          /* copies sizeof(struct big) bytes */
void f(const struct big *s);   /* copies 8 bytes                  */
/* Rule of thumb: pass by pointer above ~2 machine words, and use
   const to document that you will not modify it.               */

Prototypes matter

A function declaration without a prototype was legal in old C and disables all argument checking, which means calls can be silently wrong. Modern C closed this, and legacy code still contains it.

/* THREE different declarations, and only one is right in modern C */

int f();              /* pre-C23: UNSPECIFIED number of arguments.
                         No checking at all. C23: same as (void).  */
int f(void);          /* takes NO arguments. Checked.              */
int f(int, char *);   /* full prototype. Checked.                  */

/* With `int f();` the compiler cannot check your call site: */
f(1, 2, 3);           /* accepted; arguments passed per default
                         promotions; behaviour undefined if the
                         definition disagrees                      */

/* This is why every C project should build with: */
//   -Wstrict-prototypes    warn on ()
//   -Wmissing-prototypes   warn on a non-static function with no
//                          prior prototype (catches typos in names)
//   -Wold-style-definition

/* And why implicit declaration is fatal. Pre-C99, calling an
   undeclared function assumed it returned int:               */
double x = sqrt(2.0);       /* without #include <math.h>: assumed to
                               return int, so x gets garbage      */
/* C99 removed implicit declarations. GCC 14 and Clang 16 finally
   made it a hard error by default. If you see
   "implicit declaration of function", you are missing a header —
   never silence it with a cast.                               */

The calling convention

C says nothing about how arguments reach the callee. That is defined by the platform ABI, and it is what makes separately compiled code interoperate.

AArch64 (AAPCS64) — the convention on every ARM64 system

  X0-X7    integer/pointer arguments 1-8, and return value in X0
  X8       indirect result pointer (for large struct returns)
  X9-X15   caller-saved temporaries
  X16,X17  IP0/IP1 — reserved for linker veneers
  X18      platform register (TLS on Windows; reserved on some OSes)
  X19-X28  CALLEE-saved: if you use them, save and restore them
  X29      FP  frame pointer
  X30      LR  link register — the return address, set by BL
  SP       stack pointer, must be 16-byte aligned at every call
  V0-V7    floating point / SIMD arguments and return
  V8-V15   callee-saved (lower 64 bits only)

  Arguments beyond 8 go on the stack, right to left.

x86-64 System V (Linux, macOS)
  RDI RSI RDX RCX R8 R9  integers;  XMM0-7 floats;  RAX returns

x86-64 Microsoft
  RCX RDX R8 R9 only — just four register arguments, plus a
  32-byte "shadow space" the caller must reserve.

  This is why calling convention mismatches are a real bug class
  in cross-platform code and in hand-written assembly.
/* what a function's prologue and epilogue are actually doing */
my_func:
        stp     x29, x30, [sp, #-32]!   /* push FP and LR, SP -= 32   */
        mov     x29, sp                 /* establish the frame        */
        stp     x19, x20, [sp, #16]     /* save callee-saved regs     */
        ...
        ldp     x19, x20, [sp, #16]     /* restore                     */
        ldp     x29, x30, [sp], #32     /* pop, SP += 32               */
        ret                             /* branch to X30               */

/* The 16-byte SP alignment requirement is not advisory. Violating
   it faults on any instruction that assumes it, and produces
   corruption that looks random. Hand-written assembly gets this
   wrong constantly.                                            */

Variadic functions

Functions taking a variable number of arguments get no type checking whatsoever on those arguments, which is why printf with a mismatched format is such a reliable source of bugs.

#include <stdarg.h>

int sum(int count, ...)
{
        va_list ap;
        va_start(ap, count);           /* last NAMED parameter */

        int total = 0;
        for (int i = 0; i < count; i++)
                total += va_arg(ap, int);   /* type must be correct */

        va_end(ap);                     /* required */
        return total;
}
sum(3, 10, 20, 30);
Why varargs is the least safe construct in C
  • No type checking whatsoever. va_arg(ap, int) on a double argument reads the wrong bytes from the wrong place. There is no diagnostic.
  • No count. The function cannot know how many arguments it received. You must encode it in a named parameter or a sentinel — and if the caller lies, you read past the argument area.
  • Default argument promotions apply and surprise people: float becomes double, and anything narrower than int becomes int. So va_arg(ap, char) and va_arg(ap, float) are always wrong.
  • NULL is not a pointer. Passing bare NULL as a variadic sentinel may pass a 32-bit 0 where a 64-bit pointer is expected. Write (void *)NULL.
/* the promotion traps */
f(1, 'a', 3.14f);
        va_arg(ap, char)    /* WRONG: promoted to int   -> use int    */
        va_arg(ap, float)   /* WRONG: promoted to double -> use double */
        va_arg(ap, short)   /* WRONG                    -> use int    */

/* the sentinel trap */
execl("/bin/ls", "ls", NULL);          /* may pass 32-bit 0 */
execl("/bin/ls", "ls", (char *)NULL);  /* correct           */

/* Getting the compiler to help with printf-like functions: */
void my_log(const char *fmt, ...)
        __attribute__((format(printf, 1, 2)));
/* Now -Wformat checks your call sites exactly as it does printf's.
   Add this to every logging function you write — it is free, and
   it catches a genuinely common bug class.                      */

/* Forwarding varargs requires the v-variants: */
void my_log(const char *fmt, ...)
{
        va_list ap;
        va_start(ap, fmt);
        vfprintf(stderr, fmt, ap);      /* NOT fprintf(...) */
        va_end(ap);
}

/* Reusing a va_list after it has been consumed is UB. Copy it: */
va_list ap2;
va_copy(ap2, ap);
int len = vsnprintf(NULL, 0, fmt, ap);   /* measure */
char *buf = malloc(len + 1);
vsnprintf(buf, len + 1, fmt, ap2);       /* format  */
va_end(ap2);
Alternatives worth preferring

Pass an array plus a count. Use a struct with designated initialisers. In C11, use _Generic for type-safe dispatch. Variadic macros (__VA_ARGS__) are checked because they expand into real calls — prefer them for logging wrappers. Reserve genuine varargs for printf-shaped APIs, and always attach the format attribute.

_Generic: type-safe dispatch

C11 added a way to select an expression based on the type of an argument, which is the closest the language comes to overloading. It appears mostly inside macros that need to behave differently per type.

/* C11's answer to "I want one name for several types" */
#define abs(x) _Generic((x),        \
        int:         abs,           \
        long:        labs,          \
        long long:   llabs,         \
        float:       fabsf,         \
        double:      fabs,          \
        default:     fabs           \
)(x)

/* Selection happens at COMPILE TIME on the static type of the
   controlling expression. The unselected branches are not even
   evaluated, so this is zero-cost.                            */

/* A practical use: type-safe printing helpers */
#define print(x) _Generic((x),               \
        int:          print_int,             \
        const char *: print_str,             \
        char *:       print_str,             \
        double:       print_double           \
)(x)

inline and noreturn

inline in C does not simply mean "paste this in". It is a linkage rule with genuinely confusing semantics, and the combination that actually works in a header is worth memorising.

/* `static inline` in a header — use this, essentially always */
static inline int max(int a, int b) { return a > b ? a : b; }

/* Plain `inline` in C has a rule almost nobody applies correctly:
   an inline definition provides no external definition, so exactly
   one TU must also provide `extern inline` (C99) or a non-inline
   definition. Get it wrong and you get "undefined reference".
   `static inline` sidesteps the whole problem.                  */

/* inline is a HINT. These are not: */
__attribute__((always_inline)) static inline void f(void);
__attribute__((noinline))      void g(void);

/* noreturn lets the compiler drop the return path and improves
   warnings about uninitialised variables after a call.        */
#include <stdnoreturn.h>
noreturn void panic(const char *msg);          /* C11 */
[[noreturn]] void panic(const char *msg);      /* C23 */
__attribute__((noreturn)) void panic(const char *);   /* GCC */

Attributes worth knowing

Compiler attributes let you state things the language cannot express — that a function never returns, that its result must be used, that these arguments are a format string. Each one enables a class of warning you would otherwise never see.

AttributeEffect
format(printf, m, n)Enables -Wformat checking on your own logging functions
warn_unused_resultWarns if the return value is ignored — essential for functions that can fail
nonnull(1, 2)Documents and checks that parameters must not be NULL
mallocTells the optimiser the returned pointer does not alias anything
pure / constNo side effects / depends only on arguments — enables CSE
cleanup(fn)Calls fn when the variable goes out of scope — RAII in C
weakThe symbol may be overridden; used for optional hooks in firmware
section("name")Place in a specific linker section
 
/* cleanup gives you scope-based resource management in plain C.
   The Linux kernel adopted this in 6.5 and it is spreading fast. */
static inline void free_ptr(void *p) { free(*(void **)p); }
#define _cleanup_free_ __attribute__((cleanup(free_ptr)))

void f(void)
{
        _cleanup_free_ char *buf = malloc(100);
        if (!buf) return;                  /* freed automatically */
        if (error) return;                 /* freed automatically */
        ...
}                                          /* freed automatically */

/* This removes the goto-ladder for the common single-resource case.
   It is a GCC/Clang extension, not ISO C.                        */
