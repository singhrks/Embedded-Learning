TrustZone: hardware enforcement blocks

The NS bit is only a promise until something checks it. This chapter covers the blocks that actually do the checking — where they sit, what they can express, and what a partial implementation leaves open.

Where the checks happen

The NS bit only means something because hardware blocks enforce it. These are those blocks — and a platform missing any of them has a weaker boundary than the architecture implies.

TZASC — memory regions

The block that partitions DRAM between the worlds. Without it, secure memory would be protected only by page tables that the normal world's own hardware could be persuaded to ignore.

/* The TrustZone Address Space Controller sits in front of the
   memory controller and applies a REGION TABLE.             */

   Per region:
      base address, size (power of two, or a range)
      security setting: Secure only / Non-secure only / both
      per-master read and write permission bitmap
      subregion disable mask (split a region into 8 parts)
      LOCK bit — write-once until reset

   A Non-secure access to a Secure region gets an ERROR
   RESPONSE, which becomes an external abort at the CPU
   (ARM chapter 29, DFSC 0b010000) — or, on some
   configurations, silently returns zeros.

/* Arm's TZC-400 is the common licensed implementation; vendors
   also build their own. Typical: 8 or 9 regions, one of which
   (region 0) is the DEFAULT covering everything not otherwise
   described.                                                */

/* Configuring it — firmware only, and once: */
static void tzc_configure_region(int region, uint64_t base,
                                 uint64_t top, unsigned sec_attr,
                                 unsigned ns_master_bitmap)
{
        tzc_write_region_base(region, base);
        tzc_write_region_top(region, top);
        tzc_write_region_attributes(region,
                (sec_attr << TZC_ATTR_SEC_SHIFT) | TZC_ATTR_REGION_EN);
        tzc_write_region_id_access(region, ns_master_bitmap);
}

/* And the default region must be RESTRICTIVE: */
        tzc_set_action(TZC_ACTION_ERR);          /* fail loudly   */
        tzc_configure_region0(TZC_REGION_S_RDWR, /* secure only   */
                              0);                /* no NS masters */
        /* then open up the specific ranges the normal world needs */

/* Getting region 0 wrong — leaving it permissive — means every
   address you did not explicitly describe is wide open. This is
   the fail-closed principle from chapter 01, applied.      */

TZPC — peripheral assignment

The equivalent for peripherals: which devices the normal world may even see. A peripheral assigned to the secure world simply does not respond to non-secure accesses.

/* The TrustZone Protection Controller marks whole peripherals
   Secure or Non-secure, often at RUNTIME.                   */

   TZPCDECPROT<n>SET     mark a peripheral NON-SECURE
   TZPCDECPROT<n>CLR     mark it SECURE
   TZPCR0SIZE            how much on-chip SRAM is secure

/* Each bit corresponds to one peripheral, per the SoC's TRM.
   A Non-secure access to a Secure-marked peripheral is refused
   at the peripheral's bus interface.                        */

/* Why RUNTIME assignment is useful:
     · a fingerprint sensor is Secure while enrolling or
       matching, Non-secure the rest of the time
     · a display controller becomes Secure for a trusted-UI
       prompt, then returns
     · a crypto engine is claimed by the TEE for one operation

   The secure world flips the bit, does the work, and flips it
   back. The normal world's driver simply finds the device
   unresponsive in the meantime — which is exactly the
   "reads all zeros" symptom of chapter 08, appearing and
   disappearing.                                             */

/* Which makes for a genuinely confusing bug report: "the sensor
   works, except sometimes". Check whether a TEE operation is
   claiming it.                                             */

Caches and TLBs

Caches are tagged with the security state, so a secure line and a non-secure line at the same address are different entries. That is what prevents the obvious cache-based attack across the boundary.

Neither is "banked" — instead every entry is TAGGED with the
security state that created it.

   cache line tag:   address + NS state
   TLB entry tag:    VA + ASID + VMID + NS state + regime

  So a Non-secure lookup cannot HIT a Secure line, even at the
  same address. The two worlds' data coexists in one cache
  without leaking.

  CONSEQUENCES:

  · no cache flush is needed on a world switch for CORRECTNESS,
    which is a large part of why the switch is as fast as it is

  · but a flush may be needed for SECURITY: the two worlds share
    the cache as a RESOURCE, so timing differences leak
    information (chapter 16). Hardened monitors flush or
    partition on switch, at a real performance cost.

  · TLB maintenance from the secure world must specify the right
    regime. TLBI ALLE3 does not invalidate EL1 entries, and
    Secure EL1 entries are distinct from Non-secure EL1 entries
    even at the same VA and ASID.

  · a cache line's NS tag comes from the ACCESS, not the
    address. Secure software creating an NS=1 mapping to shared
    memory (chapter 08) produces Non-secure lines — which is
    correct, and is how sharing works without aliasing.

GIC — interrupt groups

Interrupts are partitioned by group so that a secure interrupt cannot be taken, masked or even observed by the normal world — the interrupt-controller half of the same boundary.

GroupSignalled asTaken toUsed for
Group 0FIQAlways EL3Secure firmware's own interrupts
Secure Group 1IRQ in the secure world; FIQ in the non-secure worldS-EL1, or EL3Trusted OS interrupts
Non-secure Group 1IRQEL1 (or EL2)The normal OS
 
/* Configured in GICD_IGROUPR and GICD_IGRPMODR, writable only
   from the secure world.                                     */

/* The property that matters: a Non-secure OS clearing PSTATE.I
   masks only IRQ. A secure interrupt arrives as FIQ and is
   routed to EL3 by SCR_EL3.FIQ. The normal world CANNOT
   suppress it.

   Without this, a compromised kernel could simply disable
   interrupts and prevent the secure world from ever running —
   a denial of service against the TEE, and a way to defeat any
   secure watchdog.                                          */

/* And the reverse: GICD registers themselves are usually
   Secure-only for the group configuration, so the normal world
   cannot reassign an interrupt to its own group.

   On GICv3 the redistributor and CPU interface state are also
   banked by security state.                                */

SMMU secure interface

Device transactions carry the security state too, which is why the SMMU from earlier chapters is part of the TrustZone story rather than a separate topic.

/* SMMUv3 has TWO complete programming interfaces (chapter 04): */

   +0x0000   Non-secure   SMMU_*
   +0x8000   Secure       SMMU_S_*

/* Each with its own stream table, command queue, event queue and
   enable bit. Independent.

   WHY: a device operating in the secure world must be configured
   by SECURE firmware. If the Non-secure OS could program that
   device's translations, it could point a secure DMA engine at
   normal-world memory — reading secure data out through a
   device the normal world controls. A complete TrustZone
   bypass.

   And the STE and CD carry NSCFG fields determining whether the
   resulting transaction is issued Secure or Non-secure, exactly
   as the page descriptor NS bit does for the CPU.

   So the SMMU is not merely an isolation device for the normal
   world — it is part of the TrustZone boundary itself.     */

/* A common integration gap: an SoC implements the SMMU but not
   its secure interface (SMMU_IDR1.SECURE_IMPL = 0). Secure DMA
   masters are then unprotected, and must be constrained by an
   XPU instead (chapters 17-20).                            */

The best-designed HUK is never visible to software

On a well-built SoC, the hardware unique key is wired directly into the crypto engine's key input. Software asks the engine to "derive a key using the HUK" and receives a derived key; it never sees the HUK itself. Even a compromised trusted OS cannot extract it.

A design where software reads the HUK into a register is much weaker — a single memory-disclosure bug in the secure world then reveals the root of all device storage encryption, permanently and unfixably.

Debug authentication

Debug is a complete bypass of all of the above, which is why it is gated by its own authentication signals and why those are deasserted on production parts.

Four signals gate what a debugger may see:

   DBGEN     invasive debug (halt, single-step) in the NORMAL world
   NIDEN     non-invasive (trace, PMU) in the normal world
   SPIDEN    invasive debug of the SECURE world
   SPNIDEN   non-invasive of the secure world

  Driven by fuses, by a debug authentication module, or by a
  signed unlock token.

  Typical configurations:
     development part   all four asserted
     production part    DBGEN/NIDEN maybe, SPIDEN/SPNIDEN OFF
     locked-down        all four off

  CONSEQUENCES you will meet:
     · JTAG attaches but cannot see secure state — you can halt
       the core in the normal world and not in the secure one
     · the PMU counts normal-world events only, so a profile
       silently omits secure execution
     · CoreSight trace stops at the world boundary
     · a TEE bug that reproduces only on production silicon is
       very hard to debug — which is why development firmware
       should log aggressively

  RMA UNLOCK: a controlled path back, requiring a token signed
  by the vendor and usually destroying the device keys first so
  that unlocking cannot expose user data.

Where implementations fall short

Enforcement is only as complete as the silicon

TrustZone is a system-wide contract, and a partial implementation is a bypass. Real gaps that have shipped:

  • A peripheral that ignores the NS bit. Its registers are reachable from both worlds regardless of the TZPC.
  • A bus segment that drops or hard-codes NS. Everything downstream sees a fixed value.
  • A DMA master with no SMMU and no XPU. Full access to all memory, from whichever world can program it.
  • A TZASC default region left permissive. Anything not explicitly protected is open.
  • Debug signals not fused off in production. The most common finding in device security audits.
  • A configuration register left unlocked. A compromised secure world — or in bad cases the normal world — can widen the policy at runtime.

Verifying each of these is a real part of SoC security review, and it is done by testing the negative cases, not by reading the datasheet.

Verifying the configuration

Whether these blocks are actually configured as intended is checkable rather than assumable, and checking is a standard part of any security review of a platform.

/* Write these as a boot-time self-test in development firmware.
   A policy never exercised is a policy you do not know works. */

static void security_selftest(void)
{
        /* 1. Non-secure access to Secure DRAM must FAIL */
        expect_abort(read32_ns(SECURE_DRAM_BASE));

        /* 2. Non-secure access to a Secure peripheral must FAIL */
        expect_abort(read32_ns(SECURE_CRYPTO_BASE));

        /* 3. Secure access to Non-secure DRAM must SUCCEED */
        expect_ok(read32_s(NS_DRAM_BASE));

        /* 4. the TZASC default region must be restrictive */
        assert(tzc_region0_attr() == TZC_REGION_S_RDWR);

        /* 5. every region that should be locked, is */
        for (i = 0; i < nr_regions; i++)
                assert(tzc_region_locked(i) == expected_lock[i]);

        /* 6. debug signals match the lifecycle state */
        if (lifecycle_state() == LC_SECURED)
                assert(!spiden_asserted() && !spniden_asserted());

        /* 7. SCR_EL3 has the expected bits */
        assert(read_scr_el3() & SCR_SIF);
        assert(read_scr_el3() & SCR_FIQ);
        assert(read_scr_el3() & SCR_EA);
}

/* Run it in development builds, on a part in the FINAL
   lifecycle state. Chapter 19 covers building the complete
   access matrix systematically.                            */
