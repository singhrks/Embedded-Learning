The WDF device lifecycle

Which callback runs when, what belongs in each, and what the framework guarantees about the order. Get this table right and PnP, power management and surprise removal all work without you writing a state machine.

The order

A device passes through a fixed sequence of states from discovery to removal, and your callbacks fire at defined points in it. Learning the order is what tells you where each piece of your initialisation belongs.

   DriverEntry                        once, per driver load
        |
        v
   EvtDriverDeviceAdd                 once PER DEVICE
        |   create the WDFDEVICE, queues, interrupt objects
        |   NO HARDWARE ACCESS - resources are not assigned
        v
   EvtDevicePrepareHardware           resources assigned
        |   map registers, find the interrupt's descriptor
        |   PASSIVE_LEVEL
        v
   EvtDeviceD0Entry                   powering up
        |   initialise the hardware, restore state
        |   PASSIVE_LEVEL
        v
   EvtDeviceD0EntryPostInterruptsEnabled
        |   interrupts are now live; safe to start the device
        v
   ===== RUNNING: queues dispatch requests, ISR/DPC fire =====
        |
        v
   EvtDeviceD0ExitPreInterruptsDisabled
        |   stop the device generating interrupts
        v
   EvtDeviceD0Exit                    powering down
        |   quiesce, save state. THE DEVICE IS STILL THERE.
        v
   EvtDeviceReleaseHardware           resources revoked
        |   unmap. DO NOT TOUCH THE HARDWARE.
        v
   EvtCleanupCallback / EvtDestroyCallback
        |
        v
   DriverUnload / EvtDriverUnload     once

   AND THE POWER CYCLE, which happens repeatedly WITHOUT
   PrepareHardware/ReleaseHardware:

        D0Entry -> running -> D0Exit -> (sleep) -> D0Entry ...

   THAT IS THE KEY ASYMMETRY: PrepareHardware runs once per
   resource assignment; D0Entry runs on every power-up. So
   MAPPING goes in PrepareHardware and INITIALISATION goes in
   D0Entry - and putting initialisation in PrepareHardware
   produces a device that works until the first sleep.

What belongs where

CallbackDoDo not
DriverEntryWdfDriverCreate, global stateAnything per-device
EvtDriverDeviceAddCreate device, queues, interrupts, locks, timers; publish the interfaceTouch hardware — there is none yet
EvtDevicePrepareHardwareMap MMIO, read resource descriptors, allocate buffers sized from resourcesProgram the device
EvtDeviceD0EntryReset, configure, restore registers, verify the IDEnable interrupts (use the Post callback)
EvtDeviceD0ExitStop the device, save state, flushUnmap
EvtDeviceReleaseHardwareUnmap, free what PrepareHardware allocatedTouch the hardware
EvtDeviceSelfManagedIoInitStart self-managed I/O — timers, polling threads
EvtDeviceSelfManagedIoSuspendStop them, and wait
EvtDeviceSelfManagedIoCleanupFinal teardown of self-managed I/O
The rule that prevents the worst bug

EvtDeviceReleaseHardware can run after the device has physically been removed. A register read then returns 0xFFFFFFFF; a write may hang the bus or bugcheck. All hardware quiescing belongs in EvtDeviceD0Exit, which is guaranteed to run while the device is still present in the normal path — and which the framework skips the hardware-touching parts of on surprise removal.

The callbacks, implemented

Here are those callbacks written out, with the thing that actually belongs in each. The single most common mistake is touching hardware too early — before the system has given you the resources to touch it with.

NTSTATUS
MyPrepareHardware(_In_ WDFDEVICE Device,
                  _In_ WDFCMRESLIST ResourcesRaw,
                  _In_ WDFCMRESLIST ResourcesTranslated)
{
        PMY_CONTEXT ctx = MyGetContext(Device);
        ULONG i, count;
        BOOLEAN foundMemory = FALSE;

        PAGED_CODE();
        UNREFERENCED_PARAMETER(ResourcesRaw);

        count = WdfCmResourceListGetCount(ResourcesTranslated);

        for (i = 0; i < count; i++) {
                PCM_PARTIAL_RESOURCE_DESCRIPTOR desc =
                        WdfCmResourceListGetDescriptor(
                                ResourcesTranslated, i);

                switch (desc->Type) {
                case CmResourceTypeMemory:
                        if (foundMemory)
                                break;    /* only the first */

                        ctx->RegLength = desc->u.Memory.Length;
                        ctx->RegBase = (PUCHAR)MmMapIoSpaceEx(
                                desc->u.Memory.Start,
                                desc->u.Memory.Length,
                                PAGE_READWRITE | PAGE_NOCACHE);
                        if (ctx->RegBase == NULL)
                                return STATUS_INSUFFICIENT_RESOURCES;
                        foundMemory = TRUE;
                        break;

                case CmResourceTypeInterrupt:
                        /* WdfInterruptCreate in DeviceAdd
                           already claimed it (chapter 18) */
                        break;
                }
        }

        if (!foundMemory)
                return STATUS_DEVICE_CONFIGURATION_ERROR;

        return STATUS_SUCCESS;
}

NTSTATUS
MyD0Entry(_In_ WDFDEVICE Device,
          _In_ WDF_POWER_DEVICE_STATE PreviousState)
{
        PMY_CONTEXT ctx = MyGetContext(Device);
        ULONG id;

        UNREFERENCED_PARAMETER(PreviousState);

        /* The device may have lost all state. Verify it is
           there, then configure it from scratch.          */

        id = READ_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_ID));
        if (id != MY_EXPECTED_ID) {
                /* 0xFFFFFFFF means it is gone */
                return STATUS_DEVICE_NOT_CONNECTED;
        }

        /* reset */
        WRITE_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_CTRL),
                             CTRL_RESET);
        KeStallExecutionProcessor(10);
        WRITE_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_CTRL), 0);

        /* restore our configuration */
        WRITE_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_RATE),
                             ctx->SampleRate);

        return STATUS_SUCCESS;
}

NTSTATUS
MyD0EntryPostInterruptsEnabled(_In_ WDFDEVICE Device,
                        _In_ WDF_POWER_DEVICE_STATE PreviousState)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        UNREFERENCED_PARAMETER(PreviousState);

        /* interrupts are connected NOW - safe to let the
           device raise them                                */
        WRITE_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_INT_EN),
                             INT_ALL);
        return STATUS_SUCCESS;
}

NTSTATUS
MyD0ExitPreInterruptsDisabled(_In_ WDFDEVICE Device,
                        _In_ WDF_POWER_DEVICE_STATE TargetState)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        UNREFERENCED_PARAMETER(TargetState);

        /* stop the device asserting BEFORE the framework
           disconnects the interrupt - otherwise we take one
           with no handler                                  */
        WRITE_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_INT_EN),
                             0);
        return STATUS_SUCCESS;
}

NTSTATUS
MyD0Exit(_In_ WDFDEVICE Device,
         _In_ WDF_POWER_DEVICE_STATE TargetState)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        /* quiesce. The device is still present here. */
        WRITE_REGISTER_ULONG((PULONG)(ctx->RegBase + REG_CTRL), 0);

        /* wait for our own deferred work (chapter 11) */
        WdfDpcCancel(ctx->Dpc, TRUE);
        WdfTimerStop(ctx->Timer, TRUE);

        if (TargetState == WdfPowerDeviceD3Final) {
                /* the device is going away for good */
        }

        return STATUS_SUCCESS;
}

NTSTATUS
MyReleaseHardware(_In_ WDFDEVICE Device,
                  _In_ WDFCMRESLIST ResourcesTranslated)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        PAGED_CODE();
        UNREFERENCED_PARAMETER(ResourcesTranslated);

        /* NO HARDWARE ACCESS HERE. */

        if (ctx->RegBase) {
                MmUnmapIoSpace(ctx->RegBase, ctx->RegLength);
                ctx->RegBase = NULL;
        }
        return STATUS_SUCCESS;
}

Power states

A device is not simply on or off. It moves between power states while the system is running and while the system itself sleeps, and your driver is expected to save and restore whatever the hardware forgets at each transition.

/* DEVICE states (D-states): */
        D0   fully on
        D1   light sleep, context preserved (rare)
        D2   deeper (rare)
        D3hot powered down, still in the slot
        D3cold power removed entirely

/* WDF's enumeration adds the reason: */
        WdfPowerDeviceD0
        WdfPowerDeviceD1 / D2 / D3
        WdfPowerDeviceD3Final     <-- the device is being
                                      REMOVED, not just slept
        WdfPowerDevicePrepareForHibernation
        WdfPowerDeviceMaximum

/* CHECK FOR D3Final in D0Exit: it distinguishes "going to
   sleep, we will be back" from "goodbye". Freeing things in
   the first case leaves you broken on resume.            */

/* SYSTEM states (S-states): S0 working, S3 sleep, S4
   hibernate, S5 off. The power manager maps a system
   transition onto D-state transitions for each device.

/* IDLE POWER MANAGEMENT - let the device sleep when unused: */

        WDF_DEVICE_POWER_POLICY_IDLE_SETTINGS idleSettings;

        WDF_DEVICE_POWER_POLICY_IDLE_SETTINGS_INIT(
                &idleSettings, IdleCanWakeFromS0);
        idleSettings.IdleTimeout   = 5000;    /* ms */
        idleSettings.UserControlOfIdleSettings =
                        IdleAllowUserControl;
        idleSettings.Enabled = WdfTrue;

        status = WdfDeviceAssignS0IdlePolicy(device,
                                             &idleSettings);

/* Then the framework calls D0Exit after 5 seconds of no
   requests, and D0Entry when the next one arrives - stalling
   the request until the device is up. You write nothing else.

   This is the direct counterpart of Linux's runtime PM
   (ch. 37), and it is considerably less code because the
   framework does the reference counting through the queues
   rather than making you bracket every access.           */

/* WAKE FROM SLEEP: */
        WDF_DEVICE_POWER_POLICY_WAKE_SETTINGS wakeSettings;

        WDF_DEVICE_POWER_POLICY_WAKE_SETTINGS_INIT(
                &wakeSettings);
        status = WdfDeviceAssignSxWakeSettings(device,
                                               &wakeSettings);

Self-managed I/O

Some work does not fit the ordinary power callbacks — a background poll that must stop before the device powers down, for instance. Self-managed I/O is the set of callbacks for exactly that case.

/* Queues are stopped and started by the framework around
   power transitions. But work you started YOURSELF - a
   polling timer, a system thread, a continuous DMA - is not
   known to the framework. Self-managed I/O callbacks are
   where you handle it.                                     */

        WDF_PNPPOWER_EVENT_CALLBACKS pnpPower;

        WDF_PNPPOWER_EVENT_CALLBACKS_INIT(&pnpPower);
        pnpPower.EvtDeviceSelfManagedIoInit    = MySmIoInit;
        pnpPower.EvtDeviceSelfManagedIoSuspend = MySmIoSuspend;
        pnpPower.EvtDeviceSelfManagedIoRestart = MySmIoRestart;
        pnpPower.EvtDeviceSelfManagedIoCleanup = MySmIoCleanup;

NTSTATUS
MySmIoInit(_In_ WDFDEVICE Device)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        /* runs ONCE, after the first D0Entry */
        WdfTimerStart(ctx->PollTimer,
                      WDF_REL_TIMEOUT_IN_MS(100));
        return STATUS_SUCCESS;
}

NTSTATUS
MySmIoSuspend(_In_ WDFDEVICE Device)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        /* STOP AND WAIT. The framework will not proceed with
           the power transition until this returns, so
           anything still running afterwards is a bug you
           introduced.                                       */
        WdfTimerStop(ctx->PollTimer, TRUE);   /* TRUE = wait */
        WdfWorkItemFlush(ctx->WorkItem);
        return STATUS_SUCCESS;
}

NTSTATUS
MySmIoRestart(_In_ WDFDEVICE Device)
{
        PMY_CONTEXT ctx = MyGetContext(Device);

        WdfTimerStart(ctx->PollTimer,
                      WDF_REL_TIMEOUT_IN_MS(100));
        return STATUS_SUCCESS;
}

VOID
MySmIoCleanup(_In_ WDFDEVICE Device)
{
        /* final teardown - the device is going away */
}

/* THE SEQUENCE around a sleep:
     SelfManagedIoSuspend -> D0ExitPre -> D0Exit
     ... sleep ...
     D0Entry -> D0EntryPost -> SelfManagedIoRestart

   IF YOU HAVE NO TIMERS OR THREADS OF YOUR OWN, you do not
   need these callbacks at all. That is the common case - and
   another reason to prefer queues over self-started work. */

Surprise removal

A user can unplug a device while your driver is mid-transfer. Surprise removal is that path, and it is the least-tested code in most drivers precisely because it never happens during development unless you deliberately cause it.

/* The user unplugged it. The hardware is GONE.

   WHAT THE FRAMEWORK DOES:
     · fails all new requests with STATUS_DEVICE_REMOVED
     · calls EvtDeviceSurpriseRemoval if you registered one
     · SKIPS D0Exit's hardware access expectations - but it
       still CALLS D0Exit, so your code must tolerate a
       missing device
     · calls ReleaseHardware
     · destroys the device

   WHAT YOU MUST DO:
     · detect the "all ones" read and stop rather than
       retrying forever
     · never wait for hardware without a timeout
     · complete every pending request                      */

static BOOLEAN
MyDeviceIsPresent(PMY_CONTEXT ctx)
{
        ULONG id = READ_REGISTER_ULONG(
                        (PULONG)(ctx->RegBase + REG_ID));

        return (id != 0xFFFFFFFF) && (id == MY_EXPECTED_ID);
}

        /* use it before any operation that would otherwise
           poll: */
        if (!MyDeviceIsPresent(ctx)) {
                WdfRequestComplete(request,
                                   STATUS_DEVICE_REMOVED);
                return;
        }

/* TESTING IT: in Device Manager, disable the device while I/O
   is in flight. Or, for USB, unplug it during a transfer. Or
   use the WDK's "Device Fundamentals" tests, which do exactly
   this automatically - and which you must pass for
   certification anyway (chapter 22).                     */
