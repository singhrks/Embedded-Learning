Bit manipulation: XOR, subsets and tricks

The problem-solving half. XOR as a cancelling accumulator, integers as sets, and the handful of tricks that turn a hard-looking question into two lines.

XOR as a cancelling accumulator

XOR is worth treating as an accumulator that cancels rather than as a bitwise operator. Four properties explain every XOR problem you will ever be asked.

   THE FOUR PROPERTIES, and every XOR problem uses them:

     x ^ x = 0            a value CANCELS itself
     x ^ 0 = x            zero is the identity
     COMMUTATIVE          a ^ b = b ^ a
     ASSOCIATIVE          (a^b)^c = a^(b^c)

   CONSEQUENCE: XOR-ing a whole collection together makes
   every PAIR vanish, whatever the order. Whatever survives
   is what appeared an ODD number of times.

     [4, 1, 2, 1, 2]  ->  4^1^2^1^2
                       =  4^(1^1)^(2^2)
                       =  4^0^0  =  4

   THAT IS "SINGLE NUMBER" IN ONE LINE, in O(1) space, and
   it is why the pattern is worth recognising instantly.

   ---------------------------------------------------------
   TWO NUMBERS APPEARING ONCE — the two-pass trick

     xorAll = a ^ b            (everything else cancels)

     Any set bit in xorAll is a position where a and b
     DIFFER. Pick the lowest:

        diff = xorAll & -xorAll

     Now PARTITION the input by that bit. a and b land in
     different groups, and every duplicate pair lands in the
     SAME group (equal values have equal bits). XOR each
     group separately and you get a and b.

   ---------------------------------------------------------
   EVERY NUMBER APPEARS THREE TIMES, one appears once

     XOR fails — three copies leave one behind. Instead,
     count each bit position modulo 3:

        ones = (ones ^ x) & ~twos;
        twos = (twos ^ x) & ~ones;

     `ones` holds bits seen 1 mod 3 times, `twos` bits seen
     2 mod 3. After the pass, `ones` is the answer.
     (The generic version: sum each of the 32 bit positions
      mod k. Easier to derive under pressure.)

   ---------------------------------------------------------
   XOR PREFIX — the same idea as prefix sums (chapter 06)

     P[i] = a[0] ^ a[1] ^ ... ^ a[i-1]
     XOR of range [l, r]  =  P[r+1] ^ P[l]

     because the shared prefix cancels itself. Everything
     you know about prefix sums transfers, with ^ replacing
     + and its own inverse replacing subtraction.

Integers as sets

Reading an integer as a set is the idea behind subset enumeration and bitmask DP. The translation table below is worth knowing by sight, because the code becomes unreadable otherwise.

   AN n-BIT INTEGER IS A SUBSET OF {0, 1, ..., n-1}.
   Bit i set means element i is IN the subset.

     mask = 0b1011   ->   {0, 1, 3}

   THE SET OPERATIONS:
     union            a | b
     intersection     a & b
     difference       a & ~b
     symmetric diff   a ^ b
     add element i    a | (1 << i)
     remove element i a & ~(1 << i)
     test element i   (a >> i) & 1
     size             popcount(a)
     is subset of b   (a & b) === a
     empty            a === 0
     full (n items)   a === (1 << n) - 1

   ENUMERATE ALL 2^n SUBSETS:
     for (let mask = 0; mask < (1 << n); mask++) {
         for (let i = 0; i < n; i++)
             if (mask & (1 << i)) use(items[i]);
     }
     O(2^n · n). THIS IS WHY "n <= 20" IN A CONSTRAINT
     MEANS BITMASK (chapter 02).

   ENUMERATE ALL SUBMASKS OF A MASK — a genuinely useful
   idiom:
     for (let s = mask; s > 0; s = (s - 1) & mask) { ... }
     // then handle s = 0 separately
   Total across all masks is 3^n, not 4^n.

   THIS REPRESENTATION IS THE BASIS OF BITMASK DP
   (chapter 41): the state "which items have I used?" is a
   single integer, so the DP table is a flat array.
