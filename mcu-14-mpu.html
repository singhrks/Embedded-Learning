The MPU: memory protection without an MMU

An MPU cannot translate addresses, so it gives you no virtual memory and no isolation between identical address spaces. What it does give you is the ability to turn silent corruption into an immediate, localised fault — which on a system with no SIGSEGV is worth a great deal.

What it is and is not

MMU (Cortex-A)MPU (Cortex-M)
Translates addressesYes — virtual to physicalNo. Addresses are physical, always
Granularity4 kB pages, millions of them8 or 16 regions, sized by powers of two
Configuration storePage tables in memoryA handful of registers
Per-process address spaceYesNo — one physical space, different permissions
Cost to reconfigureTLB maintenanceA few register writes; cheap enough per context switch
What it buys youIsolation and virtual memoryFault-on-mistake, and privilege separation

So the MPU is not a security boundary in the way TrustZone is (that is a separate mechanism), and it is not virtual memory. It is a programmable set of rules about which addresses may be read, written or executed, and by whom.

The three things it is genuinely worth doing

   1. STACK GUARD - the highest-value use by far.

      Place a small, no-access region immediately below each
      stack. Overflow hits it and takes a MemManage fault
      AT THE INSTRUCTION THAT OVERFLOWED, with the faulting
      task identifiable.

      Without it:  the stack grows into .bss, a variable
                   changes for no reason, and you spend
                   three days.
      With it:     an immediate fault naming the culprit.

      +----------------+ <- stack top
      |  task stack    |
      |       |        |
      |       v        |
      +----------------+ <- stack bottom
      |  GUARD 32 B    |  MPU: no access
      +----------------+
      |  other data    |
      +----------------+

   2. EXECUTE NEVER on RAM and peripherals.

      Mark everything that is not flash as XN. A corrupted
      function pointer or a smashed return address then
      faults instead of executing whatever bytes it found.
      This is the single cheapest robustness measure
      available, and it costs one region.

   3. READ-ONLY on .rodata and the vector table.

      Catches wild pointer writes at the instant they
      happen rather than when the corrupted value is later
      used.

   Everything else - full task isolation, unprivileged
   tasks, per-task peripheral permissions - is real but
   costs regions and design effort. These three are close
   to free.

Configuring a region

/* ARMv7-M MPU. Regions are numbered, sized by powers of two,
   and must be aligned to their own size - a 1 kB region
   must start on a 1 kB boundary. That constraint drives
   your linker script (chapter 05).                        */

static void mpu_region(uint32_t n, uint32_t base,
                       uint32_t size_log2, uint32_t attr)
{
    MPU->RNR  = n;
    MPU->RBAR = base & MPU_RBAR_ADDR_Msk;
    MPU->RASR = attr
              | ((size_log2 - 1u) << MPU_RASR_SIZE_Pos)
              | MPU_RASR_ENABLE_Msk;
}

/* Access permission field (AP), bits 24-26 of RASR:
     000  no access at all
     001  privileged RW,        unprivileged none
     010  privileged RW,        unprivileged RO
     011  full access           (RW for both)
     101  privileged RO,        unprivileged none
     110  read-only             (RO for both)             */

#define AP_NONE     (0u << 24)
#define AP_PRIV_RW  (1u << 24)
#define AP_FULL     (3u << 24)
#define AP_RO       (6u << 24)
#define XN          (1u << 28)
#define MEM_NORMAL  ((1u << 17) | (1u << 18))  /* C and B  */

void mpu_init(void)
{
    extern uint32_t _stack_guard;   /* from the linker script */

    MPU->CTRL = 0;                  /* disable while editing  */
    __DSB(); __ISB();

    /* 0: all of SRAM, full access, execute never.           */
    mpu_region(0, 0x20000000, 17, AP_FULL | XN | MEM_NORMAL);

    /* 1: the guard band below the stack. Higher-numbered
          regions WIN where they overlap, so this carves a
          hole out of region 0.                              */
    mpu_region(1, (uint32_t) &_stack_guard, 5, AP_NONE);

    /* 2: peripherals, privileged only, execute never.       */
    mpu_region(2, 0x40000000, 29, AP_PRIV_RW | XN);

    /* PRIVDEFENA: privileged code keeps the default memory
       map for anything no region covers. Without it, any
       address you did not explicitly describe faults - which
       is stricter, and a good way to discover you forgot
       the flash region.                                     */
    MPU->CTRL = MPU_CTRL_ENABLE_Msk | MPU_CTRL_PRIVDEFENA_Msk;
    __DSB(); __ISB();
}

/* THE BARRIERS ARE MANDATORY. Enabling the MPU changes how
   the very next fetch is permission-checked. Without DSB
   and ISB you get a fault whose address makes no sense,
   and which moves when you change unrelated code.         */
ARMv8-M redesigned this, and for the better

ARMv8-M (Cortex-M23/M33/M55) replaces power-of-two sizing with plain base and limit addresses, so a region can be any size at any 32-byte-aligned address. It also moves memory attributes into an indexed MAIR register, as on Cortex-A. If you have written v7-M MPU code, the v8-M version is substantially simpler and the alignment gymnastics disappear. Check which you have before copying an example — the register layouts are incompatible.

Per-task protection in an RTOS

/* The MPU is cheap enough to reprogram on every context
   switch, which is what FreeRTOS-MPU and Zephyr's userspace
   do. Each task carries its own region set.               */

typedef struct {
    uint32_t rbar;
    uint32_t rasr;
} mpu_region_t;

typedef struct {
    uint32_t     *stack_top;
    mpu_region_t  regions[3];   /* task stack + 2 private   */
} tcb_t;

/* Inside the context switch (chapter 18), after selecting
   the next task and before returning:                     */
static inline void mpu_load(const tcb_t *t)
{
    MPU->CTRL = 0;
    for (int i = 0; i < 3; i++) {
        MPU->RNR  = 4 + i;          /* task regions: 4,5,6  */
        MPU->RBAR = t->regions[i].rbar;
        MPU->RASR = t->regions[i].rasr;
    }
    MPU->CTRL = MPU_CTRL_ENABLE_Msk | MPU_CTRL_PRIVDEFENA_Msk;
    __DSB(); __ISB();
}

/* Roughly 20 cycles. Against a context switch of ~100
   cycles that is affordable, and it buys you a task that
   physically cannot corrupt another task's stack.

   THE HONEST LIMITATION: with 8 regions and 3-4 spent on
   global policy, you have 4-5 per task. A task needing its
   stack, a DMA buffer, two peripherals and a shared queue
   has already run out. Full isolation on Cortex-M is a real
   design constraint, not a checkbox - which is why most
   projects use the MPU for the three high-value cases above
   and stop there.                                          */

Reading a MemManage fault

/* The MPU reports through MemManage, which is a
   configurable fault - you must ENABLE it, or it escalates
   to HardFault and you lose the diagnostic detail.        */

SCB->SHCSR |= SCB_SHCSR_MEMFAULTENA_Msk;

void MemManage_Handler(void)
{
    uint32_t mmfsr = (SCB->CFSR & 0xFFu);

    /*  bit 0  IACCVIOL   instruction fetch violation - you
                          jumped into an XN region
        bit 1  DACCVIOL   data access violation
        bit 3  MUNSTKERR  fault while unstacking on return
        bit 4  MSTKERR    fault while STACKING on entry -
                          this is your stack guard firing
        bit 7  MMARVALID  MMFAR holds the faulting address  */

    uint32_t addr = (mmfsr & (1u << 7)) ? SCB->MMFAR : 0xFFFFFFFF;

    fault_record(mmfsr, addr, current_task_id());
    __asm volatile ("bkpt #0");
}

/* MSTKERR is the one to recognise on sight: the hardware
   could not push the exception frame because the stack
   pointer had already run into the guard region. That is a
   stack overflow, caught at the moment it happened, naming
   the task. Compare with the alternative - silent
   corruption discovered days later - and the MPU has paid
   for itself with this one bit.                            */

How it shows up

SymptomCause
Fault immediately on enabling the MPUA region you need is not covered and PRIVDEFENA is off
Fault address makes no senseMissing DSB/ISB after writing CTRL
Region appears to have no effectBase address not aligned to the region size — low bits ignored
Two regions overlap unexpectedlyHigher region number wins; check the ordering
MemManage never fires, HardFault doesMEMFAULTENA not set — the fault escalated
