Probability: distributions and expectation

A language model does not output text. It outputs a probability distribution over tokens, and something else turns that into text. This chapter is the vocabulary for what that distribution is and what you can do with it.

The pieces

Only a small slice of probability is needed here, but that slice is load-bearing: it is how a language model's output is defined. These are the pieces the rest of the track assumes.

   RANDOM VARIABLE   a quantity whose value is uncertain.
                     X = the next token.

   DISTRIBUTION      the assignment of probability to each
                     possible value.
                     P(X = "the") = 0.15, ...

   THE TWO RULES, and everything follows from them:
        P(x) >= 0  for every x
        sum over all x of P(x) = 1

   DISCRETE          countable outcomes; a PROBABILITY MASS
                     FUNCTION. Tokens, dice, classes.
   CONTINUOUS        a PROBABILITY DENSITY FUNCTION. P(exact
                     value) = 0; only INTERVALS have
                     probability, and the DENSITY CAN EXCEED
                     1. Weights, activations, noise.

   JOINT             P(X, Y)      both together
   MARGINAL          P(X) = sum over y of P(X, y)
                     - "sum out" what you do not care about
   CONDITIONAL       P(X | Y) = P(X, Y) / P(Y)
                     - "given that Y happened"

   INDEPENDENCE      P(X, Y) = P(X) P(Y)
                     equivalently P(X | Y) = P(X)

   AND THE CHAIN RULE OF PROBABILITY, which is the single
   most important identity in this track:

        P(x1, x2, ..., xn)
          = P(x1) P(x2|x1) P(x3|x1,x2) ... P(xn|x1..x(n-1))

   A LANGUAGE MODEL IS EXACTLY THIS FACTORISATION. The
   probability of a document is the product of the
   probability of each token given all preceding tokens, and
   the model's only job is to estimate

        P(next token | everything so far)

   Everything in chapters 16-25 is machinery for computing
   that one conditional distribution well.

Expectation and variance

Expectation and variance are the two summaries that appear in every loss function and every initialisation scheme in this track.

/* EXPECTATION: the probability-weighted average. */

        E[X] = sum over x of  x * P(x)

    A fair die:  E[X] = (1+2+3+4+5+6)/6 = 3.5
    Note it need not be an attainable value.

/* PROPERTIES THAT GET USED CONSTANTLY:
        E[aX + b]   = a E[X] + b
        E[X + Y]    = E[X] + E[Y]      ALWAYS - even if X
                                       and Y are dependent
        E[XY]       = E[X] E[Y]        ONLY IF INDEPENDENT

/* VARIANCE: the expected squared deviation. */

        Var[X] = E[(X - E[X])^2] = E[X^2] - E[X]^2

        Var[aX + b] = a^2 Var[X]       <- note the SQUARE,
                                          and that b
                                          vanishes
        Var[X + Y]  = Var[X] + Var[Y]  ONLY IF INDEPENDENT

    STANDARD DEVIATION = sqrt(Var), in the same units as X.

/* WHY THIS MATTERS DIRECTLY - WEIGHT INITIALISATION.

   A linear layer computes  y_i = sum over j of W_ij x_j.
   If the W are independent with variance v and there are
   n_in inputs with variance 1, then

        Var[y] = n_in * v

   To keep the variance at 1 through the layer - so signals
   neither explode nor vanish through depth (chapter 07) -
   you need

        v = 1 / n_in           XAVIER/GLOROT
        v = 2 / n_in           HE (for ReLU, which zeroes
                               half the outputs and so halves
                               the variance)

   THAT IS THE ENTIRE DERIVATION of the initialisation
   scheme every framework uses. It is variance arithmetic,
   nothing more (chapter 15).

/* --- IN CODE --- */
import numpy as np

x = np.random.randn(10000)
x.mean()            # ~0.0
x.var()             # ~1.0
x.std()             # ~1.0

W = np.random.randn(512, 512) * np.sqrt(2.0/512)   # He
h = np.random.randn(1000, 512)
out = h @ W
out.std()           # ~1.0 - the variance was PRESERVED

W_bad = np.random.randn(512, 512)                  # naive
(h @ W_bad).std()   # ~22.6 - and after ten layers,
                    # 22.6^10 = 1e13. Overflow.

The distributions you will meet

Four or five distributions cover essentially everything you will meet. Each one is worth associating with the situation that produces it.

/* --- BERNOULLI: one binary trial --- */
    P(1) = p,  P(0) = 1-p
    E = p,  Var = p(1-p)
    USE: binary classification output; DROPOUT masks.

/* --- CATEGORICAL: one draw from k outcomes --- */
    P(i) = p_i,  with the p_i summing to 1
    USE: THE OUTPUT OF EVERY LANGUAGE MODEL. Softmax
    produces exactly this over the vocabulary, and sampling
    from it is how text is generated (chapter 25).

    np.random.choice(vocab_size, p=probs)

/* --- BINOMIAL: n independent Bernoulli trials --- */
    E = np,  Var = np(1-p)

/* --- UNIFORM --- */
    Equal density on [a, b]. E = (a+b)/2,
    Var = (b-a)^2 / 12.
    USE: initialisation ranges, random sampling.

/* --- GAUSSIAN (NORMAL): the important one --- */
    p(x) = (1 / sqrt(2 pi sigma^2))
           * exp(-(x - mu)^2 / (2 sigma^2))

    THE 68-95-99.7 RULE: that fraction of mass lies within
    1, 2 and 3 standard deviations.

    WHY IT IS EVERYWHERE:
      · THE CENTRAL LIMIT THEOREM: the sum of many
        independent random contributions tends to a Gaussian,
        WHATEVER their individual distributions. Neural
        network pre-activations are sums of hundreds of
        terms, so they are approximately Gaussian - which is
        why the variance arithmetic above works.
      · maximum entropy for a given mean and variance
        (chapter 10)
      · analytically convenient: sums of Gaussians are
        Gaussian, and the maths stays closed-form

    USE: weight initialisation, noise, VAE latents,
    diffusion models, and the assumption behind
    least-squares loss.

/* --- MULTIVARIATE GAUSSIAN --- */
    Parameterised by a mean VECTOR and a COVARIANCE MATRIX.
    The covariance's eigenvectors are the axes of the
    probability ellipsoid - chapter 05's machinery applied
    directly.

/* --- SOFTMAX AS A DISTRIBUTION-MAKER --- */
    Any vector of real "scores" becomes a categorical
    distribution:

        P(i) = exp(z_i / T) / sum_j exp(z_j / T)

    THE TEMPERATURE T IS THE SAMPLING CONTROL YOU WILL MEET
    IN EVERY LLM API:

        T -> 0     the distribution collapses onto the
                   argmax. DETERMINISTIC, repetitive.
        T = 1      the model's own calibrated distribution.
        T > 1      FLATTENED. More surprising, more
                   incoherent.
        T -> inf   uniform. Pure noise.

    def softmax_T(z, T=1.0):
        z = z / T
        z = z - z.max()          # stability (chapter 06)
        e = np.exp(z)
        return e / e.sum()

    THAT IS THE WHOLE MECHANISM behind the "temperature"
    slider. Chapter 25 covers the rest of the sampling
    toolkit.                                              */
Log probabilities, always

A 500-token sequence has a probability like 10-800, which is zero in float32 and float64 alike. So everything is computed in log space: products become sums, tiny numbers become manageable negatives, and nothing underflows. When you see log_softmax, logsumexp, or a loss reported in "nats per token", this is why. The rule: never multiply probabilities; add log probabilities.

Sampling, and the practical side

Drawing samples is what a language model does every time it emits a token, so the mechanics — and their pitfalls — are directly relevant rather than background theory.

import numpy as np

# --- SAMPLING FROM A CATEGORICAL DISTRIBUTION ---
probs = np.array([0.1, 0.7, 0.2])
np.random.choice(3, p=probs)

# HOW IT WORKS UNDERNEATH - inverse CDF sampling:
def sample(probs):
    r = np.random.rand()
    cum = 0.0
    for i, p in enumerate(probs):
        cum += p
        if r < cum:
            return i
    return len(probs) - 1
# One uniform random number, one cumulative walk. This is
# what runs in the inner loop of text generation.

# --- THE GUMBEL-MAX TRICK, which appears in real code ---
# Sampling from softmax(z) is equivalent to:
#     argmax_i (z_i + g_i),  g_i ~ Gumbel(0,1)
g = -np.log(-np.log(np.random.rand(len(z))))
sample_idx = np.argmax(z + g)
# NO SOFTMAX NEEDED. Numerically convenient, and the basis
# of the Gumbel-softmax relaxation used when you need a
# DIFFERENTIABLE approximation to sampling.

# --- LOG-SPACE ARITHMETIC ---
def logsumexp(x):
    m = np.max(x)
    return m + np.log(np.sum(np.exp(x - m)))
# The same max-subtraction trick as softmax, and the reason
# it exists: log(sum(exp(x))) computed naively overflows.

def log_softmax(z):
    return z - logsumexp(z)

# SEQUENCE LOG-PROBABILITY - how perplexity is computed:
total_logprob = sum(log_softmax(logits[t])[token[t]]
                    for t in range(T))
avg_nll = -total_logprob / T
perplexity = np.exp(avg_nll)
# PERPLEXITY is "the effective number of tokens the model is
# choosing between". A perplexity of 20 means the model is
# about as uncertain as if it were picking uniformly from 20
# options. Chapter 10 shows why it is exp of the
# cross-entropy.

# --- REPRODUCIBILITY, which you will need ---
np.random.seed(42)
# torch.manual_seed(42)
# AND NOTE: full determinism also needs deterministic GPU
# kernels and fixed data ordering. Seeding alone is not
# enough, and "it changed between runs" is usually this.

# --- ESTIMATING AN EXPECTATION BY SAMPLING ---
# E[f(X)] ~= (1/n) sum f(x_i)
samples = np.random.randn(10000)
np.mean(samples**2)      # ~1.0, since Var = E[X^2] - 0
# MONTE CARLO. The error shrinks as 1/sqrt(n), which is slow
# - 100x more samples for 10x more accuracy. This is why
# reinforcement learning from sampled rewards (chapter 24)
# is so much noisier than supervised training.

SymptomCause

inf from expNo max subtraction in softmax or logsumexp

Generated text is incoherentTemperature too high — the distribution is flattened
