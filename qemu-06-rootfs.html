Building a root filesystem

A kernel without userspace panics in half a second. This chapter covers the four ways to give it one — an initramfs you assemble by hand, Buildroot, a debootstrap image, and a container image reused as a rootfs — and when each is the right tool.

Choosing

Method 1: initramfs, by hand

#!/bin/sh
# mkinitramfs.sh - a complete, working root filesystem in one
# script. This is the one to keep.
set -e

BB_VER=1.36.1
ARCH=arm64
CROSS=aarch64-linux-gnu-
ROOT=$PWD/rootfs

# --- busybox, statically linked -----------------------------
if [ ! -d busybox-$BB_VER ]; then
    wget -q https://busybox.net/downloads/busybox-$BB_VER.tar.bz2
    tar xf busybox-$BB_VER.tar.bz2
fi
cd busybox-$BB_VER
make ARCH=$ARCH CROSS_COMPILE=$CROSS defconfig >/dev/null
sed -i 's/# CONFIG_STATIC is not set/CONFIG_STATIC=y/' .config
sed -i 's/CONFIG_TC=y/# CONFIG_TC is not set/' .config
make ARCH=$ARCH CROSS_COMPILE=$CROSS -j$(nproc) >/dev/null
make ARCH=$ARCH CROSS_COMPILE=$CROSS CONFIG_PREFIX=$ROOT install
cd ..

# --- the directory skeleton ---------------------------------
mkdir -p $ROOT/{proc,sys,dev,tmp,run,root,etc/init.d,lib/modules}

# --- init ---------------------------------------------------
cat > $ROOT/init <<'EOF'
#!/bin/sh
mount -t proc     proc     /proc
mount -t sysfs    sysfs    /sys
mount -t devtmpfs devtmpfs /dev
mount -t tmpfs    tmpfs    /tmp
mkdir -p /dev/pts && mount -t devpts devpts /dev/pts

# load any modules we shipped
for m in /lib/modules/*.ko; do
        [ -e "$m" ] && insmod "$m" 2>/dev/null
done

# bring up loopback and the virtio NIC if present
ip link set lo up 2>/dev/null
ip link set eth0 up 2>/dev/null && udhcpc -i eth0 -q 2>/dev/null

echo
echo "=== rootfs up: $(uname -srm) ==="
echo

exec /bin/sh
EOF
chmod +x $ROOT/init

# --- minimal /etc -------------------------------------------
echo "root:x:0:0:root:/root:/bin/sh" > $ROOT/etc/passwd
echo "root:x:0:"                     > $ROOT/etc/group
echo "qemu"                          > $ROOT/etc/hostname
cat > $ROOT/etc/fstab <<'EOF'
proc  /proc  proc  defaults 0 0
sysfs /sys   sysfs defaults 0 0
EOF

# --- pack ---------------------------------------------------
( cd $ROOT && find . -print0 \
  | cpio --null -o --format=newc 2>/dev/null ) | gzip -9 \
  > initramfs.cpio.gz

echo "built: initramfs.cpio.gz ($(du -h initramfs.cpio.gz | cut -f1))"
$ ./mkinitramfs.sh
built: initramfs.cpio.gz (1.2M)

$ qemu-system-aarch64 -M virt -cpu cortex-a57 -m 512M -nographic \
    -kernel Image -initrd initramfs.cpio.gz \
    -append "console=ttyAMA0 earlycon"
...
=== rootfs up: Linux 6.8.0 aarch64 ===

/ #

# To add YOUR kernel module to the image, drop it in
# rootfs/lib/modules/ before packing. The init script loads
# everything it finds - which is exactly what you want while
# developing a driver (Linux track, chapter 28).
Why static linking matters here

An initramfs has no dynamic loader unless you put one there, and a dynamically linked busybox fails with not found — a message that describes the missing loader, not the missing binary, and sends people hunting for the wrong thing. Build static and the problem cannot occur.

Method 2: Buildroot

$ git clone --depth=1 -b 2024.02 \
    https://gitlab.com/buildroot.org/buildroot.git
$ cd buildroot

# There is a ready-made config for exactly our target:
$ make qemu_aarch64_virt_defconfig

# Customise:
$ make menuconfig
#   Target packages -> Debugging  -> gdb, strace, ltrace
#   Target packages -> Networking -> openssh, iperf3
#   Target packages -> Hardware   -> optee-client, optee-test
#   Filesystem images -> ext2/3/4 root filesystem
#                     -> cpio the root filesystem (for initramfs)
#   Toolchain -> Build cross gdb for the host
#   Kernel -> (leave off if you build your own)

$ make -j$(nproc)          # 15-40 minutes the first time

$ ls output/images/
Image  rootfs.cpio.gz  rootfs.ext4  start-qemu.sh

# Buildroot even writes the QEMU command line for you:
$ ./output/images/start-qemu.sh
# or run it yourself:
$ qemu-system-aarch64 -M virt -cpu cortex-a53 -m 512M -nographic \
    -kernel output/images/Image \
    -drive file=output/images/rootfs.ext4,if=none,format=raw,id=hd0 \
    -device virtio-blk-device,drive=hd0 \
    -append "console=ttyAMA0 root=/dev/vda rootwait"

# Rebuild just one package after changing it:
$ make optee-client-rebuild
$ make                      # repacks the images

# Buildroot is the right answer for this site's OP-TEE track
# because it already knows how to build optee-client,
# optee-test and the TA development kit, and puts them in the
# right places.

Method 3: a real Debian

# When you want apt, a package archive, and systemd.

$ sudo apt install debootstrap qemu-user-static
$ mkdir -p rootfs
$ sudo debootstrap --arch=arm64 --foreign bookworm rootfs \
      http://deb.debian.org/debian

# Second stage runs arm64 binaries via binfmt_misc + qemu-user
$ sudo cp /usr/bin/qemu-aarch64-static rootfs/usr/bin/
$ sudo chroot rootfs /debootstrap/debootstrap --second-stage

# Configure it before first boot
$ sudo chroot rootfs /bin/bash <<'EOF'
echo "root:root" | chpasswd
echo qemu > /etc/hostname
apt-get update
apt-get install -y --no-install-recommends \
    systemd-sysv udev iproute2 openssh-server vim less
systemctl enable serial-getty@ttyAMA0.service
cat > /etc/fstab <<'FSTAB'
/dev/vda / ext4 defaults 0 1
FSTAB
EOF

# Turn the directory into a disk image
$ dd if=/dev/zero of=debian.ext4 bs=1M count=4096
$ mkfs.ext4 -F debian.ext4
$ mkdir -p mnt && sudo mount -o loop debian.ext4 mnt
$ sudo cp -a rootfs/. mnt/
$ sudo umount mnt

$ qemu-system-aarch64 -M virt -cpu cortex-a57 -m 2G -nographic \
    -kernel Image \
    -drive file=debian.ext4,if=none,format=raw,id=hd0 \
    -device virtio-blk-device,drive=hd0 \
    -netdev user,id=n0 -device virtio-net-device,netdev=n0 \
    -append "console=ttyAMA0 root=/dev/vda rw rootwait"

Method 4: steal a container image

# The fastest way to a full userspace you already trust.

$ docker pull --platform linux/arm64 debian:bookworm
$ docker create --platform linux/arm64 --name tmp debian:bookworm
$ mkdir -p rootfs && docker export tmp | tar -C rootfs -xf -
$ docker rm tmp

# Container images have no init and no kernel. Add one:
$ sudo tee rootfs/init >/dev/null <<'EOF'
#!/bin/sh
mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs none /dev
exec /bin/bash
EOF
$ sudo chmod +x rootfs/init

# Then pack as initramfs, or write into an ext4 image as above.
$ ( cd rootfs && sudo find . -print0 \
    | sudo cpio --null -o --format=newc ) | gzip > initramfs.cpio.gz

# Podman works identically and does not need a daemon:
$ podman pull --arch arm64 alpine
$ podman export $(podman create --arch arm64 alpine) | tar -C rootfs -xf -

Making a bootable disk image

# A single-partition ext4 image, which is all QEMU needs:
$ truncate -s 2G rootfs.ext4
$ mkfs.ext4 -d rootfs -F rootfs.ext4      # -d populates it
                                          # directly - no
                                          # mounting, no root!

# A partitioned image, closer to a real SD card:
$ truncate -s 4G sd.img
$ sfdisk sd.img <<'EOF'
label: dos
start=2048, size=204800, type=c, bootable
start=206848, type=83
EOF
$ LOOP=$(sudo losetup -Pf --show sd.img)
$ sudo mkfs.vfat -F32 ${LOOP}p1
$ sudo mkfs.ext4 -F ${LOOP}p2
$ sudo mount ${LOOP}p2 /mnt && sudo cp -a rootfs/. /mnt/ \
  && sudo umount /mnt
$ sudo losetup -d $LOOP

# Resize later, without recreating:
$ truncate -s 8G rootfs.ext4
$ e2fsck -f rootfs.ext4 && resize2fs rootfs.ext4

# Inspect an image without mounting - useful in CI:
$ debugfs -R "ls -l /" rootfs.ext4
$ debugfs -R "cat /etc/hostname" rootfs.ext4
mkfs.ext4 -d is the trick worth remembering

It populates a filesystem image from a directory without mounting anything, which means no sudo, no loop devices, and it works inside an unprivileged container. Every CI pipeline that builds an image should use it.

Getting files in and out

# 1. virtiofs - best, needs a daemon (virt chapter 15)
$ virtiofsd --socket-path=/tmp/vfs.sock -o source=$PWD/share &
$ qemu-system-aarch64 ... \
    -object memory-backend-file,id=mem,size=2G,mem-path=/dev/shm,share=on \
    -M virt,memory-backend=mem \
    -chardev socket,id=vfs,path=/tmp/vfs.sock \
    -device vhost-user-fs-device,chardev=vfs,tag=share
# guest: mount -t virtiofs share /mnt

# 2. 9p - no daemon, slower, works everywhere
$ qemu-system-aarch64 ... \
    -fsdev local,id=fs0,path=$PWD/share,security_model=none \
    -device virtio-9p-device,fsdev=fs0,mount_tag=share
# guest: mount -t 9p -o trans=virtio,version=9p2000.L share /mnt

# 3. A second disk - simplest, no guest config
$ qemu-img create -f raw scratch.img 1G && mkfs.ext4 -F scratch.img
$ qemu-system-aarch64 ... \
    -drive file=scratch.img,if=none,format=raw,id=s0 \
    -device virtio-blk-device,drive=s0
# guest: mount /dev/vdb /mnt

# 4. SSH over user networking (chapter 8)
$ qemu-system-aarch64 ... \
    -netdev user,id=n0,hostfwd=tcp::2222-:22 \
    -device virtio-net-device,netdev=n0
$ scp -P 2222 file root@localhost:/tmp/

How it shows up

SymptomCause
No working init foundNo /init, not executable, or the archive was built from the wrong directory
/init: not found though the file existsDynamically linked binary with no loader — build static, or ship ld-linux-aarch64.so.1
VFS: Unable to mount root fs on unknown-block(0,0)Wrong root=, or no virtio-blk driver, or missing rootwait
Boots to a prompt with no working commandsbusybox installed but its symlinks were not created — run busybox --install -s
No /dev entriesdevtmpfs not mounted, or CONFIG_DEVTMPFS off
Debian image hangs after mounting rootNo getty on ttyAMA0 — systemctl enable serial-getty@ttyAMA0
Container-derived rootfs has no /procContainer images omit the pseudo-filesystem mount points; create them
Image full immediatelytruncate made a sparse file; the filesystem inside is still its original size — resize2fs
Buildroot rebuild does not pick up a changeUse make <pkg>-rebuild, not make alone
9p mount fails with "no such device"Guest kernel missing CONFIG_NET_9P_VIRTIO
