The chain rule and backpropagation

One rule from calculus, applied mechanically to a graph of operations. This is how every neural network that has ever been trained was trained, and it is simpler than its reputation.

The chain rule

Backpropagation is the chain rule applied carefully and nothing more. Getting comfortable with the rule in its simplest form is the whole preparation for the rest of the chapter.

   IF  y = f(u)  AND  u = g(x)   THEN

        dy       dy     du
        --   =   --  *  --
        dx       du     dx

   "RATES MULTIPLY ALONG A CHAIN."

   THE INTUITION THAT MAKES IT OBVIOUS: gears.

     x turns 3x as fast as u,
     u turns 2x as fast as y
     -> x turns 6x as fast as y.

   A WORKED EXAMPLE:
        y = (3x + 1)^2

        let u = 3x + 1     du/dx = 3
        then y = u^2       dy/du = 2u

        dy/dx = 2u * 3 = 6(3x + 1)

   LONGER CHAINS JUST MULTIPLY MORE TERMS:

        x -> a -> b -> c -> L

        dL     dL   dc   db   da
        --  =  -- * -- * -- * --
        dx     dc   db   da   dx

   AND THAT IS BACKPROPAGATION. A neural network IS a long
   chain: input -> layer -> activation -> layer -> ... ->
   loss. To find how the loss depends on a weight buried
   twenty layers deep, multiply the local derivatives along
   the path.

   TWO CONSEQUENCES THAT EXPLAIN MOST TRAINING PATHOLOGIES:

     each factor < 1  ->  the product SHRINKS toward zero
                          -> VANISHING GRADIENTS
     each factor > 1  ->  the product GROWS
                          -> EXPLODING GRADIENTS

   Twenty layers of sigmoid, each contributing at most 0.25:
        0.25^20 = 1e-12.
   The first layer receives essentially no signal. That is
   the entire reason deep networks were considered
   untrainable before ReLU, careful initialisation, and
   residual connections (chapters 15 and 22).

The computation graph

Representing a computation as a graph is what turns the chain rule from a manual exercise into an algorithm a machine can run — and it is the data structure every framework is built around.

/* A neural network is a DIRECTED ACYCLIC GRAPH of simple
   operations. Backpropagation walks it backwards.

   TAKE  L = (w*x + b - y)^2   -  one neuron, squared error.

   FORWARD:
        x, w  -->  [*] --> u = w*x
        u, b  -->  [+] --> v = u + b
        v, y  -->  [-] --> e = v - y
        e     -->  [^2]--> L = e^2

   BACKWARD - start with dL/dL = 1 and walk back, applying
   each node's LOCAL derivative:

        dL/dL = 1
        dL/de = 2e                 (d(e^2)/de)
        dL/dv = dL/de * 1  = 2e    (d(v-y)/dv = 1)
        dL/db = dL/dv * 1  = 2e    (d(u+b)/db = 1)
        dL/du = dL/dv * 1  = 2e
        dL/dw = dL/du * x  = 2e*x  (d(w*x)/dw = x)

   NOTE THE TWO KINDS OF NODE BEHAVIOUR - this is the whole
   of backprop:

     ADDITION  PASSES THE GRADIENT THROUGH UNCHANGED to both
               inputs. It is a gradient DISTRIBUTOR.
     MULTIPLICATION SWAPS: the gradient to each input is
               multiplied by the OTHER input's forward value.
               Which is why THE FORWARD VALUES MUST BE SAVED
               - and why training uses far more memory than
               inference.

   Every other rule follows from those two plus the local
   derivative of each elementary function (chapter 06).

Autodiff from scratch

The most effective way to stop finding autodiff mysterious is to write one. This is a complete implementation in far less code than you would expect.

"""A complete reverse-mode automatic differentiation engine.
   About sixty lines. Everything PyTorch does for scalars is
   here; the rest is tensors and performance."""

class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None   # how to push
                                        # gradient to inputs
        self._prev = set(_children)
        self._op = _op

    def __add__(self, other):
        other = other if isinstance(other, Value) \
                      else Value(other)
        out = Value(self.data + other.data,
                    (self, other), '+')
        def _backward():
            # ADDITION DISTRIBUTES THE GRADIENT
            self.grad  += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) \
                      else Value(other)
        out = Value(self.data * other.data,
                    (self, other), '*')
        def _backward():
            # MULTIPLICATION SWAPS THE FORWARD VALUES
            self.grad  += other.data * out.grad
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def __pow__(self, n):
        out = Value(self.data ** n, (self,), f'**{n}')
        def _backward():
            self.grad += n * (self.data ** (n-1)) * out.grad
        out._backward = _backward
        return out

    def relu(self):
        out = Value(max(0.0, self.data), (self,), 'relu')
        def _backward():
            # GRADIENT FLOWS ONLY WHERE THE OUTPUT WAS
            # POSITIVE
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        # 1. TOPOLOGICAL SORT: a node's gradient is only
        #    complete once every consumer has contributed.
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build(child)
                topo.append(v)
        build(self)

        # 2. SEED and walk backwards
        self.grad = 1.0
        for v in reversed(topo):
            v._backward()

    def __neg__(self):      return self * -1
    def __sub__(self, o):   return self + (-o)
    def __radd__(self, o):  return self + o
    def __rmul__(self, o):  return self * o
    def __repr__(self):
        return f"Value({self.data:.4f}, grad={self.grad:.4f})"


# --- USE IT ---
w = Value(2.0)
x = Value(3.0)
b = Value(1.0)
y = Value(10.0)

pred = w*x + b            # 7.0
loss = (pred - y)**2      # 9.0
loss.backward()

print(w.grad)   # 2*(7-10)*3 = -18.0
print(b.grad)   # 2*(7-10)   = -6.0

# NEGATIVE GRADIENTS MEAN: INCREASING w REDUCES THE LOSS. So
# the update  w -= lr * w.grad  moves w UP. Correct.

# --- ONE GRADIENT DESCENT LOOP ---
for step in range(20):
    pred = w*x + b
    loss = (pred - y)**2
    w.grad = b.grad = 0.0        # <<< ZERO THE GRADIENTS
    loss.backward()
    w.data -= 0.01 * w.grad
    b.data -= 0.01 * b.grad

# THE `+=` IN EVERY _backward IS DELIBERATE: a value used in
# two places receives gradient from BOTH paths, and they must
# ADD (the multivariable chain rule). That accumulation is
# also why you must ZERO GRADIENTS between steps - PyTorch's
# optimizer.zero_grad() does exactly this, and forgetting it
# is one of the most common bugs in the field.
The three-line summary of backpropagation 
1. FORWARD: compute the output, SAVING intermediate
   values.
2. BACKWARD: seed dL/dL = 1 and walk the graph in reverse
   topological order, each node multiplying by its local
   derivative and ACCUMULATING into its inputs.
3. UPDATE: step every parameter against its gradient.

The cost of the backward pass is roughly twice the forward pass, and it produces gradients for every parameter at once. That efficiency — one backward pass for billions of derivatives — is the entire reason this field exists.

Backprop through a layer

Applying the machinery to a real layer is where the shapes start to matter, and where the transposes that look arbitrary turn out to be forced by the dimensions.

/* THE SCALAR CASE GENERALISES TO MATRICES DIRECTLY. These
   three formulas are worth memorising - they are most of
   what a framework computes.                             */

    FORWARD:   Y = X @ W + b
        X: (batch, d_in)
        W: (d_in, d_out)
        b: (d_out,)
        Y: (batch, d_out)

    BACKWARD, given dY (the gradient of the loss w.r.t. Y):

        dX = dY @ W.T           (batch, d_in)
        dW = X.T @ dY           (d_in, d_out)
        db = dY.sum(axis=0)     (d_out,)

/* HOW TO REMEMBER THEM WITHOUT DERIVING: THE SHAPES ONLY
   WORK ONE WAY. dX must have X's shape; the only product of
   dY and W with that shape is dY @ W.T. This is a genuinely
   reliable check - if your shapes work, your formula is
   almost certainly right.

/* AND NOTE THE TRANSPOSES: (AB)^T = B^T A^T from chapter 04
   is exactly why they appear.                            */

import numpy as np

class Linear:
    def __init__(self, d_in, d_out):
        # He initialisation - chapter 15 explains the scale
        self.W = (np.random.randn(d_in, d_out) *
                  np.sqrt(2.0 / d_in))
        self.b = np.zeros(d_out)

    def forward(self, X):
        self.X = X                  # SAVED for backward
        return X @ self.W + self.b

    def backward(self, dY):
        self.dW = self.X.T @ dY
        self.db = dY.sum(axis=0)
        return dY @ self.W.T        # gradient to pass down

class ReLU:
    def forward(self, X):
        self.mask = X > 0           # SAVED
        return X * self.mask
    def backward(self, dY):
        return dY * self.mask       # zero where input was
                                    # negative

# --- A TWO-LAYER NETWORK, COMPLETE ---
layers = [Linear(784, 128), ReLU(), Linear(128, 10)]

def forward(X):
    for layer in layers:
        X = layer.forward(X)
    return X

def backward(dY):
    for layer in reversed(layers):   # <<< REVERSED
        dY = layer.backward(dY)

# training step
logits = forward(X_batch)
probs  = softmax(logits)
dlogits = (probs - one_hot_targets) / len(X_batch)
                       # ^^ chapter 06's clean gradient
backward(dlogits)

for layer in layers:
    if hasattr(layer, 'W'):
        layer.W -= lr * layer.dW
        layer.b -= lr * layer.db

/* THAT IS A COMPLETE, WORKING NEURAL NETWORK TRAINER. Add a
   data loader and it learns MNIST. Everything after this
   chapter is better architectures, better optimisers and
   more scale - the training mechanism does not change. */

What this costs, and what goes wrong

The backward pass has a characteristic cost and a small set of characteristic failures. Both are worth knowing before you meet them in a training run that has been going for six hours.

/* --- MEMORY: THE REASON TRAINING NEEDS SO MUCH RAM --- */
    The backward pass needs the forward ACTIVATIONS. So
    training stores, per layer, per batch element, the full
    activation tensor.

    For a transformer: roughly
        activations ~ batch * seq_len * d_model * n_layers
                      * (a constant around 10-20)

    This usually exceeds the parameter memory, and it is why
    a model that fits in memory for inference will not train
    on the same card.

    THE MITIGATIONS:
      GRADIENT CHECKPOINTING  save only some activations;
                              RECOMPUTE the rest during the
                              backward pass. ~30% more
                              compute for a large memory
                              saving. Standard practice.
      SMALLER BATCHES, with gradient accumulation to keep the
                              effective batch size
      MIXED PRECISION         fp16/bf16 activations
                              (chapter 26)

/* --- THE BUGS, in order of frequency --- */

   1. FORGETTING TO ZERO GRADIENTS.
      Gradients accumulate by design. Miss zero_grad() and
      each step uses the sum of all previous gradients. The
      model appears to train, badly and erratically.

   2. NOT DETACHING WHEN YOU SHOULD.
      Keeping a reference to a tensor that is part of the
      graph keeps the WHOLE GRAPH alive. In an RNN loop this
      is an unbounded memory leak. Use .detach() or
      .item() for logging - never accumulate a raw loss
      tensor into a running total.

   3. BACKWARD THROUGH THE GRAPH TWICE.
      The graph is freed after backward(). Calling it again
      raises an error; retain_graph=True is usually papering
      over a design mistake.

   4. IN-PLACE OPERATIONS ON SAVED TENSORS.
      x += 1 can corrupt a value the backward pass needs.
      PyTorch usually detects this; numpy will not.

   5. GRADIENT FLOW BLOCKED.
      An argmax, a rounding, a hard threshold, a .detach()
      in the wrong place - all have zero or undefined
      gradient, and everything upstream of them stops
      learning silently. If a parameter's gradient is
      exactly zero every step, this is why.

   6. EXPLODING GRADIENTS.
      Clip them:
          torch.nn.utils.clip_grad_norm_(params, max_norm=1.0)
      Standard in transformer training, not optional.

/* --- THE DIAGNOSTIC HABIT --- */
    for name, p in model.named_parameters():
        if p.grad is None:
            print(f"{name}: NO GRADIENT")      # detached?
        else:
            print(f"{name}: {p.grad.norm():.3e}")

    Print this once at the start of training. Gradients that
    are None, exactly zero, nan, or wildly different in
    magnitude between layers all point at specific bugs, and
    all are invisible in the loss curve for a while.      */
