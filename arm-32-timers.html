The generic timer and counters

One architected timer, present on every ARMv8 core, with a counter readable from user space and comparators for each exception level. It is why clock_gettime needs no system call, and why timekeeping code is portable across every ARM SoC.

The system counter

One counter, shared by everything

A single free-running 64-bit counter in an always-on power domain, incrementing at a fixed frequency, distributed to every core. It never stops, never wraps in any practical timeframe, and is identical on every core — which is exactly what a clocksource needs (OS chapter 17).

        mrs     x0, cntpct_el0          /* PHYSICAL count  */
        mrs     x0, cntvct_el0          /* VIRTUAL count   */
        mrs     x0, cntfrq_el0          /* frequency in Hz */

/* Readable from EL0 — no system call, no trap. This is the whole
   reason the vDSO can implement clock_gettime in user mode
   (chapter 30).                                            */

/* Frequency is IMPLEMENTATION DEFINED, commonly 1-100 MHz.
   Typical: 24 MHz, 25 MHz, 50 MHz, 19.2 MHz.

   CNTFRQ_EL0 is NOT set by hardware — FIRMWARE must program it
   at boot, on every core. If firmware forgets, software reads
   zero or garbage and all timekeeping is wrong. This is a
   classic bring-up bug, and Linux warns about it:          */
//   arch_timer: WARNING: Invalid trigger for IRQ
//   arch_timer: frequency not available

/* At 24 MHz, a 64-bit counter wraps after ~24,000 years. Treat
   it as never wrapping — but do use time_after()-style signed
   comparison anyway (OS chapter 17).                       */

Physical versus virtual counters

Every core has access to two counters, and the difference between them exists entirely for virtualisation: one counts real elapsed time, the other can be offset so a guest does not see time pass while it was not scheduled.

   CNTPCT_EL0    the raw physical count
   CNTVCT_EL0    the physical count MINUS an offset

        CNTVCT = CNTPCT - CNTVOFF_EL2

  CNTVOFF_EL2 is per-VM, written by the hypervisor. Why:

   · a guest suspended for 10 seconds and resumed should not see
     10 seconds of elapsed CPU time it did not get
   · a guest MIGRATED to another host must see a continuous
     timeline, even though the new host's counter differs
   · a guest booted later should still see its own time starting
     near zero

  So the hypervisor adjusts CNTVOFF and the guest's view stays
  coherent, with no traps and no emulation.

  CONSEQUENCE for software:
     · a guest OS uses the VIRTUAL counter and timer
     · a hypervisor, and firmware at EL2/EL3, uses the PHYSICAL one
     · Linux at EL1 uses virtual; Linux at EL2 (VHE) uses physical
     · reading the wrong one inside a VM gives host time, which
       breaks after any suspend or migration

Each level gets its own comparator so they do not have to coordinate — a hypervisor's timer cannot be disturbed by its guest, and secure firmware's cannot be disturbed by the normal world.

Programming a timer

Setting a timer is a matter of two registers and a comparison, with a choice between an absolute deadline and a relative countdown.

/* Each timer has three registers: */

   CNTV_CTL_EL0    [0] ENABLE
                   [1] IMASK — mask the interrupt output
                   [2] ISTATUS — read-only: has it fired?
   CNTV_CVAL_EL0   64-bit ABSOLUTE compare value
   CNTV_TVAL_EL0   32-bit RELATIVE value, a convenience:
                     writing it sets CVAL = CNTVCT + TVAL
                     reading it gives CVAL - CNTVCT (may go
                     negative once expired)

/* The timer fires when CNTVCT >= CVAL. It is a COMPARATOR, not a
   countdown — which is what makes it immune to drift.      */

/* Absolute deadline — the correct way for periodic work: */
static void timer_set_deadline(uint64_t deadline)
{
        asm volatile("msr cntv_cval_el0, %0" :: "r"(deadline));
        asm volatile("msr cntv_ctl_el0, %0" :: "r"(1UL));  /* enable */
        asm volatile("isb");
}

static void timer_periodic(uint64_t period_ticks)
{
        static uint64_t next;
        uint64_t now;
        asm volatile("mrs %0, cntvct_el0" : "=r"(now));

        if (!next) next = now;
        next += period_ticks;              /* ABSOLUTE, so no drift */
        timer_set_deadline(next);
}

/* Contrast with the relative form: */
        asm volatile("msr cntv_tval_el0, %0" :: "r"(period));
/* Each period restarts from NOW, so the handler's own execution
   time accumulates into permanent drift. Over an hour at 1 kHz
   with a 10 µs handler, that is 36 seconds of drift.
   Use CVAL and absolute deadlines. (OS chapter 17.)       */

Delays and timeouts

Busy-waiting for a short interval is common in low-level code, and doing it by counting loop iterations is wrong on any modern processor. The counter gives you a correct, frequency-independent alternative.

/* A portable microsecond delay, with no calibration loop: */

static void udelay(unsigned us)
{
        uint64_t freq, start, ticks;

        asm volatile("mrs %0, cntfrq_el0" : "=r"(freq));
        ticks = (freq * us) / 1000000;

        asm volatile("isb");                       /* order the read */
        asm volatile("mrs %0, cntvct_el0" : "=r"(start));

        for (;;) {
                uint64_t now;
                asm volatile("isb");
                asm volatile("mrs %0, cntvct_el0" : "=r"(now));
                if (now - start >= ticks)
                        break;
        }
}

/* The ISB matters: without it the counter read can be speculated
   or reordered, and a short delay can complete early. Linux's
   arch_counter_get_cntvct() includes it for exactly this
   reason.

   And note the subtraction: `now - start >= ticks` is correct
   across a wrap; `now >= start + ticks` is not.           */

/* A bounded wait — always prefer this to an unbounded loop: */
static bool wait_for_bit(volatile uint32_t *reg, uint32_t mask,
                         unsigned timeout_us)
{
        uint64_t freq, start, limit, now;

        asm volatile("mrs %0, cntfrq_el0" : "=r"(freq));
        asm volatile("mrs %0, cntvct_el0" : "=r"(start));
        limit = (freq * timeout_us) / 1000000;

        do {
                if (*reg & mask)
                        return true;
                asm volatile("mrs %0, cntvct_el0" : "=r"(now));
        } while (now - start < limit);

        return false;                      /* TIMED OUT — say so */
}

Why the vDSO works

Reading the counter is an ordinary instruction rather than a privileged one, which is precisely what allows the kernel to expose time to user space without a system call.

clock_gettime(CLOCK_MONOTONIC, &ts) with no system call:

   1. read a kernel-maintained page mapped read-only into every
      process. It holds:
         · a base time value
         · the counter value at that base
         · a multiplier and shift for the conversion
         · a sequence counter (a seqlock — OS chapter 09)

   2. read CNTVCT_EL0                      ← EL0-readable
   3. delta = cntvct - base_cycles
   4. ns = base_ns + ((delta * mult) >> shift)
   5. re-check the sequence counter; retry if the kernel updated
      the page mid-read

   ~25 ns, entirely in user mode. Versus ~300 ns for a syscall.

  Two architectural properties make this possible:
     · the counter is readable from EL0 (CNTKCTL_EL1 permits it)
     · it is architected, so ONE vDSO implementation works on
       every ARM SoC

  CNTKCTL_EL1.EL0VCTEN gates EL0 access. A kernel could clear it
  to hide timing from userspace — some hardened configurations do,
  as a side-channel mitigation, at the cost of losing the vDSO
  fast path.

The event stream

A periodic hardware event can wake cores out of a low-power wait without an interrupt, which is useful for spin-wait loops that should not consume power indefinitely.

/* WFE waits for an event (chapter 22). If the event never comes,
   the core waits forever — which is a problem for a spinlock
   whose holder was descheduled.

   The generic timer can generate a PERIODIC EVENT STREAM as a
   safety net:                                              */

   CNTKCTL_EL1.EVNTEN    enable the event stream
   CNTKCTL_EL1.EVNTI     which counter bit transition triggers it
   CNTKCTL_EL1.EVNTDIR   rising or falling edge

/* Typically configured for a ~100 µs period. A WFE therefore
   never sleeps longer than that, guaranteeing forward progress
   even if a SEV is missed.

   Linux enables it, and you can see the configuration:     */
//   dmesg | grep -i 'arch_timer.*event stream'
//   arch_timer: Architected timer HYP event stream enabled

/* This is also what makes WFE safe to use in a guest: the
   hypervisor may trap WFE (chapter 31), but the event stream
   ensures the guest wakes anyway.                          */

Firmware responsibilities

What must be set up before Linux boots
  • CNTFRQ_EL0 on every core, with the actual counter frequency. Hardware does not set it. If firmware forgets, all timekeeping is wrong or the kernel refuses to boot.
  • CNTVOFF_EL2 = 0 when handing off to a kernel at EL1 with no hypervisor. Firmware sometimes leaves it non-zero, and the guest's virtual time then starts at an arbitrary offset.
  • CNTHCTL_EL2 configured so EL1 may access the physical counter and timer, if that is intended.
  • The counter must be enabled and running in the always-on domain before any core reads it.

Linux checks and complains about several of these; the messages are worth recognising during bring-up.

/* The device tree describes it: */
timer {
        compatible = "arm,armv8-timer";
        interrupts = <GIC_PPI 13 IRQ_TYPE_LEVEL_LOW>,   /* secure   */
                     <GIC_PPI 14 IRQ_TYPE_LEVEL_LOW>,   /* physical */
                     <GIC_PPI 11 IRQ_TYPE_LEVEL_LOW>,   /* virtual  */
                     <GIC_PPI 10 IRQ_TYPE_LEVEL_LOW>;   /* hyp      */
        clock-frequency = <24000000>;   /* ONLY if firmware failed
                                           to set CNTFRQ — a
                                           documented workaround,
                                           not the normal path    */
        always-on;                       /* survives CPU idle      */
};

/* The PPI numbers here are relative to 16, so PPI 13 is INTID 29
   (chapter 23). Getting this wrong is a common device tree error
   and the symptom is a kernel that boots then hangs with no
   timer interrupts.                                        */

The memory-mapped timer

Besides the per-core timer, systems usually provide a memory-mapped timer block that other agents can use. It matters most in power management, when the core's own timer may be off.

/* Besides the per-core system-register timers, the architecture
   defines an optional MEMORY-MAPPED timer block (CNTControlBase,
   CNTReadBase, CNTBaseN).                                  */

/* Why it exists: devices other than CPUs may need the counter —
   a DMA engine timestamping packets, a power controller, a
   coprocessor. They cannot execute MRS.

   Software rarely touches it directly. It appears in device
   trees as:                                                */
        compatible = "arm,armv7-timer-mem";

/* Its one common use in Linux: providing a clocksource on
   systems where the per-core timer stops in deep idle, since
   the memory-mapped block is in the always-on domain.     */

The Linux view

Linux abstracts all of this behind clocksource and clockevent drivers, and mapping the kernel's vocabulary onto the architecture's is necessary when a timer misbehaves.

/* The generic timer is Linux's clocksource AND clockevent
   (OS chapter 17):                                         */

cat /sys/devices/system/clocksource/clocksource0/available_clocksource
#   arch_sys_counter                    ← the generic timer
cat /sys/devices/system/clocksource/clocksource0/current_clocksource

cat /proc/interrupts | grep arch_timer
#    3:  102394  98211  101002  99887  GICv3  27 Level  arch_timer
#                                             ^^ PPI, so counts on
#                                                every core

/* Kernel APIs built on it: */
ktime_get()                     /* CLOCK_MONOTONIC, ns          */
ktime_get_real()                /* CLOCK_REALTIME               */
ktime_get_boottime()            /* includes suspend             */
get_cycles()                    /* the raw counter              */
arch_timer_read_counter()

udelay(50);                     /* busy-wait, atomic-safe       */
usleep_range(100, 200);         /* sleeps; allows BATCHING      */
hrtimer_start(&t, ms_to_ktime(10), HRTIMER_MODE_REL);

/* And the tickless machinery (OS chapter 17) programs CVAL for
   the next actual deadline rather than a fixed tick, which is
   what lets an idle core sleep for seconds.               */
