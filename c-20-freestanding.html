C for freestanding and embedded targets

No operating system, no standard library, no main() until you arrange one. This chapter closes the C track by assembling everything into a program that runs on bare hardware — and by being explicit about what you give up.

What freestanding means

C without an operating system is a different environment with a smaller language: no standard library to speak of, no startup code written for you, and no main called by anything. The standard actually defines this mode, and knowing what it guarantees tells you what you must supply.

HostedFreestanding
Entry pointmain(int, char **)Implementation-defined: Reset_Handler, _start, DriverEntry
LibraryAll of itOnly headers with no runtime component
Startupcrt0 runs before youYou write it
HeapPresentOnly if you provide one
ExamplesLinux/Windows applicationLinux kernel, U-Boot, UEFI, Cortex-M firmware

Startup code

Before main runs on a hosted system, a great deal has already happened. On bare metal you write that yourself, and the list is shorter than you expect but every item is essential.

What crt0 does for you on a hosted system, and what you must do here:

   reset
     |
     1. set the stack pointer
     2. copy .data from its flash load address to RAM
     3. zero .bss
     4. (optional) enable FPU, caches, MPU/MMU
     5. call SystemInit / clock configuration
     6. run any constructors (__attribute__((constructor)))
     7. call main()
     8. if main returns — it should not — loop forever
startup.c — a complete, portable startup for Cortex-M
#include <stdint.h>

/* Symbols defined by the linker script (chapter 17). Their ADDRESSES
   are the values you want, so declare them as arrays or take &.  */
extern uint32_t _etext, _data_start, _data_end, _bss_start, _bss_end;
extern uint32_t _stack_top;

extern int main(void);
void Reset_Handler(void);
void Default_Handler(void);

/* Every handler is weakly aliased to Default_Handler, so the
   application overrides only the ones it cares about (chapter 12). */
#define WEAK_ALIAS __attribute__((weak, alias("Default_Handler")))
void NMI_Handler(void)        WEAK_ALIAS;
void HardFault_Handler(void)  WEAK_ALIAS;
void SysTick_Handler(void)    WEAK_ALIAS;
void UART0_IRQHandler(void)   WEAK_ALIAS;

/* The vector table, placed at address 0 by the linker script.
   KEEP(*(.vectors)) in the script prevents --gc-sections from
   discarding it, since nothing references it.                  */
__attribute__((section(".vectors"), used))
void (*const vector_table[])(void) = {
        (void (*)(void))&_stack_top,   /* initial SP  */
        Reset_Handler,                  /* initial PC  */
        NMI_Handler,
        HardFault_Handler,
        0, 0, 0, 0, 0, 0, 0,            /* reserved    */
        0,                              /* SVCall      */
        0, 0,
        0,                              /* PendSV      */
        SysTick_Handler,
        UART0_IRQHandler,               /* IRQ 0       */
};

void Reset_Handler(void)
{
        /* 2. copy .data from flash to RAM */
        uint32_t *src = &_etext;
        for (uint32_t *dst = &_data_start; dst < &_data_end; )
                *dst++ = *src++;

        /* 3. zero .bss — this is why static objects are zeroed */
        for (uint32_t *p = &_bss_start; p < &_bss_end; )
                *p++ = 0;

        /* 4-5. hardware bring-up */
        SystemInit();

        /* 6. C++ / constructor support, if used */
        extern void (*__init_array_start[])(void);
        extern void (*__init_array_end[])(void);
        for (void (**f)(void) = __init_array_start;
             f < __init_array_end; f++)
                (*f)();

        /* 7. */
        main();

        /* 8. */
        for (;;)
                __asm__ volatile("wfi");
}

void Default_Handler(void)
{
        for (;;)
                ;               /* set a breakpoint here — an
                                   unexpected interrupt lands here */
}
The copy loop is not optional, and its absence is subtle

Skip step 2 and every initialised global holds garbage. Skip step 3 and every zero-initialised global holds garbage. Both produce behaviour that looks like random corruption, works intermittently, and changes when you add an unrelated variable. If a bare-metal program behaves erratically before it does anything interesting, check the startup code first.

Providing the pieces you need

With no library, the handful of functions the compiler assumes exist must be provided by you — including some it may emit calls to without you writing them.

/* The compiler can generate calls to these four even if you never
   write them. Provide them, and mark them used so --gc-sections
   does not remove them before the reference appears.           */

void *memcpy(void *dst, const void *src, size_t n)
{
        unsigned char *d = dst;
        const unsigned char *s = src;
        while (n--) *d++ = *s++;
        return dst;
}

void *memset(void *dst, int c, size_t n)
{
        unsigned char *d = dst;
        while (n--) *d++ = (unsigned char)c;
        return dst;
}

void *memmove(void *dst, const void *src, size_t n)
{
        unsigned char *d = dst;
        const unsigned char *s = src;
        if (d < s) { while (n--) *d++ = *s++; }
        else { d += n; s += n; while (n--) *--d = *--s; }
        return dst;
}

int memcmp(const void *a, const void *b, size_t n)
{
        const unsigned char *x = a, *y = b;
        for (; n--; x++, y++) if (*x != *y) return *x - *y;
        return 0;
}

/* Compile these with -fno-tree-loop-distribute-patterns, or GCC may
   recognise the loop inside memcpy and replace it with a call to
   memcpy — infinite recursion, at -O2 only. This is a genuine and
   frequently-hit trap.                                          */
/* A minimal printf replacement — a few hundred bytes instead of
   tens of kilobytes (chapter 16).                              */
static void putc_(char c) { while (UART->FR & FR_TXFF) ; UART->DR = c; }

void print_str(const char *s) { while (*s) putc_(*s++); }

void print_hex(uint32_t v)
{
        print_str("0x");
        for (int i = 28; i >= 0; i -= 4)
                putc_("0123456789abcdef"[(v >> i) & 0xF]);
}

void print_dec(uint32_t v)
{
        char buf[11]; int i = 0;
        if (!v) { putc_('0'); return; }
        while (v) { buf[i++] = '0' + v % 10; v /= 10; }
        while (i--) putc_(buf[i]);
}
/* No format parsing, no varargs, no floating point. Covers 95% of
   embedded logging needs at 1% of the code size.               */

Living without a heap

Without dynamic allocation, data structures have to be sized at compile time. That constraint changes the designs you reach for, mostly for the better.

/* Static allocation: the linker verifies it fits, at build time. */
static struct session sessions[MAX_SESSIONS];
static uint8_t rx_buf[MAX_FRAME];

/* Fixed-size pool with a bitmap free list */
#define POOL_N 32
static struct msg pool[POOL_N];
static uint32_t  pool_used;

struct msg *msg_alloc(void)
{
        uint32_t free = ~pool_used;
        if (!free) return NULL;
        int i = __builtin_ctz(free);
        if (i >= POOL_N) return NULL;
        pool_used |= 1u << i;
        return &pool[i];
}
void msg_free(struct msg *m)
{
        pool_used &= ~(1u << (m - pool));
}
/* Deterministic time, no fragmentation, bounded memory, and the
   failure mode is a clean NULL rather than gradual degradation. */

/* If you genuinely need a heap, provide _sbrk for newlib: */
extern uint32_t _heap_start, _stack_top;
void *_sbrk(int incr)
{
        static char *brk = (char *)&_heap_start;
        char *prev = brk;
        if (brk + incr > (char *)&_stack_top - STACK_RESERVE)
                return (void *)-1;      /* out of memory */
        brk += incr;
        return prev;
}

Register access, assembled

Talking to hardware from C means describing registers in a way the compiler will not optimise away or reorder — which is exactly what volatile exists for and exactly where it is most often misused.

/* Everything from chapters 07, 08 and 10 comes together here. */

struct uart_regs {
        volatile uint32_t DR;         /* 0x00 */
        volatile uint32_t RSR;        /* 0x04 */
        uint32_t          _pad0[4];   /* 0x08 - 0x14 */
        volatile uint32_t FR;         /* 0x18 */
        uint32_t          _pad1;
        volatile uint32_t IBRD;       /* 0x20 */
        volatile uint32_t FBRD;       /* 0x24 */
        volatile uint32_t LCRH;       /* 0x28 */
        volatile uint32_t CR;         /* 0x2C */
};
_Static_assert(sizeof(struct uart_regs) == 0x30, "uart layout");
_Static_assert(offsetof(struct uart_regs, CR) == 0x2C, "CR offset");

#define UART0 ((struct uart_regs *)0x40000000u)

#define FR_TXFF     (1u << 5)
#define CR_UARTEN   (1u << 0)
#define CR_TXE      (1u << 8)

void uart_init(uint32_t baud, uint32_t clk)
{
        UART0->CR = 0;                       /* disable while configuring */
        uint32_t div = (clk * 4) / baud;
        UART0->IBRD = div >> 6;
        UART0->FBRD = div & 0x3F;
        UART0->LCRH = (3u << 5);             /* 8 bits            */
        __asm__ volatile("dsb sy" ::: "memory");   /* land before enable */
        UART0->CR = CR_UARTEN | CR_TXE;
}

Interrupts in bare metal

An interrupt handler in freestanding C has constraints no ordinary function has: it can run at any moment, between any two instructions, and what it shares with the main program must be declared carefully.

/* An ISR is an ordinary C function whose ADDRESS is in the vector
   table. On Cortex-M the hardware saves the caller-saved registers,
   so no special attribute is needed.                            */
void UART0_IRQHandler(void)
{
        uint32_t status = UART0->MIS;
        UART0->ICR = status;             /* W1C: clear at the SOURCE */
        if (status & INT_RX)
                ring_put(&rx_ring, UART0->DR);
}

/* Sharing data with mainline code: volatile is necessary but NOT
   sufficient (chapter 10). Either use atomics, or disable
   interrupts around the critical section.                      */
static volatile uint32_t tick;          /* written by ISR only, and
                                           32-bit aligned, so a single
                                           read is atomic on ARM    */

static _Atomic uint32_t events;         /* read-modify-write: needs
                                           a real atomic            */

/* Critical section, the portable way */
static inline uint32_t irq_save(void)
{
        uint32_t f;
        __asm__ volatile("mrs %0, primask\n\tcpsid i" : "=r"(f) :: "memory");
        return f;
}
static inline void irq_restore(uint32_t f)
{
        __asm__ volatile("msr primask, %0" :: "r"(f) : "memory");
}
/* Save-and-restore, never unconditional enable — otherwise nesting
   two critical sections re-enables interrupts too early.       */

The constraints to design around

Bare-metal development is defined by its limits — memory, stack, no operating system underneath. Designing around them deliberately is the difference between a system that works and one that fails once the stack grows.

ConstraintConsequence
Stack is 1–8 KBNo recursion, no VLAs, no large locals. Check with -fstack-usage.
No MMUA wild pointer corrupts anything. Use the MPU where present.
Flash is 32–512 KBprintf and math.h may not fit. Watch size output in CI.
No OSYou write the scheduler, or use a superloop plus interrupts
Often no FPUSoftware float is 10–100× slower. Use fixed point.
WatchdogMust be kicked, and must not be kicked from a timer interrupt — that defeats it
Power budgetWFI in the idle loop, not a busy wait (CA ch. 20)

The two program structures

The simplest possible architecture for a bare-metal program is a loop that does everything in turn. It scales poorly and it is the right answer more often than its reputation suggests.

/* 1. Superloop plus interrupts — simple, and adequate far more
      often than people expect.                                */
int main(void)
{
        hw_init();
        for (;;) {
                if (flag_rx)    { flag_rx = 0;   handle_rx(); }
                if (flag_tick)  { flag_tick = 0; handle_tick(); }
                kick_watchdog();
                __asm__ volatile("wfi");     /* sleep until an interrupt */
        }
}
/* ISRs stay short: set a flag, queue data, return. All real work
   happens in the loop, at a known context, with no reentrancy.  */

/* 2. An RTOS, when you need priorities and blocking */
void task_sensor(void *arg)
{
        for (;;) {
                xQueueReceive(q, &sample, portMAX_DELAY);   /* blocks */
                process(&sample);
        }
}
/* Choose an RTOS when you have several independent activities with
   different deadlines. A superloop is genuinely better when you
   do not — fewer failure modes, no stack-per-task overhead.    */
