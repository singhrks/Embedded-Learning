Graphs: shortest paths and spanning trees

Once edges have weights, BFS stops working. Four algorithms cover everything you will be asked, and choosing between them is mostly about negative edges and how many sources you need.

Choosing the algorithm

There are four shortest-path algorithms worth knowing and one question that picks between them almost every time. Ask it first, before thinking about implementation.

SituationAlgorithmTime
Unweighted, one sourceBFSO(V + E)
Weights 0 or 10-1 BFS (deque)O(V + E)
Non-negative weights, one sourceDijkstraO((V + E) log V)
Negative weights allowedBellman–FordO(V · E)
All pairs, small VFloyd–WarshallO(V³)
Cheapest set of edges connecting everythingKruskal / Prim (MST)O(E log E)
 
   THE DECISIVE QUESTION IS ALWAYS: ARE THERE NEGATIVE
   EDGES?

     no  -> Dijkstra (or BFS if unweighted)
     yes -> Bellman-Ford, which also DETECTS negative cycles

   WHY DIJKSTRA BREAKS ON NEGATIVE EDGES: it finalises a
   node the moment it is popped, assuming no cheaper route
   can appear later. A negative edge can make a later route
   cheaper, invalidating a decision already made.

        A --1--> B --1--> C
        A --5--------------> C ... and C --(-10)--> B

     Dijkstra finalises B at cost 1 and never revisits it,
     missing the cost -5 route through C.

   ---------------------------------------------------------
   DIJKSTRA — BFS with a priority queue

     dist = array filled with Infinity;  dist[src] = 0
     pq = min-heap of [distance, node], seeded with [0, src]

     while (pq not empty) {
         [d, u] = pq.pop()
         if (d > dist[u]) continue;        // STALE entry
         for ([v, w] of adj[u]) {
             const nd = d + w;
             if (nd < dist[v]) {           // RELAXATION
                 dist[v] = nd;
                 pq.push([nd, v]);
             }
         }
     }

     THE STALE CHECK IS ESSENTIAL. A node can be pushed
     several times with different tentative distances; when
     an out-of-date entry surfaces, skip it. Without that
     line the algorithm still terminates but wastes work and
     can relax from a distance that is no longer current.

     (Deleting or decreasing keys inside a heap is the
     alternative, and it is more trouble than it is worth.)

   ---------------------------------------------------------
   MINIMUM SPANNING TREE — a different question

     Dijkstra minimises the distance FROM ONE SOURCE.
     An MST minimises the TOTAL WEIGHT of edges connecting
     everything. They are not the same and one does not
     solve the other.

     KRUSKAL   sort all edges ascending; add an edge if it
               joins two different components (union-find,
               chapter 33). Stop at V-1 edges.
     PRIM      grow one tree: repeatedly take the cheapest
               edge leaving the current set. Dijkstra's shape
               with "edge weight" instead of "path length".

     Kruskal is easier to write when you already have DSU.

Problems

How it shows up

SymptomCause
Wrong distances with negative edgesDijkstra is invalid there — use Bellman–Ford
Dijkstra is slowMissing the stale-entry check, or scanning for the minimum instead of using a heap
Unreachable node reported as 0Distances must start at Infinity, not 0
Shortest path wrong on an unweighted graphUsed DFS — BFS is required
MST has a cycleKruskal must reject edges whose endpoints already share a root
MST incompleteGraph is disconnected — no spanning tree exists
Used Dijkstra for an MSTDifferent objectives — minimise edge weight, not path length
Overflow adding distancesInfinity + w in fixed-width types — guard before relaxing
