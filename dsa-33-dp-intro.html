DP: the method, memoisation and tabulation

Recursion that stops recomputing. Dynamic programming has a reputation for difficulty because people try to leap straight to the table — the reliable route is to write the recursion first and then cache it.

The method

Dynamic programming has a reputation for requiring insight, and mostly requires a procedure. It applies under exactly two conditions, and checking them is how you know DP is the answer before you have found the recurrence.

   DP APPLIES WHEN BOTH OF THESE HOLD:

     OPTIMAL SUBSTRUCTURE   the answer is built from answers
                            to smaller subproblems
     OVERLAPPING SUBPROBLEMS the same subproblem is reached
                            many times

   The second is what distinguishes DP from plain divide and
   conquer. Merge sort has optimal substructure but its
   halves never overlap, so caching would gain nothing.

   ---------------------------------------------------------
   THE FOUR-STEP RECIPE. FOLLOW IT IN ORDER.

     1. WRITE THE BRUTE-FORCE RECURSION.
        What is the smallest decision? What does it leave?
        Do not think about efficiency yet.

     2. IDENTIFY THE STATE.
        Which parameters actually change between calls?
        Those, and only those, are the memo key.

     3. ADD MEMOISATION.
        One dictionary or array. This alone usually takes
        the solution from exponential to polynomial.

     4. (optional) CONVERT TO TABULATION.
        Fill the table in dependency order with loops.
        Removes the recursion depth risk and often allows
        space to be reduced.

     MOST INTERVIEWERS ACCEPT STEP 3. Do not skip 1 and 2 to
     get there faster — writing the recursion first is what
     makes the state obvious.

   ---------------------------------------------------------
   TOP-DOWN (memoised recursion)

     const memo = new Map();
     function f(state) {
         if (isBase(state)) return baseValue;
         if (memo.has(state)) return memo.get(state);

         const result = combine(f(smaller1), f(smaller2));
         memo.set(state, result);
         return result;
     }

     + follows the natural recursion
     + only computes states actually REACHED
     - recursion depth, and hashing overhead

   BOTTOM-UP (tabulation)

     const dp = new Array(n + 1);
     dp[0] = base;
     for (let i = 1; i <= n; i++)
         dp[i] = combine(dp[i - 1], dp[i - 2]);
     return dp[n];

     + no recursion, usually faster constants
     + SPACE OPTIMISATION becomes visible
     - you must work out the fill order yourself
     - computes every state, even unreachable ones

   ---------------------------------------------------------
   SPACE OPTIMISATION — the standard follow-up

     If dp[i] depends only on dp[i-1] and dp[i-2], you never
     need the whole array:

       let prev2 = base0, prev1 = base1;
       for (let i = 2; i <= n; i++) {
           const cur = f(prev1, prev2);
           prev2 = prev1;
           prev1 = cur;
       }

     O(n) space becomes O(1). The same idea reduces a 2-D
     table to two rows, or sometimes one (chapter 38).

   ---------------------------------------------------------
   HOW TO SPOT A DP PROBLEM

     "how many ways ..."          COUNT
     "minimum / maximum cost"     OPTIMISE
     "is it possible to ..."      DECIDE
     "longest / shortest ..."     OPTIMISE

     plus: choices at each step, and the same situation
     reachable by several routes.

     IF THE PROBLEM ASKS FOR THE ACTUAL LIST OF SOLUTIONS,
     it is backtracking, not DP (chapter 36). DP gives you
     a count or an optimum, not an enumeration.

SymptomCause
