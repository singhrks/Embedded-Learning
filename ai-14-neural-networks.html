Neural networks: the multilayer perceptron

Stack the units from the last chapter, put a non-linearity between the layers, and the model can represent anything. This is the architecture every later one is a specialisation of.

The architecture

A neural network is regression from the previous chapter, stacked, with one nonlinearity between the layers. That nonlinearity is doing all the work, which is why so much of the chapter is about it.

   INPUT      HIDDEN 1     HIDDEN 2      OUTPUT
   (784)       (128)        (64)          (10)

     o ---\   /-- o ---\   /-- o ---\   /-- o
     o ----\ /--- o ----\ /--- o ----\ /--- o
     o -----X---- o -----X---- o -----X---- o
     o ----/ \--- o ----/ \--- o ----/ \--- o
     o ---/   \-- o ---/   \-- o ---/   \-- o
              W1,b1       W2,b2        W3,b3
              ReLU        ReLU         softmax

   EVERY LAYER IS:
        h = activation(W @ x + b)

   THE FORWARD PASS, in full:
        h1 = relu(x  @ W1 + b1)      (784,) -> (128,)
        h2 = relu(h1 @ W2 + b2)      (128,) -> ( 64,)
        y  = softmax(h2 @ W3 + b3)   ( 64,) -> ( 10,)

   PARAMETER COUNT:
        784*128 + 128   = 100,480
        128*64  +  64   =   8,256
        64*10   +  10   =     650
                        = 109,386 total

   THE ACTIVATION IS THE WHOLE POINT. Without it:
        W3 (W2 (W1 x)) = (W3 W2 W1) x = W x
   Three layers collapse into one matrix (chapter 03). THE
   DEPTH WOULD BUY NOTHING AT ALL. A non-linearity between
   layers is what makes composition meaningful.

   THE UNIVERSAL APPROXIMATION THEOREM says a network with
   ONE hidden layer can approximate any continuous function
   on a bounded domain, to any accuracy, given enough units.

   AND THE THEOREM IS ALMOST USELESS IN PRACTICE, which is
   worth being clear about:
     · "enough units" may be exponentially many
     · it says nothing about whether TRAINING will FIND those
       weights
     · it says nothing about GENERALISATION

   DEPTH IS WHAT ACTUALLY WORKS. Deep networks represent
   many functions exponentially more compactly than shallow
   ones, and they are the ones gradient descent can
   successfully train. That empirical fact, not the theorem,
   is why the field is called DEEP learning.

A complete implementation

Reading about backpropagation and implementing it are different experiences. This is a complete, working network in under a hundred lines, with no framework underneath it.

"""A full MLP in numpy. Every line here was derived in
   chapters 06, 07, 10 and 11 - this is just assembly."""

import numpy as np

def relu(x):          return np.maximum(0, x)
def relu_grad(x):     return (x > 0).astype(x.dtype)

def softmax(x):
    x = x - x.max(axis=-1, keepdims=True)      # ch. 06
    e = np.exp(x)
    return e / e.sum(axis=-1, keepdims=True)

class MLP:
    def __init__(self, sizes):
        self.W, self.b = [], []
        for i in range(len(sizes) - 1):
            # HE INITIALISATION - the variance argument from
            # chapter 08. Getting this wrong is the most
            # common reason a network refuses to train.
            self.W.append(np.random.randn(sizes[i],
                                          sizes[i+1])
                          * np.sqrt(2.0 / sizes[i]))
            self.b.append(np.zeros(sizes[i+1]))

    def forward(self, X):
        self.z, self.a = [], [X]     # SAVED for backward
        for i in range(len(self.W)):
            z = self.a[-1] @ self.W[i] + self.b[i]
            self.z.append(z)
            # no activation on the OUTPUT layer - the loss
            # takes raw logits (chapter 10)
            self.a.append(relu(z) if i < len(self.W) - 1
                          else z)
        return self.a[-1]

    def backward(self, y_onehot):
        N = y_onehot.shape[0]
        grads_W = [None] * len(self.W)
        grads_b = [None] * len(self.b)

        # THE CLEAN GRADIENT: softmax + cross-entropy
        # collapses to (prediction - target). Chapter 06.
        delta = (softmax(self.a[-1]) - y_onehot) / N

        for i in reversed(range(len(self.W))):
            grads_W[i] = self.a[i].T @ delta     # ch. 07
            grads_b[i] = delta.sum(axis=0)
            if i > 0:
                delta = (delta @ self.W[i].T
                         * relu_grad(self.z[i-1]))
        return grads_W, grads_b

    def step(self, gW, gb, lr):
        for i in range(len(self.W)):
            self.W[i] -= lr * gW[i]
            self.b[i] -= lr * gb[i]


# --- TRAIN IT ---
model = MLP([784, 128, 64, 10])

for epoch in range(20):

        model.step(gW, gb, lr=0.1)

    logits = model.forward(X_val)

Choosing an activation

The choice of activation looks like a minor detail and determines whether a deep network trains at all. Each of these was introduced to fix a specific, identifiable failure of the one before it.

FunctionFormulaUse
ReLUmax(0, x)The default. Cheap, no saturation for positive inputs
LeakyReLUmax(0.01x, x)When units are dying
GELUx · Φ(x)Transformers — GPT, BERT
SiLU / Swishx · σ(x)Modern LLMs, usually gated as SwiGLU
Sigmoid1/(1+e⁻ˣ)Output only — binary probability, or a gate
Tanh—LSTM internals; zero-centred
Softmax—Output layer for multi-class
None (identity)—Regression output, and every logit layer
 
/* THE DECISION IN PRACTICE:
     hidden layers, general        -> ReLU
     hidden layers, transformer    -> GELU or SwiGLU
     output, binary classification -> sigmoid
     output, multi-class           -> softmax (fused into
                                      the loss)
     output, regression            -> NONE

/* THE MOST COMMON ERROR: PUTTING AN ACTIVATION ON THE
   OUTPUT LAYER OF A CLASSIFIER AND THEN USING A LOSS THAT
   EXPECTS LOGITS. It halves your effective gradient and
   costs accuracy, and it produces no error message
   (chapter 06).

/* --- DEAD ReLUs, concretely --- */
    A unit whose pre-activation is negative for EVERY input
    outputs zero always, and its gradient is zero always, so
    it never recovers. Usually caused by too high a learning
    rate driving a large negative bias.

    DIAGNOSE:
        frac_dead = (activations == 0).all(axis=0).mean()
    A few percent is normal - ReLU sparsity is useful.
    Thirty percent means something is wrong.

    FIX: lower the learning rate, use LeakyReLU or GELU,
    check the initialisation.

/* --- AND FOR THE EMBEDDED READER (chapter 27) --- */
    ReLU is ONE COMPARISON. GELU involves a tanh or an erf
    approximation - roughly 10-20x the cost, and it needs a
    lookup table or a polynomial on a device without an FPU.
    On an MCU, ReLU (or ReLU6, which clamps at 6 and
    quantises cleanly) is almost always the right choice,
    and every embedded inference library optimises for
    it.                                                    */
What the layers are doing

Each hidden layer computes a new representation of the input — a set of learned features. The first layer of an image network learns edges; the next, corners and textures; the next, object parts. You did not specify any of those. Representation learning is the actual contribution of deep learning: instead of hand-engineering features and then fitting a linear model on top, the network learns the features and the classifier together, end to end. Every architecture after this chapter is a different structural prior about what representations are useful — convolution for spatial locality, attention for relevance across a sequence.

Why depth, and what the priors are

A single hidden layer is already a universal approximator, which raises an obvious question about why anyone builds deep networks. The answer is about efficiency and structure rather than capability.

/* --- AN MLP HAS NO STRUCTURAL PRIOR --- */
    Every input connects to every unit. The model has no
    notion that pixel (3,4) is next to pixel (3,5), or that
    token 7 came before token 8. It must learn any such
    structure from data - which needs vastly more data than
    building the assumption in.

/* --- CONVOLUTIONAL NETWORKS: the spatial prior --- */
    A small kernel slides over the input, SHARING WEIGHTS
    across positions.

      · TRANSLATION EQUIVARIANCE: a feature detector that
        works at one position works at all of them
      · LOCALITY: nearby pixels are related
      · PARAMETER SHARING: a 3x3 kernel is 9 weights,
        regardless of image size

    A 224x224 image into a 1000-unit MLP layer needs 50
    million weights for one layer. A conv layer needs
    hundreds. THE PRIOR IS THE POINT - and it is why CNNs
    beat MLPs on images by an enormous margin.

    STILL THE RIGHT CHOICE for vision on embedded hardware:
    MobileNet, EfficientNet-Lite and their kin run on
    microcontrollers (chapter 27) where a vision transformer
    does not.

/* --- RECURRENT NETWORKS: the sequential prior --- */
    A hidden state carried from step to step. Chapter 18
    covers them and why they were superseded.

/* --- TRANSFORMERS: the relevance prior --- */
    Attention lets every position look at every other
    position, WEIGHTED BY LEARNED RELEVANCE (chapter 19).
    A weaker prior than convolution - which is why
    transformers need more data, and why, with enough data,
    they win.

    THE PATTERN ACROSS ALL THREE: A STRONGER PRIOR NEEDS
    LESS DATA BUT CAPS PERFORMANCE; A WEAKER PRIOR NEEDS
    MORE DATA AND SCALES FURTHER. That trade-off is the
    single most useful lens for reading architecture papers.

/* --- WHY DEEP RATHER THAN WIDE --- */
    · COMPOSITIONAL efficiency: some functions need
      exponentially more units in a shallow network than in
      a deep one
    · HIERARCHY: features build on features
    · EMPIRICALLY, depth wins - and residual connections
      (chapter 22) made very deep networks trainable, which
      was the unlock.

/* --- THE PROBLEMS DEPTH INTRODUCES, and their fixes --- */
      vanishing/exploding gradients  -> careful init,
                                        residual connections
      internal covariate shift       -> normalisation layers
      overfitting                    -> more data, dropout,
                                        weight decay
      compute cost                   -> the entire hardware
                                        industry

    Chapters 15 and 22 cover the first three. The fourth is
    someone else's problem.                               */
