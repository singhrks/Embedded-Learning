Arrays: the sliding window

A contiguous range with two moving edges and a running summary of what is inside it. The answer to almost every question containing the word "substring" or "subarray".

The pattern

The window pattern exists because the brute force recomputes something it already knew. Seeing exactly what is being wasted is what makes the linear version feel inevitable rather than clever.

   THE PROBLEM SHAPE: "find the longest / shortest / count
   of CONTIGUOUS subarrays satisfying some condition".

   THE BRUTE FORCE regenerates every window from scratch:
     for each start i:            O(n)
       for each end j:            O(n)
         summarise a[i..j]        O(n)   -> O(n^3)

   THE INSIGHT: consecutive windows OVERLAP almost
   completely. Sliding from [i..j] to [i..j+1] adds ONE
   element. Sliding from [i..j] to [i+1..j] removes ONE.
   So maintain the summary INCREMENTALLY instead of
   recomputing it.

     [ 2, 1, 5, 1, 3, 2 ]   k = 3
       ^-----^                sum = 8
          ^-----^             sum = 8 - 2 + 1 = 7
             ^-----^          sum = 7 - 1 + 3 = 9   <- best
                ^-----^       sum = 9 - 5 + 2 = 6

   TWO KINDS OF WINDOW, and telling them apart is the whole
   skill:

   FIXED SIZE — the window is always exactly k wide.
     add a[right]; if (right >= k) remove a[right-k];
     record the answer once the window is full.

   VARIABLE SIZE — grow greedily, shrink when invalid.
     for right in 0..n-1:
         ADD a[right] to the window
         while (WINDOW IS INVALID):
             REMOVE a[left]; left++
         record the answer          <- position matters!

   WHY IT IS O(n) AND NOT O(n^2): `left` only ever moves
   FORWARD and is bounded by n, so the total number of
   shrink steps across the entire run is at most n. Each
   element enters the window once and leaves at most once.
   That is the amortised argument from chapter 02, and you
   should be ready to say it aloud.

     TIME  O(n)      SPACE  O(1), or O(k) for a frequency map

When to reach for it

"Contiguous" + longest/shortest/max/min

Maximum sum subarray of size k, longest substring without repeats, minimum window substring.

"Substring" or "subarray"

The word almost always means a window. If it says subsequence (non-contiguous), it is usually DP instead.

A constraint that is monotonic

Growing the window can only make it "more invalid", shrinking only "more valid" — that is what makes the greedy shrink correct.

Counting subarrays with a property

"At most K" is windowable; "exactly K" = atMost(K) − atMost(K−1).

/* --- TEMPLATE 1: FIXED WINDOW OF SIZE k --- */
function fixedWindow(a, k) {
    let sum = 0, best = -Infinity;
    for (let right = 0; right < a.length; right++) {
        sum += a[right];                       // ADD
        if (right >= k) sum -= a[right - k];   // REMOVE the one
                                               // that fell out
        if (right >= k - 1) best = Math.max(best, sum);
    }                                          // ^ only once full
    return best;
}

/* --- TEMPLATE 2: LONGEST VALID WINDOW --- */
function longestValid(a) {
    let left = 0, best = 0;
    for (let right = 0; right < a.length; right++) {
        add(a[right]);
        while (!valid()) { remove(a[left]); left++; }
        best = Math.max(best, right - left + 1);   // AFTER the fix
    }
    return best;
}

/* --- TEMPLATE 3: SHORTEST VALID WINDOW --- */
function shortestValid(a) {
    let left = 0, best = Infinity;
    for (let right = 0; right < a.length; right++) {
        add(a[right]);
        while (valid()) {                          // note: WHILE VALID
            best = Math.min(best, right - left + 1);  // record FIRST
            remove(a[left]); left++;
        }
    }
    return best === Infinity ? 0 : best;
}

/* THE DIFFERENCE THAT CATCHES EVERYONE:

     LONGEST   shrink while INVALID, record AFTER the loop
     SHORTEST  shrink while VALID,   record INSIDE the loop

   Get these the wrong way round and you will pass the easy
   tests and fail the rest. Write the loop, then ask
   yourself: "at the moment I record the answer, is the
   window guaranteed valid?"                             */
