DP: grids and sequences

Two more shapes: paths through a grid, where each cell depends on its neighbours, and increasing subsequences, where the classic O(n²) has a genuinely clever O(n log n) alternative.

Grid DP

Grid DP is the easiest family to recognise because the state is simply the cell you are standing on. The restriction on movement is what makes it a DP rather than a graph search — worth noticing, because it is the first thing to check.

   THE STATE IS THE CELL. Movement is restricted — usually
   right and down only — which is what makes it acyclic and
   therefore a DP rather than a graph search.

     dp[r][c] = answer for the subproblem ending at (r, c)

     dp[r][c] = f(dp[r-1][c], dp[r][c-1])
                    ^ from above   ^ from the left

   COUNT PATHS       dp[r][c] = dp[r-1][c] + dp[r][c-1]
   MINIMUM PATH SUM  dp[r][c] = grid[r][c]
                                + min(dp[r-1][c], dp[r][c-1])
   MAXIMUM SQUARE    dp[r][c] = 1 + min(up, left, diagonal)
                                when grid[r][c] === 1

   BASE CASES ARE THE FIRST ROW AND FIRST COLUMN — they have
   only one predecessor each, so they accumulate in a
   straight line.

   THE OBSTACLE VARIANT: a blocked cell gets dp = 0 and is
   skipped, which propagates naturally. Blocking the START
   makes the whole answer 0.

   SPACE: each row depends only on the row above, so one
   row updated left to right suffices — O(n) instead of
   O(m·n).

   IF MOVEMENT IS UNRESTRICTED (any direction, or weights
   vary), it is no longer a DP — it is a shortest-path
   problem and needs BFS or Dijkstra (chapter 34).

   ---------------------------------------------------------
   LONGEST INCREASING SUBSEQUENCE

   THE O(n^2) DP:
     dp[i] = length of the longest increasing subsequence
             ENDING at index i

     dp[i] = 1 + max(dp[j])  over all j < i with a[j] < a[i]
     answer = max(dp)

     Note the answer is the MAXIMUM of the table, not
     dp[n-1] — the best subsequence need not use the last
     element.

   THE O(n log n) VERSION — patience sorting:

     tails[k] = the SMALLEST possible tail value of an
                increasing subsequence of length k+1

     for (x of a) {
         i = lowerBound(tails, x);   // first tail >= x
         if (i === tails.length) tails.push(x);
         else tails[i] = x;          // REPLACE, keep it small
     }
     return tails.length;

     `tails` IS NOT THE SUBSEQUENCE. It is only guaranteed to
     have the right LENGTH. Recovering the actual sequence
     needs parent pointers.

     THE INTUITION: a shorter tail leaves more room for
     future elements, so always keep the smallest tail for
     each length. Binary searching that array is what
     removes the inner loop.
