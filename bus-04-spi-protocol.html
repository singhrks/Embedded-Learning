SPI: modes 0-3, chip select and timing

SPI is the simplest bus in this track and the one most often mis-wired, because it has no addressing, no acknowledgement, no error detection, and four clock configurations of which exactly one is right for your device.

Four wires and a shift register

   MASTER                          SLAVE
   +----------+                    +----------+
   |  SCLK  --+------------------>-+-- SCLK   |
   |  MOSI  --+------------------>-+-- MOSI   |
   |  MISO  <-+------------------<-+-- MISO   |
   |  CS    --+------------------>-+-- CS     |  active LOW
   +----------+                    +----------+

   IT IS ONE CIRCULAR SHIFT REGISTER SPANNING BOTH CHIPS:

     master reg [10110010] --MOSI--> slave reg [01001101]
                    ^                              |
                    +---------MISO-----------------+

   Every clock edge shifts one bit out of each and into the
   other. After 8 clocks the two bytes have been EXCHANGED.

   CONSEQUENCE THAT SURPRISES EVERYONE: you cannot receive
   without transmitting. To read a byte you must clock out
   a dummy byte - conventionally 0x00 or 0xFF. There is no
   "read" operation, only "exchange".

   uint8_t spi_xfer(uint8_t out) {
       while (!(SPI1->SR & SPI_SR_TXE)) { }
       *(volatile uint8_t *)&SPI1->DR = out;
       while (!(SPI1->SR & SPI_SR_RXNE)) { }
       return *(volatile uint8_t *)&SPI1->DR;
   }
   uint8_t v = spi_xfer(0xFF);      /* "read" */

   NO ADDRESSING - selection is the CS pin, so N devices
   need N chip-select pins.
   NO ACKNOWLEDGEMENT - the master cannot tell whether a
   slave is present, powered, or listening.
   NO ERROR DETECTION - none at all.
   NO SPEED NEGOTIATION - you must know the slave's limit.

   In exchange: full duplex, trivially simple, and fast.
   50-100 MHz is routine.

The four modes

   Two independent bits give four combinations:

   CPOL - clock polarity: idle level of SCLK
          0 = idle low,  1 = idle high
   CPHA - clock phase:   which edge SAMPLES
          0 = sample on the FIRST edge
          1 = sample on the SECOND edge

   MODE 0  CPOL=0 CPHA=0   sample on RISING    <- most common
     SCLK  ___|--|__|--|__
     MOSI  X====X====X====
           ^    ^    ^        sampled on rising edge

   MODE 1  CPOL=0 CPHA=1   sample on FALLING
     SCLK  ___|--|__|--|__
     MOSI  X====X====X====
              ^    ^          sampled on falling edge

   MODE 2  CPOL=1 CPHA=0   idle high, sample FALLING
     SCLK  ---|__|--|__|--
           ^    ^    ^

   MODE 3  CPOL=1 CPHA=1   idle high, sample RISING
     SCLK  ---|__|--|__|--
              ^    ^

   MODE 0 and MODE 3 cover the large majority of devices.

   THE RULE: data is SET UP on one edge and SAMPLED on the
   other. Both ends must agree, and the datasheet always
   states it - usually as a timing diagram rather than a
   mode number, so you may have to read the diagram and
   derive the mode yourself.

   WRONG MODE SYMPTOMS, and they are diagnostic:
     - every byte shifted by one bit (0x55 reads as 0xAA
       or 0x2A) -> CPHA is wrong
     - first byte wrong, rest correct -> CPHA wrong, and
       the device recovered
     - all 0x00 or all 0xFF -> often CS, wiring, or power,
       not mode
     - works at low speed, fails fast -> timing, not mode
       (see below)

Configuring it

void spi_init(uint32_t hz)
{
    RCC->APB2ENR |= RCC_APB2ENR_SPI1EN;
    (void) RCC->APB2ENR;

    /* PA5 SCK, PA6 MISO, PA7 MOSI - AF5. CS is a plain GPIO
       we drive ourselves (see below).                      */
    gpio_af(GPIOA, 5, 5); gpio_af(GPIOA, 6, 5); gpio_af(GPIOA, 7, 5);
    gpio_output(GPIOB, 6);                 /* CS            */
    GPIOB->BSRR = (1u << 6);               /* idle HIGH     */

    /* Prescaler: PCLK2 / 2^(BR+1). At 84 MHz PCLK2,
       BR=3 gives 84/16 = 5.25 MHz.                         */
    uint32_t br = 0;
    while ((84000000u >> (br + 1)) > hz && br < 7) { br++; }

    SPI1->CR1 = SPI_CR1_MSTR              /* master         */
              | (br << 3)
              | SPI_CR1_SSM | SPI_CR1_SSI /* software NSS   */
              /* CPOL=0, CPHA=0 -> mode 0: both bits clear  */
              ;
    SPI1->CR2 = 0;                        /* 8-bit          */
    SPI1->CR1 |= SPI_CR1_SPE;
}

/* SSM + SSI IS NOT OPTIONAL. Without software slave
   management the hardware NSS input, if it goes low,
   silently demotes the peripheral from master to slave and
   everything stops. This is one of the most common
   first-time SPI failures on STM32, and the symptom -
   "MOSI never toggles" - gives no hint of the cause.      */
Drive chip select yourself, in software

Hardware CS on most microcontrollers deasserts between bytes, which breaks any device expecting a multi-byte transaction to be framed by one continuous CS assertion — which is almost all of them. A GPIO you control explicitly lets you hold CS low across a command byte, an address and a data burst. It also lets you meet the setup and hold times a datasheet specifies around the CS edges.

A transaction, with the timing that matters

/* Reading a register from a typical sensor. */

uint8_t sensor_read_reg(uint8_t reg)
{
    uint8_t v;

    CS_LOW();
    delay_ns(50);              /* t_CSS: CS setup before
                                  the first clock edge     */

    (void) spi_xfer(reg | 0x80);   /* bit 7 = read         */
    v = spi_xfer(0xFF);            /* dummy out, data in   */

    /* CRITICAL: wait for the shift register to EMPTY before
       raising CS. TXE means the DATA REGISTER is free, not
       that the byte has left the pin (chapter 01).        */
    while (SPI1->SR & SPI_SR_BSY) { }
    delay_ns(50);              /* t_CSH: CS hold           */
    CS_HIGH();

    return v;
}

/* RAISING CS ON TXE INSTEAD OF BSY TRUNCATES THE LAST BYTE.
   The symptom is a device that mostly works but ignores
   the final byte of every write - so single-register
   writes fail while burst writes appear to work except for
   the last register. Memorably confusing.

   BURST TRANSFERS: most devices auto-increment their
   internal address, so one CS assertion can read many
   registers. This is much faster than N transactions and
   is how you read a FIFO:                                 */

void sensor_read_burst(uint8_t start, uint8_t *dst, size_t n)
{
    CS_LOW();
    (void) spi_xfer(start | 0xC0);    /* read + increment  */
    while (n--) { *dst++ = spi_xfer(0xFF); }
    while (SPI1->SR & SPI_SR_BSY) { }
    CS_HIGH();
}

Why it works slowly and fails fast

   The most common SPI failure after mode errors.

   THE ROUND TRIP that limits speed:

     master drives SCLK edge
       -> propagates down the trace        (~5 ns / metre...
                                            but 1-2 ns typical)
       -> slave's t_V: time to put data
          on MISO after the edge           (often 20-40 ns!)
       -> propagates back
       -> must arrive before the master's
          setup time at the NEXT edge

     So:  t_prop_out + t_V + t_prop_back + t_setup < half a
          clock period

     With t_V = 30 ns and small propagation, half a period
     must exceed ~35 ns, so the period is 70 ns and the
     maximum clock is about 14 MHz - regardless of what the
     master can generate.

   THIS IS WHY "it works at 1 MHz and fails at 20 MHz" is
   almost never a software problem. Check:
     - the slave's maximum SCLK in its datasheet
     - t_V (output valid delay) which often binds first
     - trace length, especially through a connector or
       ribbon cable
     - whether MISO has a weak pull-up fighting the driver

   RULES OF THUMB:
     - on-board, short traces: 10-25 MHz usually fine
     - through a connector or 10 cm of ribbon: 1-4 MHz
     - always bring a new device up at 1 MHz, confirm it
       works, THEN raise the clock while watching for
       errors. Starting fast conflates wiring bugs with
       timing bugs.
