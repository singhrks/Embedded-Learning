Arrays: Kadane and maximum subarray

One decision, made at every element: extend the run, or start a new one. It is the smallest dynamic program there is, and recognising its shape unlocks a whole family of problems.

The pattern

Kadane's algorithm looks like a trick and is actually a two-line dynamic program. Framing it as a choice made at each element is what makes it something you can rederive rather than recall.

   THE PROBLEM: the contiguous subarray with the largest
   sum.

   THE INSIGHT — at each element there are only TWO choices:

     EXTEND the best run ending at the previous element, or
     START a fresh run at this element.

        cur = max(a[i],  cur + a[i])
                  ^          ^
              start new    extend
        best = max(best, cur)

   AND THE EQUIVALENT FORM THAT EXPLAINS IT BEST:

        if (cur < 0) cur = 0;    // a negative prefix can
        cur += a[i];             // only HURT what follows
        best = max(best, cur);

   THE ARGUMENT: if the best run ending at i-1 has a
   NEGATIVE sum, attaching it to a[i] makes things worse
   than starting fresh. So drop it. That is the whole
   algorithm.

     a = [ -2,  1, -3,  4, -1,  2,  1, -5,  4 ]
   cur =   -2   1  -2   4   3   5   6   1   5
   best =  -2   1   1   4   4   5   6   6   6
                                   ^ answer

   THE TRAP: INITIALISE best TO -Infinity (or a[0]), NOT 0.
   With an all-negative array the answer is the largest
   single element, and starting at 0 wrongly returns 0 for
   an empty subarray the problem does not allow.

   THE SHAPE GENERALISES. Kadane is a one-state DP:
     "the best answer ENDING HERE, given the best answer
      ending one step back."
   Once you see that, the variants follow:

     MAXIMUM PRODUCT   track min AND max (negatives flip)
     CIRCULAR          answer = max(normal, total - minSubarray)
     MAX SUM WITH ONE
       DELETION        two states: no deletion used, one used
     BEST TIME TO
       BUY/SELL STOCK  Kadane on the difference array

   COST: O(n) time, O(1) space, one pass.

When to reach for it

"Maximum/minimum contiguous sum"

The plain case. Also works for products and XOR with adjustments.

Best profit from one buy and one sell

Kadane over consecutive differences, or equivalently track the running minimum.

Values can be negative and it is contiguous

A sliding window fails; Kadane does not.

"Ending here" feels natural

Whenever the answer at i depends only on the answer at i−1, it is a one-state DP.

/* --- THE TEMPLATE --- */
function maxSubArray(a) {
    let cur = a[0], best = a[0];     // NOT 0
    for (let i = 1; i < a.length; i++) {
        cur = Math.max(a[i], cur + a[i]);
        best = Math.max(best, cur);
    }
    return best;
}

/* --- RECOVERING THE ACTUAL SUBARRAY, a common follow-up --- */
let cur = a[0], best = a[0];
let s = 0, bestL = 0, bestR = 0;
for (let i = 1; i < a.length; i++) {
    if (cur + a[i] < a[i]) { cur = a[i]; s = i; }  // restarted
    else                     cur = cur + a[i];
    if (cur > best) { best = cur; bestL = s; bestR = i; }
}
// the subarray is a[bestL..bestR]

/* --- MAXIMUM PRODUCT: why one variable is not enough --- */
    A large NEGATIVE product becomes the largest POSITIVE
    product the moment it meets another negative. So you
    must carry BOTH extremes:
        newMax = max(x, max*x, min*x)
        newMin = min(x, max*x, min*x)
    and compute both from the OLD values — overwrite max
    first and newMin uses the wrong one.               */
