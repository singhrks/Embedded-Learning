Prerequisites & self-assessment

Be honest with this page. Starting the ARM track without solid C is the single most common way people waste three months. Everything here is teachable — but only in the right order.

The three hard requirements

1. C, at a working level

Not "I have written C". You need pointers to be boring. If any line below makes you pause, do the C track first.

int   a[5];
int  *p    = a;          /* what is the type of a here, and why?          */
int (*q)[5] = &a;        /* how does q differ from p?                     */
int  *r    = a + 2;      /* what address is this, in bytes?               */

char  s[] = "hi";        /* sizeof(s) is 3, not 2 — why?                  */
char *t   = "hi";        /* writing t[0] = 'H' is undefined — why?        */

struct f { uint8_t a; uint32_t b; };   /* sizeof is 8, not 5 — why?       */

void (*cb)(int) = handler;             /* declare an array of these       */

uint32_t v = 1u << 31;   /* now do 1 << 31 with a signed int. What breaks? */

2. Hexadecimal and binary fluency

You should read 0x4001_0080 and think "offset 0x80 inside the block at 0x4001_0000" without pausing. Try these in your head:

3. A command line

You will live in a shell, even for Windows driver work. You need: navigating and searching a filesystem, pipes and redirection, grep, find, editing a file over SSH, and git at the level of clone, branch, diff, log, bisect.

What you explicitly do not need

A computer science degree. Prior kernel experience. Owning hardware. Knowing C++ or Rust. Familiarity with any specific SoC vendor. Every one of those is either taught here or genuinely optional.

The self-assessment

Score yourself honestly. Each question is answerable in two or three sentences.

Section A — C (must pass 5 of 6)

  1. What is the difference between char *p and char p[] as a function parameter?
  2. Why does sizeof(struct {char a; int b;}) exceed the sum of its members?
  3. What does static mean on a file-scope function, and on a local variable?
  4. Give a concrete bug caused by omitting volatile.
  5. What is wrong with if (x = 5), and with a[i++] = i;?
  6. How do you return two values from a C function? Give two different approaches and their trade-offs.

Section B — numbers and bits (must pass 3 of 4)

  1. Convert 0b1011_0110 to hex and to decimal.
  2. Write an expression that clears bits 5:3 of reg and sets them to the value n.
  3. What is -1 as an eight-bit two's-complement pattern, and why that pattern?
  4. Why can 0.1 + 0.2 != 0.3 in floating point?

Section C — tools (must pass 3 of 4)

  1. What does a linker do that a compiler does not?
  2. What is in a .o file that is not in a .c file?
  3. How would you find every use of a symbol across a 20-million-line source tree?
  4. What does git bisect do, and when is it the right tool?

If you are coming from web or application development

Your instincts will fight you in three specific places, and it helps to name them in advance. Memory is not free and not managed — you allocate, you free, and you own the consequences. There is no exception to catch — a bad pointer is a crashed machine, not a stack trace. And the abstraction is not the machine — you will spend real time reasoning about caches, alignment and instruction ordering that a higher-level runtime hid from you. None of this is harder; it is just closer to the metal, and the feedback is less forgiving.
