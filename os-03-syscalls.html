The user/kernel boundary and system calls

The system call is the one door between an application and the kernel. Everything an OS offers passes through it, every argument crossing it is hostile until validated, and its cost shapes the design of every high-performance I/O interface ever built.

Why a special mechanism

A function call cannot cross the privilege boundary. If user code could simply call a kernel address, it could call any kernel address — landing in the middle of a function, skipping permission checks, with attacker-chosen register state. Isolation would be decorative.

The three requirements
  1. Privilege escalation must happen atomically with the control transfer.
  2. The entry point is chosen by the kernel, not the caller. User code supplies a number, not an address.
  3. The kernel must be able to return to exactly where the caller was, at its original privilege.

A synchronous exception provides all three, which is why every architecture implements system calls as a deliberate trap.

The syscall ABI is not the C ABI

Note the differences: on x86-64 the fourth argument is in r10, not rcx, because the syscall instruction clobbers rcx with the return address. On AArch64 the syscall number sits in x8, outside the normal argument registers. Kernel entry code must know both conventions, and this is exactly the mismatch that makes hand-written syscall wrappers error-prone — use libc's.

/* what write(1, "hi\n", 3) compiles to on AArch64 Linux */
        mov     x0, #1                  // fd
        adr     x1, msg                 // buf
        mov     x2, #3                  // count
        mov     x8, #64                 // __NR_write
        svc     #0
        // x0 now holds the byte count, or a negative errno

Validating what crosses

Every byte from user space is hostile

A system call argument is attacker-controlled input arriving at the highest privilege level. The kernel must assume the caller is malicious — not merely buggy — because a local user exploiting a validation gap gets kernel code execution.

/* NEVER dereference a user pointer directly. */
long sys_example(void __user *ubuf, size_t len)
{
        char kbuf[256];

        /* WRONG — the pointer may reference kernel memory, unmapped
           memory, or memory that another thread unmaps mid-call. */
        memcpy(kbuf, ubuf, len);

        /* RIGHT */
        if (len > sizeof kbuf)
                return -EINVAL;                 /* bound FIRST      */
        if (copy_from_user(kbuf, ubuf, len))
                return -EFAULT;                 /* returns bytes NOT copied */
        ...
}

/* copy_from_user / copy_to_user do three things you cannot skip:
     1. check the address really lies in user space
     2. install an exception fixup, so a fault returns -EFAULT
        instead of oopsing
     3. respect PAN/SMAP, the hardware feature that blocks kernel
        access to user pages outside these helpers          */

The five validation rules

RuleFailure if ignored
Bound every length before using itKernel buffer overflow
Copy before validating, never validate in placeTOCTOU: another thread changes the value between check and use
Check every index and enum against its rangeOut-of-bounds table access
Zero output structures fully before filling themPadding bytes leak kernel stack contents to userspace
Reject unknown flags rather than ignoring themCannot add meanings later without breaking programs
 
/* Rule 2, the TOCTOU trap, written out */
struct req *r = (struct req __user *)arg;

if (r->len > MAX) return -EINVAL;      /* read #1 — validate */
process(r->buf, r->len);                /* read #2 — USE      */
/* Another thread in the same process can change r->len between
   the two reads. The check applied to a value that no longer
   exists. This is a real and repeatedly exploited pattern.   */

/* Correct: one copy, then validate the copy */
struct req k;
if (copy_from_user(&k, r, sizeof k)) return -EFAULT;
if (k.len > MAX) return -EINVAL;
process(k.buf, k.len);

/* Rule 4, the info leak */
struct info out;
memset(&out, 0, sizeof out);           /* padding too (C ch. 07) */
out.a = x; out.b = y;
if (copy_to_user(u, &out, sizeof out)) return -EFAULT;

The ABI is forever

"We do not break userspace"

Linus Torvalds' rule, and the reason Linux binaries from 1995 still run. A system call's number, argument layout and semantics are permanent once released. You cannot change a struct, repurpose a field, or tighten validation in a way that rejects previously-accepted input.

/* This is why the syscall table has entries like: */
open, openat, openat2                  /* three generations */
stat, stat64, fstatat, statx
clone, clone3
epoll_create, epoll_create1
dup, dup2, dup3

/* Each new one adds a flags argument or a size field, because the
   old one could not be extended. Designing for extension from the
   start is the lesson:                                          */

struct my_args {
        __u32 size;         /* sizeof(struct) — lets the kernel tell
                               which version the caller compiled against */
        __u32 flags;        /* reject unknown bits, so new ones are safe */
        __u64 field_a;
        __u64 field_b;
        /* new fields appended here in future versions */
};

long sys_myop(struct my_args __user *uargs, size_t usize)
{
        struct my_args a = {};

        if (usize > PAGE_SIZE) return -E2BIG;
        /* copy_struct_from_user handles version skew both ways:
           zero-fills a smaller old struct, and requires that any
           extra bytes from a newer caller are all zero.        */
        if (copy_struct_from_user(&a, sizeof a, uargs, usize))
                return -EFAULT;

        if (a.flags & ~MY_VALID_FLAGS) return -EINVAL;   /* rule 5 */
        ...
}

Cost, and the interfaces built to avoid it

Crossing the boundary is not free, and the cost has risen noticeably since the speculative-execution vulnerabilities forced mitigations into the path. Knowing the figure explains why avoiding the crossing is worth so much.

A minimal syscall costs roughly 50-500 ns:

   trap and privilege change          ~20-50 cycles
   save and restore user registers    ~30-60 cycles
   table lookup and dispatch          ~10 cycles
   pipeline and branch predictor cost variable
   Spectre/Meltdown mitigations       +100-400 cycles on affected CPUs

That is 100-1000x a function call. For a program doing millions of
small operations it dominates everything else.

Four families of workaround, all worth recognising:

  BATCH        do more per call
               writev, readv, sendmmsg, io_submit

  AVOID        remove the kernel from the path entirely
               mmap (page-fault once, then plain loads/stores)
               vDSO (see below)
               DPDK, SPDK — poll the device from user space

  AMORTISE     submit many operations, collect many completions
               io_uring: shared ring buffers, often ZERO syscalls
               in steady state

  MOVE IN      run the logic in the kernel instead
               eBPF: verified user code, executed kernel-side
/* The vDSO — a small shared object the kernel maps into every
   process, containing implementations that need no privilege.  */
clock_gettime(CLOCK_MONOTONIC, &ts);
/* Reads a kernel-maintained page of timekeeping data plus the
   hardware counter, in USER MODE. No trap at all. Roughly 25 ns
   instead of 300 ns.                                           */

cat /proc/self/maps | grep vdso
LD_SHOW_AUXV=1 /bin/true | grep VDSO

Observing system calls

Every system call a program makes can be watched, counted and timed. That turns "the program is slow" into a specific claim about which calls it makes and how often.

# trace every syscall a process makes
strace ./program
strace -c ./program              # summary: counts, time, errors
strace -f -e trace=openat,read,write ./program
strace -p 1234                   # attach to a running process

# lower overhead, system-wide
perf trace ./program
perf stat -e raw_syscalls:sys_enter ./program

# who is making the most syscalls, system-wide
sudo bpftrace -e 'tracepoint:raw_syscalls:sys_enter {
        @[comm, args->id] = count(); }'

# Windows
# Process Monitor, or Event Tracing for Windows (ETW)

# the syscall table itself
ausyscall --dump                       # numbers to names
cat /usr/include/asm-generic/unistd.h  # canonical numbering
strace -c first

When a program is inexplicably slow, run strace -c before anything else. A count of two million read() calls of 1 byte each, or thousands of failed stat() calls probing for a file, diagnoses the problem in seconds — and both are extremely common.

Windows

Windows solves the same problem with a different structure, and comparing the two directly shows which parts of the design are essential and which are merely conventional.

Win32 is NOT the syscall layer. There are two hops:

  application
      │  CreateFile(...)                    documented, stable API
      ▼
  kernel32.dll / kernelbase.dll
      │  NtCreateFile(...)                  Native API
      ▼
  ntdll.dll
      │  mov eax, 0x55        ← syscall NUMBER, and it CHANGES
      │  syscall                 between Windows versions
      ▼
  ═══ kernel ═══
  KiSystemService → SSDT lookup → NtCreateFile

Consequences:
  · Windows' stable ABI is Win32, not the syscall interface
  · calling syscalls directly is unsupported and breaks on update
    (which is why malware does it, and why EDR products watch for it)
  · Linux is the opposite: the SYSCALL is stable and libc is a
    convenience wrapper

How it shows up

SymptomCause
