Calculus: derivatives and gradients

A derivative answers one question: if I nudge this input, how much does the output move? Training a neural network is nothing but asking that question about a few billion inputs at once and stepping downhill.

The derivative

The derivative is the whole basis of training, so it is worth reconstructing what it actually says rather than recalling rules for differentiating polynomials.

   THE DEFINITION:

        f'(x) = lim       f(x + h) - f(x)
                h->0      ---------------
                                 h

   IN WORDS: the rate of change. The slope of the tangent
   line. "If x increases by a tiny amount, f increases by
   f'(x) times that amount."

        f(x) = x^2

         |          .
         |         /
         |       ./  slope at x=3 is 6
         |     ../
         |   ..
         | ..
      ---+------------
         0    3

     f'(3) = 6  means: nudge x from 3 to 3.001 and f goes
     from 9 to about 9.006.

   THE ONLY DERIVATIVES YOU NEED HERE:

     f(x) = c            f' = 0
     f(x) = x            f' = 1
     f(x) = x^n          f' = n x^(n-1)
     f(x) = e^x          f' = e^x          <- itself!
     f(x) = ln(x)        f' = 1/x
     f(x) = sin(x)       f' = cos(x)

     sum:      (f + g)' = f' + g'
     scalar:   (c f)'   = c f'
     product:  (f g)'   = f' g + f g'
     quotient: (f/g)'   = (f' g - f g') / g^2
     CHAIN:    f(g(x))' = f'(g(x)) * g'(x)   <- CHAPTER 07.
                                                THE ONE THAT
                                                MATTERS.

   THE SIGN IS THE POINT:

     f'(x) > 0   f is INCREASING here -> to decrease f, go
                 LEFT
     f'(x) < 0   f is DECREASING here -> to decrease f, go
                 RIGHT
     f'(x) = 0   flat: a minimum, a maximum, or a saddle

   SO: TO MINIMISE f, MOVE IN THE DIRECTION OPPOSITE TO THE
   DERIVATIVE. That single sentence is gradient descent
   (chapter 11), and everything else is bookkeeping.

Partial derivatives and the gradient

Once a function has many inputs — and a network has billions — the derivative becomes a vector, and that vector is exactly what training follows downhill.

/* Real functions have many inputs. A neural network's loss
   is a function of every weight in the model - billions of
   them.

   A PARTIAL DERIVATIVE holds all other inputs fixed:

        f(x, y) = x^2 + 3xy + y^2

        df/dx = 2x + 3y        (treat y as a constant)
        df/dy = 3x + 2y        (treat x as a constant)

   THE GRADIENT collects them all into a vector:

        grad f = [df/dx, df/dy]

   At the point (1, 2):
        grad f = [2*1 + 3*2, 3*1 + 2*2] = [8, 7]

/* THE TWO FACTS ABOUT THE GRADIENT THAT MATTER:

   1. IT POINTS IN THE DIRECTION OF STEEPEST INCREASE.
      So -grad f points steepest DOWNHILL. That is the
      update rule.

   2. ITS MAGNITUDE IS THE STEEPNESS. A large gradient means
      a small step changes the loss a lot; near a minimum
      the gradient goes to zero and progress stalls
      naturally.

/* THE UPDATE RULE, in full: */

        w  <-  w - learning_rate * grad_w L

   Every training run of every model in this track is that
   line, repeated.

/* --- IN CODE --- */
import numpy as np

def f(v):
    x, y = v
    return x**2 + 3*x*y + y**2

def grad_f(v):
    x, y = v
    return np.array([2*x + 3*y, 3*x + 2*y])

# ONE STEP OF GRADIENT DESCENT
v = np.array([1.0, 2.0])
lr = 0.1
for step in range(5):
    g = grad_f(v)
    v = v - lr * g
    print(step, v, f(v))

# Watch f decrease. That is the entire mechanism of
# training, at two parameters instead of seventy billion.

/* --- HIGHER DERIVATIVES, briefly --- */
    The HESSIAN is the matrix of second partial derivatives.
    It describes CURVATURE:
      · all eigenvalues positive -> a bowl, a true minimum
      · mixed signs               -> a SADDLE POINT
      · near-zero eigenvalues     -> a flat plateau

    SECOND-ORDER METHODS (Newton's method) use it and
    converge in far fewer steps. NOBODY USES THEM FOR LARGE
    NEURAL NETWORKS: the Hessian for n parameters has n^2
    entries. For a 7-billion-parameter model that is 4.9e19
    numbers. Not storable, not computable, not close.

    SO ALL DEEP LEARNING IS FIRST-ORDER. Adam and friends
    (chapter 11) approximate curvature information cheaply
    from the history of gradients, which is the closest
    anyone gets.                                          */

The functions that actually appear

In practice a small, fixed set of functions is differentiated over and over. Knowing their derivatives cold removes most of the friction from reading a backward pass.

/* You need the derivatives of these five. They are the
   whole vocabulary of a neural network's forward pass.  */

/* --- ReLU: the default activation --- */
    relu(x)  = max(0, x)
    relu'(x) = 1 if x > 0 else 0

    ONE COMPARISON AND A SELECT. No exponentials, no
    division. That cheapness is a large part of why deep
    learning became practical - and it matters even more on
    an MCU (chapter 27).

    THE PROBLEM: for x <= 0 the gradient is EXACTLY ZERO. A
    unit that always outputs zero never updates. This is a
    DEAD ReLU, and it is a real failure mode.
    THE FIXES: LeakyReLU (slope 0.01 for x < 0), GELU, SiLU.

/* --- SIGMOID --- */
    sigmoid(x)  = 1 / (1 + e^-x)                 range (0,1)
    sigmoid'(x) = sigmoid(x) * (1 - sigmoid(x))

    NOTE THE ELEGANCE: the derivative is expressed in terms
    of the OUTPUT, so a forward pass that saved its output
    gets the backward pass almost free. Every framework
    exploits this.

    THE PROBLEM: the maximum of s(1-s) is 0.25, at x = 0.
    Multiply that through ten layers and the gradient is
    0.25^10 = 1e-6. THIS IS THE VANISHING GRADIENT PROBLEM,
    and it is why sigmoid was abandoned for hidden layers
    (chapter 18). It survives for BINARY OUTPUTS and GATES.

/* --- TANH --- */
    tanh(x)  = (e^x - e^-x)/(e^x + e^-x)        range (-1,1)
    tanh'(x) = 1 - tanh(x)^2                    max 1.0

    Zero-centred, and a maximum gradient of 1 rather than
    0.25 - strictly better than sigmoid for hidden layers,
    still saturating. Used inside LSTMs (chapter 18).

/* --- GELU and SiLU: what transformers use --- */
    gelu(x) = x * Phi(x)      Phi = the Gaussian CDF
    silu(x) = x * sigmoid(x)  (also called swish)

    Smooth, non-monotonic near zero, and empirically better
    than ReLU in transformers. GELU is in GPT and BERT;
    SwiGLU (a gated SiLU variant) is in Llama and most
    recent models (chapter 22).

/* --- SOFTMAX: turning scores into a distribution --- */
    softmax(x)_i = e^(x_i) / sum_j e^(x_j)

    Outputs are positive and sum to 1. This is how a model
    produces "the probability of each next token".

    THE NUMERICAL RULE, AND IT IS NOT OPTIONAL:

        SUBTRACT THE MAXIMUM FIRST.

        e^1000 overflows to inf in float32. But
        softmax(x) == softmax(x - c) for any constant c, so
        subtracting max(x) makes the largest exponent e^0 = 1
        and nothing overflows.

    def softmax(x):
        x = x - np.max(x, axis=-1, keepdims=True)   # <<<
        e = np.exp(x)
        return e / np.sum(e, axis=-1, keepdims=True)

    THE JACOBIAN is a full matrix (every output depends on
    every input):
        d softmax_i / d x_j = s_i (delta_ij - s_j)

    BUT - and this is the practical mercy - COMBINED WITH
    CROSS-ENTROPY LOSS THE WHOLE THING COLLAPSES TO:

        dL/dx = predicted - target

    A subtraction. That is why every framework has a fused
    `cross_entropy_with_logits` and why you should never
    apply softmax before it. Chapter 10 derives this.     */
Never apply softmax and then a separate cross-entropy

Doing it in two steps computes logs of small probabilities and loses precision, and it discards the algebraic cancellation that makes the gradient a clean subtraction. Pass raw logits to F.cross_entropy (PyTorch) or tf.nn.softmax_cross_entropy_with_logits. Applying softmax first is one of the most common beginner bugs, and it usually shows as a model that trains but plateaus early.

How derivatives are actually computed

Nobody differentiates a network by hand, and nobody uses the numerical approximation either. What frameworks actually do is a third thing, and it is worth understanding before the next chapter builds one.

/* THREE OPTIONS, and only one is used.                   */

/* --- 1. SYMBOLIC (what you did in school) --- */
    Manipulate the expression algebraically.
    PROBLEM: EXPRESSION SWELL. The symbolic derivative of a
    deep composition grows exponentially in size. Unusable
    beyond a few layers.

/* --- 2. NUMERICAL (finite differences) --- */
    f'(x) ~= (f(x + h) - f(x - h)) / (2h)

    PROBLEM 1: O(n) function evaluations for n parameters.
      Seven billion parameters means fourteen billion
      forward passes per step. Absurd.
    PROBLEM 2: precision. Too large an h and truncation
      error dominates; too small and floating-point
      cancellation destroys the answer. The sweet spot is
      narrow.

    BUT IT HAS ONE ESSENTIAL USE - CHECKING YOUR ANALYTIC
    GRADIENT:

    def grad_check(f, x, analytic_grad, h=1e-5):
        num = np.zeros_like(x)
        for i in range(x.size):
            xp = x.copy(); xp.flat[i] += h
            xm = x.copy(); xm.flat[i] -= h
            num.flat[i] = (f(xp) - f(xm)) / (2*h)
        rel = (np.abs(num - analytic_grad) /
               (np.abs(num) + np.abs(analytic_grad) + 1e-12))
        return rel.max()          # want < 1e-6 in float64

    IF YOU WRITE A CUSTOM LAYER OR A CUSTOM BACKWARD PASS,
    RUN THIS. It is the unit test of this field, and it
    catches sign errors and transposes that would otherwise
    show up as "the model just does not train well".

/* --- 3. AUTOMATIC DIFFERENTIATION: what is used --- */
    Build a graph of elementary operations during the
    forward pass. Each operation knows its own local
    derivative. Then apply the chain rule mechanically
    backwards through the graph.

      · EXACT to machine precision - not an approximation
      · costs about the SAME as one forward pass, for ALL
        parameters simultaneously
      · works for arbitrary code with loops and branches

    THIS IS THE ALGORITHM THAT MADE DEEP LEARNING POSSIBLE,
    and chapter 07 builds one from scratch.

/* --- SEEING IT WORK --- */
import torch

x = torch.tensor([1.0, 2.0], requires_grad=True)
y = (x**2).sum() + 3*x[0]*x[1]
y.backward()
x.grad          # tensor([8., 7.])  - matches our hand
                # calculation above

/* FORWARD MODE vs REVERSE MODE, since the terms appear:
     FORWARD  cheap for FEW inputs, many outputs
     REVERSE  cheap for MANY inputs, ONE output
   A loss function is many parameters -> one scalar, so deep
   learning always uses REVERSE MODE. That is what
   "backpropagation" names.                              */
