Trees: traversals, iterative and recursive

Four ways to visit every node. Choosing the right one turns most tree problems into three lines — and the interviewer will ask you for the iterative version.

The four traversals

Four traversals, one tree, four different orders. Rather than memorising the outputs, note where the visit happens relative to the recursion — that placement is the only thing that differs.

   THE TREE USED THROUGHOUT:

              1
            /   \
           2     3
          / \
         4   5

   DEPTH FIRST — the position of "visit" is the only
   difference:

     PREORDER    node, left, right      1 2 4 5 3
                 -> COPY a tree, serialise, root-first work
     INORDER     left, node, right      4 2 5 1 3
                 -> SORTED order in a BST (chapter 29)
     POSTORDER   left, right, node      4 5 2 3 1
                 -> DELETE a tree, compute sizes/heights,
                    any work needing CHILD RESULTS FIRST

   BREADTH FIRST — level by level, with a queue:

     LEVEL ORDER                        1 2 3 4 5
                 -> shortest path, level-by-level output,
                    "closest" anything

   THE CHOICE IS DETERMINED BY WHEN YOU NEED INFORMATION:

     need PARENT info before children   -> PREORDER
       (depth, path so far, passing a value down)
     need CHILD results before parent   -> POSTORDER
       (height, subtree sums, "is this subtree valid?")
     need SORTED order in a BST         -> INORDER
     need DISTANCE from the root        -> BFS

   THAT MAPPING SOLVES MOST TREE PROBLEMS BY ITSELF. If you
   are stuck on a tree question, ask: does this node need
   something from above, or something from below?

   COSTS
     every traversal   O(n) time
     recursion         O(h) space — h = height
                       O(log n) balanced, O(n) SKEWED
     BFS               O(w) space — w = maximum width,
                       which is up to n/2 for a full tree

The templates

All three depth-first orders are the same function with one line moved, and the iterative versions are worth knowing because interviewers ask for them when recursion is ruled out.

/* --- RECURSIVE: all three, one shape --- */
function dfs(node, out) {
    if (!node) return;
    // out.push(node.val);          <-- PREORDER here
    dfs(node.left, out);
    // out.push(node.val);          <-- INORDER here
    dfs(node.right, out);
    // out.push(node.val);          <-- POSTORDER here
}

/* --- ITERATIVE PREORDER: a stack, push RIGHT first --- */
function preorder(root) {
    if (!root) return [];
    const out = [], st = [root];
    while (st.length) {
        const n = st.pop();
        out.push(n.val);
        if (n.right) st.push(n.right);   // right first, so
        if (n.left)  st.push(n.left);    // LEFT pops first
    }
    return out;
}

/* --- ITERATIVE INORDER: go left, then visit, then right --- */
function inorder(root) {
    const out = [], st = [];
    let cur = root;
    while (cur || st.length) {
        while (cur) { st.push(cur); cur = cur.left; }  // dive left
        cur = st.pop();
        out.push(cur.val);                             // VISIT
        cur = cur.right;                               // then right
    }
    return out;
}

/* --- ITERATIVE POSTORDER: the trick --- */
    Do a MODIFIED PREORDER (node, RIGHT, left), then REVERSE
    the result. node-right-left reversed is left-right-node.
    Far easier than tracking whether each node's children
    have been processed.

/* --- BFS: a queue, one LEVEL per outer iteration --- */
function levelOrder(root) {
    if (!root) return [];
    const out = [], q = [root];
    while (q.length) {
        const size = q.length;        // FIX the level size FIRST
        const level = [];
        for (let i = 0; i < size; i++) {
            const n = q.shift();
            level.push(n.val);
            if (n.left)  q.push(n.left);
            if (n.right) q.push(n.right);
        }
        out.push(level);
    }
    return out;
}
/* CAPTURING `size` BEFORE THE INNER LOOP IS THE WHOLE
   TRICK — it separates the levels. Without it you get a
   flat list.

   NOTE: Array.shift() is O(n) in JavaScript, so a large BFS
   should use an index pointer instead of shift (chapter 03).
   For interview-sized inputs shift is fine, but say that
   you know.                                              */

Problems

How it shows up

SymptomCause
BFS returns one flat listLevel size not captured before the inner loop
Iterative preorder is mirroredPushed left before right — the stack reverses order
Stack overflow on a large treeSkewed tree, O(n) recursion depth — go iterative
Null children crashMissing the if (!node) return base case
Inorder of a BST is not sortedVisiting in the wrong position, or it is not a valid BST
Height off by oneDecide whether a leaf has height 0 or 1, and stay consistent
BFS very slow on a wide treeshift() is O(n) — use a head index
Result accumulates across callsOutput array declared outside and not reset
