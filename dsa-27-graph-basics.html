Graphs: representation, BFS and DFS

Nodes and edges. Half of graph problems are solved by picking the right traversal and remembering to mark visited nodes at the right moment.

Representation

The representation is the first decision and it constrains everything after it. In interviews one choice is right almost every time, and knowing when it is not is worth a sentence.

   ADJACENCY LIST — the default, and almost always correct.

     const g = new Map();          // node -> array of neighbours
     // or, for nodes 0..n-1:
     const g = Array.from({length: n}, () => []);

     space O(V + E), iterate a node's neighbours in O(deg)

   ADJACENCY MATRIX — only for dense graphs or O(1) edge
   tests.

     const g = Array.from({length: n}, () => new Array(n).fill(0));
     space O(V^2), "is there an edge u-v?" in O(1)

   EDGE LIST — just [u, v, w] triples. Used by Kruskal and
   Bellman-Ford (chapter 34).

   BUILDING FROM AN EDGE LIST — the first three lines of
   most graph solutions:

     const g = Array.from({length: n}, () => []);
     for (const [u, v] of edges) {
         g[u].push(v);
         g[v].push(u);       // OMIT for a DIRECTED graph
     }

   THE VOCABULARY YOU WILL BE ASKED FOR:
     DIRECTED / UNDIRECTED    do edges have a direction?
     WEIGHTED / UNWEIGHTED    do edges carry a cost?
     CYCLIC / ACYCLIC         a DAG is a directed acyclic
                              graph
     CONNECTED                every node reachable from every
                              other
     DEGREE                   number of incident edges;
                              in-degree / out-degree when
                              directed
     A TREE is a connected acyclic undirected graph with
     exactly V-1 edges.

BFS and DFS

BFS and DFS visit the same nodes at the same cost, and differ only in order — which is precisely what decides which problems each one solves.

   BOTH VISIT EVERY REACHABLE NODE ONCE, in O(V + E).
   THE DIFFERENCE IS THE ORDER, and it decides which
   problems each solves.

   BFS — a QUEUE, explores by DISTANCE
     · SHORTEST PATH in an UNWEIGHTED graph
     · level-by-level processing
     · "minimum number of steps"

   DFS — a STACK (or recursion), explores by DEPTH
     · connectivity, components, cycle detection
     · topological order
     · path enumeration, backtracking
     · anything needing "finish the subtree first"

   ---------------------------------------------------------
   BFS TEMPLATE

     const q = [start];
     const seen = new Set([start]);      // MARK ON ENQUEUE
     let head = 0;                       // avoid shift()
     let dist = 0;

     while (head < q.length) {
         const size = q.length - head;   // one LEVEL
         for (let i = 0; i < size; i++) {
             const u = q[head++];
             for (const v of g[u]) {
                 if (seen.has(v)) continue;
                 seen.add(v);            // <-- HERE, not on
                 q.push(v);              //     dequeue
             }
         }
         dist++;
     }

     MARKING ON DEQUEUE INSTEAD OF ENQUEUE lets the same node
     be queued many times before it is first processed. It
     still terminates, but the queue can blow up
     exponentially on dense graphs. THIS IS THE MOST COMMON
     BFS BUG.

   ---------------------------------------------------------
   DFS TEMPLATE — recursive

     const seen = new Set();
     function dfs(u) {
         seen.add(u);
         for (const v of g[u]) if (!seen.has(v)) dfs(v);
     }

   DFS TEMPLATE — iterative, when recursion may overflow

     const st = [start];
     const seen = new Set();
     while (st.length) {
         const u = st.pop();
         if (seen.has(u)) continue;   // may be queued twice
         seen.add(u);
         for (const v of g[u]) if (!seen.has(v)) st.push(v);
     }

     Note the iterative version checks on POP, because a node
     can be pushed by several neighbours before being
     processed. That is fine here — unlike BFS, it does not
     break the distance guarantee, because DFS has none.

   ---------------------------------------------------------
   WHY BFS GIVES SHORTEST PATHS

     The queue processes nodes in non-decreasing distance
     order. So the first time a node is reached, it is
     reached by a shortest path — and marking it seen
     immediately locks that in. WITH WEIGHTS THIS FAILS, and
     you need Dijkstra (chapter 34).

Problems

How it shows up

SymptomCause
Infinite loopNo visited set, or a cycle in an undirected graph
Queue grows enormouslyMarked visited on dequeue instead of enqueue
Shortest path too longUsed DFS, or the graph is weighted — use BFS or Dijkstra
Only part of the graph visitedDisconnected — loop over all nodes as start points
Stack overflowDeep recursion — convert DFS to iterative
Undirected graph behaves as directedForgot to add the reverse edge when building
Levels merged togetherLevel size not snapshot before the inner loop
Self-loops or duplicate edges break itThe visited check handles them — do not assume simplicity
