Arrays: matrix traversal patterns

Two-dimensional index arithmetic. The algorithms are simple; the bugs are all boundaries, and the trick in most of these problems is finding a transformation that makes the boundaries disappear.

The patterns

Grid problems are mostly bookkeeping, so the way to stop making mistakes is to fix the conventions once and never vary them. These are the ones used throughout the track.

   THE CONVENTIONS. Fix them once and never think again:

     R = grid.length            rows
     C = grid[0].length         columns
     grid[r][c]                 ROW FIRST, always

     in bounds:  r >= 0 && r < R && c >= 0 && c < C

   FLATTENING — a 2-D cell to a 1-D index and back:
     idx = r * C + c
     r   = Math.floor(idx / C)
     c   = idx % C
   Useful for hashing a cell, or for binary search over a
   row-sorted matrix as if it were one array.

   THE FOUR NEIGHBOUR DIRECTIONS:
     const DIRS = [[-1,0],[1,0],[0,-1],[0,1]];
     for (const [dr, dc] of DIRS) {
         const nr = r + dr, nc = c + dc;
         if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
         ...
     }
   Eight directions add the four diagonals. A DIRECTION
   ARRAY IS ALWAYS BETTER THAN FOUR COPIES OF THE BODY —
   fewer places to make a typo.

   ---------------------------------------------------------

   ROTATION BY 90 DEGREES, in place:
     TRANSPOSE (swap across the main diagonal), then
     REVERSE EACH ROW.

       1 2 3      1 4 7      7 4 1
       4 5 6  ->  2 5 8  ->  8 5 2
       7 8 9      3 6 9      9 6 3
       original   transpose  reverse rows

     Anticlockwise: transpose, then reverse each COLUMN
     (equivalently, reverse the row order first).

     THE TRANSPOSE LOOP MUST START AT j = i, not j = 0 —
     otherwise every pair is swapped twice and you get the
     original back.

   ---------------------------------------------------------

   SPIRAL — four moving boundaries:
       top, bottom, left, right
       walk right along `top`, then down `right`,
       then left along `bottom`, then up `left`,
       shrinking each boundary after use.
       CHECK top <= bottom AND left <= right BEFORE the
       last two walks, or a single remaining row/column is
       emitted twice.

   ---------------------------------------------------------

   SEARCH IN A SORTED MATRIX — start from a CORNER where
   the two directions disagree:
       start at TOP-RIGHT:
         value too big   -> move LEFT   (column decreases)
         value too small -> move DOWN   (row increases)
       Each step eliminates a whole row or column: O(R + C).

When to reach for it

"Rotate / transpose in place"

Compose two simple reversals rather than working out the rotation index formula.

Boundary walks

Spiral, diagonal, zigzag. Track explicit boundaries and shrink them.

Sorted rows and columns

Start at a corner with conflicting directions — top-right or bottom-left.

Fully row-sorted, rows chained

Treat as a flat array and binary search with idx / C, idx % C.

Flood fill / islands / shortest path

That is a graph on a grid — see chapter 32.

"O(1) extra space" on a grid

Encode markers in the matrix itself — first row/column as flags, or a sentinel value.

/* --- BUILDING A GRID, and the trap --- */
const g = Array.from({length: R}, () => new Array(C).fill(0));
// NOT new Array(R).fill(new Array(C).fill(0))
//     ^ every row is the SAME array; writing one writes all

/* --- COPYING --- */
const copy = g.map(row => row.slice());   // deep enough for
                                          // a grid of numbers

/* --- ITERATING --- */
for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++) { ... }

/* --- THE GUARD, as a helper --- */
const ok = (r, c) => r >= 0 && r < R && c >= 0 && c < C;

/* --- EMPTY-INPUT CHECK, first line of every solution --- */
if (!grid || grid.length === 0 || grid[0].length === 0) return ...;
