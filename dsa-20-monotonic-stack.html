Stacks: the monotonic stack

A stack kept sorted by construction. It answers "what is the next larger element?" for every position in one linear pass, and it is the key to several problems that look inescapably quadratic.

The pattern

A monotonic stack answers "what is the next bigger thing" for every element in one linear pass, which sounds impossible the first time. The invariant is what makes it work, so start there.

   A MONOTONIC STACK holds elements in sorted order —
   increasing or decreasing from the bottom. You maintain
   that by POPPING anything that would break it before
   pushing.

   THE RECOGNITION SIGNAL:
     "NEXT GREATER" / "NEXT SMALLER" / "PREVIOUS GREATER" /
     "PREVIOUS SMALLER" element — for EVERY position.
     Also: largest rectangle, span problems, trapping water,
     and "how far until something bigger?"

   ---------------------------------------------------------
   THE TEMPLATE — next greater to the RIGHT

     const out = new Array(n).fill(-1);
     const st = [];                      // holds INDICES
     for (let i = 0; i < n; i++) {
         while (st.length && a[st[st.length-1]] < a[i]) {
             out[st.pop()] = a[i];       // a[i] IS the answer
         }                               // for the popped index
         st.push(i);
     }
     // anything still on the stack has no greater element

     THE STACK HOLDS INDICES, NOT VALUES. You almost always
     need the position — to write the answer, or to compute
     a width.

     [2, 1, 2, 4, 3]
      i=0  push 0                 st=[0]        (values 2)
      i=1  1 < 2, push 1          st=[0,1]      (2,1)
      i=2  2 > 1 -> out[1]=2      st=[0]
           2 = 2 not >, push 2    st=[0,2]      (2,2)
      i=3  4 > 2 -> out[2]=4
           4 > 2 -> out[0]=4      st=[]
           push 3                 st=[3]        (4)
      i=4  3 < 4, push 4          st=[3,4]
      leftover 3,4 -> out = [4,2,4,-1,-1]

   ---------------------------------------------------------
   THE FOUR VARIANTS — only the comparison changes

     next GREATER right   iterate LEFT->RIGHT, pop while
                          stack top <  current   (decreasing
                                                  stack)
     next SMALLER right   pop while stack top >  current
     prev GREATER left    iterate LEFT->RIGHT, the stack top
                          AFTER popping is the answer
     prev SMALLER left    same, flipped comparison

     Equivalently, iterate right-to-left for the "next"
     versions and read the top instead. Pick one convention
     and keep it.

   ---------------------------------------------------------
   WHY IT IS O(n) DESPITE THE NESTED WHILE

     EACH INDEX IS PUSHED EXACTLY ONCE AND POPPED AT MOST
     ONCE. So the total number of pops across the whole run
     is at most n, no matter how many happen in a single
     iteration. Amortised O(1) per element (chapter 02).

     THAT SENTENCE IS THE ANSWER TO "what is the
     complexity?" — say it exactly.

   ---------------------------------------------------------
   THE >= VERSUS > DECISION

     Popping on EQUAL values or not changes which duplicate
     gets credited. For "next STRICTLY greater", pop while
     top < current (leave equals on the stack). For
     rectangle problems either works, because equal-height
     bars produce the same area — but be able to say why.

When to reach for it

Next / previous greater or smaller

Daily temperatures, next greater element, stock span.

Largest rectangle in a histogram

Each bar extends until a shorter one on each side.

Maximal rectangle in a binary matrix

Row by row, each becomes a histogram problem.

Trapping rain water

An alternative to the two-pointer solution (ch. 04).

Remove k digits / smallest subsequence

Greedily pop larger digits to make the result smaller.

Sum of subarray minimums

Count how many subarrays each element is the minimum of.

Problems

How it shows up

SymptomCause
Cannot compute widthsStack holds values instead of indices
Leftover elements have no answerCorrect — they have no next greater; initialise to −1 or 0
Duplicates credited to the wrong index< vs <= in the pop condition
Histogram misses the last barsNo sentinel — append a height of 0, or drain after the loop
Width off by oneWidth is i − st.top() − 1 after popping, not i − popped
Claimed O(n²) complexityIt is amortised O(n) — each index pushed and popped once
