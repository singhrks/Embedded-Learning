Writing and loading a module on the Pi

The Linux track covers modules in general. This chapter is the Pi-specific loop: how to build against the running kernel without building the kernel, how to iterate in seconds, and how to recover when your module wedges the board.

Headers, not a kernel build

# You do NOT need to build a kernel to build a module. You
# need the headers and build metadata for the RUNNING one.

$ sudo apt install raspberrypi-kernel-headers
$ ls -l /lib/modules/$(uname -r)/build
lrwxrwxrwx ... build -> /usr/src/linux-headers-6.6.51+rpt-rpi-2712

# If that symlink is missing or dangling, nothing below
# works, and the error is a confusing one about a missing
# Makefile. Check it first.

# PIN THE KERNEL (chapter 04), or an apt upgrade will
# replace it and your module will stop loading against the
# new one while the headers still describe the old:
$ sudo apt-mark hold raspberrypi-kernel raspberrypi-kernel-headers

# CROSS-COMPILING A MODULE needs the kernel SOURCE tree,
# prepared to match the target. This is the one case where
# chapter 15's tree is required even though you are not
# installing a kernel:
$ cd linux
$ make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- \
       bcm2712_defconfig
$ make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- \
       modules_prepare
$ make -C /path/to/linux M=$PWD ARCH=arm64 \
       CROSS_COMPILE=aarch64-linux-gnu- modules

# The source must be the SAME VERSION as the running
# kernel, or the module is rejected at load time with a
# vermagic mismatch. Native building sidesteps this
# entirely, which is why it is the recommended route here.

The smallest useful module

/* pidev.c - a character device that reports board info.
   Enough structure to be a real driver, small enough to
   read in one sitting.                                    */

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/uaccess.h>
#include <linux/of.h>

#define DEVNAME "pidev"

static dev_t         devno;
static struct cdev   pidev_cdev;
static struct class *pidev_class;

static int count;
module_param(count, int, 0644);
MODULE_PARM_DESC(count, "an example parameter");
/* Appears at /sys/module/pidev/parameters/count and can be
   written at runtime because of the 0644. Excellent for
   development knobs.                                       */

static ssize_t pidev_read(struct file *f, char __user *buf,
                          size_t len, loff_t *off)
{
    char tmp[128];
    const char *model = "unknown";
    struct device_node *root;
    int n;

    /* Read the board model straight out of the device tree
       the firmware handed us (chapter 03).                 */
    root = of_find_node_by_path("/");
    if (root) {
        of_property_read_string(root, "model", &model);
        of_node_put(root);        /* refcounted - releasing
                                     it matters             */
    }

    n = scnprintf(tmp, sizeof(tmp), "%s\ncount=%d\n", model, count);

    /* simple_read_from_buffer handles the offset and the
       copy_to_user, including the partial-read case that
       hand-rolled versions get wrong.                      */
    return simple_read_from_buffer(buf, len, off, tmp, n);
}

static const struct file_operations pidev_fops = {
    .owner = THIS_MODULE,
    .read  = pidev_read,
};

static int __init pidev_init(void)
{
    int rc;

    rc = alloc_chrdev_region(&devno, 0, 1, DEVNAME);
    if (rc) return rc;

    cdev_init(&pidev_cdev, &pidev_fops);
    rc = cdev_add(&pidev_cdev, devno, 1);
    if (rc) goto err_cdev;

    /* Creating a class and device makes udev produce
       /dev/pidev automatically. Without it you would have
       to mknod by hand.                                    */
    pidev_class = class_create(DEVNAME);
    if (IS_ERR(pidev_class)) { rc = PTR_ERR(pidev_class); goto err_class; }
    device_create(pidev_class, NULL, devno, NULL, DEVNAME);

    pr_info("pidev: loaded, major=%d\n", MAJOR(devno));
    return 0;

/* Unwind in EXACTLY reverse order. Getting this wrong is
   the most common module bug, and it only shows up when
   something fails - i.e. rarely, and at the worst time.
   The Linux track's error-handling chapter covers the
   pattern.                                                 */
err_class:
    cdev_del(&pidev_cdev);
err_cdev:
    unregister_chrdev_region(devno, 1);
    return rc;
}

static void __exit pidev_exit(void)
{
    device_destroy(pidev_class, devno);
    class_destroy(pidev_class);
    cdev_del(&pidev_cdev);
    unregister_chrdev_region(devno, 1);
    pr_info("pidev: unloaded\n");
}

module_init(pidev_init);
module_exit(pidev_exit);
MODULE_LICENSE("GPL");           /* NOT optional - a non-GPL
                                    module cannot use most
                                    exported symbols and
                                    taints the kernel      */
MODULE_AUTHOR("you");
MODULE_DESCRIPTION("Pi board info character device");

# Makefile - kbuild, not ordinary make. The "obj-m" line is
# the whole interface.

obj-m += pidev.o

KDIR ?= /lib/modules/$(shell uname -r)/build
PWD  := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

# Note the TAB before $(MAKE). Make requires tabs; a space
# gives "missing separator".

$ make
$ sudo insmod pidev.ko count=7
$ cat /dev/pidev
Raspberry Pi 5 Model B Rev 1.0
count=7
$ dmesg | tail -2
$ echo 42 | sudo tee /sys/module/pidev/parameters/count
$ sudo rmmod pidev

The iteration loop

# Combine chapter 07's sync-and-build with insmod/rmmod and
# you get a kernel development cycle of a few seconds.

# --- reload.sh, on the Pi ---
#!/usr/bin/env bash
set -euo pipefail
sudo rmmod pidev 2>/dev/null || true    # ignore "not loaded"
make
sudo insmod pidev.ko "$@"
sudo dmesg -w &                         # follow the log
sleep 0.3; cat /dev/pidev

# --- from the host, on every save ---
$ find . -name '*.c' -o -name Makefile | \
      entr -c ./push.sh

# TAIL THE LOG IN A SECOND WINDOW, always:
$ ssh pi 'sudo dmesg -w'

# pr_info and friends go to the kernel ring buffer, NOT to
# your terminal. Levels, and where they surface:
pr_emerg / pr_alert / pr_crit / pr_err / pr_warn
pr_notice / pr_info / pr_debug
#   pr_debug is compiled out unless DEBUG is defined or
#   CONFIG_DYNAMIC_DEBUG lets you enable it at runtime:
$ echo 'module pidev +p' | sudo tee /sys/kernel/debug/dynamic_debug/control
#   That turns on every pr_debug in the module with no
#   rebuild - the single most useful trick in this chapter
#   (chapter 17 covers it fully).

# Make the log readable while iterating:
$ sudo dmesg -n 8            # everything to the console
$ sudo dmesg -C              # clear before a test run
$ sudo dmesg -T              # human timestamps
Your module runs with no safety net

A null dereference in userspace is a segfault; in the kernel it is an oops that may take the machine with it. A module that leaks memory leaks it until reboot. A module that deadlocks holding a lock the filesystem needs will hang every process that touches the disk — including your SSH session, so the board looks dead while the kernel is still running. This is exactly why chapter 05's serial console and its SysRq keys matter, and why chapter 07 recommends a second board. Expect to power-cycle. Do not develop modules on a board holding anything you care about.

# READ IT LIKE THIS:
#   ESR                the ARM fault syndrome register.
#                      Decode it with the ARM track's
#                      chapter 29 - it names the exact
#                      fault type.
#   pc                 where it died: function + offset
#   Tainted: G ... O   'O' = an out-of-tree module is
#                      loaded. Yours.
#   Call trace         who called whom

# TURN THE OFFSET INTO A LINE:
$ aarch64-linux-gnu-addr2line -e pidev.ko -f -i 0x38
pidev_read
/home/me/pidev/pidev.c:41

# Or, if the module was built with debug info:
$ ./scripts/decode_stacktrace.sh pidev.ko . < oops.txt

# KEEP THE .ko WITH SYMBOLS. Once you rebuild, the offsets
# no longer correspond and the oops you saved is
# undecodable. Copy the .ko aside before iterating.

How it shows up

SymptomCause
"missing separator" from makeSpaces instead of a tab in the Makefile
No rule to make target modules/lib/modules/$(uname -r)/build missing — install headers
insmod: "invalid module format"Built against different kernel headers than the running kernel
insmod: "unknown symbol"Missing MODULE_LICENSE("GPL"), or a genuinely absent export
rmmod: "device or resource busy"Something still has the device open, or your refcounting is wrong
Module stops loading after an updateKernel replaced — hold the packages
printk output nowhere to be seenIt is in dmesg, not your terminal
pr_debug silentCompiled out — enable via dynamic debug
Board hangs, SSH dead, kernel aliveDeadlock in your module — use serial console and SysRq

Check yourself

  • Say what you need to build a module, and what you do not.
  • Explain why the kernel packages should be held during module work.
  • Explain what breaks when module and kernel versions differ.
  • Say what MODULE_LICENSE("GPL") affects beyond legality.
  • Explain why init error paths unwind in reverse order and when that code runs.
  • Say what class_create plus device_create buys you.
  • Give the runtime trick that enables every pr_debug without rebuilding.
  • Explain why a module deadlock can make a live board look dead.
  • Decode the fields of an oops: pc, Tainted, call trace.
  • Explain why you must keep the .ko to decode an oops later.
