Hashing: maps, sets and frequency

Trade memory for time. A hash map turns "have I seen this?" from an O(n) scan into an O(1) lookup, and that single substitution converts more O(n²) solutions into O(n) ones than any other technique.

The pattern

Hashing is less a data structure than a reflex: whenever a loop is searching for something, ask whether it could have been remembered instead. That trade — time for space — is the whole chapter.

   THE CORE MOVE: whenever an inner loop is SEARCHING for
   something, ask whether a hash map could have remembered
   it instead.

     for i in 0..n:
       for j in 0..n:            <-- this loop is a LOOKUP
         if a[j] == something(i)

     becomes

     seen = {}
     for i in 0..n:
       if something(i) in seen:  <-- O(1)
       seen[a[i]] = i

     O(n^2)  ->  O(n) time, O(n) space.

   THE FOUR USES, and nearly every hashing problem is one
   of them:

   1. MEMBERSHIP — "have I seen x?"            Set
        duplicates, intersections, cycle detection

   2. COUNTING — "how many times did x occur?"  Map -> int
        anagrams, majority element, frequency ranking

   3. INDEXING — "where did x occur?"           Map -> index
        two sum, longest subarray with a property

   4. GROUPING — "which items share a key?"     Map -> list
        group anagrams, bucket by some signature

   THE KEY DESIGN DECISION IS THE KEY ITSELF. Most hashing
   problems reduce to: WHAT IS THE RIGHT SIGNATURE?

     group anagrams        -> sorted letters, or a
                              26-length count vector
     find duplicates       -> the value itself
     subarray sums         -> the running prefix sum
     isomorphic strings    -> a pair of forward/backward maps
     board validation      -> "row3-val7", "col2-val7"

   CHOOSING A GOOD KEY IS THE WHOLE PROBLEM. The map itself
   is never the hard part.

   THE COSTS:
     lookup/insert/delete   O(1) AVERAGE, O(n) worst case
     space                  O(n)
     ordering               NONE — if you need sorted keys,
                            you want a balanced BST or a
                            sort, not a hash map

Choosing the structure

Set

Membership only. has, add, delete. Use when you never need counts or positions.

Map → count

Frequency. The single most common shape. Remember to delete keys that reach zero if you rely on size.

Map → index

When the answer is a position, not a value. Two Sum returns indices, so it cannot sort.

Map → array

Grouping. Push into the bucket for a computed key.

Fixed array instead of a map

If keys are small integers or lowercase letters, new Array(26).fill(0) is faster and simpler than a Map.

Not a hash map

Need order, ranks, or "next larger key"? Use sorting, a heap, or a BST — hashing has no order.

/* --- FREQUENCY, the idiom to have automatic --- */
const freq = new Map();
for (const x of arr) freq.set(x, (freq.get(x) ?? 0) + 1);

// letters only? an array is better:
const cnt = new Array(26).fill(0);
for (const ch of s) cnt[ch.charCodeAt(0) - 97]++;

/* --- GROUPING --- */
const groups = new Map();
for (const w of words) {
    const key = signature(w);
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(w);
}
return [...groups.values()];

/* --- SEEN-BEFORE WITH INDEX --- */
const seen = new Map();          // value -> index
for (let i = 0; i < a.length; i++) {
    if (seen.has(target - a[i])) return [seen.get(target - a[i]), i];
    seen.set(a[i], i);           // AFTER the check, so an element
}                                // cannot pair with itself

/* --- THE TRAPS ---
   · A JS OBJECT COERCES KEYS TO STRINGS: obj[1] and
     obj["1"] are the SAME entry. Map does not. Use Map.
   · ARRAYS AND OBJECTS AS KEYS compare by REFERENCE, so
     map.set([1,2],x) then map.get([1,2]) returns undefined.
     Serialise to a string first: a.join(',').
   · CHECK-THEN-INSERT ORDER matters (see above).
   · `map.get(k) || 0` breaks when the stored value is 0 or
     "". Use `?? 0`.
   · ITERATION ORDER of a Map is insertion order in JS, but
     do not rely on any order in C++ unordered_map.      */
