Glossary

The terms and acronyms used across this site, with the chapter that explains each one properly. Definitions here are short on purpose — they are for recognition, not for learning from.

A – C

TermMeaning
AArch64The 64-bit ARM execution state. The instruction set is A64.
ABIApplication Binary Interface — register usage, stack layout, struct layout and calling convention. What lets separately compiled code link.
AEADAuthenticated Encryption with Associated Data. Confidentiality and integrity in one primitive. cr-09
APICx86 interrupt controller. ARM's equivalent is the GIC.
ASanAddressSanitizer — compile-time instrumentation catching memory errors. ref-04
AtomicAn operation that completes indivisibly with respect to other observers.
AttentionWeighted averaging of values, with weights from query–key similarity. ai-19
BarrierAn instruction constraining the ordering of memory operations. DMB, DSB, ISB on ARM.
BSPBoard Support Package — the vendor's port of an OS or RTOS to a board.
BugcheckA Windows kernel panic. The blue screen. ref-05
Cache coherencyKeeping multiple caches consistent. A DMA device outside the coherency domain requires explicit maintenance.
CFIControl Flow Integrity — restricting indirect branches to valid targets.
ChinchillaThe scaling result: about 20 training tokens per parameter is compute-optimal. ai-23
Constant timeExecution whose timing does not depend on secret data. cr-19
Context switchSaving one execution context and restoring another.
CoreSightARM's debug and trace architecture: DWT, ITM, ETM, TPIU. ref-03
Cross-entropyThe loss function of essentially every model here; equals negative log likelihood. ai-10

D – H

TermMeaning
DMADirect Memory Access — a device reading or writing memory without the CPU. The reason SMMUs exist.
DPCDeferred Procedure Call — Windows' deferred interrupt work, at DISPATCH_LEVEL. Linux's equivalent is a softirq or tasklet.
DPADifferential Power Analysis — key recovery from many power traces. Constant-time code does not stop it. cr-19
DTB / Device treeA data structure describing non-discoverable hardware to the kernel.
ECDH / ECDSAElliptic-curve key exchange and signatures. cr-14, cr-15
EL0–EL3ARM Exception Levels: application, OS, hypervisor, firmware.
EmbeddingA learned dense vector representing a token. ai-17
ErrataDocumented silicon bugs. Read the sheet. ref-06
ETWEvent Tracing for Windows — always-compiled-in, runtime-enabled tracing. ref-05
Flash AttentionTiled attention that never materialises the n×n matrix. Exact, not approximate. ai-19
Forward secrecyPast sessions stay secret after a long-term key is stolen. Requires ephemeral keys. cr-13
ftraceThe Linux kernel's built-in function tracer. ref-04
GICGeneric Interrupt Controller — ARM's interrupt distribution and prioritisation.
GQAGrouped-Query Attention — query heads share key/value heads, shrinking the KV cache. ai-19
Hard faultCortex-M's catch-all exception for memory, bus and usage faults.
HKDFThe standard key derivation function: extract then expand, with a context string. cr-10
HMACThe standard hash-based MAC. Its nesting defeats length extension. cr-08
HSMHardware Security Module — where signing keys belong. cr-18
HypervisorSoftware running at EL2 that virtualises the machine for guest operating systems.

I – M

TermMeaning
IOMMU / SMMUAddress translation and access control for device DMA. The MMU for peripherals.
IRPI/O Request Packet — the unit of I/O in the Windows kernel. !irp decodes one.
IRQLWindows' interrupt request level. At DISPATCH_LEVEL and above you may not touch paged memory or block. ref-05
ISRInterrupt Service Routine. Keep it short; defer the rest.
ITM / SWOCortex-M instrumentation trace and its output pin. Single-cycle logging. ref-02
KASANAddressSanitizer for the Linux kernel.
KMDF / UMDFWindows Driver Framework, kernel and user mode. Preferred over raw WDM.
KV cacheCached keys and values, making generation linear instead of quadratic. Often larger than the model. ai-25
LayerNorm / RMSNormPer-sample feature normalisation; RMSNorm drops the mean subtraction. ai-22
LockdepLinux's lock-order validator — reports potential deadlocks before they happen.
LoRALow-Rank Adaptation — fine-tuning via a small low-rank weight update. ai-24
MACEither Message Authentication Code (cr-08) or Multiply-Accumulate (ai-04). Context disambiguates.
Memory-boundLimited by bandwidth rather than arithmetic. Token generation is memory-bound. ai-04
MFUModel FLOPs Utilisation — achieved over peak. 40–55% is good. ai-23
MMIOMemory-Mapped I/O — device registers in the address space. Always volatile.
MMUMemory Management Unit — virtual to physical translation and permissions.
MoEMixture of Experts — many FFNs, a router picks a few per token. Saves compute, not memory. ai-22
MPUMemory Protection Unit — region-based permissions without translation. Cortex-M.

N – R

TermMeaning
NEON / SVE / HeliumARM SIMD: Cortex-A, scalable vector, and Cortex-M (MVE) respectively.
NonceA number used once. Reuse breaks GCM catastrophically. cr-09
NPUNeural Processing Unit — a fixed-function accelerator, usually int8 matmul. ai-27
NVICCortex-M's nested vectored interrupt controller.
OTP / eFuseOne-time programmable bits. Where root key hashes and anti-rollback counters live. cr-18
Paged attentionBlock-allocated KV cache with a per-request block table. Virtual memory, for attention. ai-25
Perplexityexp of the cross-entropy — the effective number of options the model is choosing between. Not comparable across tokenisers. ai-10
PKIPublic Key Infrastructure — certificates chaining to a trusted root. cr-16
Pre-normNormalisation inside the residual branch. What makes deep transformers trainable. ai-22
Priority inversionA high-priority task blocked by a low-priority lock holder that a medium-priority task preempts. ref-06
PSA CryptoARM's crypto API abstracting hardware and software implementations. cr-21
PUFPhysically Unclonable Function — a key derived from manufacturing variation, never stored.
QuantisationRepresenting weights in fewer bits, with a scale factor. ai-26
RAIIResource Acquisition Is Initialisation — C++ ownership tied to object lifetime.
Residual streamThe un-transformed path through a transformer; a shared bus every layer reads and adds to. ai-22
RLHF / DPOPreference-based post-training, with and without a reward model. ai-24
RoPERotary position embedding — rotate Q and K by angle ∝ position, giving relative position for free. ai-21
RTTSEGGER Real-Time Transfer — logging via a RAM buffer read by the probe while running. ref-02

S – Z

TermMeaning
Scaling lawsLoss falls as a power law in parameters, data and compute. Lets you predict a large run from small ones. ai-23
Secure bootEach stage verifies the next before transferring control, rooted in immutable ROM. cr-15
Secure elementA separate certified chip holding keys that never leave it. cr-18
SFTSupervised Fine-Tuning — instruction pairs, with the prompt masked out of the loss. ai-24
SMCSecure Monitor Call — the instruction that enters EL3 / the secure world.
SoftmaxTurns scores into a distribution. Always subtract the maximum first. ai-06
Speculative decodingA small model drafts, the big model verifies in one pass. Identical output distribution. ai-25
Straight-through estimatorPassing the gradient through a non-differentiable step such as rounding. ai-26
SWDSerial Wire Debug — ARM's two-pin debug port. ref-03
SwiGLUThe gated FFN used by most recent models; d_ff becomes 8/3·d. ai-22
TEETrusted Execution Environment — an isolated world, typically TrustZone plus a trusted OS.
TokeniserText to integers, usually by BPE. Matched permanently to its model. ai-16
TPMTrusted Platform Module — PCRs, sealing, attestation, monotonic counters.
TransformerAttention plus FFN, each wrapped in a norm and a residual, stacked. ai-20
TrustZoneARM's secure/non-secure partitioning, propagated across the interconnect by the NS bit.
TSanThreadSanitizer — data race detection. ~10× slowdown, worth it.
UBUndefined Behaviour — the optimiser may assume it never happens, and does. ref-06
volatilePrevents the compiler caching a value in a register. Provides no atomicity and no ordering between objects.
WCETWorst-Case Execution Time — the number that matters in a real-time system, not the average.
WDMWindows Driver Model — the raw IRP-based interface beneath KMDF.
WPPWindows software tracing: formatted off-device, negligible cost, runtime-enabled. ref-02
WatchpointA breakpoint on data access. The fastest way to find what corrupts a variable. ref-03
X25519Curve25519 key exchange. 32-byte keys, constant time, no validation to get wrong. cr-13
XPUAccess-control hardware gating which masters may reach which address ranges.
XTSThe disk-encryption mode. Confidentiality only — no integrity. cr-18
ZeRO / FSDPSharding optimiser state, gradients and parameters across devices. ai-23
Terms that mean different things in different tracks 
MAC       Message Authentication Code / Multiply-Accumulate
          / Media Access Control
KEY       a cryptographic key / an attention key vector
BLOCK     a cipher block / a storage block / a transformer
          block / a scheduling state
CACHE     CPU cache / KV cache / page cache
TENSOR    an n-dimensional array (the physics meaning is
          not implied)
TRACE     execution trace / matrix trace
DECODE    instruction decode / token generation
PAGE      a memory page / a flash page
ATTENTION the mechanism / what you should pay to the
          errata sheet

Check yourself

  • Define IRQL and state the rule that causes most Windows driver bugchecks.
  • Explain what a nonce is and what its reuse costs in GCM.
  • Say what the KV cache is and why it can exceed the model.
  • Explain what volatile does and the two things it does not.
  • Distinguish MMU, MPU and SMMU.
  • Say what forward secrecy requires.
  • Explain why perplexity is not comparable across tokenisers.
  • Give three meanings of "MAC" and say how context disambiguates.
  • Say what XTS provides and what it conspicuously does not.
  • Explain what a watchpoint does and why it is underused.
