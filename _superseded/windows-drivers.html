Windows driver development

WDM taught a generation of engineers to write PnP and power code by hand, and most of them got it wrong. WDF exists so you never have to. This chapter covers the WDF object model, request queues, I/O, INF packaging, signing, and how to debug what you build.

Choosing a driver model

ModelRuns inUse whenReality
UMDF (User-Mode Driver Framework)User modeUSB, HID, sensors, anything not needing high IRQL or direct DMAPrefer this. A crash kills a service, not the machine.
KMDF (Kernel-Mode Driver Framework)Kernel modeHardware needing interrupts, DMA, or high IRQL accessThe default for real hardware. What this chapter covers.
WDMKernel modeFilter drivers in stacks that require it, or maintaining legacy codeOnly when WDF genuinely cannot express what you need.
What WDF actually does for you

It implements the PnP and power state machines — roughly 3,000 lines of extremely subtle code that every WDM driver had to get right and most did not. It manages IRP queuing, cancellation, and synchronisation scopes. You write callbacks for the events you care about and WDF handles the rest, including all the transitions you did not think about.

The WDF object model

Everything is a handle to a framework object. Objects have a parent, so freeing a parent frees its children — the same idea as Linux's devm_.

WDFDRIVER                     one per driver, created in DriverEntry
   │
   └── WDFDEVICE              one per device instance
         ├── WDFQUEUE         holds pending requests; you can have several
         │     └── WDFREQUEST one I/O request (wraps an IRP)
         │           └── WDFMEMORY  the buffers
         ├── WDFINTERRUPT     ISR + DPC pair
         ├── WDFDMAENABLER    DMA capability
         │     └── WDFCOMMONBUFFER / WDFDMATRANSACTION
         ├── WDFTIMER, WDFWORKITEM, WDFSPINLOCK, WDFWAITLOCK
         ├── WDFFILEOBJECT    per open handle
         └── WDFCHILDLIST     for bus drivers enumerating children

Every object can carry a "context" — your own struct, allocated with the object
and retrieved with a generated accessor. This is where your state lives.
// Declare your per-device state and generate a typed accessor
typedef struct _DEVICE_CONTEXT {
        ULONG   Value;
        WDFQUEUE ManualQueue;
        PVOID   Registers;
} DEVICE_CONTEXT, *PDEVICE_CONTEXT;

WDF_DECLARE_CONTEXT_TYPE_WITH_NAME(DEVICE_CONTEXT, DeviceGetContext)

// ...then anywhere you have the WDFDEVICE handle:
PDEVICE_CONTEXT ctx = DeviceGetContext(device);

Driver lifecycle and callbacks

Request queues

WDF does not hand you IRPs as they arrive. It puts them in a queue whose configuration you choose, and calls your handler according to that configuration. This is where WDF's concurrency model lives.

Dispatch typeBehaviourUse when
WdfIoQueueDispatchSequentialOne request delivered at a time; the next arrives only after the current one completesHardware that can do one operation at a time. Simplest and safest — start here.
WdfIoQueueDispatchParallelRequests delivered as they arrive, possibly concurrently on several CPUsHardware with deep queues; you handle your own synchronisation
WdfIoQueueDispatchManualNothing is delivered; you pull requests with WdfIoQueueRetrieveNextRequest()Pending requests that complete later — the classic "wait for data" pattern
 
WDF_IO_QUEUE_CONFIG queueConfig;
WDF_IO_QUEUE_CONFIG_INIT_DEFAULT_QUEUE(&queueConfig,
                                       WdfIoQueueDispatchSequential);
queueConfig.EvtIoRead          = MyEvtIoRead;
queueConfig.EvtIoWrite         = MyEvtIoWrite;
queueConfig.EvtIoDeviceControl = MyEvtIoDeviceControl;
queueConfig.EvtIoStop          = MyEvtIoStop;   // called on power-down

status = WdfIoQueueCreate(device, &queueConfig,
                          WDF_NO_OBJECT_ATTRIBUTES, &queue);

The manual queue pattern

The Windows answer to a blocking read: park the request, complete it when data arrives.

// In EvtIoRead — no data yet, so park the request instead of completing it
status = WdfRequestForwardToIoQueue(Request, ctx->ManualQueue);
if (!NT_SUCCESS(status))
        WdfRequestComplete(Request, status);
return;   // note: NOT completed. The caller is still waiting.

// Later, from a DPC when the hardware has data
WDFREQUEST pending;
status = WdfIoQueueRetrieveNextRequest(ctx->ManualQueue, &pending);
if (NT_SUCCESS(status)) {
        PVOID buf; size_t len;
        WdfRequestRetrieveOutputBuffer(pending, 1, &buf, &len);
        RtlCopyMemory(buf, data, min(len, dataLen));
        WdfRequestCompleteWithInformation(pending, STATUS_SUCCESS,
                                          min(len, dataLen));
}
Cancellation is not optional

A request sitting in a manual queue can be cancelled at any moment — the application pressed Ctrl+C, or called CancelIo, or exited. WDF handles the mechanics if the request is in a queue, which is exactly why you should park requests in a queue rather than in your own list. If you must hold a request outside a queue, you have to implement EvtRequestCancel correctly, and getting that race right is genuinely hard.

Accessing I/O buffers

NTSTATUS status;
PVOID    buffer;
size_t   length;

// input buffer (what the caller sent you)
status = WdfRequestRetrieveInputBuffer(Request,
                                       sizeof(MY_INPUT),  // minimum required
                                       &buffer, &length);
if (!NT_SUCCESS(status)) {
        WdfRequestComplete(Request, status);   // too small -> STATUS_BUFFER_TOO_SMALL
        return;
}

// output buffer (what you fill in for the caller)
status = WdfRequestRetrieveOutputBuffer(Request, sizeof(MY_OUTPUT),
                                        &buffer, &length);

// completing: the second value becomes the caller's bytes-transferred
WdfRequestCompleteWithInformation(Request, STATUS_SUCCESS, bytesWritten);
WDF validates lengths for you

Passing a minimum size to WdfRequestRetrieve*Buffer makes the framework return STATUS_BUFFER_TOO_SMALL rather than handing you a short buffer. Always pass the real minimum — this one habit eliminates an entire class of kernel buffer-overflow vulnerabilities.

IOCTL codes

#define FILE_DEVICE_MYDEV  0x8000u    // 0x8000+ is reserved for third parties

#define IOCTL_MYDEV_GET_VERSION \
        CTL_CODE(FILE_DEVICE_MYDEV, 0x800, METHOD_BUFFERED, FILE_READ_ACCESS)
#define IOCTL_MYDEV_SET_CONFIG \
        CTL_CODE(FILE_DEVICE_MYDEV, 0x801, METHOD_BUFFERED, FILE_WRITE_ACCESS)
#define IOCTL_MYDEV_XFER \
        CTL_CODE(FILE_DEVICE_MYDEV, 0x802, METHOD_OUT_DIRECT, FILE_ANY_ACCESS)
CTL_CODE(DeviceType, Function, Method, Access) packs into 32 bits:

 31    16 15   14 13         2 1  0
+--------+------+-------------+----+
|DeviceType|Access| Function   |Meth|
+--------+------+-------------+----+

  Function  0x000-0x7FF reserved by Microsoft, 0x800-0xFFF yours
  Method    how buffers are passed: BUFFERED / IN_DIRECT / OUT_DIRECT / NEITHER
  Access    FILE_READ_ACCESS / FILE_WRITE_ACCESS / FILE_ANY_ACCESS
            — checked against how the handle was opened. Use it.

Hardware resources

NTSTATUS MyEvtDevicePrepareHardware(WDFDEVICE Device,
                                    WDFCMRESLIST Raw, WDFCMRESLIST Translated)
{
        PDEVICE_CONTEXT ctx = DeviceGetContext(Device);
        ULONG count = WdfCmResourceListGetCount(Translated);

        for (ULONG i = 0; i < count; i++) {
                PCM_PARTIAL_RESOURCE_DESCRIPTOR d =
                        WdfCmResourceListGetDescriptor(Translated, i);

                switch (d->Type) {
                case CmResourceTypeMemory:
                        ctx->Registers = MmMapIoSpaceEx(d->u.Memory.Start,
                                                        d->u.Memory.Length,
                                                        PAGE_READWRITE | PAGE_NOCACHE);
                        ctx->RegLength = d->u.Memory.Length;
                        break;

                case CmResourceTypeInterrupt:
                        /* WDF claims this automatically if you created a
                         * WDFINTERRUPT in EvtDeviceAdd */
                        break;

                case CmResourceTypePort:
                        /* legacy x86 I/O ports */
                        break;
                }
        }
        return ctx->Registers ? STATUS_SUCCESS : STATUS_INSUFFICIENT_RESOURCES;
}

// register access - note PAGE_NOCACHE above; this is the Device memory type
// from chapter 03, and getting it wrong causes exactly the bugs described there
ULONG v = READ_REGISTER_ULONG((PULONG)((PUCHAR)ctx->Registers + REG_STATUS));
WRITE_REGISTER_ULONG((PULONG)((PUCHAR)ctx->Registers + REG_CTRL), v | ENABLE);

// in EvtDeviceReleaseHardware
MmUnmapIoSpace(ctx->Registers, ctx->RegLength);

Interrupts

WDF_INTERRUPT_CONFIG intConfig;
WDF_INTERRUPT_CONFIG_INIT(&intConfig, MyEvtInterruptIsr, MyEvtInterruptDpc);
intConfig.EvtInterruptEnable  = MyEvtInterruptEnable;   // called at D0Entry
intConfig.EvtInterruptDisable = MyEvtInterruptDisable;  // called at D0Exit

status = WdfInterruptCreate(device, &intConfig,
                            WDF_NO_OBJECT_ATTRIBUTES, &ctx->Interrupt);

// --- ISR: runs at DIRQL. Do the minimum. ---
BOOLEAN MyEvtInterruptIsr(WDFINTERRUPT Interrupt, ULONG MessageID)
{
        PDEVICE_CONTEXT ctx = DeviceGetContext(WdfInterruptGetDevice(Interrupt));
        ULONG status = READ_REGISTER_ULONG(REG(ctx, REG_STATUS));

        if (!(status & ST_IRQ))
                return FALSE;          // not ours - essential for shared lines

        WRITE_REGISTER_ULONG(REG(ctx, REG_STATUS), ST_IRQ);   // clear at source
        ctx->LastStatus = status;                             // capture volatile state
        WdfInterruptQueueDpcForIsr(Interrupt);
        return TRUE;
}

// --- DPC: runs at DISPATCH_LEVEL. Still no paging, still no waiting. ---
VOID MyEvtInterruptDpc(WDFINTERRUPT Interrupt, WDFOBJECT Device)
{
        PDEVICE_CONTEXT ctx = DeviceGetContext((WDFDEVICE)Device);
        WDFREQUEST request;

        if (NT_SUCCESS(WdfIoQueueRetrieveNextRequest(ctx->ManualQueue, &request))) {
                /* fill the buffer and complete the parked request */
                WdfRequestCompleteWithInformation(request, STATUS_SUCCESS, len);
        }
}

// To synchronise your normal code against the ISR, use the interrupt lock:
WdfInterruptAcquireLock(ctx->Interrupt);      // raises to DIRQL
ctx->SharedWithIsr = value;
WdfInterruptReleaseLock(ctx->Interrupt);

// ...or run a whole function at DIRQL with the lock held:
WdfInterruptSynchronize(ctx->Interrupt, MySyncedRoutine, ctx);

DMA

// 1. Declare DMA capability in EvtDeviceAdd or PrepareHardware
WDF_DMA_ENABLER_CONFIG dmaConfig;
WDF_DMA_ENABLER_CONFIG_INIT(&dmaConfig, WdfDmaProfileScatterGather64,
                            MAX_TRANSFER_LENGTH);
status = WdfDmaEnablerCreate(device, &dmaConfig,
                             WDF_NO_OBJECT_ATTRIBUTES, &ctx->DmaEnabler);

// 2. Per transfer: create a transaction, initialise it from the request,
//    and let WDF call you back with the scatter-gather list
status = WdfDmaTransactionCreate(ctx->DmaEnabler, WDF_NO_OBJECT_ATTRIBUTES,
                                 &dmaTransaction);
status = WdfDmaTransactionInitializeUsingRequest(dmaTransaction, Request,
                                                 MyEvtProgramDma,
                                                 WdfDmaDirectionWriteToDevice);
status = WdfDmaTransactionExecute(dmaTransaction, WDF_NO_CONTEXT);

// 3. Your callback receives the SG list — program the hardware here
BOOLEAN MyEvtProgramDma(WDFDMATRANSACTION Transaction, WDFDEVICE Device,
                        PVOID Context, WDF_DMA_DIRECTION Direction,
                        PSCATTER_GATHER_LIST SgList)
{
        for (ULONG i = 0; i < SgList->NumberOfElements; i++) {
                program_descriptor(SgList->Elements[i].Address.QuadPart,
                                   SgList->Elements[i].Length);
        }
        start_dma();
        return TRUE;
}

// 4. On completion (from your DPC)
if (WdfDmaTransactionDmaCompleted(dmaTransaction, &status)) {
        /* the whole transfer is done */
        WdfDmaTransactionRelease(dmaTransaction);
        WdfRequestComplete(request, status);
}
The same physics as chapter 05

SgList->Elements[i].Address is a logical address — Windows' name for what Linux calls a dma_addr_t. If an IOMMU is present it is an IOVA; if not it is a physical address. Never program the device with a virtual address, and never DMA to a buffer you have not described with an MDL. The reasoning in chapter 05 applies unchanged.

INF files — installation and matching

An INF is both the driver's "device tree" (what hardware it matches) and its installer.

Signing

StageWhat you needWorks on
Test signingA self-made certificate; bcdedit /set testsigning on on the targetYour test VM only
Attestation signingAn EV code-signing certificate + a Microsoft Partner Center account; submit the package, get it signed backWindows 10/11 desktop. No hardware lab tests required.
WHQL / HLKAll of the above plus passing the Hardware Lab Kit test suiteEverything, and eligible for Windows Update distribution
creating and using a test certificate
:: 1. make a self-signed test certificate
makecert -r -pe -ss PrivateCertStore -n "CN=MyTestCert" mytest.cer

:: 2. sign the driver
signtool sign /v /s PrivateCertStore /n "MyTestCert" ^
              /t http://timestamp.digicert.com mydriver.sys

:: 3. sign the catalog too - Windows checks the .cat, not just the .sys
signtool sign /v /s PrivateCertStore /n "MyTestCert" mydriver.cat

:: 4. on the TEST machine, trust the certificate
certmgr /add mytest.cer /s /r localMachine root
certmgr /add mytest.cer /s /r localMachine trustedpublisher

:: 5. verify
signtool verify /v /kp mydriver.sys
Why the certificate must be in two stores

root makes Windows trust the chain; trustedpublisher suppresses the installation prompt. Missing either one gives "the third-party INF does not contain digital signature information" even though the file is signed correctly.

Chapter checklist

  • You can explain why WDF exists and what it takes off your hands.
  • You can name the WDF object hierarchy and say what a context is for.
  • You can choose a queue dispatch type and justify it.
  • You can describe the manual-queue pattern for a request that completes later.
