Glossary & resources

Every acronym used on this site, defined in one line, plus the manuals and books worth owning and the free hardware-free ways to practise.

ARM architecture

AArch64 / AArch32The 64-bit and 32-bit execution states of ARMv8+
A64The AArch64 instruction set: fixed 32-bit encodings
ARM ARMThe ARM Architecture Reference Manual — the definitive specification
AAPCS64The procedure call standard: which registers hold arguments, which are callee-saved
ASIDAddress Space ID — tags TLB entries so a context switch need not flush them
VMIDThe same idea per virtual machine
PSTATEProcessor state: NZCV flags, DAIF masks, current EL, stack selection
MRS / MSRRead from / write to a system register
SCTLRSystem Control Register: MMU, cache and alignment enables
TTBR0 / TTBR1Translation Table Base Registers: roots of the user and kernel page tables
TCRTranslation Control Register: VA size, granule, walk cacheability
MAIRMemory Attribute Indirection Register: the 8 memory types descriptors index into
VBARVector Base Address Register: where the exception vector table lives
ESRException Syndrome Register: why the exception happened
FARFault Address Register: which address faulted
ELR / SPSRException Link Register (return address) and Saved PSTATE
ERETException Return — restores PC from ELR and PSTATE from SPSR, atomically
VA / IPA / PAVirtual, Intermediate Physical (guest-physical), and Physical address
MMU / TLBMemory Management Unit; Translation Lookaside Buffer (its cache)
GranuleBase page size: 4 KB, 16 KB or 64 KB
Block vs page descriptorA large mapping (1 GB / 2 MB) vs a 4 KB one
AP / UXN / PXN / AF / nGDescriptor bits: access permissions, execute-never, access flag, not-global
DMB / DSB / ISBData Memory / Data Synchronization / Instruction Synchronization Barrier
LDXR / STXRLoad/store exclusive — the retry-loop atomic primitive
LSELarge System Extensions: single-instruction atomics (LDADD, CAS)
Normal / Device memoryCacheable, reorderable, speculatable vs strictly ordered MMIO
nGnRnEDevice sub-type: no Gathering, no Reordering, no Early ack — the strictest
ShareabilityHow far coherency and barriers propagate: inner, outer, full system
PoC / PoUPoint of Coherency / Point of Unification — how far cache maintenance reaches
GICGeneric Interrupt Controller
SGI / PPI / SPI / LPISoftware-generated / private per-core / shared peripheral / message-signalled interrupts
AMBA / AXI / ACE / CHI / APBARM's on-chip bus protocol family, from simple (APB) to coherent mesh (CHI)
NEON / SVEFixed 128-bit SIMD; scalable vector extension
PMUPerformance Monitor Unit — the counters perf reads
big.LITTLE / DynamIQHeterogeneous cores with the same ISA but different power/performance
ErrataDocumented silicon bugs and the software workarounds they require

Exception levels, security and isolation

EL0–EL3Exception levels: applications, OS kernel, hypervisor, secure monitor
S-EL0/1/2The secure-world counterparts
SVC / HVC / SMCSupervisor / Hypervisor / Secure Monitor Call — deliberate exceptions to EL1/EL2/EL3
SCR_EL3Secure Configuration Register — holds the NS bit that selects the world below
HCR_EL2Hypervisor Configuration Register — enables stage 2 and configures traps
NS bitThe Non-secure signal (AxPROT[1]) on every bus transaction — all of TrustZone rests on it
TrustZoneSystem-wide hardware partitioning into a secure and a normal world
TEETrusted Execution Environment — the secure-world OS plus its trusted applications
TATrusted Application, running at S-EL0
TF-ATrusted Firmware-A — the reference EL3 secure monitor
OP-TEEOpen Portable TEE — the open-source trusted OS. Runs on QEMU.
SMCCCSMC Calling Convention — how function IDs and arguments are encoded
PSCIPower State Coordination Interface — standard SMCs for CPU on/off/suspend
BL1/BL2/BL31/BL32/BL33Boot stages: ROM, trusted boot firmware, EL3 runtime, trusted OS, normal-world loader
Root of trustThe immutable starting point of the verification chain — boot ROM plus fused key hash
HUKHardware Unique Key — per-device, secure-only, used to derive storage keys
Anti-rollbackA fuse counter preventing installation of older, signed-but-vulnerable firmware
AttestationProving a device's identity and boot state to a remote party
SMMU / IOMMUAn MMU for non-CPU bus masters
StreamID / SubstreamIDIdentifies which device (and which context within it) issued a transaction
STE / CDStream Table Entry / Context Descriptor — the SMMUv3 lookup chain
CMDQ / EVTQ / PRIQSMMU command, event and page-request queues
SVAShared Virtual Addressing — a device using a process's own page tables
ATS / PASIDAddress Translation Services; the PCIe name for a SubstreamID
XPU / TZASC / TZPC / RDC / IOPMPVendor names for interconnect access-control firewalls
MPUMemory Protection Unit — core-local, region-based, no translation (Cortex-M/R)
SAU / IDAUSecurity Attribution Unit / Implementation Defined AU — TrustZone-M's partitioning
eFuse / OTPOne-time-programmable storage for keys, lifecycle state and counters
Confused deputyTricking privileged code into misusing its authority on your behalf
TOCTOUTime-of-check to time-of-use — a value changes between validation and use

What to read

Primary sources — free, and definitive

  • Arm Architecture Reference Manual for A-profile (the "ARM ARM") — developer.arm.com. Reference, not textbook. Use it to answer questions.
  • Arm Cortex-A Series Programmer's Guide for ARMv8-A — far more readable than the ARM ARM. Start here.
  • Arm System Memory Management Unit Architecture Specification (SMMUv3)
  • Arm Generic Interrupt Controller Architecture Specification (GICv3/v4)
  • Arm Trusted Firmware-A documentation — trustedfirmware.org
  • OP-TEE documentation — optee.readthedocs.io
  • Linux kernel Documentation/ — especially driver-api/, devicetree/bindings/, core-api/ and arch/arm64/
  • Microsoft Learn: Windows Drivers — learn.microsoft.com/windows-hardware/drivers

Where to go from here

Path

Platform / BSP engineer

Bootloaders, device tree, kernel configuration, board bring-up, Yocto. Bring up a board end to end, then do it again on different silicon.

Path

Driver / kernel engineer

Go deep in one subsystem — networking, storage, media, USB. Read its core, then send a patch. The review you get back is the best teaching available anywhere.

Path

Firmware / security engineer

TF-A, OP-TEE, secure boot, attestation, side channels. The rarest and most durable specialisation on this site; start by building OP-TEE on QEMU and reading BL31.

Path

Real-time / safety

PREEMPT_RT, Zephyr, latency analysis, ISO 26262 / IEC 61508. Where determinism matters more than throughput.

The last piece of advice

Everything on this site is a map. Maps are only useful once you start walking. Pick the project in chapter 10 or chapter 13, build it today, and break it tomorrow. Six months of that beats six years of reading.
