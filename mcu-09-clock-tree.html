The clock tree: oscillators, PLLs and dividers

Almost every "the peripheral does not respond" bug on a microcontroller is a clock bug. This chapter covers where clocks come from, how they are multiplied and divided to reach every block, and the two ordering rules that must never be violated.

Where clocks come from

   FOUR SOURCES, in rough order of accuracy and cost:

   INTERNAL RC  (HSI, MSI)      1-3% accurate, sometimes 0.1%
     +--[~~~]--+               after factory trim.
                               Starts in microseconds.
                               Drifts with temperature.
                               Free - no external parts.
                               THE CHIP BOOTS ON THIS.

   CRYSTAL      (HSE)           10-50 ppm. Needs two load
     +--[X]--+                  capacitors chosen to match
                                the crystal's spec.
                                Starts in 1-10 ms.
                                Required for USB, Ethernet,
                                CAN and anything with a
                                protocol-defined bit rate.

   LOW-SPEED    (LSE)           32.768 kHz, 20 ppm.
     +--[x]--+                  2^15 Hz, so a 15-bit counter
                                overflows at exactly 1 Hz.
                                Runs in the lowest power
                                modes; drives the RTC.

   EXTERNAL     (bypass mode)   A clock signal from another
     --->                       chip. Used when one oscillator
                                serves a whole board.

   Accuracy is a REQUIREMENT, not a preference. UART at 3%
   error fails at 115200 baud (chapter bus-02 does the
   arithmetic). USB requires 0.25%. Sleep-mode wake timing
   needs the LSE or you drift seconds per day.
The internal oscillator is not good enough for a UART, usually

A 1% clock error plus a 1% error at the other end plus baud-rate rounding can exceed the ~2% that asynchronous serial framing tolerates. Many parts can trim the HSI against the LSE at runtime to reach 0.1%, which is enough. Otherwise you fit a crystal. "It works on my desk and fails in the cold chamber" is this problem: the RC oscillator's temperature coefficient moved you outside the window.

The PLL and the tree

   A realistic STM32F4 clock tree, simplified:

   HSI 16 MHz --+
                |    +---------------------------+
   HSE  8 MHz --+-->-| /M  ->  xN  ->  /P        |--> PLLCLK
                     |  VCO input   VCO output   |     168 MHz
                     +---------------------------+
                        |
                        v
                  +-----------+
   HSI ---------> |  SYSCLK   |  <- mux: HSI, HSE or PLL
   HSE ---------> |   MUX     |
   PLL ---------> +-----------+
                        |
                        v  /AHBPRE (1,2,4...512)
                  +-----------+
                  |  HCLK     |  168 MHz -> core, DMA, memory
                  +-----------+
                     |     |
          /APB1PRE   |     |   /APB2PRE
                     v     v
              +--------+ +--------+
              | PCLK1  | | PCLK2  |
              | 42 MHz | | 84 MHz |
              +--------+ +--------+
               I2C,UART2  UART1,SPI1
               TIM2-7     TIM1,TIM8

   THE TIMER EXCEPTION, and it catches everyone:
   if an APB prescaler is not 1, the TIMER clock on that bus
   is PCLK x2, not PCLK. So with PCLK1 = 42 MHz, TIM2 counts
   at 84 MHz. Getting this wrong makes every period exactly
   half or double what you intended.

   CONSTRAINTS the reference manual imposes on the PLL:
     VCO input  (HSE/M)     must be 1-2 MHz
     VCO output (that x N)  must be 100-432 MHz
     PLLCLK     (that /P)   must be <= 168 MHz
   Pick M, N, P to satisfy all three simultaneously. Vendor
   clock-configuration tools exist precisely because this is
   a constraint-satisfaction problem, not a calculation.

Two ordering rules

/* RULE 1: raise flash wait states BEFORE raising the clock,
   and lower them AFTER lowering it.

   Flash cannot be read at 168 MHz with zero wait states. If
   you switch SYSCLK to the PLL while the flash controller
   still expects 16 MHz timing, the very next instruction
   fetch returns garbage and you fault - before any code of
   yours can report it.                                      */

void clock_init_168mhz(void)
{
    /* 1. Turn on HSE and WAIT for it. */
    RCC->CR |= RCC_CR_HSEON;
    while (!(RCC->CR & RCC_CR_HSERDY)) { }

    /* 2. Flash: 5 wait states + caches + prefetch, FIRST. */
    FLASH->ACR = FLASH_ACR_LATENCY_5WS
               | FLASH_ACR_PRFTEN
               | FLASH_ACR_ICEN
               | FLASH_ACR_DCEN;
    while ((FLASH->ACR & FLASH_ACR_LATENCY) != FLASH_ACR_LATENCY_5WS) { }

    /* 3. Bus prescalers BEFORE the core speeds up, so no bus
          ever momentarily exceeds its maximum.              */
    RCC->CFGR |= RCC_CFGR_HPRE_DIV1     /* AHB  = 168 MHz */
              |  RCC_CFGR_PPRE1_DIV4    /* APB1 =  42 MHz */
              |  RCC_CFGR_PPRE2_DIV2;   /* APB2 =  84 MHz */

    /* 4. Configure and start the PLL: 8/8 = 1, x336, /2. */
    RCC->PLLCFGR = (8u)            /* M */
                 | (336u << 6)     /* N */
                 | (0u   << 16)    /* P = 2, encoded as 0 */
                 | RCC_PLLCFGR_PLLSRC_HSE
                 | (7u << 24);     /* Q = 7, for USB 48 MHz */
    RCC->CR |= RCC_CR_PLLON;
    while (!(RCC->CR & RCC_CR_PLLRDY)) { }

    /* 5. Only now switch SYSCLK, and confirm it took. */
    RCC->CFGR &= ~RCC_CFGR_SW;
    RCC->CFGR |= RCC_CFGR_SW_PLL;
    while ((RCC->CFGR & RCC_CFGR_SWS) != RCC_CFGR_SWS_PLL) { }

    SystemCoreClock = 168000000u;
}

/* RULE 2: every WAIT loop above is mandatory. An oscillator
   takes milliseconds to stabilise; a PLL takes hundreds of
   microseconds to lock. Switching to an unlocked PLL gives
   you an unstable clock, which gives you behaviour that
   changes with temperature and supply voltage and looks
   exactly like a hardware fault.                            */
Every wait loop needs a timeout in production code

The loops above hang forever if the crystal never starts — a cracked crystal, a bad solder joint, or the wrong load capacitors. A field unit that hangs in clock_init is indistinguishable from a dead board. Real firmware counts iterations, and on timeout falls back to the internal oscillator and sets a fault flag, so the device boots degraded and can report the failure rather than appearing dead.

Peripheral clock gating

/* Every peripheral has an individual clock enable, and it
   is OFF at reset. A peripheral with no clock does not
   fault when you write its registers - it silently ignores
   them, and reads return zero.

   This is the number one cause of "my GPIO does nothing".  */

RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

/* THE DELAY THAT IS NOT SUPERSTITION:
   the enable write is posted on the bus. On several ST
   families the peripheral needs a couple of clock cycles
   before its registers respond. Writing GPIOA->MODER on the
   very next instruction can be lost.

   The idiomatic fix is a dummy read-back, which forces the
   write to complete before proceeding:                     */

volatile uint32_t tmp = RCC->AHB1ENR;   /* read back */
(void) tmp;

/* ST's own HAL does exactly this, in the __HAL_RCC_*_CLK_ENABLE
   macros. If you write registers directly and skip it, you
   get an initialisation that works at -O0 and fails at -O2,
   because the optimiser tightened the instruction spacing.

   Gating is also your main static power lever: an unused
   peripheral with its clock off draws essentially nothing.
   Chapter 13 uses this heavily.                             */

Verifying the clock is what you think

/* NEVER trust the arithmetic. Measure. Two ways: */

/* 1. MCO - route a clock to a pin and put a scope on it.
      Almost every part can output SYSCLK/2, /4 etc.        */
RCC->CFGR |= RCC_CFGR_MCO1_1        /* source: PLL          */
          |  RCC_CFGR_MCO1PRE_DIV4; /* divide so it fits    */
/* configure PA8 as alternate function 0 - now PA8 carries
   SYSCLK/4 and one scope reading confirms the whole tree.  */

/* 2. Blink at a known rate and time it with a stopwatch.
      Crude, needs no equipment, and catches factor-of-two
      errors instantly - which are the errors you actually
      make (the APB timer doubling, or a /2 you forgot).    */
for (;;) {
    GPIOA->ODR ^= (1u << 5);
    for (volatile int i = 0; i < 168000000 / 20; i++) { }
}
/* Should toggle at roughly 10 Hz if SYSCLK is 168 MHz and
   the loop is ~2 cycles. If you count 5 Hz, you are at
   84 MHz and your PLL config is off by one divider.        */

/* SystemCoreClock is a VARIABLE, not a measurement. It is
   whatever the last line of your clock init assigned. If
   the PLL silently failed to lock and you fell back to HSI,
   SystemCoreClock still reads 168000000 and every delay in
   the system is wrong by 10x while the variable insists
   everything is fine.                                       */
