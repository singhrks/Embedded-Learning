Sorting: interval patterns

Meetings, bookings, ranges. Almost every interval problem starts with one decision — sort by start or sort by end — and that decision determines whether the rest is three lines or impossible.

The pattern

Almost every interval problem turns on one decision made before any code is written — sort by start, or sort by end. Get the overlap predicate and that choice right and the rest is a short loop.

   TWO INTERVALS [a1, a2] AND [b1, b2] OVERLAP when

        a1 <= b2  AND  b1 <= a2

   equivalently, they do NOT overlap when one ends entirely
   before the other starts. Get this predicate right once
   and write it down.

   ---------------------------------------------------------

   THE DECISION THAT DETERMINES EVERYTHING:

   SORT BY START  -> MERGING, and "can I attend all?"
        Walk left to right; each interval either extends the
        current block or begins a new one.

   SORT BY END    -> MAXIMISING THE COUNT of
                     non-overlapping intervals
        The classic activity-selection greedy: always keep
        the interval that FINISHES EARLIEST, because it
        leaves the most room for everything after it.

   SWEEP LINE     -> "how many are active at once?"
        Turn each interval into two EVENTS,
        (start, +1) and (end, -1), sort all events by time,
        and scan keeping a running counter. The maximum
        counter value is the answer.

   ---------------------------------------------------------

   MERGE, after sorting by start:

     [1,3] [2,6] [8,10] [15,18]
       |-----|              sorted by start
        overlap -> merge to [1,6]
                   |---|    8 > 6, new block
                        |---|

     out = [];
     for (const [s, e] of sorted) {
         const last = out[out.length - 1];
         if (last && s <= last[1]) last[1] = Math.max(last[1], e);
         else out.push([s, e]);
     }

     THE Math.max IS NOT OPTIONAL. [1,10] followed by [2,3]
     must stay [1,10]; without it the end shrinks to 3.

   ---------------------------------------------------------

   THE TOUCHING QUESTION: do [1,2] and [2,3] overlap?
   IT DEPENDS ON THE PROBLEM. Merging usually says yes
   (use <=); meeting rooms usually says no, because a
   meeting ending at 2 frees the room for one starting at 2
   (use <). ASK, or state your assumption.

When to reach for it

Merge overlapping ranges

Sort by start, extend or append.

Minimum removals to make disjoint

Sort by end, greedily keep the earliest finisher.

Minimum rooms / max concurrent

Sweep line, or a min-heap of end times.

Insert into a sorted set of intervals

Three phases: before, overlapping (merge), after.

Free time / gaps

Merge first, then read the gaps between blocks.

Minimum arrows / points hitting all

Sort by end — the same greedy as activity selection.

/* --- SWEEP LINE, the general tool --- */
const events = [];
for (const [s, e] of intervals) {
    events.push([s, +1]);
    events.push([e, -1]);
}
// tie-break: process ENDS before STARTS when touching
// intervals do NOT count as overlapping
events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);
//                                   ^ -1 sorts before +1

let cur = 0, best = 0;
for (const [, delta] of events) {
    cur += delta;
    best = Math.max(best, cur);
}

/* THE TIE-BREAK IS THE WHOLE SUBTLETY. With events at the
   same time, processing the -1 first means a meeting ending
   at 10 releases the room before one starting at 10 claims
   it. Flip the tie-break and you need an extra room.     */
