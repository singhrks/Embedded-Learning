Zero-cost abstraction: reading the generated assembly

C++'s central claim is that its abstractions cost nothing you would not have paid by hand. That claim is checkable in about thirty seconds per case, and this chapter is a series of those checks — the ones that hold, and the ones that do not.

The claim, stated precisely

"You don't pay for what you don't use" is C++'s central promise, and it is largely true and frequently misquoted. Stating it precisely is what lets you tell which features to adopt freely and which to weigh.

   Stroustrup's formulation:

     "What you don't use, you don't pay for. And what you do
      use, you couldn't hand-code any better."

   THE FIRST HALF IS ABOUT ABSENCE: a program that uses no
   virtual functions carries no vtables; one that throws no
   exceptions pays nothing on the happy path.

   THE SECOND HALF IS ABOUT PRESENCE: an abstraction whose
   types are known at compile time is compiled away entirely.

   WHAT MAKES AN ABSTRACTION FREE:
     · the type is known at compile time
     · the function is visible for inlining
     · no indirection the compiler cannot see through
     · no allocation

   WHAT MAKES ONE COST:
     · TYPE ERASURE - virtual, std::function, dynamic_cast.
       The compiler cannot know the target, so it cannot
       inline.
     · ALLOCATION - vector, string, shared_ptr, exceptions
     · ATOMIC OPERATIONS - shared_ptr's refcount
     · CODE the abstraction adds that you would not have
       written: bounds checks, refcounts, unwind tables

   THE METHOD FOR THE REST OF THIS CHAPTER: write both
   versions, compile both at -O2 for aarch64, and diff the
   assembly (compilers chapter 16).

The ones that are free

These features genuinely compile away to the same code you would have written by hand in C. Adopting them costs nothing at run time and buys real safety and clarity.

Check it yourself, in thirty seconds

Open godbolt.org, set the compiler to armv8-a clang or ARM64 gcc, flags to -O2, and paste both versions side by side. Every claim in this chapter is verifiable that way, and the habit of verifying rather than believing is the actual skill being taught.

The ones that are not

These do have a cost, and the cost is not always obvious from the source — a hidden allocation, a run-time lookup, or code the linker cannot remove.

Measuring properly

The only way to settle whether an abstraction was free is to look at what the compiler emitted. These are the tools, and using them turns the question from a debate into an observation.

# --- CODE SIZE, per symbol ---
    nm --size-sort -S -C prog.elf | tail -20
    bloaty prog.elf -d symbols,compileunits
    size -A prog.elf

# --- DIFF TWO VERSIONS ---
    g++ -O2 -S -o a.s a.cpp
    g++ -O2 -S -o b.s b.cpp
    diff -u a.s b.s

# --- COUNT INSTRUCTIONS IN A FUNCTION ---
    objdump -d prog.elf | awk '/<myfunc>:/,/^$/' | wc -l

# --- PROVE NO ALLOCATION HAPPENS ---
    /* on bare metal, simply do not provide operator new:
       any accidental allocation becomes a LINK ERROR - the
       strongest guarantee available */

    /* on a hosted system, count them: */
    static std::atomic<size_t> g_allocs{0};
    void *operator new(size_t n) { g_allocs++; return malloc(n); }
    void operator delete(void *p) noexcept { free(p); }

    size_t before = g_allocs;
    hot_path();
    assert(g_allocs == before);         /* in a test */

# --- PROVE A TYPE IS WHAT YOU THINK ---
    static_assert(sizeof(Wrapper) == sizeof(uint32_t));
    static_assert(std::is_trivially_copyable_v<Message>);
    static_assert(std::is_standard_layout_v<RegBlock>);
    static_assert(alignof(Buffer) == 64);

# --- AND ACTUAL TIME, which is the only thing that
#     ultimately matters ---
    perf stat -r 10 ./prog
    /* cycles, instructions, IPC, cache-misses,
       branch-misses (compilers chapter 16) */

When the abstraction is not free

Abstractions that are normally free stop being free under specific, identifiable conditions. Knowing what breaks the optimisation is what lets you avoid it.

/* Usually because inlining did not happen. The causes, in
   order of frequency: */

   1. THE DEFINITION IS NOT VISIBLE.
        A member function defined in a .cpp cannot be inlined
        into another translation unit without LTO
        (compilers chapter 12). Define small functions in the
        HEADER.

   2. IT IS TOO LARGE for the inliner's threshold.
        Split it: a small inlinable wrapper around a large
        out-of-line body.
                inline int fast_path(int x) {
                        if (likely(x < 16)) return table[x];
                        return slow_path(x);   /* not inlined,
                                                  and that is
                                                  fine       */
                }

   3. IT IS VIRTUAL and the type is not provable.
        Mark the class or the function `final` (chapter 11),
        or use a template.

   4. IT IS CALLED THROUGH A FUNCTION POINTER or
      std::function.

   5. THE ADDRESS OF A LOCAL ESCAPED, so the variable cannot
      be promoted to a register (compilers chapter 05).

   6. -O0. Nothing is inlined; measuring there tells you
      nothing.

/* FORCE IT, when you have measured a reason: */
        __attribute__((always_inline)) inline void f();
        [[gnu::always_inline]] inline void f();
/* AND FORBID IT, for cold paths that would pollute the
   I-cache: */
        __attribute__((noinline)) void error_path();

/* ASK WHY IT DID NOT HAPPEN: */
        clang -Rpass-missed=inline -Rpass-analysis=inline
        gcc -fopt-info-inline-missed
/* which prints the reason per call site - "cost exceeds
   threshold", "function not inlinable", "recursive". That
   output is the answer far more often than guessing.    */

A worked comparison

Here is the whole argument on one concrete example, from source through generated assembly, so the claim can be checked rather than believed.

/* A realistic embedded case: a GPIO abstraction. */

/* --- C --- */
        #define GPIO_BASE 0x40020000
        #define GPIO_ODR  (*(volatile uint32_t *)(GPIO_BASE + 0x14))
        static inline void gpio_set(int pin)
                { GPIO_ODR |= (1u << pin); }

/* --- C++ --- */
template<uintptr_t Base>
class GpioPort {
        struct Regs {
                volatile uint32_t MODER, OTYPER, OSPEEDR,
                                  PUPDR, IDR, ODR;
        };
        static Regs *regs()
                { return reinterpret_cast<Regs *>(Base); }
public:
        template<uint8_t Pin>
        class Pin_t {
                static_assert(Pin < 16, "invalid pin");
        public:
                static void set()    { regs()->ODR |=  (1u << Pin); }
                static void clear()  { regs()->ODR &= ~(1u << Pin); }
                static bool read()   { return regs()->IDR &
                                              (1u << Pin); }
        };
};
        using PortA = GpioPort<0x40020000>;
        using LedPin = PortA::Pin_t<5>;

        LedPin::set();

/* BOTH COMPILE TO: */
        movz w8, #0x2000, lsl #16       ; the base
        movk w8, #0x14                  ; + ODR offset
        ldr  w9, [x8]
        orr  w9, w9, #0x20              ; bit 5
        str  w9, [x8]

/* IDENTICAL. And the C++ version additionally gives you:
     · a static_assert on the pin number - an invalid pin is
       a BUILD error
     · named, typed registers instead of offsets
     · LedPin as a TYPE, passable to templates
     · no macros, so no namespace pollution and no
       double-evaluation hazard
     · the port and pin cannot be mismatched, because they
       are one type

   THAT IS THE ARGUMENT for C++ in firmware, in one example:
   the same instructions, with errors moved from run time to
   compile time.                                          */

A verification checklist

Rather than reasoning about each feature from scratch, this reduces the chapter to a procedure you can apply to any abstraction you are considering.

ClaimHow to check
"This wrapper is free"Diff the assembly against the raw version
"No allocation in this path"Instrument operator new, or omit it entirely
"This type is one word"static_assert(sizeof(T) == ...)
"This is inlined"Look for the bl; or -Rpass=inline
"This call is devirtualised"A named bl rather than ldr+blr
"This is computed at compile time"It is in .rodata; readelf -x
"This loop vectorises"v registers in the output; -fopt-info-vec
"Exceptions cost nothing here"size -A with and without -fno-exceptions
"This is faster"perf stat -r 10 — the only claim that needs timing

How it shows up

SymptomCause
