DP: string problems

Two strings, one table. Nearly every two-string problem is the same grid with a different combine rule, and recognising that turns edit distance, LCS and pattern matching into one technique.

The pattern

String DP is unusually uniform: the state is nearly always a pair of prefix lengths, and the table nearly always has one extra row and column. Knowing that in advance removes most of the guesswork.

   THE STATE IS ALWAYS A PAIR OF PREFIX LENGTHS:

     dp[i][j] = answer for the first i characters of s
                and the first j characters of t

   The table is (m+1) x (n+1) — the extra row and column are
   the EMPTY prefixes, and they are where the base cases live.

   THE RECURRENCE ALWAYS SPLITS ON ONE QUESTION:
   DO THE LAST TWO CHARACTERS MATCH?

     if (s[i-1] === t[j-1])
         dp[i][j] = f(dp[i-1][j-1])          // consume both
     else
         dp[i][j] = g(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])

   NOTE THE INDEX SHIFT: dp[i] refers to the first i
   characters, so the LAST one is s[i-1]. Mixing this up is
   the single most common bug in this chapter.

   ---------------------------------------------------------
   THE THREE NEIGHBOURS AND WHAT THEY MEAN

        dp[i-1][j-1]   dp[i-1][j]
        dp[i][j-1]     dp[i][j]

     dp[i-1][j-1]  both consumed  -> match / replace
     dp[i-1][j]    only s consumed -> delete from s
     dp[i][j-1]    only t consumed -> insert into s

   EDIT DISTANCE IS EXACTLY THAT READING:
     match   -> dp[i-1][j-1]
     replace -> dp[i-1][j-1] + 1
     delete  -> dp[i-1][j]   + 1
     insert  -> dp[i][j-1]   + 1

   ---------------------------------------------------------
   THE FAMILY

     LCS                     longest common subsequence
     edit distance           insert / delete / replace
     is subsequence          greedy two-pointer, no DP needed
     longest common substring  must be CONTIGUOUS: reset to
                             0 on a mismatch, and the answer
                             is the table MAXIMUM, not the
                             corner
     distinct subsequences   count instead of maximise
     regex / wildcard match  extra cases for * and ?
     shortest common
       supersequence         m + n - LCS

   ---------------------------------------------------------
   SUBSEQUENCE VERSUS SUBSTRING — the distinction that
   decides the recurrence:

     SUBSEQUENCE  characters need not be adjacent; on a
                  mismatch you carry the best so far forward
     SUBSTRING    must be contiguous; on a mismatch the run
                  is BROKEN and the entry resets to 0

   ---------------------------------------------------------
   SPACE: each row depends only on the row above, so two rows
   suffice — O(min(m, n)) after swapping so the shorter
   string indexes the columns.

Check yourself

  • State what dp[i][j] means and why the table is (m+1)×(n+1).
  • Explain the index shift between dp[i] and s[i-1].
  • Give the meaning of each of the three neighbouring cells.
  • Map the four edit-distance operations onto those cells.
  • Contrast the subsequence and substring recurrences.
  • Say where the answer is read from in each case.
  • Explain how to reduce the table to two rows and the trap in doing so.
