Trees: the recursive pattern

Almost every tree problem is the same three lines: a base case, a call on each child, and a combine step. The skill is deciding what each child should return.

The pattern

Almost every tree question is the same four-line function with different contents. Learning the shape rather than the problems is what makes an unfamiliar tree question tractable.

   THE UNIVERSAL SHAPE:

     function solve(node) {
         if (!node) return BASE;              // 1. base case
         const L = solve(node.left);          // 2. recurse
         const R = solve(node.right);
         return COMBINE(L, R, node.val);      // 3. combine
     }

   THE ONLY QUESTION THAT MATTERS:

     WHAT SHOULD A SUBTREE REPORT TO ITS PARENT?

   Answer that and the code writes itself. Examples:

     height            report the height below me
     sum               report the subtree sum
     "is this a BST?"  report (isBST, min, max)
     diameter          report the height, and record the
                       best diameter in an outer variable
     balanced?         report the height, or -1 for
                       "already unbalanced"

   ---------------------------------------------------------
   THE TWO DIRECTIONS OF INFORMATION

     TOP-DOWN (preorder): the parent passes context DOWN as
     a parameter.
         dfs(node, depth)      dfs(node, pathSoFar)
         dfs(node, lowerBound, upperBound)

     BOTTOM-UP (postorder): the child returns a result UP.
         const h = 1 + max(dfs(left), dfs(right));

     MANY PROBLEMS NEED BOTH. Validating a BST passes bounds
     DOWN; computing the diameter sends heights UP. When you
     are stuck, ask which direction the missing information
     travels.

   ---------------------------------------------------------
   THE "GLOBAL BEST + LOCAL RETURN" IDIOM

   Some problems ask for the best value ANYWHERE in the tree,
   but the recursion must return something DIFFERENT to be
   composable. Keep the answer outside:

     let best = -Infinity;

     function gain(node) {
         if (!node) return 0;
         const L = Math.max(gain(node.left), 0);   // drop
         const R = Math.max(gain(node.right), 0);  // negatives
         best = Math.max(best, node.val + L + R);  // path
                                                   // THROUGH me
         return node.val + Math.max(L, R);         // path
     }                                             // ENDING at me

   THE TWO EXPRESSIONS ARE DIFFERENT AND BOTH ARE NEEDED.
   A path through a node uses both children; a path handed
   to a parent may use only one, or the parent could not
   extend it. Confusing them is the classic bug in maximum
   path sum and in diameter.

When to reach for it

Any aggregate over a subtree

Height, size, sum, count of something. Pure bottom-up.

Structural comparison

Same tree, symmetric tree, subtree of another — recurse on pairs of nodes.

Path questions

Root-to-leaf sums pass context down; any-to-any paths use the global-best idiom.

Validation with constraints

Pass the allowed range down (chapter 29).

Lowest common ancestor

Return the node found, or null; a node seeing both sides non-null is the answer.

Tree modification

Invert, flatten, prune — return the new subtree root.

Problems

How it shows up

SymptomCause
