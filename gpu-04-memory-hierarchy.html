The GPU memory hierarchy

Most GPU kernels are limited by memory, not arithmetic. The hierarchy has more levels than a CPU's, several of them are explicitly managed by you, and the single most important rule — coalescing — has no CPU equivalent at all.

The levels

                                   latency   bandwidth   scope
   REGISTERS                        ~1 cyc   ~20 TB/s    thread
     256 KB per SM. Private per thread. The fastest storage in
     the machine, and the budget that caps occupancy.
        |
   SHARED MEMORY / LDS             ~20-30    ~10 TB/s    block
     up to 164 KB per SM, split with L1. SOFTWARE MANAGED -
     you decide what lives here. Banked (see below).
        |
   L1 / TEXTURE CACHE              ~30       ~10 TB/s    SM
     automatic. Small per thread once you divide by occupancy.
        |
   L2 CACHE                        ~200      ~2 TB/s     device
     2-100 MB. Shared by all SMs. Where atomics resolve.
        |
   GLOBAL MEMORY (VRAM/HBM)        ~400-800  0.5-3 TB/s  device
     GB. Everything else lives here. THE BOTTLENECK.
        |
   HOST MEMORY over PCIe           ~1-2 us   ~25 GB/s    system
     100x less bandwidth than VRAM. Avoid crossing it.

   PLUS TWO READ-ONLY PATHS:
     CONSTANT MEMORY   64 KB, broadcast-optimised. One value
                       to all lanes in a cycle; serialised if
                       lanes read different addresses.
     TEXTURE/__ldg     read-only path with its own cache,
                       spatial (2D) locality, free filtering
                       and border handling.

   THE RATIO THAT MATTERS: registers are ~40x the bandwidth of
   global memory. Every byte you keep in registers or shared
   memory instead of re-reading is the highest-value
   optimisation available.

Coalescing: the rule with no CPU analogue

   Memory is served in 32-byte SECTORS (four per 128-byte
   line). A warp issues 32 addresses AT ONCE, and the hardware
   merges them into as few transactions as it can.

   PERFECT - consecutive lanes, consecutive floats

     lane:   0  1  2  3  ...            31
     addr: 000 004 008 012 ...         124
                                     -> ONE 128-byte transaction
                                        128 bytes requested,
                                        128 used. 100%.

   STRIDED BY 2 - c[i*2]

     lane:   0    1    2   ...           31
     addr: 000  008  016  ...           248
                                     -> TWO transactions
                                        256 fetched, 128 used.
                                        50% of bandwidth wasted.

   STRIDED BY 32 - a column of a row-major matrix

     lane:   0     1     2  ...          31
     addr: 000   128   256  ...        3968
                                     -> 32 SEPARATE transactions
                                        4096 fetched, 128 used.
                                        3% efficiency.
                                        THIRTY-TWO TIMES SLOWER
                                        than the perfect case,
                                        for the same code.

   RANDOM - a gather

     32 transactions, and no prefetcher can help.

   THE RULE: adjacent THREADS should touch adjacent MEMORY.
   Not adjacent iterations - adjacent threads. Getting this
   backwards is the single most common GPU performance bug.
/* THE CLASSIC MISTAKE - each thread handles a contiguous
   chunk, "like a CPU would". */

__global__ void bad(float *a, int n, int per_thread)
{
        int t = blockIdx.x * blockDim.x + threadIdx.x;
        int base = t * per_thread;                 /* lane 0 -> 0
                                                      lane 1 -> 64
                                                      lane 2 -> 128 */
        for (int i = 0; i < per_thread; i++)
                a[base + i] *= 2.0f;               /* stride 64
                                                      between
                                                      lanes!    */
}

/* THE FIX - grid-stride loop. Lanes stay adjacent; the WHOLE
   GRID strides. */
__global__ void good(float *a, int n)
{
        int stride = blockDim.x * gridDim.x;
        for (int i = blockIdx.x * blockDim.x + threadIdx.x;
             i < n; i += stride)
                a[i] *= 2.0f;              /* lanes 0..31 touch
                                              adjacent floats,
                                              every iteration   */
}
/* Same work, same instruction count, typically 5-20x faster.
   And the grid-stride form is independent of grid size, so
   the same kernel is correct for any launch configuration. */
Structure of arrays, not array of structures

An AoS layout (struct Particle { float x, y, z; }; Particle p[N];) means lane 0 reads offset 0 and lane 1 reads offset 12 — a stride of 12 bytes, so reading just x wastes two-thirds of every transaction. SoA (float px[N], py[N], pz[N];) makes each field perfectly coalesced. This is the same transformation that helps SIMD on a CPU, but on a GPU the penalty for getting it wrong is far larger.

Shared memory and bank conflicts

/* Shared memory is divided into 32 BANKS, 4 bytes wide,
   interleaved. Bank = (address / 4) % 32.

   The 32 lanes of a warp can each access a DIFFERENT bank in
   one cycle. Two lanes hitting the SAME bank at DIFFERENT
   addresses serialise.                                     */

__shared__ float tile[32][32];

/* CONFLICT-FREE - row access. Lane i reads tile[k][i], which
   is bank i. All 32 banks, one cycle.                       */
        float v = tile[k][threadIdx.x];

/* 32-WAY CONFLICT - column access. Lane i reads tile[i][k],
   at address (i*32 + k)*4, so bank = (i*32 + k) % 32 = k for
   EVERY lane. All 32 lanes hit bank k. 32x serialisation. */
        float v = tile[threadIdx.x][k];

/* THE FIX - PAD THE ROW. One extra column shifts each row by
   one bank. */
__shared__ float tile[32][33];      /* <-- 33, not 32          */
        float v = tile[threadIdx.x][k];
        /* address = (i*33 + k)*4, bank = (i*33 + k) % 32
                                       = (i + k) % 32
           every lane a different bank. Conflict-free.        */

/* Four bytes of waste per row buys a 32x speed-up on the
   transpose. It is the best-known trick in GPU programming
   and it is one character.

   BROADCAST IS FREE: if every lane reads the SAME address,
   the hardware broadcasts in one cycle. Same-bank same-address
   is not a conflict; same-bank different-address is.       */

Tiling: the reason shared memory exists

/* Naive matrix multiply: every thread reads a whole row and a
   whole column from global memory. Each element of A is read
   N times.                                                 */

__global__ void matmul_naive(float *C, const float *A,
                             const float *B, int N)
{
        int r = blockIdx.y * blockDim.y + threadIdx.y;
        int c = blockIdx.x * blockDim.x + threadIdx.x;
        float sum = 0;
        for (int k = 0; k < N; k++)
                sum += A[r * N + k] * B[k * N + c];   /* B is
                                                         strided! */
        C[r * N + c] = sum;
}
/* Global traffic: 2 * N^3 * 4 bytes. Bandwidth-bound, and B's
   access pattern is a column walk. Perhaps 5% of peak.     */

#define T 32
__global__ void matmul_tiled(float *C, const float *A,
                             const float *B, int N)
{
        __shared__ float As[T][T + 1];      /* +1: no conflicts */
        __shared__ float Bs[T][T + 1];

        int r = blockIdx.y * T + threadIdx.y;
        int c = blockIdx.x * T + threadIdx.x;
        float sum = 0;

        for (int t = 0; t < N / T; t++) {
                /* COALESCED loads: adjacent lanes (threadIdx.x)
                   read adjacent floats. */
                As[threadIdx.y][threadIdx.x] =
                        A[r * N + t * T + threadIdx.x];
                Bs[threadIdx.y][threadIdx.x] =
                        B[(t * T + threadIdx.y) * N + c];

                __syncthreads();            /* tile is loaded   */

                for (int k = 0; k < T; k++)
                        sum += As[threadIdx.y][k] * Bs[k][threadIdx.x];

                __syncthreads();            /* before OVERWRITING
                                               the tile - this
                                               second barrier is
                                               the one people
                                               forget           */
        }
        C[r * N + c] = sum;
}
/* Global traffic: 2 * N^3 / T * 4 bytes - THIRTY-TWO TIMES
   LESS. Each element is loaded once per tile instead of once
   per output. Typically 10-20x faster.

   THE PRINCIPLE: load a tile cooperatively into fast memory,
   reuse it many times, move on. It is the same blocking
   transformation as a cache-oblivious CPU algorithm, except
   you write it explicitly.                                  */
Both __syncthreads() are load-bearing

The first ensures the tile is fully written before anyone reads it. The second ensures everyone has finished reading before the next iteration overwrites it. Omitting the second is a classic bug: it works at small sizes where warps happen to stay in step, and corrupts results once the block spans enough warps that they drift apart. Also note __syncthreads() must be reached by every thread in the block — putting one inside a divergent branch hangs the block.
