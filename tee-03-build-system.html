The source tree and the build system

An OP-TEE build is nine git repositories, three toolchains and a makefile that coordinates them. The repo manifest exists because assembling that by hand is unreasonable — but you should know what it assembled, because the day something breaks you will be building one component alone.

The nine repositories

The build pulls from several independent repositories, each owning one layer. Knowing which is which is what lets you find the file you need rather than searching everything.

RepositoryWhat it isRuns at
optee_osThe trusted OS itself. The core of everything in this trackS-EL1
optee_clientlibteec and tee-supplicantNormal world EL0
optee_testxtest — the GlobalPlatform conformance suite plus OP-TEE's own testsBoth worlds
optee_examplesSmall, complete CA+TA pairs. Copy these to start a projectBoth worlds
trusted-firmware-aBL1, BL2, BL31 — the monitorEL3
u-boot or edk2BL33, the normal-world bootloaderEL2/EL1
linuxThe kernel, with drivers/tee/optee/EL1
buildrootBuilds the normal-world root filesystem and packages the client toolshost
buildThe makefiles that tie all of the above together, one .mk per platformhost

Building

One command builds a great deal, and knowing roughly what it is doing is what makes the failures interpretable rather than opaque.

$ cd ~/optee/build

# 1. Toolchains - downloads aarch64 and arm cross compilers
$ make toolchains -j2

# 2. Everything. First build: 20-60 minutes.
$ make -j$(nproc)

# 3. Run it. Opens three windows.
$ make run
# or, if you have no X display:
$ make run-only CFG_TEE_CORE_LOG_LEVEL=2

# In the QEMU console that appears:
(qemu) c

# In the "Normal World" window, log in as root, then:
# ls /dev/tee*
/dev/tee0  /dev/teepriv0
# xtest -t regression 1001
# optee_example_hello_world
Make targetDoes
makeBuild everything and assemble the images
make runBuild if needed, then launch QEMU with three consoles
make run-onlyLaunch without rebuilding
make optee-osJust the trusted OS
make optee-clientJust libteec and tee-supplicant
make optee-examplesJust the example CA/TA pairs
make buildrootRepack the root filesystem — needed after changing anything that lands in it
make arm-tfJust TF-A
make linuxJust the kernel
make optee-os-cleanClean one component
make -n runPrint the QEMU command line without running it — very useful
The rebuild trap that costs everyone an hour

Changing a TA or a client and running make optee-examples is not enough. The binaries live in the root filesystem image, which must be repacked:

# The correct incremental cycle after editing a TA or CA:
$ make optee-examples
$ make buildroot          # <-- repacks rootfs.cpio.gz
$ make run-only

# Or in one line, which is what you should alias:
$ make optee-examples buildroot run-only

# Same for the trusted OS itself:
$ make optee-os
$ make run-only           # OP-TEE is in the FIP, not the
                          # rootfs, so no buildroot needed

# Prove which binary is actually running - the timestamp is in
# the boot log:
I/TC: OP-TEE version: 4.1.0-12-gabc1234 (gcc version 12.2.0)
      #1 Fri Aug 22 10:14:02 UTC 2026 aarch64

The configuration flags that matter

A handful of build flags change behaviour substantially — debug output, paging, the platform. These are the ones worth knowing before you need them.

# OP-TEE is configured with CFG_ variables, passed on the make
# command line or set in the platform's conf.mk.

$ make CFG_TEE_CORE_LOG_LEVEL=3 \
       CFG_TEE_TA_LOG_LEVEL=4 \
       CFG_CORE_ASLR=n \
       CFG_UNWIND=y \
       DEBUG=1

#   CFG_TEE_CORE_LOG_LEVEL   0 none 1 error 2 info 3 debug 4 flow
#   CFG_TEE_TA_LOG_LEVEL     the same, for TAs
#   CFG_CORE_ASLR=n          turn off ASLR so addresses in a
#                            panic dump match your ELF
#   CFG_UNWIND=y             stack traces on panic
#   DEBUG=1                  -O0 and assertions
#   CFG_CORE_SANITIZE_UNDEFINED=y   UBSan inside OP-TEE
#   CFG_CORE_SANITIZE_KADDRESS=y    KASAN inside OP-TEE

# Feature flags you will meet:
#   CFG_RPMB_FS=y            secure storage in RPMB (ch. 15)
#   CFG_RPMB_TESTKEY=y       use a test RPMB key - DEV ONLY
#   CFG_REE_FS=y             secure storage via the normal world
#   CFG_WITH_PAGER=y         demand-paged OP-TEE (ch. 5)
#   CFG_WITH_LPAE=y          large physical addresses
#   CFG_NS_VIRTUALIZATION=y  OP-TEE aware of normal-world VMs
#   CFG_SECURE_DATA_PATH=y   secure buffers for media
#   CFG_TA_ASLR=y            ASLR inside TAs
#   CFG_ATTESTATION_PTA=y    remote attestation pseudo-TA

# See everything a platform defines:
$ make -C optee_os PLATFORM=vexpress-qemu_armv8a \
       CFG_TEE_CORE_LOG_LEVEL=2 -n | head -40
$ cat optee_os/core/arch/arm/plat-vexpress/conf.mk

Building one component alone

Building your own component into this tree, rather than alongside it, is what makes iteration fast. This is how the build expects that to be arranged.

# When you are iterating on the trusted OS, the top-level make
# is slow. Go direct:

$ cd ~/optee/optee_os
$ make -j$(nproc) \
    PLATFORM=vexpress-qemu_armv8a \
    CFG_ARM64_core=y \
    CROSS_COMPILE=aarch64-linux-gnu- \
    CROSS_COMPILE_core=aarch64-linux-gnu- \
    CROSS_COMPILE_ta_arm64=aarch64-linux-gnu- \
    CFG_TEE_CORE_LOG_LEVEL=3 \
    DEBUG=1

# The client library alone:
$ cd ~/optee/optee_client
$ cmake -B build -DCMAKE_INSTALL_PREFIX=./out/export \
        -DCMAKE_C_COMPILER=aarch64-linux-gnu-gcc
$ cmake --build build && cmake --install build

# A TA on its own, against the dev kit (ch. 14):
$ export TA_DEV_KIT_DIR=~/optee/optee_os/out/arm-plat-vexpress/export-ta_arm64
$ export CROSS_COMPILE=aarch64-linux-gnu-
$ make -C my_ta

# Find every CFG_ that affects the build:
$ grep -rn "CFG_MY_FEATURE" optee_os/ | head

How it shows up

SymptomCause
repo sync failsNetwork, or a manifest branch that no longer exists. Pin a release tag
Build fails on a Python modulepycryptodome, pyelftools or cryptography missing from pip3
Changes to a TA have no effectmake buildroot not run — the old .ta is still in the image
Changes to OP-TEE core have no effectStale FIP; run the top-level make or rebuild the FIP
make run opens nothingNo X display; use make run-only and read make -n run for the command line
TA build cannot find headersTA_DEV_KIT_DIR unset or pointing at the wrong architecture
Two toolchains, wrong one usedThree separate CROSS_COMPILE* variables — core, TA arm32, TA arm64
Panic addresses do not match the ELFASLR — rebuild with CFG_CORE_ASLR=n
Out of diskA full tree with objects is 20–30 GB
