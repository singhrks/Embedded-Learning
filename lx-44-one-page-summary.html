The whole track compressed to what you actually need in your head. Nothing here teaches a concept for the first time — every line is a reminder with a chapter number attached, so the moment one does not make sense, you know exactly where to go. Read it before an interview, before a code review, or whenever you come back to kernel work after months away.

The seven rules that are never negotiable

Break any of these and the machine, not your process, pays for it
  1. Never dereference a user pointer. copy_to_user / copy_from_user, and check the return — it reports bytes not copied (ch. 09).
  2. Never sleep in atomic context. Not in a hard IRQ handler, not holding a spinlock, not with preemption disabled. GFP_KERNEL, mutexes, I2C/SPI transfers and _cansleep calls all sleep (ch. 07 · 12 · 15).
  3. Never DMA to vmalloc memory or to the stack. Physically discontiguous or not DMA-able; virt_to_phys is meaningless on both (ch. 06 · 30).
  4. Always check every allocation and every return. Even GFP_KERNEL can fail. Error codes are negative, and IS_ERR — never NULL — tests an ERR_PTR (ch. 06 · 33).
  5. Unwind in exactly reverse order. A goto ladder, or devm_ and no ladder at all (ch. 33).
  6. The stack is 16 KB, shared with interrupts. No large locals, no deep recursion (ch. 02).
  7. The user-space ABI is permanent; the internal API is not. Your ioctl numbers and sysfs files are forever. The kernel functions you call are not (ch. 02 · 23 · 38).

The stack, in one paragraph

User space calls libc, which traps through the syscall interface — the only door in (ch. 38). Inside, policy subsystems decide what should happen: the scheduler picks who runs (ch. 11), the memory manager finds pages (ch. 06–08), the VFS resolves paths (ch. 41), the page cache answers most reads without any device at all (ch. 42), and the block or network stack turns the rest into requests (ch. 43). Those hand down to mechanism: the driver core binds a device to a driver (ch. 19), and a bus subsystem — I2C, SPI, GPIO, USB — speaks the device's actual language. Below that sits the architecture layer, and then hardware. Chapter 03 is this same paragraph as a diagram.

The pre-review checklist

  • Every allocation checked; every error path unwinds in reverse.
  • No sleeping call reachable from atomic context — trace each path back to its caller.
  • Every hardware access bracketed by runtime PM get/put, including error paths.
  • No board-specific value hard-coded — it belongs in the device tree.
  • No new custom ioctl or sysfs file where a subsystem ABI already exists.
  • Locking documented: which lock protects which field, stated in a comment.
  • -EPROBE_DEFER returned, not swallowed, when a resource is not ready.
  • Unload path tested — build as a module and actually rmmod it under load.
  • Tested with KASAN and lockdep enabled, not just a release build.
  • A binding document for any new device-tree property, validated with make dtbs_check.
If you remember only one sentence from this track

Kernel code runs with no process boundary underneath it, on every CPU at once, and nothing will catch your mistakes for you — so the discipline that feels excessive in user space (checking every return, knowing your context, unwinding precisely, locking deliberately) is not style here. It is the entire difference between a driver that works and a machine that stops.
