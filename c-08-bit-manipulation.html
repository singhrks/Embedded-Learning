Bit manipulation

Embedded work is bit work. Every hardware register is a packed collection of fields, every protocol header is bit-aligned, and every flag set is a bitmask. This chapter is the complete idiom set, plus the traps that make bit code subtly wrong.

Ground rules

Four rules that prevent most bit bugs
  1. Use unsigned types. Signed shifts, signed overflow and sign extension are all undefined or implementation-defined. There is no upside.
  2. Suffix your literals. 1u, 1ul, 1ull — a bare 1 is an int, and 1 << 40 is undefined behaviour.
  3. Parenthesise. Bitwise operators bind looser than comparison (ch. 03).
  4. Name your masks. A bare 0x38 in a shift is unreviewable.

Single-bit operations

Setting, clearing and testing individual bits is the vocabulary of hardware programming. The operations are simple; the value is in writing them so that intent is obvious at a glance six months later.

#define BIT(n)  (1u << (n))        /* for <32-bit fields          */
#define BIT_ULL(n) (1ull << (n))   /* when n may reach 32 or more */

x |=  BIT(n);                /* set        */
x &= ~BIT(n);                /* clear      */
x ^=  BIT(n);                /* toggle     */
if (x & BIT(n)) ...          /* test       */

/* conditionally set or clear without a branch */
x = (x & ~BIT(n)) | ((-(unsigned)cond) & BIT(n));
/* -(unsigned)cond is 0x00000000 or 0xFFFFFFFF — a mask from a bool */

/* the same idea, more readable */
if (cond) x |=  BIT(n);
else      x &= ~BIT(n);
The shift traps, again 
1 << 31            /* UB: shifting into the sign bit of an int */
1u << 31           /* fine                                     */
1 << 32            /* UB: n must be < width of the type        */
1ull << 40         /* fine                                     */

uint64_t m = 1 << bit;      /* BUG for bit >= 32: computed in int,
                               THEN widened                       */
uint64_t m = 1ull << bit;   /* correct                            */

x >> n             /* if x is signed and negative, the result is
                      implementation-defined (arithmetic shift in
                      practice, but do not rely on it)            */

/* And a shift by a variable that can equal the width: */
uint32_t mask = (1u << width) - 1;    /* UB when width == 32 */
uint32_t mask = width >= 32 ? ~0u : (1u << width) - 1;   /* safe */
uint32_t mask = (uint32_t)((1ull << width) - 1);          /* also safe */

Multi-bit fields

Most hardware registers pack several multi-bit fields into one word. Extracting and inserting them is a shift and a mask, and doing it consistently with macros prevents a whole class of off-by-one errors.

A 32-bit control register, as a TRM would document it:

  31    24 23  20 19        8 7    4 3  1  0
 +--------+------+-----------+------+----+--+
 | RESVD  | MODE |  DIVISOR  | PRIO |RSV |EN|
 +--------+------+-----------+------+----+--+

  EN       bit  0
  PRIO     bits 7:4
  DIVISOR  bits 19:8
  MODE     bits 23:20

Turn each field into a shift and a mask, once, at the top of the file.
#define CTRL_EN            BIT(0)
#define CTRL_PRIO_SHIFT    4
#define CTRL_PRIO_MASK     (0xFu   << CTRL_PRIO_SHIFT)
#define CTRL_DIV_SHIFT     8
#define CTRL_DIV_MASK      (0xFFFu << CTRL_DIV_SHIFT)
#define CTRL_MODE_SHIFT    20
#define CTRL_MODE_MASK     (0xFu   << CTRL_MODE_SHIFT)

/* extract */
unsigned prio = (reg & CTRL_PRIO_MASK) >> CTRL_PRIO_SHIFT;

/* insert — ALWAYS clear before OR-ing, and mask the value so an
   out-of-range input cannot corrupt neighbouring fields          */
reg = (reg & ~CTRL_PRIO_MASK) |
      ((prio << CTRL_PRIO_SHIFT) & CTRL_PRIO_MASK);

/* generic helpers, if you have no library */
#define FIELD_MASK(hi, lo)  (((1ull << ((hi) - (lo) + 1)) - 1) << (lo))
#define FIELD_GET(r, hi, lo)  (((r) & FIELD_MASK(hi, lo)) >> (lo))
#define FIELD_SET(r, hi, lo, v) \
        (((r) & ~FIELD_MASK(hi, lo)) | \
         (((uint64_t)(v) << (lo)) & FIELD_MASK(hi, lo)))
/* Linux's version, which you should copy the design of: the mask is
   the single source of truth and the shift is derived from it, so
   the two can never disagree.                                     */
#include <linux/bitfield.h>

#define CTRL_PRIO  GENMASK(7, 4)      /* 0x000000F0 */
#define CTRL_DIV   GENMASK(19, 8)
#define CTRL_MODE  GENMASK(23, 20)

prio = FIELD_GET(CTRL_PRIO, reg);
reg  = (reg & ~CTRL_PRIO) | FIELD_PREP(CTRL_PRIO, prio);

/* FIELD_PREP checks at COMPILE TIME that the value fits in the
   field and that the mask is a contiguous run of bits. That is
   the whole reason to prefer it over hand-rolled shifts.       */

Register access semantics

Hardware registers do not behave like memory. A read can have side effects, a write of 1 may clear rather than set a bit, and reading back what you wrote may give a different value — so the read-modify-write you would use on a variable is often simply wrong.

TypeMeaningCorrect access
RWRead/writeRead-modify-write is fine
RORead onlyNever write
WOWrite only; reads return garbageNever read-modify-write — keep a shadow copy
W1CWrite 1 to clearWrite only the bits you want cleared
W1SWrite 1 to setSame
RCRead clearsRead exactly once and keep the value
 
/* W1C is the one people get wrong. */
reg |= IRQ_DONE;             /* WRONG: read-modify-write on W1C.
                                The read returns ALL pending bits, and
                                writing them back clears interrupts you
                                have not handled yet — silently losing
                                events.                               */

writel(IRQ_DONE, base + STATUS);   /* correct: write ONLY that bit */

/* Write-only registers need a shadow, because you cannot read back */
static uint32_t ctrl_shadow;
static void ctrl_update(uint32_t set, uint32_t clr)
{
        ctrl_shadow = (ctrl_shadow & ~clr) | set;
        writel(ctrl_shadow, base + CTRL);
}

Counting, finding and rounding

Counting set bits, finding the first or last one, and rounding to a power of two appear constantly in allocators and schedulers. Modern processors do all of these in a single instruction, and the compiler will use it if you ask correctly.

/* Use the builtins. They map to single instructions (CLZ, RBIT,
   CNT on ARM) and are far faster than a loop.                  */

__builtin_popcount(x)        /* number of set bits, unsigned int  */
__builtin_popcountll(x)      /* ...long long                      */
__builtin_clz(x)             /* count leading zeros  — UB if x==0 */
__builtin_ctz(x)             /* count trailing zeros — UB if x==0 */
__builtin_ffs(x)             /* find first set, 1-based, 0 if x==0 */
__builtin_parity(x)          /* 1 if an odd number of bits set    */

/* C23 standardises these in <stdbit.h>: */
stdc_count_ones(x)  stdc_leading_zeros(x)  stdc_trailing_zeros(x)
stdc_bit_width(x)   stdc_bit_ceil(x)       stdc_has_single_bit(x)

/* Linux equivalents that handle zero safely */
hweight32(x)   fls(x)   ffs(x)   __ffs(x)   ilog2(x)
/* Derived idioms — worth recognising instantly */

x & (x - 1)               /* clear the LOWEST set bit             */
x & -x                    /* ISOLATE the lowest set bit           */
x | (x - 1)               /* set all bits below the lowest set bit */
!(x & (x - 1)) && x       /* is x a power of two?                 */

/* iterate over set bits efficiently */
while (mask) {
        int bit = __builtin_ctzll(mask);
        handle(bit);
        mask &= mask - 1;          /* clear the one we just did */
}

/* round up to a multiple of a power of two */
#define ALIGN_UP(x, a)    (((x) + (a) - 1) & ~((a) - 1))
#define ALIGN_DOWN(x, a)  ((x) & ~((a) - 1))
#define IS_ALIGNED(x, a)  (((x) & ((a) - 1)) == 0)
/* NOTE: these require `a` to be a power of two. Assert it. */

/* round up to the next power of two */
static uint32_t next_pow2(uint32_t x)
{
        return x <= 1 ? 1 : 1u << (32 - __builtin_clz(x - 1));
}

/* ceiling division without floating point */
#define DIV_ROUND_UP(n, d)  (((n) + (d) - 1) / (d))

Byte order

Byte order matters the moment data leaves the processor — to a file, a network or a device. The conversions are simple; knowing exactly where in the code they belong is the part people get wrong.

/* Endianness is about the order of BYTES within a multi-byte value.
   It matters whenever bytes cross a boundary: a network, a file,
   another chip.                                                   */

uint32_t v = 0x12345678;

/* little endian (ARM, x86): low byte first  */   78 56 34 12
/* big endian ("network order"):             */   12 34 56 78

/* Never swap by hand with a cast — use the standard conversions. */
#include <arpa/inet.h>    /* htonl htons ntohl ntohs           */
#include <endian.h>       /* htobe32 htole32 be32toh le32toh   */

uint32_t on_wire = htobe32(v);       /* host -> big endian     */
uint32_t host    = be32toh(on_wire); /* big endian -> host     */

/* Linux kernel, with type annotations that sparse checks: */
__be32 x = cpu_to_be32(v);
v = be32_to_cpu(x);
/* Declaring the field as __be32 and building with `make C=1` makes
   a missing conversion a WARNING rather than a silent bug.      */

/* the builtins, if you need a raw swap */
__builtin_bswap16(x)  __builtin_bswap32(x)  __builtin_bswap64(x)

/* On a little-endian host these conversions compile to a single
   REV instruction; on a big-endian host they compile to nothing.
   There is no reason to avoid them.                             */
Endianness is not the same as bit order

Within a byte, bit numbering is a documentation convention, not a hardware property — x & 1 is the least significant bit everywhere. Endianness only reorders bytes. But a bitfield spanning a byte boundary is affected by both, which is one more reason bitfields are unsuitable for wire formats (ch. 07).

Bitmaps

A bit array is the most compact way to track the state of many things at once, which is why allocators and schedulers use them everywhere. The indexing arithmetic is worth writing once, carefully.

/* A bitmap over N items, packed into words. */
#define BITS_PER_WORD   (8 * sizeof(unsigned long))
#define BITMAP_WORDS(n) (((n) + BITS_PER_WORD - 1) / BITS_PER_WORD)

unsigned long map[BITMAP_WORDS(1024)];

static inline void bm_set(unsigned long *m, size_t i)
{ m[i / BITS_PER_WORD] |=  1ul << (i % BITS_PER_WORD); }

static inline void bm_clear(unsigned long *m, size_t i)
{ m[i / BITS_PER_WORD] &= ~(1ul << (i % BITS_PER_WORD)); }

static inline bool bm_test(const unsigned long *m, size_t i)
{ return m[i / BITS_PER_WORD] & (1ul << (i % BITS_PER_WORD)); }

/* find the first zero bit — an allocator in four lines */
static size_t bm_find_free(const unsigned long *m, size_t n)
{
        for (size_t w = 0; w < BITMAP_WORDS(n); w++)
                if (~m[w])
                        return w * BITS_PER_WORD + __builtin_ctzl(~m[w]);
        return n;                 /* none free */
}

/* Linux has a complete, tested API — use it in kernel code:
     DECLARE_BITMAP, set_bit, clear_bit, test_and_set_bit,
     find_first_zero_bit, bitmap_weight, for_each_set_bit

   Note that set_bit() and friends are ATOMIC; __set_bit() is not.
   Choosing wrongly gives you a lost-update race under concurrency. */

Branchless and constant-time code

Code that compares secrets must take the same time regardless of the data, or the timing itself leaks the secret. That rules out branches and early exits, and bit tricks are how the alternative is written.

/* Two reasons to avoid branching on data:
     1. performance, when the branch is unpredictable (CA ch. 12)
     2. SECURITY, when the data is secret — branch timing leaks it */

/* select without a branch */
uint32_t mask = -(uint32_t)cond;          /* 0 or 0xFFFFFFFF */
result = (a & mask) | (b & ~mask);        /* cond ? a : b     */

/* min and max */
int min = b ^ ((a ^ b) & -(a < b));

/* absolute value, without a branch */
int mask = x >> (sizeof(int) * 8 - 1);    /* 0 or -1 (arithmetic shift) */
int abs  = (x + mask) ^ mask;

/* constant-time comparison — never use memcmp on secrets */
static int ct_eq(const uint8_t *a, const uint8_t *b, size_t n)
{
        uint8_t d = 0;
        for (size_t i = 0; i < n; i++)
                d |= a[i] ^ b[i];         /* no early exit */
        return d == 0;
}

/* The compiler may still reintroduce a branch. In real cryptographic
   code, verify the generated assembly, or use a vetted library.
   See the cryptography track, chapter 19.                         */

How it shows up

SymptomCause
A flag test is always falsex & MASK == 0 — precedence
Setting bit 32 or higher does nothing1 << n computed in int
