The preprocessor

The preprocessor is a text substitution engine that runs before the compiler sees anything. It knows nothing about types, scopes or expressions. That ignorance is the source of both its power and every macro bug you will ever write.

The mental model

It is a separate language

Preprocessing happens in translation phase 4 (ch. 01), operating on preprocessing tokens. There are no variables, no types and no scopes — only names, replacement lists and conditional inclusion. By the time the compiler runs, every macro has vanished.

# See exactly what the compiler receives. Do this whenever a macro
# misbehaves — it turns a mystery into an obvious text problem.
gcc -E file.c | less
gcc -E -P file.c            # -P strips the line markers
gcc -E -dM - < /dev/null    # every predefined macro on this target
gcc -E -dM file.c | sort    # every macro visible in this TU

#include

The preprocessor runs before the compiler sees anything and does pure text substitution. #include is literally "paste this file here", which explains both its simplicity and every problem it causes.

#include <stdio.h>      /* search the SYSTEM include path first  */
#include "myheader.h"   /* search relative to THIS file first,
                           then fall back to the system path     */

/* It is literal text substitution. The entire file's contents are
   pasted at this point, and phases 1-4 run on them recursively.  */

# where does it look?
gcc -I dir      # add dir to the quoted AND angle search path
gcc -isystem d  # add d as a system dir (suppresses warnings from it)
gcc -E -v -     # print the actual search paths in order

Include guards

/* Every header needs one, or a struct definition included twice
   becomes a redefinition error.                                */
#ifndef MYMODULE_H
#define MYMODULE_H
...
#endif /* MYMODULE_H */

/* #pragma once is shorter, supported by every compiler you will
   meet, and is not standard. It also behaves better with symlinks
   and hard links, where a guard macro can be duplicated.       */
#pragma once

/* Use whichever your project already uses. Do not mix them. */
Header hygiene that pays for itself
  • Self-contained. A header must compile on its own — include everything it needs. Test it mechanically: gcc -fsyntax-only header.h.
  • Minimal. Forward-declare (struct foo;) rather than including, when callers only handle pointers. This is the single biggest lever on build times in large C projects.
  • Include your own header first in the matching .c file. If it is not self-contained, you find out immediately.
  • No using-style pollution. Do not define short unprefixed macros (MAX, OK, ERROR) in a public header — they will collide.

Object-like macros

A macro is not a constant. It is a textual replacement with no type and no scope, which is why it can produce surprises that a genuine constant never would.

#define BUFFER_SIZE 1024
#define PI 3.14159265358979
#define DEVICE_NAME "uart0"

/* Prefer these to `const int` for array bounds and case labels,
   because in C a const object is NOT a constant expression
   (chapter 10).                                                 */
char buf[BUFFER_SIZE];

/* But for typed constants, an enum is better: it is visible to the
   debugger, obeys scope, and is type-checked.                    */
enum { BUFFER_SIZE = 1024 };
enum state { S_IDLE, S_RUN, S_DONE };

/* C23 finally gives a real alternative: */
constexpr int buffer_size = 1024;

Function-like macros, and the four rules

Macros that take arguments look like functions and are not: arguments may be evaluated several times or not at all, and missing parentheses lets surrounding operators bind in ways you did not intend.

/* WRONG — every one of these is a real bug */
#define SQUARE(x) x * x
#define MAX(a, b) a > b ? a : b

SQUARE(2 + 3)      /* -> 2 + 3 * 2 + 3  = 11, not 25 */
10 / SQUARE(2)     /* -> 10 / 2 * 2     = 10, not 2.5 */
MAX(1, 2) + 1      /* -> 1 > 2 ? 1 : 2 + 1 = 3, not 3... by luck */
The four rules
  1. Parenthesise every parameter where it appears.
  2. Parenthesise the whole replacement.
  3. Evaluate each parameter exactly once, or document that you do not.
  4. Wrap multi-statement macros in do { } while (0).
/* Rules 1 and 2 */
#define SQUARE(x) ((x) * (x))
#define MAX(a, b) (((a) > (b)) ? (a) : (b))

/* Rule 3 is the one you cannot fix with parentheses: */
MAX(i++, j++)      /* one of them is incremented TWICE */
SQUARE(f())        /* f() is CALLED TWICE              */

/* GNU statement expressions solve it — used throughout Linux: */
#define MAX(a, b) __extension__ ({      \
        __auto_type _a = (a);           \
        __auto_type _b = (b);           \
        _a > _b ? _a : _b;              \
})
/* Each argument is evaluated exactly once into a temporary. The
   leading underscores avoid capturing a caller's variable named
   `a`. Not ISO C, but available in GCC and Clang.             */

/* Rule 4: why do/while(0) rather than braces alone */
#define LOG(msg) do { timestamp(); puts(msg); } while (0)

if (x) LOG("hi"); else other();
/* With bare braces this would be:
       if (x) { ... };  else other();
   — a stray semicolon before else, which is a syntax error.
   do/while(0) makes the macro a single statement that REQUIRES
   a trailing semicolon, so it composes exactly like a function
   call.                                                       */

Stringification and pasting

Two obscure operators turn macro arguments into text and paste tokens together. They are what make assertion and logging macros possible, and both have a quirk requiring an extra layer of indirection.

#define STR(x)   #x            /* # turns a parameter into a string */
#define XSTR(x)  STR(x)        /* the extra level forces expansion  */

#define VERSION 42
STR(VERSION)     /* "VERSION"  — # does NOT expand its argument */
XSTR(VERSION)    /* "42"       — the outer call expands it first */

/* This two-level idiom is essential and non-obvious. The same
   applies to token pasting:                                    */

#define CAT(a, b)   a##b       /* ## joins two tokens          */
#define XCAT(a, b)  CAT(a, b)

#define PREFIX dev
CAT(PREFIX, _init)     /* PREFIX_init — not expanded           */
XCAT(PREFIX, _init)    /* dev_init                             */

/* A practical use: generating parallel declarations */
#define DEFINE_ACCESSOR(name, type)                     \
        static type get_##name(void) { return name; }   \
        static void set_##name(type v) { name = v; }

DEFINE_ACCESSOR(baud, uint32_t)   /* get_baud / set_baud */

/* And a debug macro that shows both expression and value */
#define TRACE(expr) \
        printf("%s:%d: %s = %d\n", __FILE__, __LINE__, #expr, (expr))
TRACE(x + y);         /* main.c:42: x + y = 7 */

Variadic macros

Macros can take a variable number of arguments, which is what logging macros need. Handling the zero-argument case portably has been awkward for years and is only now properly solved.

#define LOG(fmt, ...) fprintf(stderr, fmt, __VA_ARGS__)
LOG("x=%d\n", x);
LOG("hello\n");        /* ERROR: __VA_ARGS__ is empty, leaving a
                          trailing comma                        */

/* Three fixes, in order of preference: */

/* 1. C23 / C++20: __VA_OPT__ — standard and clean */
#define LOG(fmt, ...) fprintf(stderr, fmt __VA_OPT__(,) __VA_ARGS__)

/* 2. GNU: ##__VA_ARGS__ deletes the preceding comma if empty */
#define LOG(fmt, ...) fprintf(stderr, fmt, ##__VA_ARGS__)

/* 3. Portable: require at least the format, forward the rest */
#define LOG(...) fprintf(stderr, __VA_ARGS__)

/* Counting arguments — a classic trick worth recognising */
#define NARGS(...) NARGS_(__VA_ARGS__, 5, 4, 3, 2, 1, 0)
#define NARGS_(_1, _2, _3, _4, _5, N, ...) N
NARGS(a, b, c)        /* 3 */

Conditional compilation

Conditional compilation is how one source tree targets several platforms — and how it becomes unreadable. The difference is almost entirely a matter of discipline about where the conditionals live.

#if defined(__aarch64__)
        /* ARM64 */
#elif defined(__x86_64__)
        /* x86-64 */
#else
#       error "unsupported architecture"
#endif

#ifdef DEBUG
#       define DBG(...) printf(__VA_ARGS__)
#else
#       define DBG(...) ((void)0)
#endif

/* Prefer #if over #ifdef when the macro has a VALUE — it catches
   the case where the config system defines it to 0:            */
#if CONFIG_FEATURE_X        /* 0 is false; undefined is also false */
#ifdef CONFIG_FEATURE_X     /* TRUE even when defined to 0!        */

/* Useful predefined macros */
__FILE__  __LINE__  __func__  __DATE__  __TIME__
__STDC__  __STDC_VERSION__       /* 201112L = C11, 202311L = C23 */
__GNUC__  __clang__  __ARM_ARCH  __BYTE_ORDER__
__has_include(<threads.h>)       /* C23; GCC/Clang earlier        */
__has_attribute(cleanup)
__has_builtin(__builtin_expect)
Ifdef sprawl is a maintenance disease 
/* BAD: the logic is unreadable and only one branch is ever compiled,
   so the others silently rot.                              */
void send(void)
{
#ifdef LINUX
        write(fd, buf, n);
#elif defined(WINDOWS)
        WriteFile(h, buf, n, &w, NULL);
#endif
}

/* BETTER: isolate platform code behind one interface, implemented
   in separate FILES selected by the build system. Then every
   line compiles on its platform and the logic stays readable. */

/* port.h */
int port_send(const void *buf, size_t n);
/* port_linux.c, port_win.c — chosen in the Makefile */

/* Where a conditional is unavoidable, prefer one that keeps both
   branches compiled: */
if (IS_ENABLED(CONFIG_FEATURE_X))    /* Linux idiom: a real `if`,
        do_x();                         evaluated at compile time,
                                        but both sides type-check  */

Compile-time assertions

Checking an invariant at compile time costs nothing at run time and catches structural mistakes — a struct that grew, a constant that no longer fits — at build time rather than in the field.

#include <assert.h>

/* C11: fails the BUILD, not the program. Free, and enormously
   valuable for layout assumptions.                             */
static_assert(sizeof(struct packet) == 16, "packet layout changed");
static_assert(sizeof(void *) == 8, "64-bit only");
static_assert(CHAR_BIT == 8, "assumes 8-bit bytes");
_Static_assert(offsetof(struct regs, FR) == 0x18, "FR offset");

/* Pre-C11 idiom you will still meet in older code */
#define STATIC_ASSERT(c, name) \
        typedef char static_assert_##name[(c) ? 1 : -1]

/* Put these next to every struct that describes hardware or a wire
   format (chapter 07). A compiler upgrade or an ABI change that
   shifts padding then becomes a build failure instead of a
   runtime mystery.                                              */

X-macros

This technique keeps a list in one place and generates several things from it — an enum, a name table, a dispatch table — so they cannot drift apart. It looks alarming and solves a real maintenance problem.

/* One list, many derived artefacts, guaranteed in sync. This is the
   most useful advanced preprocessor technique.                   */

#define ERROR_LIST                       \
        X(ERR_NONE,    0, "success")     \
        X(ERR_TIMEOUT, 1, "timed out")   \
        X(ERR_NOMEM,   2, "out of memory")

/* generate the enum */
#define X(name, val, str) name = val,
enum error { ERROR_LIST };
#undef X

/* generate the string table from the SAME list */
#define X(name, val, str) [val] = str,
static const char *const error_strings[] = { ERROR_LIST };
#undef X

const char *strerr(enum error e)
{
        return (size_t)e < ARRAY_SIZE(error_strings)
                ? error_strings[e] : "unknown";
}

/* Adding an error is ONE line. The enum and the strings can never
   drift apart — which is exactly the bug this prevents.        */

Macros remain irreplaceable for: include guards, conditional compilation, stringification and pasting, capturing __FILE__/__LINE__ at the call site, X-macros, and anything that must work in a constant expression.

Debugging macros

When a macro misbehaves, the fastest route is to look at what the compiler actually saw after expansion rather than reasoning about what you think it produced.

# the first thing to do, always
gcc -E problem.c | grep -A5 'my_macro'

# clang-format the output to make it readable
gcc -E -P problem.c | clang-format

# see where a macro was defined
gcc -E -dD problem.c | grep 'define MY_MACRO'

# a macro redefined with a different value
gcc -Wall            # -Wmacro-redefined / "redefined" warning

# check a header is self-contained
gcc -fsyntax-only -x c myheader.h

# undefine from the command line
gcc -UDEBUG -DLOG_LEVEL=3
