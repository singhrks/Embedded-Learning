Warps, wavefronts and divergence

Thirty-two threads share one program counter. When an if sends them different ways the hardware does not pick one — it runs both sides, masking off the lanes that should not be there. Understanding exactly when that costs you, and when it does not, is the difference between a fast kernel and a correct one.

Execution masking

   if (threadIdx.x % 2 == 0)  even_work();
   else                       odd_work();

   ONE warp, 32 lanes. 16 want each branch.

     mask 11111111111111111111111111111111   all active
        |
        +-- evaluate the condition -> a 32-bit predicate
        |
     mask 10101010101010101010101010101010   even lanes
        run even_work()          <-- 16 lanes idle, burning
                                     the same cycles
        |
     mask 01010101010101010101010101010101   odd lanes
        run odd_work()           <-- the other 16 idle
        |
     mask 11111111111111111111111111111111   reconverge

   TIME TAKEN = time(even_work) + time(odd_work)
   WORK DONE  = half of it

   The branch was not mispredicted. It was not slow. BOTH
   SIDES SIMPLY RAN, and half your lanes were switched off for
   each. That is divergence.

   THE COST IS THE SUM OF ALL TAKEN PATHS. A switch with 8
   cases hit by different lanes of one warp costs 8x.
Divergence is per-warp, not per-thread

If every lane of a warp takes the same branch, there is no cost at all — the hardware skips the untaken side entirely. A branch on blockIdx.x, or on data that is uniform across 32 consecutive elements, is free. It is only divergence within a warp that hurts. So the question is never "does my kernel branch" but "do adjacent threads branch differently".

Divergent and uniform, side by side

/* DIVERGENT - alternate lanes disagree. Worst case. */
        if (threadIdx.x % 2 == 0) { ... }

/* UNIFORM - the whole warp agrees. FREE. */
        if (blockIdx.x == 0)      { ... }
        if (N > 1024)             { ... }    /* same for all   */

/* UNIFORM BY CONSTRUCTION - the standard trick: branch on
   something that changes only every 32 threads. */
        if ((threadIdx.x / 32) % 2 == 0) { ... }   /* per-warp  */

/* THE BOUNDS CHECK - technically divergent, and free anyway,
   because only the LAST warp of the grid diverges. */
        int i = blockIdx.x * blockDim.x + threadIdx.x;
        if (i < n) c[i] = a[i] + b[i];

/* DATA-DEPENDENT - the real problem, because you cannot see
   it in the source. */
        if (particle[i].alive) simulate(i);
/* If alive/dead are scattered randomly, every warp diverges
   and you pay 2x for ever. If particles are SORTED by
   liveness, whole warps agree and it is free. Same code, same
   data, ten times the difference.                          */

/* A LOOP WITH A DATA-DEPENDENT TRIP COUNT - divergence that
   lasts as long as the longest lane. */
        while (x > threshold) { x = step(x); }
/* The warp runs until the SLOWEST lane finishes. 31 lanes
   idle while one iterates 400 more times.                  */

Removing divergence

/* 1. PREDICATION - for tiny branches, the compiler does it
      for you: compute both, select. No branch at all. */
        y = (x > 0) ? f(x) : g(x);
/* becomes: compute f, compute g, select. Costs both, but no
   branch overhead and no reconvergence. Good when both sides
   are one or two instructions; bad when one side is
   expensive - you now always pay for it.                    */

/* 2. SORT THE DATA so lanes agree. Usually the biggest win
      available. */
        /* before: particles in creation order, alive scattered
           after:  partition alive to the front               */
        int n_alive = partition_by_alive(particles);
        simulate<<<grid(n_alive), 256>>>(particles);
/* Now the whole grid is alive and the branch disappears. The
   sort costs a kernel; the divergence cost every frame.    */

/* 3. STREAM COMPACTION - build a dense index list of the
      items that need work, then launch over that. */
        // pass 1: ballot + prefix sum to compact indices
        // pass 2: kernel over the compacted list
/* This is the general form of (2) and the standard answer for
   ray tracing, sparse grids and particle systems.          */

/* 4. SEPARATE KERNELS per case, when the cases are big and
      known in advance. Two uniform kernels beat one divergent
      one, even with two launches.                           */

/* 5. RESTRUCTURE INDEXING so that consecutive lanes handle
      consecutive similar work. Often as simple as swapping
      which dimension maps to threadIdx.x.                   */

/* 6. PERSISTENT THREADS + a work queue. Each warp pulls the
      next item when it finishes, so a long-running lane does
      not stall a whole block. Complex, but the standard answer
      for highly irregular workloads.                        */
Do not fight divergence you do not have

A branch that every lane of a warp takes together is free, and branch-free tricks (bit twiddling, arithmetic selects) cost real instructions. Measure the divergence first — Nsight Compute reports branch efficiency and warp execution efficiency directly. Rewriting a uniform branch into branch-free arithmetic is a pure loss, and it happens constantly.

Reconvergence, and the deadlock it used to cause

   The hardware must know where diverged lanes rejoin. It
   tracks this with a stack of (mask, reconvergence-PC) pairs.

     push  (else-mask, PC-after-if)
     run   the if-body with the if-mask
     pop   -> restore else-mask, jump to else
     run   the else-body
     pop   -> full mask, continue at PC-after-if

   PRE-VOLTA this stack was PER WARP, and reconvergence was
   forced at the immediate post-dominator. Consequence:

        if (lane == 0) {
                while (atomicCAS(&lock, 0, 1) != 0) ;   /* spin */
                critical();
                atomicExch(&lock, 0);
        }
   Lane 0 acquires the lock. The other 31 lanes are masked off
   at the SAME PC, waiting to reconverge. Lane 0 proceeds,
   releases - fine. But reverse it:

        while (atomicCAS(&lock, 0, 1) != 0) ;
   with several lanes competing: one lane wins and wants to
   move on; the losers are still in the loop. The warp cannot
   be in two places, so the winner is held back at the loop,
   which means it never releases the lock. DEADLOCK, in code
   that is obviously correct on a CPU.

   VOLTA+ gives each thread its own PC, so the winner really
   can proceed. That is why the change was made, and why any
   intra-warp locking on old hardware is a trap.

   The trade: reconvergence is no longer guaranteed at the
   post-dominator, so you must call __syncwarp() where you
   need it.

Measuring it

# Nsight Compute - the two metrics that matter.
$ ncu --metrics \
    smsp__thread_inst_executed_per_inst_executed.ratio,\
    smsp__sass_average_branch_targets_threads_uniform.pct \
    ./app

  smsp__thread_inst_executed_per_inst_executed.ratio   18.4
# "average active threads per issued instruction", out of 32.
# 32.0 = perfect. 18.4 means you are wasting ~43% of every
# instruction issue.

  ...branch_targets_threads_uniform.pct                61.2%
# fraction of branches where the whole warp agreed.

# Source-level attribution, which is what you actually want:
$ ncu --set full --import-source yes -o report ./app
$ ncu-ui report.ncu-rep
# the source view colours each line by divergence.

# AMD:
$ rocprof --stats ./app

# DX12 / HLSL: PIX and RenderDoc both show wave occupancy and
# divergence per draw. Nsight Graphics does the same for
# Vulkan and DX12.

# THE CHEAP ESTIMATE, if you have no profiler: comment out the
# divergent branch (take one side unconditionally, accept the
# wrong answer) and time it. The gap is your divergence cost.

Warp width is not always 32

VendorWidthNote
NVIDIA32Stable since 2006; warpSize is still a variable, do not hardcode
AMD GCN64Divergence costs twice as much per branch
AMD RDNA32 or 64Wave32 by default for graphics, wave64 available; the compiler chooses
Intel Xe8, 16 or 32Chosen per shader by the compiler — SIMD8 for register-heavy shaders
ARM Mali4–16Much narrower, so divergence is far cheaper; older Mali is effectively scalar
Apple32SIMD group

Write portable code with WaveGetLaneCount() (HLSL), gl_SubgroupSize (Vulkan) or warpSize (CUDA), and never assume 32 in a loop bound. A reduction hardcoded to five shuffle steps is silently wrong on a 64-wide wavefront.
