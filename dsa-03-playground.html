The playground: write and run code

A scratch pad that runs in this page. Use it to try an idea, trace an algorithm with console.log, or check a language detail without leaving the site.

Scratch pad

Write anything and press Run (or Ctrl/⌘+Enter). Output from console.log appears below. Your code is saved in this browser, so it survives a reload.

Built-in helpers

Linked lists and trees are pre-defined in the sandbox, on this page and inside every problem, so you never have to write the plumbing:

/* --- LINKED LISTS --- */
function ListNode(val, next)      // constructor
buildList([1,2,3])                // array  -> list, returns head
listToArray(head)                 // list   -> array

/* --- BINARY TREES (level-order, null for a missing child) --- */
function TreeNode(val, left, right)
buildTree([3,9,20,null,null,15,7])   // array -> tree, returns root
treeToArray(root)                    // tree  -> array

/* EXAMPLE — reverse a list and print it: */
const head = buildList([1,2,3,4,5]);
let prev = null, cur = head;
while (cur) { const nx = cur.next; cur.next = prev; prev = cur; cur = nx; }
console.log(listToArray(prev));     // [5,4,3,2,1]

/* EXAMPLE — the tree [3,9,20,null,null,15,7] is:
        3
       / \
      9  20
         / \
        15  7                                        */
const root = buildTree([3,9,20,null,null,15,7]);
function depth(n) { return n ? 1 + Math.max(depth(n.left), depth(n.right)) : 0; }
console.log('depth =', depth(root));      // 3

How the runner works

Knowing what runs your code, and what it does not do for you, saves a lot of confusion the first time something behaves unexpectedly.

   YOUR CODE ---> a Web Worker (a separate thread)
                       |
                       |  runs the test harness
                       |  captures console.log
                       |  4-second timeout
                       v
                  results back to the page

   WHY A WORKER:
     · an INFINITE LOOP cannot freeze the page — the worker
       is terminated after 4 seconds and you get a clear
       message instead of a dead tab
     · your code cannot touch the page
     · console.log is captured rather than lost

   IF WORKERS ARE UNAVAILABLE — which happens when the site
   is opened directly from disk with a file:// URL in some
   browsers — the runner FALLS BACK to executing on the main
   thread. Everything still works, with one caveat: an
   infinite loop will freeze the tab and you will have to
   close it. Serving the site over http (even
   `python -m http.server`) avoids that entirely.

   WHAT IS NOT HERE, and honestly:
     · NO C++, Python or Java execution. Running those needs
       a compiler toolchain or a multi-megabyte WebAssembly
       runtime downloaded from a CDN, which would break the
       offline, no-dependency design of this site.
       Reference solutions are given in all four languages
       on every problem; the JUDGE runs JavaScript.
     · no file I/O, no network, no npm packages.
     · no stdin. Problems pass arguments to a function
       rather than reading input, which is also how
       LeetCode-style interviews work.

   IF YOUR TARGET LANGUAGE IS C++ OR JAVA: read the
   reference solution in your language, then type the
   JavaScript. For these problems the algorithm is the whole
   content and the syntax gap is small. Practise the real
   syntax separately in your own editor before the
   interview.

JavaScript for people who write C++ or Java

Every problem here can be solved in JavaScript, and the syntax you need is smaller than you would expect. This is the whole of it, written for someone whose instincts come from another language.

/* Enough to solve every problem in this track. */

/* --- ARRAYS --- */
const a = [1, 2, 3];
a.length                      // size
a.push(4); a.pop();           // back:  O(1)
a.unshift(0); a.shift();      // front: O(n)  <-- AVOID IN LOOPS
a.slice(1, 3)                 // copy of [1,3)   — non-destructive
a.splice(1, 2)                // REMOVE 2 items at index 1 — mutates
new Array(n).fill(0)          // n zeros
Array.from({length: n}, (_, i) => i)          // [0..n-1]
Array.from({length: r}, () => new Array(c).fill(0))   // r x c grid

/* THE 2-D ARRAY TRAP: */
new Array(3).fill([])         // WRONG — three refs to the SAME array
Array.from({length: 3}, () => [])   // right — three distinct arrays

/* --- SORTING: THE #1 JAVASCRIPT BUG --- */
[10, 9, 1].sort()                  // ["1","10","9"] — LEXICOGRAPHIC!
[10, 9, 1].sort((x, y) => x - y)   // [1, 9, 10] — always pass a comparator
arr.sort((p, q) => p[0] - q[0] || q[1] - p[1]);   // by [0] asc, then [1] desc

/* --- MAP AND SET --- */
const m = new Map();
m.set(k, v); m.get(k); m.has(k); m.delete(k); m.size;
m.get(k) ?? 0                 // default when absent
for (const [k, v] of m) {}
const s = new Set([1, 2, 2]); // size 2
s.add(3); s.has(1); s.delete(1);
[...s]                        // Set -> array

/* A PLAIN OBJECT works for string keys, but Map keeps
   INSERTION ORDER, allows ANY key type, and has O(1) size.
   Prefer Map. */

/* --- STRINGS are immutable --- */
s[i]  s.charCodeAt(i)  s.split('')  arr.join('')
s.slice(1, 4)   s.toLowerCase()
// building a string in a loop with += is O(n^2) in the
// worst case — push to an array and join once.

/* --- NUMBERS --- */
Math.floor(7 / 2)   // 3   — / is FLOAT division, unlike C++ int/int
(7 / 2) | 0         // 3   — fast truncation, but 32-bit only
Math.trunc(-3.5)    // -3  — toward zero
Math.floor(-3.5)    // -4  — toward -infinity  (they DIFFER for
                    //       negatives — a real source of bugs)
Number.MAX_SAFE_INTEGER   // 2^53 - 1; beyond this use BigInt
Infinity, -Infinity       // handy initial values for min/max

/* --- DESTRUCTURING AND SWAP --- */
[a[i], a[j]] = [a[j], a[i]];
const [lo, hi] = [0, n - 1];

/* --- THE EQUALITY RULE: ALWAYS USE === --- */
0 == '0'    // true   — do not use
0 === '0'   // false  — use this

/* --- COMMON IDIOMS --- */
const freq = new Map();
for (const c of s) freq.set(c, (freq.get(c) ?? 0) + 1);

const seen = new Set();
if (!seen.has(x)) { seen.add(x); }

let best = -Infinity;
for (const v of a) best = Math.max(best, v);

// a grid of visited flags
const vis = Array.from({length: R}, () => new Array(C).fill(false));

How it shows up

SymptomCause
Sorting gives [1, 10, 9]Default sort is lexicographic — pass (a,b)=>a-b
All rows of a grid change togetherfill([]) shares one array — use Array.from
Loop is unexpectedly O(n²)shift()/unshift() or += on strings inside the loop
Negative division off by oneMath.floor vs Math.trunc differ for negatives
Large integers lose precisionPast 253 — use BigInt
"No function named X was defined"Renamed the function, or wrapped it in a class
Timed out after 4 sInfinite loop — a pointer that never advances
Tab freezes instead of timing outRunning from file:// with no Worker support — serve over http
Output emptyNothing was logged — the runner shows console.log, not return values
