Textures, samplers and compression

Textures are the largest thing in memory and the largest source of bandwidth in most frames. The hardware gives you filtering, mip selection and decompression for free — provided you set up half a dozen things correctly, each of which has a characteristic artefact when you do not.

What a sample actually does

   Texture.Sample(sampler, uv) is not a memory read. It is a
   fixed-function unit doing five things:

   1. ADDRESS      apply the wrap mode to uv
                   (wrap / clamp / mirror / border)

   2. MIP SELECT   from ddx(uv), ddy(uv) - the derivatives
                   from the 2x2 quad (chapter 7) - compute how
                   many texels fall in one pixel, and pick the
                   level where that ratio is ~1.

   3. FETCH        read 4 texels (bilinear) from level N, and
                   4 more from level N+1 if trilinear

   4. DECOMPRESS   BC/ASTC blocks are decoded in hardware, for
                   free, at full rate

   5. FILTER       blend the 4 (or 8) samples

   A trilinear anisotropic 16x sample can read 128 texels. It
   is one instruction in your shader and a great deal of work
   in the texture unit - which is why texture-bound is such a
   common state, and why the SAMPLER settings matter as much
   as the shader.

Mipmaps

/* A chain of half-size images. Level 0 is full resolution,
   level 1 is half, and so on to 1x1.

   COST: +33% memory.        1 + 1/4 + 1/16 + ... = 4/3
   BENEFIT: enormous, and in two ways.                     */

/* 1. CORRECTNESS. Without mips, a surface at a distance where
      one pixel covers 16 texels samples ONE of those 16 at
      random. As the camera moves, WHICH one changes -> the
      texture crawls and shimmers. This is the single most
      visible aliasing artefact in real-time graphics.

   2. PERFORMANCE. Without mips, adjacent pixels sample texels
      far apart, so the texture cache misses constantly. WITH
      mips, a distant surface reads a small image that fits in
      cache. Mips often make distant geometry SEVERAL TIMES
      faster, not just prettier.

   MIP SELECTION uses the derivatives, which is why:
     - implicit-mip sampling in divergent flow is undefined
       (chapter 7)
     - a shader that computes uv from a branch may pick the
       wrong level and produce a visible seam
     - SampleLevel() with a hardcoded 0 disables all of this,
       reintroducing shimmer AND the cache misses. Use it only
       when you genuinely want level 0.                     */

/* MIP BIAS: nudge the selection. */
        tex.SampleBias(s, uv, -0.5);   /* sharper, more aliased */
        tex.SampleBias(s, uv, +1.0);   /* blurrier, cheaper     */
/* A slight negative bias is standard when using TAA, because
   temporal accumulation restores the detail while suppressing
   the aliasing.                                            */
Generate mips offline, not at load time

A proper offline chain uses a good filter (Kaiser or similar), can be gamma-correct, and handles normal maps specially — renormalising after downsampling, because averaging unit vectors does not produce a unit vector. Runtime GenerateMips is a box filter in linear space applied to whatever you give it, which makes normal maps flatten and sRGB textures darken as they recede. It is fine for a prototype and wrong for a product.

/* WHY ANISOTROPIC EXISTS

   A floor stretching to the horizon: one pixel covers a
   footprint that is 1 texel wide and 16 texels long.

   Isotropic mip selection must pick ONE level. It picks based
   on the LONGEST axis, so it chooses a level 16x too blurry -
   and the floor turns to mush in the distance. Choose by the
   shortest axis instead and it shimmers violently.

   Anisotropic filtering takes several samples ALONG the long
   axis at the sharper mip level. Correct in both directions.

   16x anisotropic typically costs a few percent of frame time
   and is the most visible quality setting in any game. Enable
   it.                                                       */

D3D12_SAMPLER_DESC s = {};
s.Filter         = D3D12_FILTER_ANISOTROPIC;
s.MaxAnisotropy  = 16;
s.AddressU       = D3D12_TEXTURE_ADDRESS_MODE_WRAP;
s.AddressV       = D3D12_TEXTURE_ADDRESS_MODE_WRAP;
s.AddressW       = D3D12_TEXTURE_ADDRESS_MODE_WRAP;
s.MipLODBias     = 0.0f;
s.MinLOD         = 0.0f;
s.MaxLOD         = D3D12_FLOAT32_MAX;    /* NOT 0 - a very
                                            common typo that
                                            disables mips
                                            entirely          */

/* COMPARISON SAMPLERS - for shadow maps. The hardware does
   the depth compare AND the bilinear filter in one go, giving
   free 2x2 percentage-closer filtering: */
s.Filter         = D3D12_FILTER_COMPARISON_MIN_MAG_LINEAR_MIP_POINT;
s.ComparisonFunc = D3D12_COMPARISON_FUNC_LESS_EQUAL;
        /* HLSL: shadowMap.SampleCmpLevelZero(cmpSampler, uv, z) */

Block compression

   Textures are stored compressed and decoded IN THE TEXTURE
   UNIT, for free, on every sample. This is not a load-time
   decompression - the compressed data stays compressed in
   VRAM, so it saves memory AND bandwidth AND cache space, all
   at once. It is the highest-leverage decision in your asset
   pipeline.

   Fixed 4x4 blocks, fixed bits per block -> random access.

   DESKTOP (BC / DXT / S3TC)
     BC1   0.5 B/texel  RGB + 1-bit alpha   8:1   albedo
     BC3   1.0 B/texel  RGBA               4:1   albedo+alpha
     BC4   0.5 B/texel  single channel     -     height, mask
     BC5   1.0 B/texel  two channels       -     NORMAL MAPS
     BC6H  1.0 B/texel  HDR RGB (float)    -     env maps
     BC7   1.0 B/texel  high-quality RGBA  4:1   everything
                                                 modern

   MOBILE
     ETC2  0.5-1 B/texel   the Android baseline
     ASTC  0.9-8 bpp       variable block size, best quality
                           per bit available anywhere

   THE RULES

   * NORMAL MAPS USE BC5, not BC7 or BC3. BC5 stores two
     channels at high precision; reconstruct z in the shader:
         n.xy = tex.Sample(s, uv).rg * 2 - 1;
         n.z  = sqrt(saturate(1 - dot(n.xy, n.xy)));
     Using a three-channel format for a normal map wastes bits
     on a channel you can derive, and BC1's colour-space
     assumptions produce visible blocking on normals.

   * sRGB IS PART OF THE FORMAT. Use BC7_UNORM_SRGB for
     albedo so the hardware converts to linear for free on
     every sample. Doing the conversion in the shader is
     slower and wrong for filtering - the hardware filters in
     linear space, which is correct; shader conversion
     filters in sRGB space, which is not.

   * NEVER compress data that is not colour. Masks, IDs,
     lookup tables and anything you index with must be
     uncompressed or BC4 - block compression is lossy and
     interpolates across block boundaries.
Compressing a normal map with BC1 or BC7

The classic asset-pipeline bug. BC1 and BC7 are designed around perceptual colour and will happily introduce blocky artefacts in the X and Y of a normal — which show up as faceted, shimmering lighting on smooth surfaces that looks like a shader bug. BC5 exists for exactly this. If lighting looks blocky and the geometry is smooth, check the normal map's format before anything else.

Memory and streaming

/* THE ARITHMETIC that decides whether your game fits in VRAM. */

  4096 x 4096 RGBA8, uncompressed .... 64 MB   (+33% mips = 85)
  4096 x 4096 BC7 .................... 16 MB   (+mips = 21)
  4096 x 4096 BC1 .................... 8 MB    (+mips = 11)

  200 such textures, uncompressed .... 17 GB   impossible
  200 such textures, BC7 ............. 4.2 GB  plausible
  200 such textures, BC7 + streaming . ~1 GB   what ships

/* STREAMING: keep only the mip levels you need resident.

   A texture on a distant object needs only its 64x64 mip -
   16 KB instead of 21 MB. The standard system:
     1. every frame, work out the desired mip per texture,
        either from a feedback buffer or from distance
     2. asynchronously load missing levels
     3. evict levels nobody wants

   DX12 gives you RESERVED (tiled) RESOURCES for this: a
   texture whose pages are mapped individually, so you can
   have a 16K x 16K texture with only the visible tiles
   resident. Vulkan calls them sparse resources.

   SAMPLER FEEDBACK (DX12 Ultimate) makes the GPU tell you
   which tiles were actually sampled, which removes the
   guesswork.                                              */

/* AND THE PRACTICAL ADVICE: measure with a tool, not by
   adding up your assets. */
$ # PIX on Windows: memory view shows per-resource residency
$ # RenderDoc: resource inspector, and the texture viewer
$ #   shows the actual format and mip chain
$ nvidia-smi                       # total VRAM in use
