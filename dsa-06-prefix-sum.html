Arrays: prefix sums and difference arrays

Precompute once so every range query is O(1). The technique that rescues you when a sliding window fails because the array contains negative numbers.

The pattern

One precomputed array turns every range-sum question into a single subtraction. The only detail that matters is where the array starts, and it is the source of nearly every bug in the pattern.

   PREFIX SUM: P[i] = sum of the first i elements.

     a =      [ 3,  1,  4,  1,  5 ]
     P = [ 0,   3,  4,  8,  9, 14 ]
          ^
          P[0] = 0, the EMPTY prefix — always include it

   THEN THE SUM OF ANY RANGE IS ONE SUBTRACTION:

     sum(a[l..r])  =  P[r+1] - P[l]

     sum(a[1..3]) = P[4] - P[1] = 9 - 3 = 6   (1+4+1) ✓

   BUILD O(n) ONCE, then EVERY QUERY IS O(1). Without it,
   q queries cost O(n·q).

   THE OFF-BY-ONE IS THE WHOLE DIFFICULTY. Using a
   1-INDEXED prefix array of length n+1 makes it disappear:
   P[i] means "sum of the first i elements", so P[0] = 0
   needs no special case and l = 0 works naturally.

   ---------------------------------------------------------

   DIFFERENCE ARRAY — the mirror image. Use it for RANGE
   UPDATES with a single query at the end.

     to add v to a[l..r]:
         D[l]   += v
         D[r+1] -= v          <-- one operation, not r-l+1

     after all updates, PREFIX-SUM D to recover the array.

     add 5 to [1..3] of a zero array of length 5:
        D = [0, 5, 0, 0, -5]
        prefix sums -> [0, 5, 5, 5, 0]  ✓

   m updates in O(m), one reconstruction in O(n), instead of
   O(m·n).

   ---------------------------------------------------------

   WHICH TO USE:
     many RANGE QUERIES, no updates      -> PREFIX SUM
     many RANGE UPDATES, one final read  -> DIFFERENCE ARRAY
     both, interleaved                   -> a Fenwick tree
                                            or segment tree

   AND THE COMBINATION THAT SOLVES THE HARD PROBLEMS:
   PREFIX SUM + HASH MAP. When you need a range with a
   particular property and the values can be negative, store
   each prefix sum you have seen and look up the one you
   need (chapter 14's Subarray Sum Equals K).

When to reach for it

Repeated range-sum queries

"Sum between i and j" asked many times. Build once, answer in O(1).

Subarray sum with negatives

A sliding window needs monotonicity. Negatives break it — use prefix sums plus a hash map.

"Divisible by k", "equal counts"

Map the property onto a prefix value: remainder, or +1/−1 balance.

Many range increments

Difference array: two writes per update, one reconstruction.

2-D region sums

Inclusion–exclusion on a 2-D prefix table.

Running product / XOR

Any associative, invertible operation works the same way.

/* --- BUILD --- */
const P = new Array(a.length + 1).fill(0);
for (let i = 0; i < a.length; i++) P[i + 1] = P[i] + a[i];
// range [l, r] inclusive:  P[r + 1] - P[l]

/* --- 2-D PREFIX SUM, inclusion–exclusion --- */
//  P[i+1][j+1] = a[i][j] + P[i][j+1] + P[i+1][j] - P[i][j]
//                                                  ^ added twice
//  sum of rectangle (r1,c1)..(r2,c2):
//    P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]

/* --- THE PREFIX + HASH MAP SHAPE --- */
const seen = new Map([[0, -1]]);   // prefix value -> earliest index
let running = 0;
for (let i = 0; i < a.length; i++) {
    running += a[i];
    const key = f(running);         // the property you care about
    if (seen.has(key)) best = Math.max(best, i - seen.get(key));
    else seen.set(key, i);          // KEEP THE EARLIEST index only
}
/* STORING ONLY THE FIRST OCCURRENCE gives the LONGEST range.
   Storing counts instead gives the NUMBER of ranges
   (chapter 14). Which one you need decides the map's value
   type — get this backwards and the answer is subtly wrong. */

Problems

How it shows up

SymptomCause
Off by one on every rangeMixing 0-indexed and 1-indexed prefix conventions
Ranges starting at 0 are wrongMissing the P[0] = 0 entry
Sliding window gives the wrong answerArray has negatives — switch to prefix sums
Longest range too shortOverwrote the map entry — keep the earliest index
Count of ranges too smallStored an index where a count was needed
Negative remainder in a modulo problem((x % k) + k) % k — JS % keeps the sign
2-D sums double-countForgot to add back the doubly-subtracted corner
Difference array off by one at the endD needs length n+1 for r+1
