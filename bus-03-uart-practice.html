UART in practice: flow control, DMA and ring buffers

The frame from the previous chapter is the easy part. Making a UART link that does not drop bytes under load, recovers from a peer that disappears, and finds message boundaries in a byte stream is the engineering — and it is the same work for every stream protocol you will meet.

Why bytes get lost

   A UART has ONE receive holding register (or a shallow
   FIFO). At 115200 baud a byte arrives every 87 us. If your
   software has not read the previous byte by then, it is
   OVERWRITTEN and the OVERRUN flag sets.

   87 us is a long time - about 14,000 cycles at 168 MHz -
   which is why interrupt-per-byte works fine at this rate.

   At 3 Mbaud a byte arrives every 3.3 us: 550 cycles. An
   ISR with a 12-cycle entry, a prologue, a ring-buffer
   write and an exit is perhaps 40 cycles, so it still fits
   - until something disables interrupts for 10 us. Then you
   lose three bytes and the protocol desynchronises.

   WHAT DISABLES INTERRUPTS LONG ENOUGH TO HURT:
     - a flash write or erase (can stall the bus for MS)
     - a long critical section in another driver
     - a higher-priority ISR doing too much
     - a debugger halting the core

   THE FIX IS NOT "OPTIMISE THE ISR". It is DMA, which
   removes software from the per-byte path entirely. Once
   the DMA controller is writing to memory, an interrupt
   disabled for 10 us costs you nothing at all.

The ring buffer, done right

/* Single producer (ISR), single consumer (task). Power-of-
   two size so the mask is free. No lock needed - the
   argument is in the mcu track, chapter 17.               */

#define RXSZ 512                       /* MUST be 2^n       */
typedef struct {
    uint8_t  buf[RXSZ];
    volatile uint16_t head;            /* written by ISR    */
    volatile uint16_t tail;            /* written by task   */
    volatile uint32_t dropped;
} ring_t;

static inline int ring_put(ring_t *r, uint8_t c)
{
    uint16_t next = (uint16_t)((r->head + 1u) & (RXSZ - 1u));
    if (next == r->tail) {
        r->dropped++;                  /* COUNT it          */
        return -1;
    }
    r->buf[r->head] = c;
    r->head = next;                    /* publish AFTER     */
    return 0;
}

static inline int ring_get(ring_t *r, uint8_t *c)
{
    if (r->tail == r->head) { return -1; }
    *c = r->buf[r->tail];
    r->tail = (uint16_t)((r->tail + 1u) & (RXSZ - 1u));
    return 0;
}

/* THREE THINGS THAT MAKE THIS CORRECT:

   1. head is published AFTER the data byte is stored. The
      consumer therefore never sees an index for a byte not
      yet written.

   2. The buffer is full when next == tail, which wastes one
      slot but avoids the ambiguity of head == tail meaning
      both empty and full. The alternative - a separate
      count - is a variable BOTH sides write, and needs a
      lock.

   3. dropped is counted, not ignored. A link that silently
      discards data under load is unbudgetable; one that
      reports it tells you exactly how much bigger the
      buffer needs to be.

   SIZING: buffer must cover the longest time the consumer
   can be delayed, times the byte rate.
     115200 baud = 11.5 bytes/ms
     consumer delayed up to 20 ms
     -> 230 bytes minimum. Round up to 512.               */

Circular DMA plus IDLE: the design worth memorising

/* This combination receives continuously, at any rate, with
   no per-byte software, AND tells you where messages end.
   It is the standard answer for a serious UART link.      */

static uint8_t dma_buf[512];
static uint16_t last_pos;

void uart_dma_rx_init(void)
{
    /* Circular DMA: NDTR reloads and the address wraps. */
    DMA1_Stream5->PAR  = (uint32_t) &USART2->RDR;
    DMA1_Stream5->M0AR = (uint32_t) dma_buf;
    DMA1_Stream5->NDTR = sizeof(dma_buf);
    DMA1_Stream5->CR   = (4u << 25) | DMA_SxCR_MINC
                       | DMA_SxCR_CIRC | DMA_SxCR_TCIE
                       | DMA_SxCR_HTIE;
    DMA1_Stream5->CR  |= DMA_SxCR_EN;

    USART2->CR3 |= USART_CR3_DMAR;
    USART2->CR1 |= USART_CR1_IDLEIE;   /* THE KEY PIECE     */
}

/* IDLE fires when the line has been quiet for one full
   character time after data. That is exactly "the message
   ended", for any protocol with gaps between messages.   */
void USART2_IRQHandler(void)
{
    if (USART2->ISR & USART_ISR_IDLE) {
        USART2->ICR = USART_ICR_IDLECF;
        uart_process_upto(sizeof(dma_buf) - DMA1_Stream5->NDTR);
    }
}

/* NDTR counts DOWN from the buffer size, so
     bytes_written_so_far = size - NDTR
   and the new data is everything between last_pos and that
   position, handling the wrap.                            */
static void uart_process_upto(uint16_t pos)
{
    if (pos == last_pos) { return; }

    if (pos > last_pos) {
        parse(&dma_buf[last_pos], pos - last_pos);
    } else {                                  /* wrapped    */
        parse(&dma_buf[last_pos], sizeof(dma_buf) - last_pos);
        if (pos > 0) { parse(&dma_buf[0], pos); }
    }
    last_pos = pos;
}

/* Also call uart_process_upto from the DMA half-transfer
   and transfer-complete interrupts, so a message longer
   than half the buffer is processed before it is
   overwritten. Three interrupt sources, one function.

   RESULT: zero per-byte CPU, message boundaries detected in
   hardware, and a link that survives the CPU being busy for
   milliseconds. This handles 3 Mbaud comfortably on a part
   that could not manage 921600 with per-byte interrupts.  */
IDLE detection is the answer to "how do I know the message ended?"

A UART is a byte stream with no framing above the character. Every protocol on top must delimit messages somehow, and there are only four options: a fixed length, a length field near the start, a terminator byte, or a timing gap. IDLE detection implements the last of these in hardware, for free, and it is why Modbus RTU (chapter 14) specifies a 3.5-character silent interval as its frame delimiter — it was designed for exactly this mechanism.

Flow control

   HARDWARE (RTS/CTS) - two extra wires, and the only kind
   that works reliably.

     Device A                    Device B
     RTS (out) ----------------> CTS (in)
     CTS (in)  <---------------- RTS (out)

     "RTS" now means "I am Ready To Receive" (the name is
     historical and misleading). A drives RTS low when its
     buffer has room; B's UART checks CTS before starting
     each character and pauses if it is high.

     ENTIRELY IN HARDWARE once enabled:
       USART1->CR3 |= USART_CR3_RTSE | USART_CR3_CTSE;

     The peripheral asserts RTS from its own FIFO level, so
     it works even if your software is completely stalled.
     This is the only flow control that survives a
     millisecond-long interrupt lockout.

   SOFTWARE (XON/XOFF) - in-band, no extra wires.
     Receiver sends 0x13 (XOFF) to pause, 0x11 (XON) to
     resume. Problems:
       - those two byte values can never appear in your data,
         so it is unusable for binary
       - the XOFF itself takes a character time to send and
         another to be noticed, so several bytes still
         arrive after it
       - if XON is lost, the link deadlocks permanently
     Use only with legacy equipment that requires it.

   NONE - the default, and correct when the receiver is
     always faster than the sender, or the protocol has its
     own acknowledgement and retry at a higher layer.

Making the link survive reality

/* Four things that separate a driver that works on the
   bench from one that works in a cabinet for five years. */

/* 1. NEVER BLOCK FOREVER. */
int uart_send(const uint8_t *p, size_t n, uint32_t timeout_ms)
{
    uint32_t deadline = g_ms + timeout_ms;
    while (n--) {
        while (!(USART2->ISR & USART_ISR_TXE)) {
            if ((int32_t)(g_ms - deadline) >= 0) { return -ETIMEDOUT; }
        }
        USART2->TDR = *p++;
    }
    return 0;
}

/* 2. RECOVER FROM ERRORS, DO NOT JUST COUNT THEM.
      An overrun on some parts BLOCKS further reception
      until cleared. If your error path forgets to clear it,
      the link dies permanently after the first burst.     */
static void uart_error_recover(void)
{
    uint32_t isr = USART2->ISR;
    if (isr & (USART_ISR_ORE|USART_ISR_FE|USART_ISR_NE|USART_ISR_PE)) {
        USART2->ICR = USART_ICR_ORECF | USART_ICR_FECF
                    | USART_ICR_NECF  | USART_ICR_PECF;
        (void) USART2->RDR;
        stats.resyncs++;
        parser_reset();          /* the stream is desynced  */
    }
}

/* 3. RESYNCHRONISE THE PARSER. After any error the byte
      stream has lost alignment. A parser that keeps its
      state machine across an error will mis-frame every
      subsequent message. Reset to hunting-for-header.     */

/* 4. TIME OUT A PARTIAL MESSAGE. If a header arrives and
      the rest never does, the parser must not wait
      indefinitely holding a buffer.                       */
if (parser.state != HUNTING &&
    (int32_t)(g_ms - parser.started_ms - 100) >= 0) {
    stats.partial_timeouts++;
    parser_reset();
}

/* Every one of these four is learned the hard way. A UART
   link with no timeout, no error recovery, no resync and
   no partial-message timeout will work perfectly until the
   day a connector is jostled, and then stay broken until
   someone power-cycles it.                                */

How it shows up

SymptomCause

Every message after an error is mis-framedParser state not reset on error

Ring buffer occasionally corruptHead published before the data, or two producers
