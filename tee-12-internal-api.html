The TA Internal Core API in depth

Inside a trusted application there is no libc, no filesystem, no sockets and no printf — there is one specified API covering memory, cryptography, storage, time and arithmetic. It is deliberately small and deliberately awkward in places; this chapter is the whole of it, organised by what you actually reach for.

The five entry points

A trusted application is defined by the entry points it exports. The framework calls them at defined moments, and their signatures are fixed by the standard rather than by you.

/* Every TA implements exactly these. They are the TA's whole
   interface to the world.                                    */

TEE_Result TA_CreateEntryPoint(void)
{
        /* Called ONCE, when the TA is loaded into memory,
           before any session exists. Initialise global state.
           Returning an error prevents the TA loading at all. */
        DMSG("has been called");
        return TEE_SUCCESS;
}

void TA_DestroyEntryPoint(void)
{
        /* Called once, when the last session closes and the TA
           is unloaded. Free global state. Cannot fail.       */
}

TEE_Result TA_OpenSessionEntryPoint(uint32_t param_types,
                                    TEE_Param params[4],
                                    void **sess_ctx)
{
        /* Once per client session. Allocate per-session state
           and store the pointer in *sess_ctx - it comes back
           on every later call for this session.

           params[] are whatever the client passed to
           TEEC_OpenSession. Check param_types here too.      */
        struct my_session *s = TEE_Malloc(sizeof *s, 0);
        if (!s)
                return TEE_ERROR_OUT_OF_MEMORY;
        *sess_ctx = s;
        return TEE_SUCCESS;
}

void TA_CloseSessionEntryPoint(void *sess_ctx)
{
        TEE_Free(sess_ctx);
}

TEE_Result TA_InvokeCommandEntryPoint(void *sess_ctx,
                                      uint32_t cmd_id,
                                      uint32_t param_types,
                                      TEE_Param params[4])
{
        /* THE REAL WORK. One switch on cmd_id.              */
        switch (cmd_id) {
        case CMD_SIGN:   return do_sign(sess_ctx, param_types, params);
        case CMD_VERIFY: return do_verify(sess_ctx, param_types, params);
        default:         return TEE_ERROR_NOT_SUPPORTED;
        }
}

Memory

Memory inside a trusted application comes with the obligation to check every buffer that arrived from outside — and the API provides the function that performs exactly that check.

/* hint:
     TEE_MALLOC_FILL_ZERO   (0)  zeroed. The default, and what

     TEE_USER_MEM_HINT_NO_FILL_ZERO   uninitialised, faster   */

/* TEE_MemCompare is NOT constant time. For comparing a MAC or
   a password against a stored value, that is a timing oracle.
   Write your own:                                            */

static bool ct_equal(const uint8_t *a, const uint8_t *b, size_t n)
{
        uint8_t diff = 0;
        for (size_t i = 0; i < n; i++)
                diff |= a[i] ^ b[i];
        return diff == 0;
}

Cryptography

The cryptographic API is deliberately object-based: allocate, initialise, use, free. That shape is what allows an implementation to back it with hardware transparently.

   allocate and populate an OBJECT for the key, attach one to
   the other, then init/update/final.                        */

/* A complete AES-GCM encrypt, showing the shape end to end. */

static TEE_Result encrypt(const uint8_t *key, size_t keylen,
                          const uint8_t *nonce, size_t noncelen,
                          const uint8_t *pt, size_t ptlen,
                          uint8_t *ct, size_t *ctlen,
                          uint8_t *tag, size_t *taglen)
{
        TEE_OperationHandle op = TEE_HANDLE_NULL;
        TEE_ObjectHandle    ko = TEE_HANDLE_NULL;
        TEE_Attribute       attr;
        TEE_Result          res;

        res = TEE_AllocateOperation(&op, TEE_ALG_AES_GCM,
                                    TEE_MODE_ENCRYPT, keylen * 8);
        if (res) goto out;

        res = TEE_AllocateTransientObject(TEE_TYPE_AES,
                                          keylen * 8, &ko);
        if (res) goto out;

        TEE_InitRefAttribute(&attr, TEE_ATTR_SECRET_VALUE,
                             key, keylen);
        res = TEE_PopulateTransientObject(ko, &attr, 1);
        if (res) goto out;

        res = TEE_SetOperationKey(op, ko);
        if (res) goto out;

        res = TEE_AEInit(op, nonce, noncelen, *taglen * 8, 0, ptlen);
        if (res) goto out;

        res = TEE_AEEncryptFinal(op, pt, ptlen, ct, ctlen,
                                 tag, taglen);
out:
        /* Both are safe to call on TEE_HANDLE_NULL. */
        TEE_FreeOperation(op);
        TEE_FreeTransientObject(ko);
        return res;
}

/* Note TEE_FreeTransientObject on the key: the key material is
   wiped when the object is freed. Never keep raw key bytes in
   a local array longer than necessary, and TEE_MemFill(0) any
   you do keep.                                              */
Handles are opaque and must be freed on every path

TEE_OperationHandle and TEE_ObjectHandle are allocations inside OP-TEE. A TA that leaks them exhausts its own heap and eventually fails with TEE_ERROR_OUT_OF_MEMORY — after running correctly for hours. Initialise every handle to TEE_HANDLE_NULL and use a single goto out cleanup path, as above; the free functions accept NULL precisely so this pattern works.

Time, properties and arithmetic

The remaining services — time, random, properties — are small but each has a detail that matters, particularly around what can be trusted.

/* TIME - three sources, three trust levels. */

void TEE_GetSystemTime(TEE_Time *time);
    /* monotonic since boot, from the secure world. TRUSTED
       for measuring intervals. Not wall-clock.              */

TEE_Result TEE_GetREETime(TEE_Time *time);
    /* wall-clock, FROM THE NORMAL WORLD. An attacker can set
       it to anything. NEVER use for expiry or replay
       protection (chapter 17).                              */

TEE_Result TEE_GetTAPersistentTime(TEE_Time *time);
TEE_Result TEE_SetTAPersistentTime(const TEE_Time *time);
    /* a per-TA time that survives reboot, stored securely.
       Returns TEE_ERROR_TIME_NOT_SET / TIME_NEEDS_RESET so
       you can tell whether to trust it.                     */

TEE_Result TEE_Wait(uint32_t timeout);   /* an RPC - holds a
                                            thread! (ch. 9)   */

/* PROPERTIES - configuration, declared in the TA's header or
   provided by the implementation.                           */

                                   const char *name,

Tracing from inside a TA

Printing from a trusted application is possible and has to route through the normal world, which has both practical and security consequences.

/* There is no printf. There are these, from
   lib/libutee/include/trace.h - they go to the SECURE console. */

    EMSG("error: %d", x);      /* always shown                 */
    IMSG("info: %s", s);       /* CFG_TEE_TA_LOG_LEVEL >= 2    */
    DMSG("debug: %p", p);      /* >= 3                          */
    FMSG("flow");              /* >= 4                          */

    EMSG_RAW("no prefix\n");
    DHEXDUMP(buf, len);        /* a hex dump - very useful     */

/* Output:
     E/TA: do_sign:112 error: -1
     I/TA: something happened
   with the function name and line number added for you.

   NEVER log key material. DHEXDUMP of a buffer that might be a
   key is a habit that ships. If you need it during
   development, guard it:
     #ifdef DEBUG_SECRETS
     DHEXDUMP(key, keylen);
     #endif
   and make sure DEBUG_SECRETS cannot be defined in a release
   build.                                                     */
