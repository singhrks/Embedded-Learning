Attention

Every position looks at every other position and takes a weighted average of what it finds, with the weights computed from the content itself. One equation, and it is the central mechanism of every modern language model.

The idea, before the equation

Attention is easiest to grasp as a soft dictionary lookup before any equation appears, and one worked example of pronoun resolution carries the whole intuition.

   THE PROBLEM: "The animal didn't cross the street because
   IT was too tired."

   What does "it" refer to? To represent "it" properly, the
   model must incorporate information from "animal" -
   which is six positions away, and which position varies
   from sentence to sentence.

   THE MECHANISM - a soft, differentiable dictionary lookup:

     QUERY   what this position is LOOKING FOR
     KEY     what each position OFFERS
     VALUE   what each position CONTRIBUTES if selected

   A HARD DICTIONARY: find the key that matches exactly,
                      return its value.
   ATTENTION:         compare the query to EVERY key, get a
                      similarity score for each, softmax the
                      scores into weights, and return the
                      WEIGHTED AVERAGE OF ALL VALUES.

   IT IS DIFFERENTIABLE, so it can be learned.

   FOR THE TOKEN "it":
      query("it") · key("animal")  -> HIGH
      query("it") · key("street")  -> medium
      query("it") · key("because") -> low
      ...
      softmax  ->  [0.6, 0.2, 0.05, ...]
      output   =  0.6*value("animal") + 0.2*value("street")
                  + ...

   The representation of "it" now CONTAINS information about
   "animal". That is what "contextual embedding"
   (chapter 17) means, mechanically.

   AND THE THREE PROPERTIES THAT MATTER:
     · CONTENT-BASED. The weights depend on what the tokens
       ARE, not on their positions. Attention itself is
       PERMUTATION-INVARIANT - which is why positional
       encoding must be added separately (chapter 21).
     · O(1) PATH LENGTH between any two positions. Contrast
       the RNN's O(distance) (chapter 18).
     · FULLY PARALLEL. Every position's output is computed
       simultaneously - one matrix multiply.

Scaled dot-product attention

This is the equation to memorise. Every term in it has a reason, including the scaling factor that looks like an afterthought and is not.

/* THE EQUATION. Memorise it. */

    Attention(Q, K, V) = softmax( Q K^T / sqrt(d_k) ) V

    Q: (n, d_k)     queries   - one per position
    K: (n, d_k)     keys
    V: (n, d_v)     values
    output: (n, d_v)

/* STEP BY STEP, WITH SHAPES - the only way to read
   attention code:

    1. SCORES = Q @ K.T              (n, n)
       Every query dotted with every key. THIS MATRIX IS THE
       QUADRATIC COST.

    2. SCALE by 1/sqrt(d_k)          (n, n)

    3. MASK (optional)               (n, n)
       set forbidden positions to -inf

    4. WEIGHTS = softmax(scores, dim=-1)   (n, n)
       each ROW sums to 1

    5. OUTPUT = WEIGHTS @ V          (n, d_v)
       a weighted average of the values

/* WHY DIVIDE BY sqrt(d_k) - AND THIS IS NOT ARBITRARY:

   If q and k have independent components with mean 0 and
   variance 1, then their dot product over d_k dimensions
   has variance d_k (chapter 08). So for d_k = 64 the scores
   have a standard deviation of 8, and for d_k = 128, about
   11.

   LARGE SCORES SATURATE THE SOFTMAX: it approaches a
   one-hot distribution, the gradient becomes almost zero,
   and the layer stops learning. Dividing by sqrt(d_k)
   returns the variance to 1 and keeps the softmax in its
   useful range.

   SKIP THE SCALING AND DEEP TRANSFORMERS SIMPLY DO NOT
   TRAIN. It is one line and it is load-bearing.

/* --- WHERE Q, K AND V COME FROM --- */
    They are LEARNED LINEAR PROJECTIONS of the same input:

        Q = X @ W_Q
        K = X @ W_K
        V = X @ W_V

    W_Q, W_K, W_V are (d_model, d_k) parameter matrices.

    SELF-ATTENTION:  Q, K, V all from the SAME sequence.
                     "How do these tokens relate to each
                     other?"
    CROSS-ATTENTION: Q from one sequence, K and V from
                     another. Used in encoder-decoder
                     translation, and in multimodal models
                     where text queries attend to image
                     patches.

/* --- THE IMPLEMENTATION --- */
import torch
import torch.nn.functional as F
import math

def attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0,
                                    float('-inf'))
    weights = F.softmax(scores, dim=-1)
    return weights @ V, weights

/* SEVEN LINES. That is the mechanism that made large
   language models possible.                             */

Masking

Masking is the one-line difference between a model that can see the future and one that cannot, and therefore between an encoder and a generative language model.

/* --- CAUSAL MASKING: the one that makes generation
       possible --- */

    A language model predicts the next token. If position 3
    could see position 4, it would be reading the answer -
    and the model would learn nothing useful and fail
    completely at inference, when the future does not exist.

    SO POSITION i MAY ATTEND ONLY TO POSITIONS 0..i.

    THE MASK (chapter 03's tril):

        [1 0 0 0]        the score matrix becomes
        [1 1 0 0]        [ s00  -inf -inf -inf ]
        [1 1 1 0]        [ s10   s11 -inf -inf ]
        [1 1 1 1]        [ s20   s21  s22 -inf ]
                         [ s30   s31  s32  s33 ]

    -inf becomes exactly 0 after softmax. NOT a small
    number - exactly zero, because exp(-inf) = 0.

    mask = torch.tril(torch.ones(n, n))
    scores = scores.masked_fill(mask == 0, float('-inf'))

/* WHY THIS IS BRILLIANT FOR TRAINING: with the causal mask,
   ONE forward pass over a sequence of length n produces n
   training examples simultaneously - each position predicts
   its own next token, and none of them can cheat. That is
   the parallelism the RNN could not offer (chapter 18), and
   it is the whole efficiency argument for transformers.

/* --- PADDING MASKS --- */
    Batched sequences are padded (chapter 16). Attending to
    padding pollutes the representation, so pad positions
    must also be masked to -inf.

    THE TWO MASKS COMBINE:
        mask = causal_mask & padding_mask

/* --- THE NUMERICAL TRAP --- */
    A row that is ENTIRELY -inf gives softmax(all -inf) =
    nan. This happens when a sequence is all padding, or
    when a mask is constructed wrongly.

    USE A LARGE FINITE NEGATIVE NUMBER instead of -inf if
    you cannot guarantee otherwise:
        scores.masked_fill(mask == 0, -1e9)
    And in fp16, -1e9 overflows - use -65504 or the dtype's
    minimum. This is a real and frequently-hit bug when
    moving a model to half precision.

/* --- BIDIRECTIONAL: NO CAUSAL MASK --- */
    BERT-style encoders let every position see every other
    position. Better representations for classification and
    retrieval, IMPOSSIBLE FOR GENERATION.

    THE FAMILIES:
      DECODER-ONLY (causal)    GPT, Llama, Mistral, Claude.
                               Generation.
      ENCODER-ONLY (bidir.)    BERT, RoBERTa. Classification,
                               embeddings.
      ENCODER-DECODER          T5, BART. Translation,
                               summarisation.
    DECODER-ONLY HAS WON for general-purpose models, largely
    because one simple objective plus scale beat
    architectural specialisation.                        */
The cost, and why context length is expensive 
The (n, n) score matrix means attention is
O(n² · d) in compute and O(n²) in memory.

  n =  1,000    1,000,000 scores      4 MB in fp32
  n = 10,000  100,000,000 scores    400 MB
  n = 100,000  10 BILLION scores      40 GB, per head,
                                      per layer

That is why context length was stuck at 512-2048 for
years, and why every efficiency technique in this
field is ultimately an attack on this quadratic.

Making it cheaper

The quadratic cost in sequence length is the central engineering problem of long context, and the responses to it fall into a few recognisable families.

/* --- FLASH ATTENTION: the one that actually mattered --- */
    THE INSIGHT: the (n, n) matrix is never needed in full.
    Process it in TILES that fit in on-chip SRAM, computing
    a running softmax with the online-normalisation trick, so
    the full score matrix is NEVER WRITTEN TO MAIN MEMORY.

      · MATHEMATICALLY IDENTICAL output - not an
        approximation
      · MEMORY becomes O(n) instead of O(n^2)
      · 2-4x FASTER, because attention is MEMORY BOUND
        (chapter 04) and this removes most of the traffic

    THIS IS A PURE SYSTEMS OPTIMISATION - cache blocking,
    exactly as in chapter 04's matmul - and it is the single
    largest practical advance in transformer efficiency. It
    is why long contexts became affordable.

    In PyTorch you get it for free:
        F.scaled_dot_product_attention(q, k, v,
                                       is_causal=True)

/* --- SPARSE ATTENTION PATTERNS --- */
    Do not attend to everything.
      SLIDING WINDOW   only the last w tokens. O(n*w).
                       Mistral uses this.
      DILATED          every k-th token, for a wider
                       receptive field
      GLOBAL + LOCAL   a few global tokens everyone sees,
                       plus a local window (Longformer,
                       BigBird)
      BLOCK-SPARSE     structured blocks that map well onto
                       hardware

/* --- LINEAR ATTENTION --- */
    Replace softmax with a kernel so the operation
    reassociates:
        (Q K^T) V   becomes   Q (K^T V)
    O(n^2 d) becomes O(n d^2). This is chapter 04's
    associativity argument, applied to make the sequence
    length linear.
    THE CATCH: quality has consistently lagged. Related to
    the state-space models of chapter 18.

/* --- MULTI-QUERY AND GROUPED-QUERY ATTENTION --- */
    Share K and V across attention heads.
      MHA   every head has its own K, V
      MQA   ALL heads share ONE K, V
      GQA   groups of heads share - the middle ground, and
            what Llama 2/3 and most current models use

    THIS DOES NOT REDUCE TRAINING COMPUTE. It reduces the KV
    CACHE SIZE AT INFERENCE by the sharing factor - often 8x
    - and since generation is memory-bandwidth bound
    (chapters 04, 25), that is a direct throughput win.

/* --- AND THE PRACTICAL SUMMARY --- */
    · use F.scaled_dot_product_attention, always. It selects
      the best available kernel.
    · GQA for inference-heavy deployments
    · sliding-window if you need very long contexts cheaply
    · and do not implement attention by hand in production -
      write it once, as in this chapter, to understand it,
      then use the fused kernel.                          */

What attention learns

Attention weights can be inspected directly, which makes this one of the few genuinely interpretable parts of a modern network — with caveats worth stating.

/* THE WEIGHTS ARE INSPECTABLE, which makes this one of the
   few interpretable parts of a modern model.            */

    out, weights = attention(Q, K, V)
    # weights: (n, n) - row i shows what position i
    # attended to

    import matplotlib.pyplot as plt
    plt.imshow(weights.detach(), cmap='Blues')

/* PATTERNS THAT SHOW UP CONSISTENTLY ACROSS MODELS:

   POSITIONAL HEADS      attend to the previous token, or
                         the one before that. Effectively
                         learned n-gram features.
   SYNTACTIC HEADS       verbs to their subjects, adjectives
                         to their nouns, and matching
                         brackets in code
   COREFERENCE HEADS     pronouns to their antecedents -
                         exactly the "it" example above
   DELIMITER HEADS       attend heavily to the first token
                         or to punctuation. Often an
                         ATTENTION SINK: a place to dump
                         probability mass when the head has
                         nothing useful to do, since softmax
                         forces the row to sum to 1.
   INDUCTION HEADS       the important one. They implement
                         "[A][B] ... [A] -> predict [B]" -
                         copying a pattern seen earlier in
                         the context. They FORM ABRUPTLY
                         during training, and their
                         appearance coincides with the model
                         acquiring IN-CONTEXT LEARNING -
                         the ability to pick up a pattern
                         from examples in the prompt.

   THE INDUCTION HEAD RESULT IS WORTH KNOWING because it is
   one of the clearest cases where a specific circuit was
   identified and connected to a capability. Most
   interpretability is not this clean.

/* AND THE CAVEAT, because attention maps are over-read:
   ATTENTION WEIGHTS ARE NOT AN EXPLANATION. A head can
   attend strongly to a token whose value vector contributes
   almost nothing, and information also flows through the
   residual stream and the feed-forward layers (chapter 22).
   "The model attended to X, therefore it used X" is not a
   valid inference. Attention maps are a useful signal and a
   poor proof.                                            */
