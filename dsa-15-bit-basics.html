Bit manipulation: the fundamentals

The operators, the idioms, and the two-line tricks worth memorising. Everything here is O(1) and appears constantly in embedded work as well as in interviews.

The operators

Six operators, and the only ones that cause trouble are the two shifts and the way negative numbers are represented. Everything later in this chapter and the next is built from these.

   &   AND    1 only where BOTH are 1      1100 & 1010 = 1000
   |   OR     1 where EITHER is 1          1100 | 1010 = 1110
   ^   XOR    1 where they DIFFER          1100 ^ 1010 = 0110
   ~   NOT    flip every bit               ~1100       = 0011
                                           (in two's
                                            complement,
                                            ~x === -x - 1)
   <<  SHIFT LEFT    x << k  ==  x * 2^k
   >>  SHIFT RIGHT   arithmetic — copies the SIGN bit
   >>> SHIFT RIGHT   logical — fills with ZEROS (JavaScript;
                     Java uses >>> too, C++ depends on
                     signedness)

   THE SIX IDIOMS TO KNOW COLD:

     TEST bit i        (x >> i) & 1
     SET bit i         x | (1 << i)
     CLEAR bit i       x & ~(1 << i)
     TOGGLE bit i      x ^ (1 << i)
     LOWEST SET BIT    x & -x        -> isolates it
     CLEAR LOWEST SET  x & (x - 1)   -> removes it

   THE LAST TWO ARE THE ONES THAT WIN PROBLEMS.

     x       = 1011 0100
     x - 1   = 1011 0011      borrow flips the lowest 1 and
                              everything below it
     x&(x-1) = 1011 0000      lowest set bit REMOVED
     -x      = 0100 1100      two's complement = ~x + 1
     x & -x  = 0000 0100      lowest set bit ISOLATED

   USEFUL CONSEQUENCES:
     x & (x - 1) === 0        ->  x is a POWER OF TWO
                                  (or zero — check separately)
     counting with x &= x-1   ->  loops once per SET BIT,
                                  not once per bit

   THE XOR PROPERTIES, which power chapter 18:
     x ^ x = 0        a value cancels itself
     x ^ 0 = x        zero is the identity
     XOR is COMMUTATIVE and ASSOCIATIVE — order never matters
     a ^ b ^ b = a    XOR is its own inverse
JavaScript's bitwise operators are 32-bit

All of & | ^ ~ << >> convert their operands to signed 32-bit integers, so 1 << 31 is negative and anything above 2³¹ loses its high bits. Use >>> 0 to read a result as unsigned, and BigInt if you genuinely need more than 32 bits. In C++ and Java the same care applies: shifting by ≥ the width is undefined in C++, and in Java the shift count is taken modulo 32 (or 64 for long), so 1 << 32 is 1, not 0.

/* --- COUNTING SET BITS (population count) --- */
function popcount(x) {
    let c = 0;
    while (x) { x &= x - 1; c++; }   // one iteration PER SET BIT
    return c;
}
// built-ins: __builtin_popcount (C++), Integer.bitCount (Java),
//            bin(x).count('1') (Python)

/* --- ITERATE THE SET BITS --- */
while (mask) {
    const bit = mask & -mask;        // isolate the lowest
    const i   = Math.log2(bit);      // its index
    mask ^= bit;                     // remove it
}

/* --- SWAP WITHOUT A TEMPORARY (a party trick, not
       production code — it breaks when a === b aliases) --- */
a ^= b; b ^= a; a ^= b;

/* --- USEFUL MASKS --- */
(1 << k) - 1        // k low bits set:  k=4 -> 0b1111
x & ((1 << k) - 1)  // keep the low k bits
x >> k & 1          // read bit k
~0                  // all ones (-1)

/* --- PARITY of the set-bit count --- */
x ^= x >> 16; x ^= x >> 8; x ^= x >> 4;
x ^= x >> 2;  x ^= x >> 1;  return x & 1;

/* --- MULTIPLY / DIVIDE BY POWERS OF TWO --- */
x << 3   // x * 8
x >> 3   // floor(x / 8) for NON-NEGATIVE x
// CAREFUL: -7 >> 1 === -4, but -7 / 2 truncates to -3.
// Arithmetic shift rounds toward NEGATIVE INFINITY.  */

Problems

How it shows up

SymptomCause
Result is negative unexpectedlyBit 31 set — JavaScript bitwise ops are signed 32-bit; use >>> 0
Shift by 32 does nothingJava/JS take the count mod 32; C++ it is undefined
Loop never terminates on a negative input>> preserves the sign forever — use >>>
Zero reported as a power of twox & (x−1) === 0 is also true for 0 — add x > 0

Precedence bug& and | bind looser than == — parenthesise
