Backtracking

Build a candidate one choice at a time, abandon it the moment it cannot work, and undo the choice on the way out. One template covers subsets, permutations, combinations and every puzzle-solver.

The pattern

Backtracking is one template that solves every "generate all valid arrangements" problem, with the specifics living in two small functions. Learn the shape and the two lines that are easy to omit.

   THE TEMPLATE — learn this shape, not the individual
   problems:

     function backtrack(path, choices) {
         if (isComplete(path)) {
             result.push([...path]);      // COPY, not the ref
             return;
         }
         for (const c of choices) {
             if (!isValid(c, path)) continue;   // PRUNE

             path.push(c);                // 1. CHOOSE
             backtrack(path, next(c));    // 2. EXPLORE
             path.pop();                  // 3. UN-CHOOSE
         }
     }

   THE THREE STEPS ARE ALWAYS CHOOSE / EXPLORE / UN-CHOOSE.
   The un-choose is what makes it "backtracking" rather than
   plain recursion — it restores the state so the next branch
   starts clean.

   ---------------------------------------------------------
   THE TWO MISTAKES THAT ACCOUNT FOR MOST BUGS

   1. PUSHING THE PATH WITHOUT COPYING
        result.push(path);      // WRONG — stores a reference
        result.push([...path]); // right — snapshot

      `path` keeps mutating, so every stored reference ends
      up pointing at the same (eventually empty) array.

   2. FORGETTING TO UNDO
        Every mutation before the recursive call needs a
        matching undo after it — the array push, a `used[]`
        flag, a board cell, a running sum.

   ---------------------------------------------------------
   SUBSETS VERSUS PERMUTATIONS VERSUS COMBINATIONS

     SUBSETS       order does NOT matter, each item optional
                   -> pass `start` so you never look back
                   -> 2^n results
     COMBINATIONS  subsets of a fixed size k
                   -> same `start`, plus a size check
                   -> C(n, k) results
     PERMUTATIONS  order DOES matter, all items used
                   -> no `start`; a `used[]` array instead
                   -> n! results

     THE `start` PARAMETER IS THE WHOLE DIFFERENCE between
     subsets and permutations. `start` forbids revisiting
     earlier indices, which is exactly what makes [1,2] and
     [2,1] the same subset but different permutations.

   ---------------------------------------------------------
   HANDLING DUPLICATE INPUT

     SORT FIRST, then inside the loop skip a value equal to
     the previous one at the SAME LEVEL:

        if (i > start && nums[i] === nums[i-1]) continue;

     `i > start` is essential: the first occurrence at each
     level must be allowed; only repeats are skipped.

   ---------------------------------------------------------
   COST: exponential by nature. Backtracking is what you use
   when the answer genuinely requires enumeration —
   which is why constraints of n <= 20 or so point here
   (chapter 02). PRUNING is what makes it survivable in
   practice: the earlier you can reject a partial candidate,
   the more of the tree you never build.

When to reach for it

"All possible …"

Subsets, permutations, combinations, partitions.

"Generate every valid …"

Parentheses, IP addresses, palindrome partitions.

Constraint puzzles

N-Queens, Sudoku, word search.

Path enumeration

All root-to-leaf paths, all routes in a maze.

Small n with no better structure

n ≤ 20 and the problem resists DP or greedy.

Do NOT use it

When you only need a count or an optimum — that is usually DP (ch. 37).

Problems

How it shows up

SymptomCause
All results identical or emptyPushed the path by reference instead of copying
Results contaminated across branchesMissing the un-choose step
Permutations appear as subsetsUsed start where a used[] array was needed
Duplicate resultsInput not sorted, or the same-level skip missing
Valid first occurrence skippedSkip condition missing the i > start guard
Times outNo pruning — reject invalid partials earlier
Stack overflowRecursion never reaches the completion check

Check yourself

  • Write the template and name the three steps.
  • Explain why the path must be copied when recorded.
  • Say what the start parameter does and which problems need it.
  • Contrast subsets, combinations and permutations in result count and mechanism.
  • Give the duplicate-skip line and explain the i > start guard.
  • Say what pruning buys and give an example.
  • State when backtracking is the wrong tool.
