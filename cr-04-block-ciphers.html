Block ciphers and AES

A keyed permutation on fixed-size blocks — the workhorse primitive of symmetric cryptography. This chapter is how AES works, why its structure resists the known attacks, and what a hardware or software implementation actually costs.

What a block cipher is

A block cipher transforms one fixed-size block under a key, and on its own it is almost useless — it encrypts exactly 16 bytes. Everything practical comes from how it is used, which is the next chapter's subject.

   E : {0,1}^k × {0,1}^n -> {0,1}^n

   For each key K, E_K is a PERMUTATION of the n-bit blocks -
   a bijection, so decryption exists and is unique.

   THE SECURITY GOAL: E_K should be indistinguishable from a
   RANDOM PERMUTATION chosen uniformly from all 2^n!
   permutations, to an adversary who does not know K.

   That is a strong requirement, and it is what the design
   effort goes into. A block cipher is not "scrambling"; it
   is an attempt to build something that behaves like a
   randomly chosen lookup table of size 2^128, using a few
   kilobytes of logic.

   THE PARAMETERS THAT MATTER:

     BLOCK SIZE n     AES: 128 bits.
                      Too small is dangerous: with a 64-bit
                      block, a birthday collision appears
                      after ~2^32 blocks (32 GB), which is
                      the SWEET32 attack that killed 3DES
                      and Blowfish in TLS.
     KEY SIZE k       AES: 128, 192 or 256.

   AND THE CRITICAL POINT: a block cipher encrypts ONE BLOCK.
   Encrypting a message requires a MODE OF OPERATION
   (chapter 05), and the mode is where most of the security
   properties - and most of the mistakes - live.

Design principles

Block ciphers are built from repeated simple rounds rather than one complex operation. The principles behind that structure explain why the designs look the way they do and why the round count matters.

/* Shannon, 1949, and still the framework: */

   CONFUSION   the relationship between key and ciphertext
               must be complex.
               -> achieved by SUBSTITUTION (S-boxes),
                  which are non-linear.

   DIFFUSION   changing one plaintext bit must change about
               half the ciphertext bits.
               -> achieved by PERMUTATION and MIXING, which
                  spread local changes globally.

   A cipher applies both, alternately, for many ROUNDS. Each
   round is weak; the composition is not.

/* THE AVALANCHE CRITERION: flip one input bit, and each
   output bit should flip with probability 1/2. AES achieves
   full avalanche after two rounds - and then does eight more.

/* THE TWO STRUCTURES:

   SUBSTITUTION-PERMUTATION NETWORK (SPN) - AES
       every round transforms the WHOLE block:
           substitute -> permute -> mix -> add key
       decryption needs the INVERSE of each step.

   FEISTEL NETWORK - DES, Blowfish, Camellia
       split the block in half:
           L' = R
           R' = L XOR F(R, K)
       decryption is the SAME circuit with the round keys
       reversed - so F need not be invertible, which was
       valuable when gates were expensive.

/* THE ROUND COUNT is chosen with a SECURITY MARGIN: the best
   known attacks reach some number of rounds, and the cipher
   uses substantially more. AES-128 uses 10 rounds; the best
   published attack on reduced-round AES reaches 7. That
   margin is the design's insurance against future
   cryptanalysis.                                          */

AES

The standard, in practically everything. Knowing its structure matters less than knowing its properties — the block size, the key sizes, and the fact that modern processors implement it in hardware.

   The state is a 4x4 matrix of BYTES - 128 bits - filled
   COLUMN-WISE:

        b0  b4  b8  b12
        b1  b5  b9  b13
        b2  b6  b10 b14
        b3  b7  b11 b15

   ROUNDS: 10 for AES-128, 12 for AES-192, 14 for AES-256.

   ENCRYPTION:
        AddRoundKey(state, K0)
        for r = 1 .. Nr-1:
                SubBytes(state)
                ShiftRows(state)
                MixColumns(state)
                AddRoundKey(state, Kr)
        // the final round OMITS MixColumns
        SubBytes(state)
        ShiftRows(state)
        AddRoundKey(state, KNr)

   THE FOUR OPERATIONS:

   SubBytes     each byte replaced via a fixed 256-entry
                S-BOX. THE ONLY NON-LINEAR STEP, and
                therefore the whole source of confusion.
                Constructed as the multiplicative inverse in
                GF(2^8) followed by an affine map - chosen for
                provably good resistance to differential and
                linear cryptanalysis, not by trial and error.

   ShiftRows    row 0 unchanged, row 1 left by 1, row 2 by 2,
                row 3 by 3. Spreads bytes ACROSS columns.

   MixColumns   each column multiplied by a fixed matrix in
                GF(2^8). Every output byte of a column depends
                on all four inputs. Spreads WITHIN columns.
                ShiftRows and MixColumns together give full
                diffusion in two rounds.

   AddRoundKey  XOR the round key. The only step involving
                the key.

   THE KEY SCHEDULE expands the key into Nr+1 round keys,
   using the S-box, a byte rotation and round constants -
   deliberately non-linear so that recovering one round key
   does not immediately give the others.

   DECRYPTION uses InvSubBytes, InvShiftRows, InvMixColumns
   with the round keys reversed - or, in the "equivalent
   inverse cipher" form, the same structure with modified
   keys, which is what implementations use.
Why AES is the answer

Selected in 2001 after a five-year open competition with fifteen candidates and worldwide public cryptanalysis. Twenty-five years later, the best attack on full AES-128 is a biclique attack costing about 2126 operations — a factor of four better than brute force, and entirely academic. Meanwhile every general-purpose CPU and most microcontrollers have hardware instructions for it. There is no reason to use anything else for block encryption, and choosing something else needs a specific justification.

Implementing it

A textbook implementation using lookup tables leaks the key through cache timing. This is not theoretical; it is why hardware instructions and bit-sliced implementations exist, and why writing your own is discouraged.

The cryptanalysis

The academic attacks on AES do not threaten it in practice, and knowing roughly what they achieve is useful for reading security claims critically rather than taking "broken" at face value.

/* Understanding what these attacks look for explains why AES
   is shaped as it is. */

   DIFFERENTIAL CRYPTANALYSIS
     Track how a chosen INPUT DIFFERENCE propagates to an
     output difference. If some difference pair occurs with
     probability much higher than 2^-n, that bias reveals key
     bits.
     -> AES's S-box has a maximum differential probability of
        2^-6, which is the best achievable for an 8-bit
        S-box, and the wide-trail design bounds how few
        S-boxes an attack can involve.

   LINEAR CRYPTANALYSIS
     Find a linear approximation relating plaintext,
     ciphertext and key bits that holds slightly more often
     than half the time.
     -> AES's S-box has maximum linear bias 2^-3, again
        optimal.

   RELATED-KEY ATTACKS
     Exploit relationships between keys. AES-256's key
     schedule is weaker here than AES-128's - there is a
     related-key attack on full AES-256 at 2^99. It requires
     the attacker to obtain encryptions under keys with a
     chosen relationship, which a sane protocol never
     provides, so it is not a practical concern - but it is
     why "AES-256 is stronger than AES-128" is not
     unqualifiedly true.

   BICLIQUE ATTACK (2011)
     The best known attack on FULL AES: 2^126.1 for AES-128.
     A factor of four better than exhaustive search, and
     entirely theoretical.

   THE PRACTICAL BREAKS ARE ALL IMPLEMENTATION:
     cache timing on T-tables
     power analysis (DPA) on unprotected hardware
     fault injection (isolation chapter 16)
     nonce and IV misuse (chapter 05)
     key management failures (chapter 18)

/* WHICH IS THE THEME OF THIS WHOLE TRACK: the mathematics
   holds; the engineering is where things break.         */

The other block ciphers

A handful of other block ciphers appear in real systems, usually for legacy reasons or because of a specific constraint. This is what each is and whether you should accept it.

AES128 / 128-256The default. Hardware everywhere
DES64 / 56Broken — 56-bit key, brute-forced since 1998
3DES64 / 112Deprecated — 64-bit block, SWEET32
Blowfish64 / 32-448Legacy — 64-bit block. bcrypt uses its key schedule

How it shows up

SymptomCause
