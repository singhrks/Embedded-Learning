I2C: start, stop, addressing and ACK

Two wires, up to 127 devices, and an acknowledgement on every byte — I2C gives you far more than SPI for two fewer pins, and charges for it in protocol complexity and a set of failure modes that have no SPI equivalent.

Two wires, open drain

                    VDD
                     |
              +------+------+
              |             |
            [Rp]          [Rp]        2.2k - 4.7k
              |             |
   SDA -------+-------------|----------+----------+
   SCL -------------------- +----------|----------|--+
              |             |          |          |  |
          +---+---+     +---+---+  +---+---+  +---+--+--+
          |MASTER |     |slave 1|  |slave 2|  | slave 3 |
          +-------+     +-------+  +-------+  +---------+

   EVERY DEVICE IS OPEN-DRAIN: it can pull a line LOW, or
   release it. Nobody ever DRIVES a line high - the pull-up
   resistors do that (mcu chapter 10).

   THIS ONE DECISION EXPLAINS ALMOST EVERYTHING ABOUT I2C:

   - Two devices can transmit simultaneously without damage,
     because low always wins. That makes ARBITRATION
     possible (chapter 07).
   - A slave can hold SCL low to say "wait", which is CLOCK
     STRETCHING (chapter 07).
   - A receiver can pull SDA low during the 9th bit to
     ACKNOWLEDGE.
   - Rise time is set by Rp and the bus capacitance, so the
     RESISTOR VALUE LIMITS THE SPEED. This is why the
     internal pull-ups (~40 kO) cannot do 400 kHz.

     t_rise ~ 0.8 x Rp x C_bus
     400 kHz needs t_rise < 300 ns
     With C_bus = 100 pF:  Rp < 3.75 kO

   SPEEDS: 100 kHz standard, 400 kHz fast, 1 MHz fast-plus,
   3.4 MHz high-speed (rare, needs a current-source pull-up).

Start, stop, and the bytes between

   START and STOP are the only times SDA changes while SCL
   is HIGH. During data, SDA may only change while SCL is
   LOW. That distinction is the entire framing mechanism.

   START:  SDA falls while SCL high
   STOP:   SDA rises while SCL high

     SDA  ---+                          +---
             |                          |
             +--------------------------+
     SCL  ------+                    +------
                |                    |
                +--------------------+
            ^                          ^
          START                      STOP

   A COMPLETE WRITE OF ONE BYTE TO REGISTER 0x10:

   S | 0x76<<1|W | A | 0x10 | A | 0x42 | A | P
   ^      ^       ^    ^      ^    ^     ^   ^
   |      |       |    |      |    |     |   stop
   |      |       |    |      |    |     slave ACKs data
   |      |       |    |      |    data byte
   |      |       |    |      slave ACKs register
   |      |       |    register address
   |      |       slave ACKs its address
   |      address + direction bit (0 = write)
   start

   THE 9TH BIT OF EVERY BYTE IS THE ACKNOWLEDGEMENT. The
   transmitter releases SDA; the receiver pulls it LOW to
   say "got it". A high 9th bit is a NACK.

   ACK = 0 (SDA low). This inversion catches everyone.

The repeated start

   Reading a register needs BOTH directions: write the
   register number, then read the value. A STOP between them
   would release the bus and let another master interleave -
   so I2C provides a REPEATED START, which changes direction
   without releasing.

   S | addr|W | A | 0x10 | A | Sr | addr|R | A | data | N | P
                                ^                       ^
                                |                       master
                                repeated start,         NACKs the
                                no STOP first           LAST byte

   THE MASTER NACKS THE FINAL BYTE IT READS. This is how it
   says "stop sending" - the slave sees the NACK and
   releases SDA so the master can generate a STOP. ACK the
   last byte instead and the slave keeps driving SDA,
   the STOP cannot be generated, and the bus hangs.

   Multi-byte read: ACK every byte except the last.

     for (i = 0; i < n; i++) {
         data[i] = i2c_read_byte(i < n - 1);   /* ack flag */
     }

   THE ALTERNATIVE some code uses - stop, then start again -
   works with most devices and fails with some, because it
   allows another master in between and because a few
   devices reset their internal address pointer on STOP.
   Use a repeated start; it is what the datasheet's timing
   diagram shows.

Addressing

/* 7-bit addresses, shifted left, with the direction bit in
   position 0. This shift is the single most common source
   of confusion in I2C code.                              */

/*   Datasheet says: "the device address is 0x76"
     On the wire:     0xEC for write (0x76 << 1 | 0)
                      0xED for read  (0x76 << 1 | 1)

   Some datasheets quote the SHIFTED value, so "address
   0xEC" means the same device. If a scan finds a device at
   half your expected address - or double it - this is why.

   ALWAYS SCAN. Twelve lines that answer "is it even there":  */

void i2c_scan(void)
{
    for (uint8_t a = 0x08; a < 0x78; a++) {   /* reserved
                                                 outside     */
        i2c_start();
        int ack = i2c_send_byte(a << 1);      /* write        */
        i2c_stop();
        if (ack) { printf("found 0x%02X\r\n", a); }
    }
}

/* RESERVED ADDRESSES - do not use, and do not scan:
     0x00       general call / start byte
     0x01       CBUS
     0x02-0x03  reserved
     0x04-0x07  Hs-mode master code
     0x78-0x7B  10-bit addressing
     0x7C-0x7F  reserved

   ADDRESS COLLISIONS are I2C's practical limit. Many sensors
   offer only two addresses via an ADDR pin, so three
   identical sensors will not fit on one bus. Solutions:
     - a second I2C peripheral
     - an I2C multiplexer (TCA9548A and similar)
     - devices with more address pins
   Discovering this after the PCB is made is a common and
   expensive mistake - check address availability during
   schematic review, not bring-up.                          */
NACK is information, not failure

A NACK on the address byte means no device answered — wrong address, unpowered, or not connected. A NACK on a data byte means the device is refusing, usually because it is busy: an EEPROM performing an internal write cycle NACKs its address until the write completes, and the correct response is to retry. This is called acknowledge polling, and it is the documented way to wait for an EEPROM write rather than a fixed delay. Treat NACK as a status code with a meaning that depends on when it arrived.

A blocking master transaction

/* Every step has a timeout. An I2C bus with a confused
   slave WILL hang otherwise, and hang forever.            */

#define I2C_TIMEOUT_MS 10

static int wait_flag(volatile uint32_t *r, uint32_t m, int set)
{
    uint32_t deadline = g_ms + I2C_TIMEOUT_MS;
    while (((*r & m) != 0) != (set != 0)) {
        if ((int32_t)(g_ms - deadline) >= 0) { return -ETIMEDOUT; }
    }
    return 0;
}

int i2c_write_reg(uint8_t addr, uint8_t reg, uint8_t val)
{
    int rc;

    I2C1->CR2 = (addr << 1) | (2u << 16)     /* 2 bytes      */
              | I2C_CR2_START | I2C_CR2_AUTOEND;

    if ((rc = wait_flag(&I2C1->ISR, I2C_ISR_TXIS, 1)) < 0) { goto err; }
    if (I2C1->ISR & I2C_ISR_NACKF) { rc = -ENXIO; goto err; }
    I2C1->TXDR = reg;

    if ((rc = wait_flag(&I2C1->ISR, I2C_ISR_TXIS, 1)) < 0) { goto err; }
    I2C1->TXDR = val;

    if ((rc = wait_flag(&I2C1->ISR, I2C_ISR_STOPF, 1)) < 0) { goto err; }
    I2C1->ICR = I2C_ICR_STOPCF;
    return 0;

err:
    i2c_recover();          /* chapter 07 - do NOT skip this */
    return rc;
}

int i2c_read_regs(uint8_t addr, uint8_t reg, uint8_t *d, size_t n)
{
    /* Phase 1: write the register pointer, NO autoend -
       we want a repeated start.                            */
    I2C1->CR2 = (addr << 1) | (1u << 16) | I2C_CR2_START;
    if (wait_flag(&I2C1->ISR, I2C_ISR_TXIS, 1) < 0) { goto err; }
    if (I2C1->ISR & I2C_ISR_NACKF) { goto err; }
    I2C1->TXDR = reg;
    if (wait_flag(&I2C1->ISR, I2C_ISR_TC, 1) < 0) { goto err; }

    /* Phase 2: repeated start, read direction. */
    I2C1->CR2 = (addr << 1) | I2C_CR2_RD_WRN | (n << 16)
              | I2C_CR2_START | I2C_CR2_AUTOEND;

    for (size_t i = 0; i < n; i++) {
        if (wait_flag(&I2C1->ISR, I2C_ISR_RXNE, 1) < 0) { goto err; }
        d[i] = (uint8_t) I2C1->RXDR;
    }
    if (wait_flag(&I2C1->ISR, I2C_ISR_STOPF, 1) < 0) { goto err; }
    I2C1->ICR = I2C_ICR_STOPCF;
    return 0;

err:
    i2c_recover();
    return -EIO;
}

/* The v2 peripheral handles ACK/NACK of the final byte from
   the NBYTES count, which is why the loop above has no
   explicit ack flag. Older peripherals require you to clear
   the ACK bit before reading the second-to-last byte -
   check which generation you have.                         */
