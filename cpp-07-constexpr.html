constexpr and compile-time computation

Moving work from run time to compile time. On embedded this is not a micro-optimisation — a lookup table computed by the compiler costs zero cycles and lives in flash, and a configuration validated at compile time cannot be wrong in the field.

The keywords

C++ offers several degrees of compile-time evaluation, from "may be" to "must be", and they are easy to confuse. The distinction determines whether a failure appears at build time or never.

/* --- const: "I will not modify this" ------------------- */
        const int a = 42;               /* compile-time
                                           constant here    */
        const int b = read_sensor();    /* runtime value that
                                           does not change  */

/* --- constexpr: "usable in a constant expression" ------ */
        constexpr int c = 42;
        constexpr int d = read_sensor();        /* ERROR */

        constexpr int square(int x) { return x * x; }
        constexpr int e = square(5);    /* computed at COMPILE
                                           time              */
        int n = get_n();
        int f = square(n);              /* the SAME function,
                                           called at RUN time */

/* A constexpr FUNCTION may be evaluated at compile time; it
   is not required to be. Called with runtime arguments it is
   an ordinary function.

/* --- consteval (C++20): "MUST be compile time" --------- */
        consteval int must_be_static(int x) { return x * x; }
        constexpr int g = must_be_static(5);    /* OK */
        int h = must_be_static(n);              /* ERROR */

/* Use it for anything whose whole point is compile-time
   evaluation - a hash of a string literal, a validated
   configuration, a register encoding.

/* --- constinit (C++20): "initialised at compile time" -- */
        constinit int counter = 0;      /* guaranteed static
                                           initialisation - no
                                           constructor runs
                                           before main
                                           (chapter 01)     */
/* It does NOT make the variable const; it only guarantees
   the initialisation is not dynamic. Exactly what you want
   for a mutable global on a bare-metal target.           */

Compile-time tables

Computing a lookup table at compile time puts it in read-only memory with no startup cost — which on an embedded target is precisely what you want, and used to require a code generator.

/* THE HIGHEST-VALUE USE ON EMBEDDED. A table computed by the
   compiler costs nothing at run time and lives in flash.  */

/* --- CRC-32 table --- */
constexpr std::array<uint32_t, 256> make_crc_table()
{
        std::array<uint32_t, 256> table{};

        for (uint32_t i = 0; i < 256; i++) {
                uint32_t c = i;
                for (int k = 0; k < 8; k++)
                        c = (c & 1) ? (0xEDB88320u ^ (c >> 1))
                                    : (c >> 1);
                table[i] = c;
        }
        return table;
}

inline constexpr auto crc_table = make_crc_table();

uint32_t crc32(std::span<const uint8_t> data)
{
        uint32_t c = 0xFFFFFFFFu;

        for (uint8_t b : data)
                c = crc_table[(c ^ b) & 0xFF] ^ (c >> 8);

        return c ^ 0xFFFFFFFFu;
}

/* THE TABLE IS IN .rodata - flash, not RAM - fully computed.
   No initialisation code, no startup cost, and the source
   documents how it was derived rather than being 256
   inscrutable hex constants.

/* --- a sine table --- */
constexpr std::array<int16_t, 256> make_sine()
{
        std::array<int16_t, 256> t{};
        for (size_t i = 0; i < 256; i++) {
                /* a constexpr-friendly sine - std::sin is not
                   constexpr until C++26, so use a Taylor
                   series or CORDIC */
                t[i] = static_cast<int16_t>(
                        32767.0 * const_sin(2.0 * PI * i / 256));
        }
        return t;
}

/* --- a gamma correction table, from a formula --- */
template<size_t N, int GammaTimes100>
constexpr std::array<uint8_t, N> make_gamma()
{
        std::array<uint8_t, N> t{};
        for (size_t i = 0; i < N; i++)
                t[i] = static_cast<uint8_t>(
                        255.0 * const_pow(i / double(N - 1),
                                          GammaTimes100 / 100.0));
        return t;
}
        constexpr auto gamma22 = make_gamma<256, 220>();

/* CHANGE THE PARAMETER, GET A NEW TABLE. No script, no
   generated file to keep in sync, no build step. That is the
   argument.

/* CHECK IT LANDED IN FLASH: */
        nm -S prog.elf | grep crc_table
        readelf -S prog.elf         /* which section? */
/* If it is in .data rather than .rodata, something is not
   const and it is costing you RAM.                       */
The embedded case, in one sentence

A constexpr table trades flash for RAM and cycles, is generated from readable source rather than a checked-in blob, and cannot drift out of sync with the formula that produced it. On a part with 32 KB of RAM and 512 KB of flash, that is nearly always the right trade.

What is allowed

What may appear in a compile-time function has loosened substantially with each standard, and knowing where the boundary is for your version saves fighting the compiler.

/* The rules have relaxed substantially with each standard. */

/* C++11: essentially one return statement.
   C++14: loops, local variables, multiple statements, if.
   C++17: if constexpr, lambdas.
   C++20: try/catch (may not throw), dynamic allocation IF it
          is freed within the same evaluation, virtual calls,
          std::vector and std::string.

Compile-time configuration

Compile-time evaluation lets configuration be validated when you build rather than when the device boots — a wrong clock divider becomes a build error rather than a field failure.

/* Validate an entire board configuration at compile time. */

struct ClockConfig {
        uint32_t xtal_hz;
        uint32_t pll_mult;
        uint32_t pll_div;
        uint32_t ahb_div;

        constexpr uint32_t pll_hz() const
                { return xtal_hz * pll_mult / pll_div; }
        constexpr uint32_t ahb_hz() const
                { return pll_hz() / ahb_div; }

        constexpr bool valid() const
        {
                return xtal_hz >= 4'000'000
                    && xtal_hz <= 26'000'000
                    && pll_mult >= 2 && pll_mult <= 64
                    && pll_hz() <= 480'000'000
                    && ahb_hz() <= 200'000'000;
        }
};

inline constexpr ClockConfig board_clock{
        .xtal_hz  = 25'000'000,
        .pll_mult = 32,
        .pll_div  = 2,
        .ahb_div  = 2,
};
static_assert(board_clock.valid(), "invalid clock configuration");
static_assert(board_clock.ahb_hz() == 200'000'000);

/* AND DERIVED VALUES computed once, at compile time: */
        constexpr uint32_t uart_divisor(uint32_t clk,
                                        uint32_t baud)
        {
                return (clk + baud / 2) / (16 * baud);
        }
        constexpr auto UART_DIV =
                uart_divisor(board_clock.ahb_hz(), 115200);
        static_assert(UART_DIV > 0 && UART_DIV < 65536);

   change the crystal, recompute the divisors", and the bug

/* A COMPILE-TIME STRING HASH, for command dispatch with no
   strcmp at run time: */

        {

                for (char c : s) {

                }

Type-safe units

Encoding units in the type system catches an entire class of error at compile time, and done with compile-time evaluation it costs nothing at run time.

/* Strong types with constexpr arithmetic: correctness with
   literally zero runtime cost.                            */

class Milliseconds {
        uint32_t v_;
public:
        explicit constexpr Milliseconds(uint32_t v) : v_(v) {}
        constexpr uint32_t count() const { return v_; }

        constexpr Milliseconds operator+(Milliseconds o) const
                { return Milliseconds{v_ + o.v_}; }
        constexpr auto operator<=>(const Milliseconds&) const
                = default;                      /* C++20 */
};

constexpr Milliseconds operator""_ms(unsigned long long v)
{
        return Milliseconds{static_cast<uint32_t>(v)};
}

        void delay(Milliseconds t);

        delay(100_ms);          /* clear */
        delay(100);             /* ERROR - explicit ctor */
        delay(1_s);             /* if you define _s too */

/* THE GENERATED CODE is identical to passing a bare uint32_t.
   The class is entirely compiled away - check on godbolt
   (chapter 14).

/* AND THE STANDARD LIBRARY ALREADY HAS THIS: */
        #include <chrono>
        using namespace std::chrono_literals;

        void delay(std::chrono::milliseconds t);
        delay(100ms);
        delay(2s);              /* converted automatically */
        delay(1500us);          /* and this */

/* std::chrono::duration is constexpr throughout, converts
   between units correctly at compile time, and refuses
   lossy conversions unless you ask with duration_cast. On
   embedded it is worth using even if you use nothing else
   from the standard library - it prevents an entire class of
   unit-confusion bug for free.                           */

Verifying it happened

Whether something was actually evaluated at compile time is not visible in the source. These are the ways to confirm it, which matters because a silent fallback to run time defeats the purpose.

/* THE RISK: you wrote constexpr, and it is being evaluated at
   run time anyway. Check.                                  */

/* 1. FORCE IT with a constexpr variable: */
        constexpr auto table = make_table();
/* If make_table() cannot be evaluated at compile time, this
   is a COMPILE ERROR - which is exactly the feedback you
   want. Assigning to `auto table = make_table();` would
   silently run it at startup.

/* 2. USE consteval where it must be compile time. */

/* 3. LOOK AT THE BINARY: */
        nm -S prog.elf | grep table
        readelf -x .rodata prog.elf | head
        objdump -s -j .rodata prog.elf
/* The table's bytes should be visible in .rodata. If the
   symbol is in .bss and there is code in .init_array, it is
   being computed at startup.

/* 4. CHECK .init_array IS EMPTY: */
        readelf -x .init_array prog.elf
/* For a well-configured firmware image it should be, or
   nearly so (chapter 01).

/* 5. AND THE COMPILE-TIME COST, which is real: */
        clang -ftime-trace ...
        /* then load the .json in speedscope or
           chrome://tracing */
/* Heavy constexpr evaluation - a large table with a complex
   formula - can add seconds to a build. Usually worth it;
   occasionally not.

/* THE LIMITS THE COMPILER IMPOSES: */
        -fconstexpr-depth=512           /* recursion */
        -fconstexpr-steps=1048576       /* clang: total
                                           operations */
        -fconstexpr-ops-limit=...       /* gcc */
/* Hitting these produces "constexpr evaluation exceeded
   maximum steps" - raise the limit, or simplify.        */

How it shows up

SymptomCause
Table is in RAM, not flashNot constexpr, or not const — check the section
Startup code initialises a tableComputed at run time — force it with a constexpr variable
"call to non-constexpr function"Something in the chain is not marked
"not a constant expression"Reading a runtime value, or UB in the evaluation
Overflow error only in a constexpr contextCorrect — the same code is silent UB at run time

Check yourself

  • Distinguish const, constexpr, consteval and constinit.
  • Write a constexpr function that generates a lookup table.
  • Verify the table is in .rodata and that nothing runs at startup.
  • Say what is forbidden in a constant evaluation, and why the UB rule is valuable.
  • Use static_assert to validate a board configuration.
  • Compute a derived hardware constant at compile time and assert its range.
  • Write a compile-time string hash and use it in a switch.
  • Build a strong unit type and prove it costs nothing.
  • Use std::chrono for durations and explain what it prevents.
  • Detect and fix a case where constexpr silently became runtime evaluation.
