Bug patterns and their signatures

Most bugs are one of about twenty recurring shapes. Recognising the shape from the symptom takes you from "something is wrong" to a short list of causes in seconds, which is most of what experience buys.

Memory bugs

   BUFFER OVERFLOW
     SIGNATURE   corruption of a variable ADJACENT to the
                 one you wrote; a smashed stack canary;
                 crash in free() far from the real bug;
                 works until a struct layout changes
     CAUSES      off-by-one on a bound, strcpy, sprintf,
                 a length in elements used as bytes
     FIND IT     ASan, Driver Verifier, a canary pattern
                 around buffers

   USE AFTER FREE
     SIGNATURE   works most of the time, then garbage; the
                 data is plausible but WRONG; often
                 timing-dependent
     CAUSES      a second pointer to freed memory; a
                 callback firing after teardown; refcount
                 dropped early
     FIND IT     ASan; set pointers to NULL after free; use
                 a poison pattern

   DOUBLE FREE
     SIGNATURE   heap corruption, a crash in the allocator,
                 an abort from glibc
     CAUSES      two error paths both freeing; ownership
                 unclear

   MEMORY LEAK
     SIGNATURE   RSS grows monotonically; fails after hours
                 or days; degrades then dies
     CAUSES      an error path that returns without
                 freeing; a missing put() on a refcounted
                 object
     FIND IT     heaptrack, Valgrind, kmemleak,
                 !poolused

   UNINITIALISED READ
     SIGNATURE   works in debug, fails in release; the
                 value is different every run; adding a
                 printf changes it
     CAUSES      a missing initialiser; a struct field
                 added and not set in one construction site
     FIND IT     MSan, Valgrind, and simply initialising
                 everything

   STACK OVERFLOW
     SIGNATURE   corruption with no obvious writer;
                 hard fault; crash on entering a function;
                 only under deep recursion or a large local
     CAUSES      a large local array, deep recursion, an
                 ISR stack too small, alloca
     FIND IT     paint the stack with a pattern at boot and
                 measure the high-water mark. DO THIS ON
                 EVERY EMBEDDED PROJECT.

   THE UNIFYING CHARACTERISTIC OF ALL SIX: THE SYMPTOM
   APPEARS FAR FROM THE CAUSE, in space and in time. That
   is exactly why the sanitisers are worth their slowdown -
   they move the report back to the moment of the mistake.

Concurrency bugs

/* --- DATA RACE --- */
    SIGNATURE   rare, load-dependent, disappears under a
                debugger, differs between machines, worse
                or better on more cores
    THE CLASSIC:
        if (!ptr)              /* thread A checks */
            ptr = alloc();     /* thread B also checks,
                                  both allocate */
    ALSO:  count++ is READ, MODIFY, WRITE - three
           operations, interruptible between any two.
    FIND IT     TSan, KCSAN, helgrind
    FIX IT      a lock, or an ATOMIC operation - not a
                volatile, which orders nothing (see the C
                track)

/* --- DEADLOCK --- */
    SIGNATURE   total hang, no CPU usage, threads blocked
                on locks
    CAUSE       inconsistent lock ORDER. A takes L1 then
                L2; B takes L2 then L1.
    FIND IT     lockdep, !locks, all-thread backtraces
    FIX IT      A GLOBAL LOCK ORDERING, documented, and
                enforced. Never acquire a lock while
                holding one you did not plan for.

/* --- LOST WAKEUP --- */
    SIGNATURE   a thread waits forever even though the
                condition became true
    CAUSE       the condition was signalled between the
                check and the wait
    FIX         the condition-variable pattern, ALWAYS with
                a loop:
                    while (!condition)
                        wait(cv, lock);
                The `while` also handles SPURIOUS WAKEUPS,
                which are permitted by the specification and
                do occur.

/* --- PRIORITY INVERSION --- */
    SIGNATURE   a high-priority task misses its deadline
                for no visible reason; intermittent and
                load-dependent
    CAUSE       high waits on a lock held by low, and
                MEDIUM preempts low so it never releases
    FIX         priority inheritance, or a priority
                ceiling. (This is the Mars Pathfinder bug,
                and it is worth knowing the story.)

/* --- ABA --- */
    SIGNATURE   a lock-free structure corrupts under load
    CAUSE       a value read as A, changed to B and back to
                A; the compare-and-swap succeeds but the
                world moved
    FIX         a tagged pointer with a version counter, or
                hazard pointers. And seriously consider not
                writing lock-free code.

/* --- TORN READ/WRITE --- */
    SIGNATURE   a 64-bit value observed half-updated on a
                32-bit machine
    FIX         atomics of the right width, or a lock

/* --- MISSING MEMORY BARRIER --- */
    SIGNATURE   works on x86, fails on ARM. Reordering
                visible only on weakly-ordered
                architectures.
    CAUSE       the compiler or the CPU reordered stores;
                a peripheral write was buffered
    FIX         the right barrier, or the right atomic
                ordering (see the ARM track on memory
                ordering)
    AND NOTE: THIS IS WHY x86 EXPERIENCE MISLEADS ON ARM.
    x86's strong ordering hides bugs that ARM exposes
    immediately.

/* --- REENTRANCY --- */
    SIGNATURE   corruption when an ISR fires during a
                function that the main loop also calls
    CAUSE       shared state, a static local, a non-atomic
                read-modify-write on a peripheral register
    FIX         critical sections, or lock-free by design  */

C and arithmetic

/* --- INTEGER OVERFLOW --- */
    SIGNATURE   a negative length; an enormous allocation;
                a loop that never terminates; a bounds
                check that passes when it should not
        if (offset + len > size)    /* OVERFLOWS -> passes */
        if (len > size - offset)    /* correct, given
                                       offset <= size    */
    AND SIGNED OVERFLOW IS UNDEFINED BEHAVIOUR, so the
    optimiser may delete the check entirely (see the C and
    compilers tracks).

/* --- IMPLICIT CONVERSION --- */
    SIGNATURE   a comparison that is always true or always
                false
        if (strlen(s) - 1 >= 0)    /* size_t: ALWAYS TRUE */
        int c = getchar();
        if (c == EOF)              /* correct - and `char c`
                                      would be a bug */
    FIND IT     -Wconversion, -Wsign-compare

/* --- SIZEOF ON A POINTER --- */
        void f(int arr[]) { sizeof(arr); }   /* = 8, not
                                                the array */
    Arrays DECAY to pointers when passed. Pass the length.

/* --- UNINITIALISED STRUCT PADDING --- */
    memcmp on structs compares PADDING, which is
    indeterminate. Two logically equal structs compare
    unequal.
    FIX: compare fields, or memset the struct first.

/* --- STRICT ALIASING --- */
        float f = *(float*)&i;     /* UB */
    The optimiser assumes an int* and a float* cannot alias
    and reorders accordingly. Use memcpy - it compiles to
    the same instruction and is defined.

/* --- MISSING volatile --- */
    SIGNATURE   a loop reading a hardware register or an
                ISR-modified flag never exits; works at -O0
                and hangs at -O2
    FIX         volatile on the variable. And note that
                volatile provides NO atomicity and NO
                ordering between different objects.

/* --- FORMAT STRING MISMATCH --- */
        printf("%d", (long)x);      /* UB */
        printf("%d", size_t_value); /* wrong on 64-bit */
    Use the macros: %zu for size_t, PRIu32 from inttypes.h.
    FIND IT     -Wformat=2, which catches all of these.

/* --- THE ERROR PATH NOBODY TESTED --- */
    SIGNATURE   fine until something fails, then a leak, a
                double free, or a crash
    CAUSE       cleanup paths that are never exercised
    FIND IT     FAULT INJECTION. Make every allocation fail
                once. Driver Verifier does this for you on
                Windows; on Linux, failslab and
                fail_page_alloc do the same. THIS FINDS
                REAL BUGS EVERY TIME IT IS RUN.            */
The debug/release divide

"Works in debug, fails in release" is almost always one of five things: uninitialised memory (debug builds often zero it), a missing volatile, undefined behaviour the optimiser exploited, a timing-dependent race that the slower debug build hid, or an assertion that had a side effect and was compiled out. Check those five before anything else.

Hardware and embedded

/* --- CLOCK NOT ENABLED --- */
    SIGNATURE   the peripheral reads back all zeros or
                reset values; writes have no effect; no
                error reported
    THE SINGLE MOST COMMON EMBEDDED BRING-UP BUG. Enable
    the peripheral clock before touching any of its
    registers.

/* --- PIN NOT MUXED --- */
    SIGNATURE   the peripheral looks correctly configured
                and nothing appears on the pin
    A pin has one function at a time. Check the alternate
    function register, and check with a scope.

/* --- READ-MODIFY-WRITE ON A REGISTER --- */
        REG |= BIT;      /* three operations */
    An interrupt between them loses the other write. And
    some registers are WRITE-1-TO-CLEAR, where |= clears
    every pending flag, not just yours. READ THE REGISTER
    DESCRIPTION.

/* --- ALIGNMENT FAULT --- */
    SIGNATURE   hard fault on a cast from a byte buffer;
                works on x86, faults on Cortex-M0
    FIX         memcpy into a properly aligned object

/* --- ENDIANNESS --- */
    SIGNATURE   values byte-swapped over a network or a bus
    FIX         explicit conversion at every boundary;
                never cast a buffer to a struct

/* --- DMA AND CACHE COHERENCY --- */
    SIGNATURE   DMA'd data is stale or partially correct;
                works with the cache off
    CAUSE       the CPU wrote to a cached buffer the device
                then read, or the device wrote to memory the
                CPU has cached
    FIX         clean before the device reads, invalidate
                after it writes - or use the DMA API and
                let it do this (Linux track), or a
                non-cacheable buffer.
    AND WATCH THE CACHE LINE: an invalidate affects a whole
    line, so an adjacent variable sharing the line gets
    discarded too. Align and pad DMA buffers to a cache
    line.

/* --- BUFFER NOT IN DMA-CAPABLE MEMORY --- */
    A stack buffer, or memory the device's address space
    cannot reach. Silently transfers garbage.

/* --- ISR TOO LONG --- */
    SIGNATURE   missed interrupts, jitter, a watchdog
                reset, a DPC watchdog bugcheck
    FIX         do the minimum in the ISR; defer the rest

/* --- MISSING FLAG CLEAR --- */
    SIGNATURE   the ISR fires continuously and the system
                appears hung
    FIX         clear the interrupt source, and re-read the
                register afterwards to ensure the write has
                landed before returning.

/* --- FLOATING INPUT --- */
    SIGNATURE   a GPIO reads randomly, and touching the
                board changes it
    FIX         enable a pull-up or pull-down

/* --- POWER AND DECOUPLING --- */
    SIGNATURE   resets under load, corruption during radio
                transmission or motor start, only on some
                units
    FIX         scope the rail WITH THE LOAD APPLIED, at a
                fast timebase. A brownout of a few
                microseconds does not show on a multimeter.

/* --- SILICON ERRATA --- */
    SIGNATURE   the hardware does not do what the reference
                manual says
    THE FIX     READ THE ERRATA SHEET. Vendors publish
                them. Some of them are extraordinary, and
                the workaround is usually documented.    */

Symptom to cause

SymptomLook at first
Works in debug, fails in releaseUninitialised memory, volatile, UB, a race, an assertion with a side effect
Works on x86, fails on ARMMemory ordering, alignment, signedness of char
Fails only under loadA race, a resource limit, or a timing margin
Fails after hours or daysA leak, a counter wrap, fragmentation
Fails on one unit onlyHardware, calibration data, or a per-unit configuration
A printf makes it go awayA race, or a timing-dependent bug
Crash in free or the allocatorHeap corruption from an earlier overflow
Corrupted value with no writerBuffer overflow, stack overflow, or DMA
Total hang, no CPU useDeadlock — get all thread stacks
Total hang, 100% CPUInfinite loop, or an interrupt flag never cleared
Peripheral reads all zerosClock not enabled
Data byte-swappedEndianness at a boundary
Stale DMA dataCache maintenance missing
Fails only when cold or hotTiming margin, crystal drift, marginal supply
Bounds check passes wronglyInteger overflow or an implicit conversion
