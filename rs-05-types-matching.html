Structs, enums and pattern matching

Rust's enums carry data and its match is exhaustive. Together they let you make invalid states unrepresentable — which is a stronger guarantee than any amount of validation, and the single most useful design technique the language offers.

Structs

Structs are familiar from C, and the differences are in the details — construction, privacy, and how methods attach.

    struct Point { x: i32, y: i32 }             // named fields
    struct Wrapper(u32);                        // TUPLE struct
    struct Marker;                              // UNIT struct -
                                                // zero sized

    let p = Point { x: 1, y: 2 };
    let w = Wrapper(42);
    println!("{}", w.0);

    let x = 1; let y = 2;
    let p = Point { x, y };                     // field
                                                // shorthand

    let q = Point { x: 5, ..p };                // struct
                                                // update
                                                // syntax

/* METHODS live in an `impl` block, separate from the data: */

                                        // function - no self
        fn magnitude(&self) -> f64 { ... }      // borrows
        fn translate(&mut self, dx: i32) { ... }// mutates
        fn into_tuple(self) -> (i32, i32) { ... }// consumes

Enums that carry data

This is the feature that most changes how you model a problem. A Rust enum is a tagged union the compiler checks, and it eliminates a whole family of C bugs by construction.

/* THE CENTRAL DIFFERENCE FROM C: a Rust enum is a TAGGED
   UNION, and each variant may carry different data.      */

    enum Message {
        Quit,                                   // no data
        Move { x: i32, y: i32 },                // named
                                                // fields
        Write(String),                          // one value
        Colour(u8, u8, u8),                     // a tuple
    }

/* IN C YOU WOULD WRITE: */
        struct Message {
                enum { QUIT, MOVE, WRITE, COLOUR } tag;
                union {
                        struct { int x, y; } move_;
                        char *write;
                        struct { uint8_t r,g,b; } colour;
                } data;
        };
/* ...and nothing stops you reading `data.write` when the tag
   says MOVE. Rust makes that impossible: you can only reach
   the payload through a `match` that has already checked the
   tag.

/* SIZE: as large as the biggest variant, plus a
   discriminant - and Rust applies NICHE OPTIMISATION: */
    assert_eq!(size_of::<Option<&u8>>(), size_of::<&u8>());
/* A reference can never be null, so `None` is represented by
   the null bit pattern - Option<&T> is EXACTLY the size of a
   pointer. Same for Option<Box<T>>, Option<NonZeroU32>, and
   any enum with an unused bit pattern available. So the
   safety costs nothing.

/* C-LIKE ENUMS with explicit values, for hardware: */
    #[derive(Clone, Copy, PartialEq)]
    #[repr(u8)]
    enum Mode { Idle = 0, Run = 1, Fault = 0xFF }

    let raw = Mode::Run as u8;          // enum -> integer:
                                        // free
    let m = Mode::try_from(raw)?;       // integer -> enum:
                                        // CHECKED
/* `#[repr(u8)]` fixes the representation, which matters for
   FFI and for register fields (chapter 15). Converting FROM
   an integer must be fallible, because not every value is
   valid - and that is exactly the check C omits.        */

Pattern matching

Pattern matching is exhaustive, which is what turns enums from a convenience into a correctness tool: adding a variant makes the compiler list every place that must be updated.

    match msg {
        Message::Quit => cleanup(),
        Message::Move { x, y } => move_to(x, y),
        Message::Write(text) => print(&text),
        Message::Colour(r, g, b) => set_colour(r, g, b),
    }
/* EXHAUSTIVE: omit a variant and it does not compile. Add a
   variant to the enum later, and every match that does not
   handle it fails to build - which is precisely the review
   you want.

/* PATTERN FORMS: */
    match x {
        0 => "zero",
        1 | 2 | 3 => "small",           // alternatives
        4..=9 => "medium",              // an inclusive RANGE
        n if n < 0 => "negative",       // a GUARD
        _ => "large",                   // the wildcard
    }

    match point {
        Point { x: 0, y: 0 } => "origin",
        Point { x: 0, y } => "on the y axis",
        Point { x, .. } => "elsewhere",         // .. ignores
                                                // the rest
    }

    match slice {
        [] => "empty",
        [one] => "one element",
        [first, .., last] => "several",         // slice
                                                // patterns
        [first, rest @ ..] => "head and tail",  // BINDING with
                                                // @
    }

    match opt {
        Some(n @ 1..=9) => println!("single digit {n}"),
        Some(n) => println!("{n}"),
        None => println!("nothing"),
    }

/* MATCH ERGONOMICS - matching on a reference binds
   references, so you rarely need to write & or *: */
    match &opt {
        Some(v) => use(v),      // v is &T automatically
        None => {}
    }

/* THE SHORTHANDS: */
    if let Some(v) = opt { use(v); }
    else { handle_none(); }

    let Some(v) = opt else { return; };  // LET-ELSE - the
                                         // else branch must
                                         // diverge

    while let Some(item) = queue.pop() { process(item); }

    // and matches! for a boolean test:
    if matches!(state, State::Running | State::Paused) { }

/* LET-ELSE IS THE ONE TO ADOPT: it replaces the pyramid of
   `if let` nesting with early returns, which reads exactly
   like the guard-clause style good C already uses.      */
Make invalid states unrepresentable 
// BAD: four booleans = sixteen states, twelve invalid
struct Conn { connected: bool, authed: bool,
              error: bool, session: Option<u32> }

// GOOD: exactly the states that exist
enum Conn {
    Disconnected,
    Connecting { started: Instant },
    Authenticated { session: u32 },
    Failed(Error),
}

The second version cannot represent "authenticated but not connected", so no code needs to check for it and no test needs to cover it. This is the highest-leverage design technique in the language, and it transfers directly to C++ (std::variant) and even to C with discipline.

Modelling hardware

Where this pays off for embedded work: register fields, states and protocol messages are exactly the things that enums and matching describe well, and that integers describe badly.

/* --- A REGISTER FIELD as an enum --- */
    #[repr(u8)]
    #[derive(Clone, Copy, PartialEq, Debug)]
    pub enum Prescaler { Div1 = 0, Div2 = 1, Div4 = 2,
                         Div8 = 3 }

    impl Prescaler {
        pub const fn divisor(self) -> u32 {
            1 << (self as u8)
        }
    }
/* An invalid prescaler value cannot exist, and the divisor
   is computed at compile time.

/* --- A COMMAND PROTOCOL --- */
    enum Command {
        Read  { addr: u16, len: u8 },
        Write { addr: u16, data: [u8; 4] },
        Reset,
        SetMode(Mode),
    }

    fn encode(cmd: &Command, out: &mut [u8]) -> usize {
        match cmd {
            Command::Read { addr, len } => {
                out[0] = 0x01;
                out[1..3].copy_from_slice(&addr.to_le_bytes());
                out[3] = *len;
                4
            }
            Command::Write { addr, data } => {
                out[0] = 0x02;
                out[1..3].copy_from_slice(&addr.to_le_bytes());
                out[3..7].copy_from_slice(data);
                7
            }
            Command::Reset => { out[0] = 0x03; 1 }
            Command::SetMode(m) => { out[0] = 0x04;
                                     out[1] = *m as u8; 2 }
        }
    }
/* Add a command and every encoder, decoder and handler that
   does not cover it fails to compile. In C that is a
   comment; here it is the build.

/* --- A STATE MACHINE, where the state OWNS its data --- */
    enum State {
        Idle,
        Sampling { buffer: [u16; 64], count: usize },
        Transmitting { remaining: usize },
        Error(ErrorKind),
    }

    fn step(state: State, ev: Event) -> State {
        match (state, ev) {
            (State::Idle, Event::Start) =>
                State::Sampling { buffer: [0; 64], count: 0 },

            (State::Sampling { mut buffer, count },
             Event::Sample(v)) if count < 64 => {
                buffer[count] = v;
                State::Sampling { buffer, count: count + 1 }
            }

            (State::Sampling { count: 64, .. },
             Event::Sample(_)) =>
                State::Transmitting { remaining: 64 },

            (s, Event::Reset) => { let _ = s; State::Idle }

            (s, _) => s,        // unchanged
        }
    }
/* MATCHING ON A TUPLE of (state, event) is the idiomatic
   transition table, and it is checked for exhaustiveness
   across BOTH dimensions.

   NOTE the buffer lives INSIDE the Sampling variant - so it
   does not exist while Idle, and cannot be touched from any
   other state. That is the same "invalid states
   unrepresentable" idea applied to memory.             */

Traits on your types, briefly

A brief look ahead at how behaviour attaches to types, enough to read the code in the next few chapters before traits are covered properly.

/* Full coverage is chapter 06; the ones you implement on
   almost every type: */

    use core::fmt;

    impl fmt::Display for Temperature {
        fn fmt(&self, f: &mut fmt::Formatter<'_>)
                -> fmt::Result {
            write!(f, "{:.1}°C", self.0)
        }
    }
    // Display is for USERS; Debug (usually derived) is for
    // PROGRAMMERS.

    impl From<u16> for Raw {
        fn from(v: u16) -> Self { Raw(v) }
    }
    // implementing From gives you Into for free:
    let r: Raw = 42u16.into();

    impl TryFrom<u8> for Mode {
        type Error = ();
        fn try_from(v: u8) -> Result<Self, ()> {
            match v {
                0 => Ok(Mode::Idle),
                1 => Ok(Mode::Run),
                0xFF => Ok(Mode::Fault),
                _ => Err(()),
            }
        }
    }
    // the CHECKED integer-to-enum conversion from above

    impl Default for Config {
        fn default() -> Self {
            Config { rate: 48_000, gain: 0 }
        }
    }

/* AND THE DERIVE LIST worth putting on most data types: */
    #[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
/* Debug for diagnostics, Clone/Copy if it is plain data,
   PartialEq for tests, Default if there is a sensible one. */
