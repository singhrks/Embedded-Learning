Bringing OP-TEE up on QEMU

This is the chapter to get right before any other. A working QEMU setup with two consoles — one per world — and a passing xtest is the foundation for everything that follows, and every later failure is much easier to diagnose when you have seen the system work once.

The fast path

The shortest path from nothing to a running secure world. Getting this working early matters because every later chapter assumes you can try things.

$ cd ~/optee/build
$ make -j$(nproc)
$ make run

# Three windows appear:
#   1. QEMU's own monitor
#   2. "Normal World" - Linux
#   3. "Secure World" - OP-TEE's console
#
# In window 1:
(qemu) c

# In window 2, after Linux boots (login: root, no password):
buildroot login: root
# ls /dev/tee*
/dev/tee0  /dev/teepriv0

# optee_example_hello_world
Invoking TA to increment 42
TA incremented value to 43

# WATCH WINDOW 3 while that runs. You will see the TA load and

Without a graphical display

The default configuration wants a graphical terminal, which is inconvenient on a build server or over a connection. This is how to run it entirely in a console.

# make run needs X for the three xterms. On a headless machine
# or over SSH, drive QEMU yourself.

$ cd ~/optee/build
$ make -n run-only | tr ' ' '\n' | grep -v '^$' | head -40
# ...prints the exact qemu invocation. Adapt it:

$ cd ~/optee
$ qemu-system-aarch64 \
    -nographic \
    -serial mon:stdio \
    -serial file:secure.log \
    -smp 2 \
    -machine virt,secure=on,mte=off,gic-version=3,virtualization=false \
    -cpu max,sve=off \
    -d unimp -semihosting-config enable=on,target=native \
    -m 1057 \
    -bios bl1.bin \
    -initrd rootfs.cpio.gz \
    -kernel Image -no-acpi \
    -append 'console=ttyAMA0,38400 keep_bootcon root=/dev/vda2'

# The two -serial lines are the point:
#   first  -> ttyAMA0 -> the NORMAL world, on your terminal
#   second -> the SECURE world's console -> secure.log
#
# Watch the secure console live in another terminal:
$ tail -f secure.log

# To have both on one screen without X, use tmux:
$ tmux new-session -d 'cd ~/optee/build && make run-only'
$ tmux split-window -h 'tail -f ~/optee/secure.log'
$ tmux attach
Two consoles or nothing

OP-TEE reports TA panics, parameter errors, allocation failures and its own assertions on the secure console — never on the normal-world one. A client that returns TEEC_ERROR_GENERIC tells you nothing; the secure console tells you exactly which assertion failed and where. If you set up only one thing from this chapter, set up the second serial port.

The device tree node

The device tree tells the normal-world kernel that a TEE exists and how to reach it. Without that node, the driver never probes and nothing works.

/* Linux finds OP-TEE through the device tree. On QEMU the node
   is added by TF-A/QEMU; on real hardware you write it.     */

    firmware {
        optee {
            compatible = "linaro,optee-tz";
            method = "smc";
        };
    };

# Confirm it is there, from inside the guest:
$ ls /proc/device-tree/firmware/optee/
compatible  method  name
$ cat /proc/device-tree/firmware/optee/method
smc

# method = "smc"  bare metal - the driver issues SMC directly
# method = "hvc"  running under a hypervisor that forwards

# Kernel config required:
#   CONFIG_TEE=y
#   CONFIG_OPTEE=y
#   CONFIG_ARM_PSCI_FW=y
$ zcat /proc/config.gz | grep -E 'CONFIG_(TEE|OPTEE)='
CONFIG_TEE=y
CONFIG_OPTEE=y

tee-supplicant

A user-space daemon provides services the secure world cannot perform itself. If it is not running, operations fail in ways that look unrelated to it.

# Without it, sessions fail with TEEC_ERROR_ITEM_NOT_FOUND,
# because nothing can load the .ta file from the filesystem.
# It is a normal-world daemon (chapter 9 explains why it must
# exist at all).

# Is it running?
$ ps aux | grep [t]ee-supplicant
root  123  tee-supplicant /dev/teepriv0

# Start it by hand:
$ tee-supplicant -d          # daemonise
$ tee-supplicant -f          # foreground, so you see its errors

# Where it looks for trusted applications:
$ ls /lib/optee_armtz/
8aaaf200-2450-11e4-abe2-0002a5d5c51b.ta   # hello_world
f4e750bb-1437-4fbf-8785-8d3580c34994.ta   # aes
...

# The filename IS the UUID. A TA whose UUID does not match its
# filename will never be found.

# systemd unit, on a real distribution:
$ systemctl status tee-supplicant
$ systemctl enable --now tee-supplicant

Your first client, from nothing

Running the supplied examples confirms the whole stack works end to end before you write anything of your own — which is the right order to establish confidence in.

// hello.c - the smallest complete client. Links against
// libteec, talks to the hello_world TA that ships with
// optee_examples.
#include <stdio.h>
#include <string.h>
#include <tee_client_api.h>

#define TA_HELLO_WORLD_UUID \
    { 0x8aaaf200, 0x2450, 0x11e4, \
      { 0xab, 0xe2, 0x00, 0x02, 0xa5, 0xd5, 0xc5, 0x1b} }
#define TA_HELLO_WORLD_CMD_INC_VALUE 0

int main(void)
{
        TEEC_Context   ctx;
        TEEC_Session   sess;
        TEEC_Operation op;
        TEEC_UUID      uuid = TA_HELLO_WORLD_UUID;
        uint32_t       err_origin;
        TEEC_Result    res;

        res = TEEC_InitializeContext(NULL, &ctx);
        if (res != TEEC_SUCCESS) {
                printf("InitializeContext failed 0x%x\n", res);
                return 1;
        }

        res = TEEC_OpenSession(&ctx, &sess, &uuid,
                               TEEC_LOGIN_PUBLIC, NULL, NULL,
                               &err_origin);
        if (res != TEEC_SUCCESS) {
                printf("OpenSession failed 0x%x origin 0x%x\n",
                       res, err_origin);
                TEEC_FinalizeContext(&ctx);
                return 1;
        }

        memset(&op, 0, sizeof op);
        op.paramTypes = TEEC_PARAM_TYPES(TEEC_VALUE_INOUT,
                                         TEEC_NONE,
                                         TEEC_NONE,
                                         TEEC_NONE);
        op.params[0].value.a = 42;

        res = TEEC_InvokeCommand(&sess, TA_HELLO_WORLD_CMD_INC_VALUE,
                                 &op, &err_origin);
        if (res != TEEC_SUCCESS)
                printf("InvokeCommand failed 0x%x origin 0x%x\n",
                       res, err_origin);
        else
                printf("TA returned %u\n", op.params[0].value.a);

        TEEC_CloseSession(&sess);
        TEEC_FinalizeContext(&ctx);
        return 0;
}
$ aarch64-linux-gnu-gcc -o hello hello.c \
    -I ~/optee/optee_client/out/export/usr/include \
    -L ~/optee/optee_client/out/export/usr/lib \
    -lteec

# Get it into the guest. Easiest: put it in the rootfs and
# repack (chapter 3), or use the shared 9p mount:
$ cp hello ~/optee/out-br/target/root/

The bring-up checklist

When the environment does not come up, these are the checks in the order that finds the problem fastest.

   Work through these in order. Each one depends on the last.

   [ ] 1. TF-A prints "BL31: v2.x"
          -> if not: FIP or build problem (ch. 2)

   [ ] 2. Secure console shows "I/TC: OP-TEE version:"
          -> if not: SPD=opteed missing, or BL32 not in the FIP

   [ ] 3. Secure console shows "switching to normal world boot"
          -> if not: OP-TEE init failed. Read the lines above it.

   [ ] 4. Linux boots to a shell
          -> ordinary kernel debugging (QEMU ch. 5)

   [ ] 5. dmesg | grep optee shows all four driver lines
          -> if not: device tree node, or CONFIG_OPTEE

   [ ] 6. /dev/tee0 exists
          -> follows from 5

   [ ] 7. tee-supplicant is running
          -> if not: start it, check /lib/optee_armtz exists

   [ ] 8. optee_example_hello_world works
          -> if not: the .ta is missing, or signed with the
             wrong key

   [ ] 9. xtest -l 0 passes
          -> broad sanity

   [ ] 10. xtest passes completely
          -> you have a working system. STOP HERE and commit
             the exact versions you used.

   Do not start writing your own TA before step 10 passes. A
   failure at step 11 with steps 1-10 unverified is
   unattributable, and you will spend the afternoon looking in
   the wrong place.

Check yourself

  • Get xtest passing on QEMU and record the exact versions.
  • Explain what each of the three make run windows shows.
  • Set up two serial ports without X and explain why the second one matters.
  • Name the four optee: lines in dmesg and what each confirms.
  • Write the device tree node OP-TEE needs and say what method selects.
  • Explain what tee-supplicant does and what fails without it.
  • Say where .ta files live and how their filename relates to the UUID.
  • Write and run a client that opens a session and invokes one command.
  • Work through the ten-step bring-up checklist and say why the order matters.
  • Explain what the "might be insecure" warning is telling you.
