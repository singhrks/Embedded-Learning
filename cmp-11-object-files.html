Object files, symbols and relocation

What the assembler produces: machine code with holes in it, a list of the names it defines, a list of the names it needs, and instructions for filling the holes. Understanding this makes linker errors readable and explains where every byte of your binary comes from.

ELF structure

   +-----------------------------+
   |  ELF HEADER                 |  magic, class (32/64),
   |                             |  endianness, type, machine,
   |                             |  entry point, offsets to
   |                             |  the two tables below
   +-----------------------------+
   |  PROGRAM HEADERS            |  for the LOADER: which
   |  (segments)                 |  chunks to map, where, with
   |                             |  what permissions.
   |                             |  Absent in a .o file.
   +-----------------------------+
   |  .text      code            |
   |  .rodata    constants       |
   |  .data      initialised     |
   |  .bss       zero-initialised|  (occupies NO file space)
   |  .symtab    symbol table    |
   |  .strtab    strings         |
   |  .rela.text relocations     |
   |  .debug_*   DWARF (ch. 14)  |
   |  ...                        |
   +-----------------------------+
   |  SECTION HEADERS            |  for the LINKER: name,
   |                             |  type, flags, size, offset
   +-----------------------------+

  TWO VIEWS OF THE SAME BYTES:
     SECTIONS  are what the LINKER manipulates
     SEGMENTS  are what the LOADER maps

  A relocatable object (.o) has sections and no segments.
  An executable has both. The linker's job is largely to
  combine sections into segments.

  INSPECT:
     readelf -h prog.o        ; header
     readelf -S prog.o        ; sections
     readelf -l prog          ; segments
     readelf -s prog.o        ; symbols
     readelf -r prog.o        ; relocations
     objdump -d prog.o        ; disassembly
     size prog.o              ; text/data/bss totals

Sections

/* WHERE EACH DECLARATION LANDS: */

        int   global_init  = 42;        /* .data           */
        int   global_zero;              /* .bss            */
        const int global_ro = 7;        /* .rodata         */
        static int file_static = 1;     /* .data, local    */
        char *s = "hello";              /* the POINTER in
                                           .data, the STRING
                                           in .rodata      */

        void f(void) { }                /* .text           */

        void g(void) {
                static int counter;     /* .bss - a static
                                           local is a global
                                           with local scope */
                int local;              /* the STACK - not in
                                           the object file  */
        }

/* .bss COSTS NO FILE SPACE. It records "reserve N zeroed
   bytes at this address"; the loader provides zeroed pages.
   Which is why a program with a 1 GB zero array is a small
   file, and why moving a large zero-initialised array into
   .data by writing `= {0}`... does nothing, because the
   compiler recognises all-zero initialisers and puts it in
   .bss anyway.                                            */

/* SECTION FLAGS - what readelf -S shows: */
        A   ALLOC      occupies memory at run time
        X   EXECINSTR  executable
        W   WRITE      writable
        M   MERGE      identical entries may be merged
        S   STRINGS    contains NUL-terminated strings

        .text    AX     read + execute, not writable (W^X)
        .rodata  A      read only
        .data    WA     read + write
        .bss     WA     read + write, NOBITS type
        .symtab  (none) not loaded at run time

/* CUSTOM SECTIONS, which embedded code uses constantly: */
        __attribute__((section(".isr_vector")))
        const void *vectors[] = { &stack_top, reset_handler };

        __attribute__((section(".fastcode")))
        void hot_function(void) { ... }

/* and the linker script places them (chapter 12).

/* THE PATTERN FOR REGISTRATION TABLES, used by the kernel's
   initcalls (Linux chapter 05) and by test frameworks: */

        #define REGISTER(fn) \
            static void (*const _reg_##fn)(void) \
                __attribute__((section("my_table"), used)) = fn;

/* The linker gathers every entry into one contiguous section
   and defines __start_my_table and __stop_my_table
   automatically, so you can iterate the table without
   maintaining a list.                                     */

Symbols

$ readelf -s prog.o

Num: Value  Size Type    Bind   Vis      Ndx Name
  0: 0         0 NOTYPE  LOCAL  DEFAULT  UND
  5: 0         4 OBJECT  LOCAL  DEFAULT    3 file_static
  8: 0        24 FUNC    GLOBAL DEFAULT    1 main
  9: 0         4 OBJECT  GLOBAL DEFAULT    3 global_init
 10: 0         0 NOTYPE  GLOBAL DEFAULT  UND printf
 11: 0         4 OBJECT  WEAK   DEFAULT  COM global_zero

/* THE FIELDS THAT MATTER:

   TYPE     FUNC, OBJECT (data), SECTION, FILE, NOTYPE
   BIND     LOCAL   - not visible outside this object
                     (`static`)
            GLOBAL  - visible; duplicate definitions are an
                      error
            WEAK    - may be overridden by a GLOBAL of the
                      same name; if never defined, resolves
                      to 0
   NDX      the section it lives in, or:
            UND     - UNDEFINED. This object NEEDS it.
            ABS     - an absolute value
            COM     - a COMMON symbol (see below)
   VIS      DEFAULT, HIDDEN, PROTECTED, INTERNAL

/* UND SYMBOLS ARE THE UNRESOLVED REFERENCES. Every
   "undefined reference to X" from the linker means: some
   object had X as UND, and nothing supplied a definition
   (chapter 12).

/* WEAK SYMBOLS, and why embedded code uses them: */
        __attribute__((weak)) void board_init(void) { }
        /* a default that a board file may override */

        __attribute__((weak)) extern int optional_feature;
        if (&optional_feature)          /* NULL if absent */
                use_it();

/* This is exactly how a vendor SDK provides overridable
   default handlers, and how the kernel provides
   architecture-overridable functions.

/* COMMON SYMBOLS - a historical C wart: */
        int x;          /* at file scope, in TWO .c files */
/* Traditionally this was legal: both become COMMON, and the
   linker merges them into one object. That silently merges
   what were meant to be two separate variables.
   -fno-common is now the DEFAULT (GCC 10+), making it an
   error. Do not turn it off.                            */

/* VISIBILITY, for shared libraries: */
        __attribute__((visibility("hidden")))
        void internal_helper(void);
/* Not exported from the .so: faster calls (no PLT), smaller
   dynamic symbol table, and a real API boundary. Build with
   -fvisibility=hidden and mark exports explicitly - this is
   what well-behaved libraries do.                       */

Relocations

/* The assembler does not know where anything will end up. So
   it leaves HOLES and records how to fill them.          */

        extern int counter;
        void inc(void) { counter++; }

$ objdump -d inc.o
0000000000000000 <inc>:
   0:   90000000        adrp    x0, 0 <inc>       ; hole
   4:   f9400001        ldr     x1, [x0]          ; hole
   8:   b9400020        ldr     w0, [x1]
   c:   11000400        add     w0, w0, #0x1
  10:   b9000020        str     w0, [x1]
  14:   d65f03c0        ret

$ readelf -r inc.o
Offset  Type                    Symbol
000000  R_AARCH64_ADR_GOT_PAGE  counter
000004  R_AARCH64_LD64_GOT_LO12_NC  counter

/* THE `adrp x0, 0` has a ZERO where the address should be.
   The relocation says: "at offset 0, patch in the page
   address of counter's GOT entry, using the ADRP encoding".

/* A RELOCATION IS: (offset, type, symbol, addend)
     offset  where in the section to patch
     type    HOW to patch - which bits, what encoding, what
             arithmetic
     symbol  what to patch in
     addend  a constant to add

/* AARCH64 RELOCATION TYPES you will see:
     R_AARCH64_CALL26          bl/b, +/-128 MB range
     R_AARCH64_JUMP26          b
     R_AARCH64_ADR_PREL_PG_HI21   adrp - the page address
     R_AARCH64_ADD_ABS_LO12_NC    add - the page offset
     R_AARCH64_LDST32_ABS_LO12_NC ldr/str offset
     R_AARCH64_ABS64              a full 64-bit address, in
                                  data
     R_AARCH64_ADR_GOT_PAGE       via the GOT (chapter 13)
     R_AARCH64_TLSLE_*            thread-local storage

/* THE ADRP + ADD PAIR is the standard AArch64 idiom for
   forming an address:
        adrp x0, symbol          ; the 4 KB PAGE containing it
        add  x0, x0, :lo12:symbol ; plus the offset within
   Two instructions, +/-4 GB range, position independent.
   You will see it constantly in ARM64 disassembly.      */

/* THE 128 MB LIMIT ON `bl` matters in large binaries: if a
   call is further than that, the linker inserts a VENEER - a
   small stub that does a full 64-bit indirect branch, using
   x16/x17 (chapter 10). That is what those registers are
   reserved for, and it is why a huge kernel or browser binary
   contains thousands of tiny thunks.                    */
Reading a relocation tells you what the linker will do

When a symbol resolves to the wrong thing, or a call goes to address zero, readelf -r on the object shows exactly which reference the linker was asked to patch and with what. That is usually faster than reasoning about link order, and it distinguishes "the reference is wrong" from "the definition is missing".

What the assembler does

/* Two passes, conceptually:

   PASS 1: read the source, build the symbol table, assign
           offsets. Every instruction's size must be known -
           which is why ARM's fixed 32-bit instructions make
           this trivial and x86's variable-length ones do not.

   PASS 2: emit the encodings. For anything whose value is not
           yet known, emit zero and record a relocation.

/* ASSEMBLER DIRECTIVES - not instructions, but commands to
   the assembler: */

        .text                   ; switch to the .text section
        .section .rodata
        .globl  main            ; make `main` GLOBAL
        .type   main, %function
        .size   main, .-main    ; current position minus start
        .align  3               ; align to 2^3 = 8 bytes
        .p2align 4,,15
        .word   0x12345678      ; emit 4 bytes
        .quad   symbol          ; emit 8 bytes + a relocation
        .byte   1, 2, 3
        .asciz  "hello"         ; string with a NUL
        .space  100             ; 100 zero bytes
        .equ    CONST, 42       ; a symbolic constant
        .macro  / .endm         ; assembler macros
        .cfi_startproc          ; unwind information
        .cfi_def_cfa_offset 32  ; (chapter 14)
        .cfi_offset 29, -32
        .cfi_endproc

/* THE .cfi_* DIRECTIVES generate .eh_frame, which is how
   backtraces and C++ exceptions work without frame pointers.
   Hand-written assembly that omits them is invisible to
   unwinders - which is why kernel assembly routines carry
   them, and why a missing one breaks perf's call graphs. */

/* THE LOCAL LABEL CONVENTION:
        .L...      a local label, NOT in the symbol table
        1:  2:     numeric labels, referenced as 1b (back)
                   or 1f (forward) - reusable, and the usual
                   choice inside macros                    */

The toolchain

# --- What is in this object? ---
    readelf -a prog.o | less
    objdump -x prog.o
    nm prog.o                   ; symbols, compactly
      0000000000000000 T main       T = text, global
      0000000000000000 D global      D = data, global
      0000000000000004 B counter     B = bss
      0000000000000000 R constant    R = rodata
                       U printf      U = UNDEFINED
      0000000000000000 t helper      lowercase = LOCAL
      0000000000000000 W weak_fn     W = weak

    nm -C prog.o                ; DEMANGLE C++ names
    nm --defined-only prog.o
    nm -u prog.o                ; undefined only - "what does
                                ; this object need?"

# --- Disassemble ---
    objdump -d prog.o           ; code only
    objdump -D prog.o           ; ALL sections, including data
    objdump -dS prog.o          ; interleaved with SOURCE
                                ; (needs -g)
    objdump -drwC prog.o        ; with relocations, demangled

    llvm-objdump -d --mcpu=cortex-a53 prog.o

# --- Where did the size go? ---
    size prog.o
       text    data     bss     dec     hex filename
       1234     100     256    1590     636 prog.o

    size -A prog                ; PER SECTION
    nm --size-sort -S prog | tail -20      ; the biggest
                                           ; symbols
    bloaty prog                 ; the best tool - attributes
                                ; every byte to a source file

# --- Manipulate ---
    strip prog                  ; remove symbols
    strip --strip-debug prog    ; keep the symbol table
    objcopy -O binary prog.elf prog.bin      ; for flashing
    objcopy --only-keep-debug prog prog.debug
    objcopy --add-gnu-debuglink=prog.debug prog
    ; ship a stripped binary plus separate debug info

    ar rcs libfoo.a a.o b.o     ; a static library is just an
    ar t libfoo.a               ; archive of object files
    ranlib libfoo.a             ; build the symbol index

How it shows up

SymptomCause
"undefined reference to X"X is UND in some object and defined nowhere — nm -u finds who needs it
"multiple definition of X"Two objects define it — likely a definition in a header
Two variables silently became oneCommon symbols — build with -fno-common
A weak default is not overriddenThe strong definition is in a library the linker did not pull in (ch. 12)
Binary far larger than expectedDebug info, or no --gc-sections. Run bloaty
A 1 GB array makes a small fileIt is in .bss — correct
"relocation truncated to fit"Target out of range — usually a large binary or a wrong memory model
Thousands of tiny stubs in the disassemblyLinker veneers for out-of-range calls
Backtrace stops in assembly codeMissing .cfi_* directives
A symbol is exported that should not beDefault visibility — use -fvisibility=hidden
C++ symbol names are unreadableMangled — use nm -C or c++filt
A custom section is droppedMissing used attribute, or --gc-sections removed it
