Building QEMU from source

Distribution packages lag, omit machine types, and are built without the debug information you need the first time a device model misbehaves. Building QEMU takes about ten minutes and gives you a tree you can patch — which you will, the first time you add a device model in chapter 13.

When the packaged one is not enough

You needBecause
A newer versionMachine types, CPU features (FEAT_NV2, MTE, S-EL2) and virtio devices land in QEMU long before distributions ship them

# The three that actually matter and are most often missing:
#   libglib2.0-dev   - QEMU will not configure without it
#   libpixman-1-dev  - graphics; required even headless
#   libslirp-dev     - user-mode networking (-netdev user)
#                      Without it, "-netdev user" silently
#                      disappears from the help output and you
#                      will spend an hour wondering why.

The build

$ git clone https://gitlab.com/qemu-project/qemu.git
$ cd qemu

# Pin a release. Building master is fine for development but a
# terrible idea for anything you want to reproduce later.
$ git checkout v8.2.2
$ git submodule update --init --recursive

# Out-of-tree build. Always.
$ mkdir build && cd build

# Minimal, fast build: only the targets you need.
$ ../configure \
    --target-list=aarch64-softmmu,arm-softmmu,aarch64-linux-user \
    --enable-slirp \
    --enable-debug \
    --enable-debug-info \
    --enable-plugins \
    --prefix=$HOME/opt/qemu

$ ninja -j$(nproc)
$ ninja install

# Building ALL targets takes 20+ minutes and produces 40
# binaries you will never run. --target-list is the single
# most valuable configure flag.

$ ~/opt/qemu/bin/qemu-system-aarch64 --version
QEMU emulator version 8.2.2

# Put it on your PATH ahead of the packaged one:
$ export PATH=$HOME/opt/qemu/bin:$PATH
configure flagEffect
--target-list=Which guest architectures to build. *-softmmu = system emulation, *-linux-user = user mode
--enable-debugNo optimisation, assertions on. Roughly 2x slower; worth it while developing a device
--enable-debug-infoSymbols without disabling optimisation — the middle ground
--enable-pluginsTCG plugin support (chapter 12)
--enable-trace-backends=log,ftraceBuilt-in tracepoints
--enable-slirpUser-mode networking
--enable-sanitizersASan/UBSan. Invaluable when your own device model corrupts memory
--disable-werrorNeeded when building an older QEMU with a newer compiler
--staticA binary you can copy to a machine with different libraries
--enable-kvmUsually autodetected; force it to catch a missing header
Two builds, side by side

Keep an optimised build for daily use and a --enable-debug --enable-sanitizers build for when something breaks. Meson supports several build directories against one source tree, so this costs disk space and nothing else:

$ mkdir build-opt build-dbg
$ (cd build-opt && ../configure --target-list=aarch64-softmmu \
      --prefix=$HOME/opt/qemu && ninja)
$ (cd build-dbg && ../configure --target-list=aarch64-softmmu \
      --enable-debug --enable-sanitizers && ninja)

# Run from the build directory without installing - the
# binaries work in place:
$ ./build-dbg/qemu-system-aarch64 -M virt -nographic ...

Firmware you will also need

# QEMU ships some firmware blobs, but for arm64 work you build
# your own. These are the ones this site's tracks use.

# 1. U-Boot - for a realistic boot chain
$ git clone https://source.denx.de/u-boot/u-boot.git
$ cd u-boot && make qemu_arm64_defconfig
$ make CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)
# produces u-boot.bin -> qemu -bios u-boot.bin

# 2. EDK2 / UEFI - for an ACPI-based boot, as on servers
$ sudo apt install qemu-efi-aarch64
$ ls /usr/share/AAVMF/AAVMF_CODE.fd
# -drive if=pflash,format=raw,readonly=on,file=AAVMF_CODE.fd

# 3. TF-A - EL3 firmware, needed for the OP-TEE track
$ git clone https://github.com/ARM-software/arm-trusted-firmware
$ cd arm-trusted-firmware
$ make CROSS_COMPILE=aarch64-none-elf- PLAT=qemu \
       BL33=/path/to/u-boot.bin all fip
# produces bl1.bin and fip.bin -> loaded with -bios and -device
# loader; the OP-TEE track's chapter 4 does this properly.

# 4. A cross toolchain, if you do not have one
$ sudo apt install gcc-aarch64-linux-gnu       # Linux userspace
$ sudo apt install gcc-aarch64-none-elf        # bare metal
# or fetch the Arm GNU toolchain:
#   https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads

Verifying the build

# 1. Does it run at all?
$ qemu-system-aarch64 -M virt -nographic -kernel /dev/null 2>&1 | head -2

# 2. Are the accelerators there?
$ qemu-system-aarch64 -accel help

# 3. Is slirp present? (the silent-failure one)
$ qemu-system-aarch64 -netdev help | grep -q user && \
    echo "user networking OK" || echo "MISSING libslirp"

# 4. Are plugins enabled?
$ ls build/tests/plugin/*.so

# 5. Run the smoke tests - fast, and they catch a broken build:
$ cd build && ninja check-qtest-aarch64

# 6. The full suite, if you have changed something:
$ ninja check           # unit tests
$ ninja check-qtest     # device-level tests
$ ninja check-tcg       # requires cross compilers

# 7. Boot something real. The definitive test:
$ qemu-system-aarch64 -M virt -cpu cortex-a57 -m 512M -nographic \
    -kernel Image -append "console=ttyAMA0 rdinit=/bin/sh" \
    -initrd initramfs.cpio.gz

SymptomCause

-netdev user not acceptedBuilt without libslirp. Reconfigure with --enable-slirp
Unsupported machine typeWrong target list, or wrong binary (qemu-system-arm vs -aarch64)
Build fails with new-compiler warningsOld QEMU, new GCC. Add --disable-werror
Meson errors about a stale build directoryrm -rf build and reconfigure; meson caches aggressively
Submodule errors during configuregit submodule update --init --recursive
Enormous build timeNo --target-list — you are building every architecture
