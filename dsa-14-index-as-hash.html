Hashing: cyclic sort and index-as-hash

When the values are a permutation of 1..n, the array is the hash table. This is the pattern behind every "find the missing/duplicate number in O(1) space" problem.

The pattern

This pattern has the most specific recognition signal in the track, and once you have seen it you will never miss it again. The constraint in the problem statement is the hint.

   THE RECOGNITION SIGNAL, and it is very specific:

     "an array of n integers where each value is in the
      range [1, n]"      (or [0, n-1])

   plus a request for O(1) EXTRA SPACE.

   THAT RANGE IS THE WHOLE HINT. Values and indices are
   drawn from the same set, so each value has a NATURAL HOME:

        value v  belongs at index  v - 1     (for 1..n)
        value v  belongs at index  v         (for 0..n-1)

   TWO WAYS TO EXPLOIT IT:

   ---------------------------------------------------------
   1. CYCLIC SORT — put every value where it belongs

        i = 0
        while (i < n) {
            const home = a[i] - 1;
            if (a[i] !== a[home]) swap(a, i, home);  // not home
            else i++;                                 // settled
        }
        // now scan: the first index where a[i] !== i+1
        // exposes the missing / duplicate value

        [3, 1, 5, 4, 2]
         ^  3 belongs at index 2, swap with 5
        [5, 1, 3, 4, 2]
         ^  5 belongs at index 4, swap with 2
        [2, 1, 3, 4, 5]
         ^  2 belongs at index 1, swap with 1
        [1, 2, 3, 4, 5]  sorted, in O(n)

      WHY IT IS O(n) DESPITE THE NESTED-LOOKING LOOP: every
      swap places at least one value in its final position,
      so there are at most n swaps in total. The amortised
      argument from chapter 02, again.

      COMPARE `a[i] !== a[home]` RATHER THAN `i !== home` —
      with duplicates present, comparing indices loops
      forever when two equal values want the same slot.

   ---------------------------------------------------------
   2. SIGN MARKING — use the sign bit as a "seen" flag

        for (const x of a) {
            const idx = Math.abs(x) - 1;
            if (a[idx] < 0) -> value idx+1 is a DUPLICATE
            a[idx] = -a[idx];        // mark as seen
        }
        // afterwards, any index still positive is MISSING

      Non-destructive if you restore the signs afterwards.
      Only works when the values are strictly positive, so
      the sign is free to carry information.

   ---------------------------------------------------------

   THE OTHER O(1) TRICKS IN THIS FAMILY:
     SUM FORMULA   expected n(n+1)/2 minus the actual sum
                   gives one missing value. Simple, but
                   overflows for large n and only finds one.
     XOR           XOR all values with 1..n; pairs cancel and
                   the survivor is the answer (chapter 18).
     FLOYD'S CYCLE fast/slow pointers over the "value as next
                   index" graph — finds a duplicate without
                   modifying the array at all (chapter 21).

When to reach for it

"Values are 1..n" + O(1) space

Cyclic sort or sign marking. This phrasing is essentially a giveaway.

Find all missing / all duplicates

Sign marking finds every one in a single pass.

First missing positive

Cyclic sort, ignoring values outside 1..n.

Cannot modify the array

Floyd's cycle detection, or binary search on the value range.

Exactly one missing, no duplicates

Sum formula or XOR — one line each.

Problems

How it shows up

SymptomCause
Infinite loop in cyclic sortCompared indices instead of values — duplicates never settle
Index out of rangeValues outside 1..n not filtered before computing the home
Sign marking gives wrong answersForgot Math.abs when reading an already-flipped value
Marks a zeroZero has no sign — shift to 1-based or use a different marker
Sum formula overflowsn(n+1)/2 exceeds 32 bits — use XOR or 64-bit
Works for one missing, fails for severalSum/XOR find exactly one — use marking
Input array corrupted for the callerThese techniques mutate — restore or document it
