Linear algebra: matrices as transformations

A matrix is a grid of numbers. It is more usefully a function that takes vectors to vectors. Once you see a matrix as a transformation, every neural network layer becomes readable.

A matrix is a function

The single most useful shift in perspective in this chapter is to stop reading a matrix as a grid of numbers and start reading it as a function. Once that lands, matrix multiplication stops being arbitrary.

   THE DEFINITION THAT MAKES EVERYTHING CLICK:

     THE COLUMNS OF A MATRIX ARE WHERE THE BASIS VECTORS GO.

   Take W = [ 2  0 ]     as columns:  [2]  and  [0]
            [ 0  3 ]                  [0]       [3]

   e1 = [1,0] is sent to [2,0]   (the first column)
   e2 = [0,1] is sent to [0,3]   (the second column)

   And because the transformation is LINEAR, everything else
   follows:
       W [3,4] = 3*(where e1 goes) + 4*(where e2 goes)
               = 3*[2,0] + 4*[0,3]
               = [6, 12]

   THAT IS THE WHOLE OF MATRIX-VECTOR MULTIPLICATION. You
   never have to remember the index formula: just read the
   columns as destinations.

   SOME TRANSFORMATIONS IN 2-D:

     SCALE          [2 0]      stretch x by 2, y by 3
                    [0 3]

     ROTATION       [cos -sin]  rotate by theta
                    [sin  cos]

     SHEAR          [1 1]      slide x by the amount of y
                    [0 1]

     PROJECTION     [1 0]      flatten onto the x-axis;
                    [0 0]      INFORMATION IS LOST

     IDENTITY       [1 0]      change nothing
                    [0 1]

   WHAT "LINEAR" MEANS, precisely:
       W(a + b) = Wa + Wb
       W(c * a) = c * (Wa)
   Grid lines stay straight, parallel and evenly spaced, and
   the origin does not move.

   THAT LAST CLAUSE IS WHY NEURAL NETWORKS NEED A BIAS TERM
   AND NON-LINEARITIES. A linear map alone cannot move the
   origin, cannot bend anything, and a stack of them
   collapses into a single matrix (chapter 14).

Shapes, and what they tell you

Shape errors are the most common bug in machine-learning code by a wide margin, and they are entirely preventable by reading shapes deliberately rather than trusting them.

import numpy as np

W = np.array([[1., 2., 3.],
              [4., 5., 6.]])
W.shape        # (2, 3)  -> 2 ROWS, 3 COLUMNS

# A (m, n) MATRIX MAPS R^n -> R^m.
#   n = the INPUT dimension  (columns)
#   m = the OUTPUT dimension (rows)
# Read it right to left: it eats an n-vector, emits an
# m-vector.

x = np.array([1., 1., 1.])     # (3,)
W @ x                          # (2,)  -> [6., 15.]

# TRANSPOSE: flip rows and columns
W.T.shape                      # (3, 2)

# --- THE INDEX FORMULA, for completeness ---
#   (W x)_i = sum_j W_ij * x_j
#   Row i of W, dotted with x. So a matrix-vector product is
#   m DOT PRODUCTS (chapter 02).

# --- IN CODE, so it is concrete: ---
# void matvec(float *y, const float *W, const float *x,
#             int m, int n) {
#     for (int i = 0; i < m; i++) {
#         float s = 0.0f;
#         for (int j = 0; j < n; j++)
#             s += W[i*n + j] * x[j];     /* ROW-MAJOR */
#         y[i] = s;
#     }
# }
# NOTE THE ROW-MAJOR INDEXING W[i*n + j]. C, numpy and
# PyTorch are row-major; Fortran and BLAS conventions are
# column-major. Getting this wrong transposes your model
# silently.

# --- A NEURAL NETWORK LAYER IS EXACTLY THIS ---
#      y = W x + b
#   W: (out_features, in_features)
#   x: (in_features,)
#   b: (out_features,)
#   y: (out_features,)
#
# nn.Linear(768, 3072) holds a (3072, 768) weight matrix.
# It maps a 768-dimensional vector to a 3072-dimensional
# one. THAT IS ALL A LINEAR LAYER IS.

# --- BATCHED, which is how it actually runs ---
X = np.random.randn(32, 768)      # 32 inputs, ROWS
W = np.random.randn(3072, 768)
b = np.random.randn(3072)

Y = X @ W.T + b                   # (32, 3072)
# One matrix multiply does all 32 at once. This is why
# batching matters for throughput - see chapter 04.

Special matrices worth recognising

A handful of matrix forms show up constantly, and recognising one tells you something immediate about what it does and what it costs. These are the ones worth knowing on sight.

/* --- IDENTITY --- */
    I = np.eye(3)
    I @ x == x       for every x

/* --- DIAGONAL: independent scaling per dimension --- */
    D = np.diag([2., 3., 4.])
    D @ x            # [2*x0, 3*x1, 4*x2]
    /* CHEAP: O(n) instead of O(n^2). Whenever a
       transformation is diagonal, the implementation should
       be an elementwise multiply, not a matmul. LayerNorm's
       scale parameter is exactly this (chapter 22). */

/* --- SYMMETRIC: A == A.T --- */
    Covariance matrices, Gram matrices, attention scores
    before masking when queries and keys are the same. They
    have real eigenvalues and orthogonal eigenvectors
    (chapter 05).

/* --- ORTHOGONAL: Q.T @ Q == I --- */
    ROTATIONS AND REFLECTIONS. They PRESERVE LENGTHS AND
    ANGLES:
        ||Q x|| == ||x||
    And the inverse is free: Q^-1 == Q.T.

    WHY THIS MATTERS FOR TRAINING: an orthogonal
    transformation neither amplifies nor shrinks. Orthogonal
    weight initialisation is used in deep networks precisely
    to stop signals exploding or vanishing as they pass
    through many layers (chapter 15).

/* --- TRIANGULAR --- */
    np.tril(np.ones((4,4)))
        [[1 0 0 0]
         [1 1 0 0]
         [1 1 1 0]
         [1 1 1 1]]
    THIS EXACT MATRIX IS THE CAUSAL MASK IN A TRANSFORMER
    (chapter 20): position i may attend to positions 0..i and
    nothing later. When you see tril() in model code, that is
    what it is doing.

/* --- SPARSE --- */
    Mostly zeros. Stored as (index, value) pairs. Pruned
    networks and mixture-of-experts routing produce these,
    and exploiting sparsity is a major topic in inference
    hardware - but only STRUCTURED sparsity (e.g. 2:4)
    reliably translates into speed, because unstructured
    sparsity destroys memory locality.                    */

Inverse, rank and singularity

Inversion is the operation people reach for from school algebra and almost never actually want here. Understanding why leads directly to rank, which is the idea behind LoRA and low-rank compression.

/* --- INVERSE: the transformation that undoes it --- */
    A @ A_inv == I

    A_inv = np.linalg.inv(A)

/* NOT EVERY MATRIX HAS ONE. If the transformation LOST
   INFORMATION, it cannot be undone:

        P = [1 0]     flattens the plane onto a line.
            [0 0]     Every point on a vertical line maps to
                      the same output. Which one would the
                      inverse return?

   Such a matrix is SINGULAR, and its DETERMINANT IS ZERO.

/* --- DETERMINANT: the volume scale factor --- */
    np.linalg.det(np.diag([2., 3.]))     # 6.0
    /* the unit square becomes a 2x3 rectangle */

    det == 0   ->  the transformation COLLAPSES space
                   -> singular, no inverse
    det < 0    ->  orientation is FLIPPED (a reflection)

/* --- RANK: the dimension of the output space --- */
    np.linalg.matrix_rank(A)

    A (3, 3) matrix with rank 3 is FULL RANK - invertible.
    Rank 2 means it squashes 3-D into a plane. Rank 1 means
    everything lands on a line.

/* --- WHY THIS SECTION MATTERS, and it does concretely ---

   1. LOW-RANK ADAPTATION (LoRA), the standard way to
      fine-tune a large model (chapter 24), works by adding
      a LOW-RANK UPDATE:

          W_new = W + B @ A       with A: (r, d), B: (d, r)
                                  and r much smaller than d

      Instead of training d*d numbers, you train 2*d*r. For
      d = 4096 and r = 8 that is 16.7 million parameters
      versus 65,536 - a 250x reduction. THE ENTIRE TECHNIQUE
      IS A STATEMENT ABOUT RANK.

   2. YOU ALMOST NEVER COMPUTE AN INVERSE NUMERICALLY.
      To solve Ax = b, use np.linalg.solve(A, b), not
      inv(A) @ b. It is faster and far more numerically
      stable. Explicit inversion is a red flag in numerical
      code.

   3. NEAR-SINGULAR MATRICES are the practical problem. A
      determinant of 1e-15 is not zero, but the inverse will
      be numerically garbage. The CONDITION NUMBER
      (np.linalg.cond) measures this: how much a small input
      error is amplified. A condition number of 1e10 means
      you have lost ten digits of precision.

   4. AND IN DEEP LEARNING, INVERSES BARELY APPEAR AT ALL.
      Training uses gradient descent (chapter 11), not
      solving linear systems. The concepts matter for
      UNDERSTANDING - especially rank - more than for the
      code you will write.                               */
Composition is multiplication

Applying transformation A and then B is the same as applying the single matrix B @ A. Note the order: the rightmost matrix acts first, because it is written next to the vector in B @ (A @ x). This is exactly why stacked linear layers with no non-linearity between them collapse into one layer — W3 @ W2 @ W1 is just some other matrix, and the depth bought you nothing. The whole reason activation functions exist is to break this collapse (chapter 14).
