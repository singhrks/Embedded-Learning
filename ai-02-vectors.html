Linear algebra: vectors and vector spaces

A vector is an array of numbers, and also a point in space, and also a direction with a length. Holding all three pictures at once is most of what "having intuition for linear algebra" means.

Three views of the same object

A vector is one object that three different fields describe in three different ways, and every one of those descriptions is useful somewhere later. Being able to switch between them on demand is the actual skill.

   x = [3, 4]

   AS AN ARRAY          two numbers in order. This is what
                        the computer stores:
                            float x[2] = {3.0f, 4.0f};

   AS A POINT           the location (3, 4) in the plane

   AS AN ARROW          from the origin to (3, 4), with a
                        DIRECTION and a LENGTH of 5

         y
         |
       4 +--------* (3,4)
         |       /|
         |      / |
         |     /  |    length = sqrt(3^2 + 4^2) = 5
         |    /   |
         |   /    |
         |  /     |
         | /      |
         +--------+------ x
         0        3

   IN MACHINE LEARNING, THE THIRD VIEW IS THE USEFUL ONE:
   a vector represents something, its DIRECTION carries the
   meaning, and its LENGTH is often incidental. Two word
   embeddings pointing the same way mean similar things,
   whether one has length 3 and the other 30 (chapter 17).

   AND THE DIMENSION IS NOT TWO. A word embedding lives in
   768 or 4096 dimensions. YOU CANNOT PICTURE THAT, and you
   do not need to: every operation below is defined
   element by element and works identically at any
   dimension. The 2-D picture is for intuition; the
   arithmetic is what runs.

The operations

Four operations, and they account for essentially everything done to vectors in this track. Each one has a geometric meaning worth attaching to it now, because the geometry is what you will reason with later.

import numpy as np

a = np.array([3.0, 4.0])
b = np.array([1.0, 2.0])

# --- ADDITION: elementwise. Geometrically, tip to tail. ---
a + b            # [4., 6.]

# --- SCALAR MULTIPLICATION: scales the length,
#     keeps the direction (or reverses it if negative) ---
2 * a            # [6., 8.]
-1 * a           # [-3., -4.]

# --- IN C, so the loop is visible: ---
#   void vec_add(float *out, const float *x,
#                const float *y, int n) {
#       for (int i = 0; i < n; i++)
#           out[i] = x[i] + y[i];
#   }
#   That is the whole operation, at any dimension.

# --- NORM: the length ---
np.linalg.norm(a)                  # 5.0
np.sqrt(np.sum(a**2))              # the same thing

#   L2 norm (Euclidean):  sqrt(sum(x_i^2))     <- the default
#   L1 norm (Manhattan):  sum(|x_i|)
#   L-inf norm:           max(|x_i|)
#   These appear again as REGULARISERS in chapter 15: L2
#   shrinks all weights, L1 drives some to exactly zero.

# --- NORMALISATION: length 1, direction preserved ---
a_hat = a / np.linalg.norm(a)      # [0.6, 0.8]
np.linalg.norm(a_hat)              # 1.0

#   A UNIT VECTOR IS PURE DIRECTION. This is why embeddings
#   are often normalised before comparison - you want to ask
#   "same direction?" without "same magnitude?" muddying it.

# --- DOT PRODUCT: the operation everything is built on ---
np.dot(a, b)                       # 3*1 + 4*2 = 11
a @ b                              # the same

#   int dot(const float *x, const float *y, int n) {
#       float s = 0;
#       for (int i = 0; i < n; i++) s += x[i] * y[i];
#       return s;
#   }

#   MULTIPLY-ACCUMULATE. One line. It is the single most
#   executed operation in all of machine learning, which is
#   why every DSP and NPU has a MAC unit and why chapter 04
#   is about doing many of these at once.

What the dot product means

The dot product is the single most important operation in the subject — attention, similarity search and every linear layer are built from it — so it is worth understanding what it means rather than only how to compute it.

   THE GEOMETRIC IDENTITY, and it is worth memorising:

        a · b = ||a|| ||b|| cos(theta)

   where theta is the angle between them.

   SO THE SIGN AND SIZE OF A DOT PRODUCT TELL YOU ABOUT
   ALIGNMENT:

     a · b  LARGE POSITIVE   ->  pointing the same way
     a · b  ZERO             ->  PERPENDICULAR (orthogonal)
     a · b  LARGE NEGATIVE   ->  pointing opposite ways

        b               b            b
        ^               ^             \
        |               |              \
        +---> a         +---> a    a <--+
     theta = 45         theta = 90   theta = 135
     dot > 0            dot = 0      dot < 0

   COSINE SIMILARITY removes the magnitudes:

        cos(theta) = (a · b) / (||a|| ||b||)

        +1  identical direction
         0  unrelated
        -1  opposite

   THIS IS THE STANDARD MEASURE OF SEMANTIC SIMILARITY
   BETWEEN EMBEDDINGS. When a vector database "finds similar
   documents", it is computing this, or its unnormalised
   cousin, against every stored vector.

   AND IT IS ALSO WHAT ATTENTION COMPUTES (chapter 19): a
   query vector is dotted with every key vector, and the
   result says how much each position matters. The whole
   mechanism is "dot product as a relevance score".
def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) *
                           np.linalg.norm(b))

king  = np.array([0.9, 0.7, 0.1])
queen = np.array([0.8, 0.8, 0.1])
truck = np.array([0.1, 0.2, 0.9])

cosine_similarity(king, queen)   # 0.99  - very similar
cosine_similarity(king, truck)   # 0.36  - not similar

# IF THE VECTORS ARE ALREADY NORMALISED, cosine similarity
# IS JUST THE DOT PRODUCT - which is why production
# retrieval systems normalise once at insert time and then
# do nothing but MACs at query time. A useful optimisation
# to recognise when reading such code.

Vector spaces, bases and spans

The vocabulary of bases, spans and dimension sounds abstract and turns out to be the language you need for embeddings, rank and low-rank adaptation. This is the minimum that pays for itself.

/* A VECTOR SPACE is a set of vectors closed under addition
   and scalar multiplication. For our purposes: R^n, the set
   of all n-element real vectors. Nothing exotic.

/* LINEAR COMBINATION - the central idea: */

        c1*v1 + c2*v2 + ... + ck*vk

   Everything in linear algebra is a statement about which
   vectors can be written as linear combinations of which
   others.

/* SPAN: all the vectors you can reach. */
    span{[1,0]}           = the x-axis (a LINE)
    span{[1,0], [0,1]}    = the whole plane
    span{[1,0], [2,0]}    = still just the x-axis - the
                            second vector adds NOTHING

/* LINEAR INDEPENDENCE: no vector in the set is a
   combination of the others. [1,0] and [2,0] are DEPENDENT.
   [1,0] and [0,1] are INDEPENDENT.

/* BASIS: an independent set that spans the space. A basis
   for R^n always has exactly n vectors.
   THE STANDARD BASIS for R^3:
        e1 = [1,0,0], e2 = [0,1,0], e3 = [0,0,1]
   and [3, 4, 5] = 3*e1 + 4*e2 + 5*e3. The COORDINATES ARE
   THE COEFFICIENTS - that is all a coordinate is.

/* DIMENSION: the number of vectors in a basis.

/* WHY THIS MATTERS FOR MACHINE LEARNING - and it does,
   directly:

   AN EMBEDDING SPACE IS A VECTOR SPACE, and the interesting
   claim is that MEANING IS ENCODED IN DIRECTIONS. The famous
   example:

        vec("king") - vec("man") + vec("woman")
             lands near vec("queen")

   Read that as: there is a DIRECTION in the space that
   corresponds roughly to "gender", and another to "royalty",
   and they combine linearly. THE LINEAR ALGEBRA IS DOING
   SEMANTIC WORK.

   (The real behaviour is messier than the popular version
   suggests - the analogy only works with certain
   normalisations and often the nearest neighbour is one of
   the input words. But the underlying claim, that
   directions carry meaning, holds up and is central to
   chapter 17.)

   THE MODERN VERSION OF THIS IDEA IS THE SUPERPOSITION
   HYPOTHESIS: a model with d dimensions represents far more
   than d features, by placing them in ALMOST-orthogonal
   directions. In high dimensions there are exponentially
   many nearly-perpendicular directions, so this is
   possible - and it is one reason big models do
   disproportionately better than small ones.            */
High dimensions are strange

In 768 dimensions, two random unit vectors are almost always nearly orthogonal — the expected cosine similarity is about zero with a standard deviation near 1/√768 ≈ 0.036. So any measured similarity above ~0.1 is meaningful, and near-orthogonality is the default rather than a coincidence. Most of the volume of a high-dimensional ball is near its surface, and most of a Gaussian's mass is in a thin shell. Do not trust 2-D intuition about distances in these spaces; trust the arithmetic.

Vectors in practice

Everything above, in the form you will actually meet it — which is array code where the loops have been hidden inside a library, and where knowing what is really happening is the difference between fast and slow.

import numpy as np

# SHAPES. Track them obsessively (chapter 01).
v = np.array([1.0, 2.0, 3.0])
v.shape           # (3,)      a 1-D array - NOT a column
                  #           or a row, just 1-D

col = v.reshape(3, 1)     # (3, 1)  a column
row = v.reshape(1, 3)     # (1, 3)  a row

# NUMPY BROADCASTING - the rule that makes batched code
# short, and the source of many silent bugs:
#   compare shapes from the RIGHT; dimensions must be equal
#   or one of them must be 1; size-1 dimensions are
#   stretched.

batch = np.random.randn(32, 768)     # 32 vectors of dim 768
bias  = np.random.randn(768)         # (768,)
out   = batch + bias                 # (32, 768) - bias
                                     # added to every row

# THE CLASSIC BUG:
a = np.random.randn(32, 1)
b = np.random.randn(1, 32)
c = a + b                            # (32, 32) !!
# You wanted elementwise addition of 32 numbers and got a
# 32x32 outer sum. It runs, it produces numbers, and the
# model trains badly. ASSERT YOUR SHAPES:
assert c.shape == (32, 1), c.shape

# BATCHED OPERATIONS - one vector per row, always:
X = np.random.randn(32, 768)         # a BATCH of 32

norms = np.linalg.norm(X, axis=1, keepdims=True)  # (32, 1)
X_normalised = X / norms                          # (32, 768)

# all pairwise dot products between two batches:
A = np.random.randn(32, 768)
B = np.random.randn(64, 768)
sims = A @ B.T                        # (32, 64)
# THIS IS ATTENTION'S CORE COMPUTATION IN ONE LINE
# (chapter 19), and it is why chapter 04 exists.

# --- AND THE PRECISION NOTE, for the embedded reader ---
# float32 gives ~7 decimal digits; float16 gives ~3.
# Summing 4096 products in float16 accumulates real error,
# so hardware MAC units accumulate in HIGHER PRECISION than
# they multiply in - int8 x int8 -> int32, fp16 x fp16 ->
# fp32. When you meet quantisation in chapter 26, this is
# the reason the accumulator is always wider.

How it shows up

SymptomCause
A result is (32, 32) where (32, 1) was expectedBroadcasting a column against a row
Cosine similarity above 1.0Floating-point error, or the norms were computed on the wrong axis
All similarities near zeroNormal in high dimensions — compare against 1/√d, not against 0.5
Division by zero in normalisationA zero vector — add a small epsilon
Similarity dominated by one long vectorDot product used where cosine similarity was meant
ValueError: shapes not alignedMissing transpose — A @ B instead of A @ B.T
Silently wrong results with no errorBroadcasting hid a shape mistake — assert shapes
Accuracy collapses in float16Accumulation error over long dot products — widen the accumulator
