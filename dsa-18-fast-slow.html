Linked lists: fast and slow pointers

Two pointers moving at different speeds. It finds the middle in one pass, detects a cycle in O(1) space, and locates where the cycle begins — the last of which has a proof worth knowing.

The pattern

Two pointers moving at different speeds answers a surprising range of questions with no extra memory at all. The loop guard is the part to get exactly right.

   TWO POINTERS, ONE MOVING TWICE AS FAST.

     slow = head, fast = head
     while (fast && fast.next) {
         slow = slow.next;
         fast = fast.next.next;
     }

   THE GUARD `fast && fast.next` IS BOTH CONDITIONS. Checking
   only `fast` crashes on `fast.next.next` when fast is the
   last node; checking only `fast.next` crashes when fast is
   already null.

   ---------------------------------------------------------
   USE 1 — FIND THE MIDDLE, one pass

     When fast reaches the end, slow is at the middle.

       1 -> 2 -> 3 -> 4 -> 5        odd:  slow lands on 3
       s    f
            s         f
                 s              f=null -> slow = 3

       1 -> 2 -> 3 -> 4             even: slow lands on 3,
                                    the SECOND middle
     For the FIRST middle on even length, start
     `fast = head.next`. Decide which one the problem wants.

   ---------------------------------------------------------
   USE 2 — CYCLE DETECTION (Floyd's tortoise and hare)

     If there is a cycle, fast eventually laps slow and they
     MEET. If there is none, fast runs off the end.

     WHY THEY MUST MEET: once both are inside the cycle,
     fast gains exactly one position on slow per step. The
     gap shrinks by 1 each step and cannot skip over zero,
     so it hits zero — they meet.

   ---------------------------------------------------------
   USE 3 — FIND THE CYCLE'S START

     After they meet, reset one pointer to the head and
     advance BOTH ONE STEP AT A TIME. They meet at the entry.

        head ---- F ----> [ entry ]
                            |    ^
                            v    |
                            \____/   cycle length C

     THE PROOF, and it is short enough to give aloud:
       Let F = distance head -> entry,
           a = distance entry -> meeting point,
           C = cycle length.
       Slow travelled F + a. Fast travelled twice that, and
       is at the same place, so fast's distance is
       F + a + kC for some k >= 1.
         2(F + a) = F + a + kC
              F + a = kC
                  F = kC - a
       So walking F steps from the head, and F steps forward
       from the meeting point, both land on the entry —
       because kC - a steps past the meeting point is exactly
       a whole number of laps back to the entry.

   COST: O(n) time, O(1) space — versus a hash set of visited
   nodes which is O(n) space. That space difference is the
   entire reason this pattern is asked.

When to reach for it

"Find the middle"

One pass instead of counting then walking half.

"Is there a cycle?" / "where does it start?"

Floyd's algorithm, O(1) space.

Palindrome linked list

Find the middle, reverse the second half, compare.

Duplicate number in an array

Treat i → nums[i] as a linked list; the duplicate creates a cycle.

Happy number

The digit-square sequence either reaches 1 or cycles.

Reorder / split a list

Middle first, then operate on each half.

Problems

How it shows up

SymptomCause
Crash reading next of nullGuard must be fast && fast.next, both
Middle is off by one on even lengthTwo valid definitions — start fast at head or head.next
Cycle detection never terminatesMoving both pointers at the same speed
Cycle start is wrongReset to head after the meeting, then move both by one
Reports a cycle on a clean listComparing values instead of node identity
Palindrome check fails on odd lengthMiddle node belongs to neither half — skip it
Input list left reversedRestore the second half if the caller reuses the list
