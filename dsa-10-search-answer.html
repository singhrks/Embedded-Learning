Searching: binary search on the answer

Binary search without a sorted array anywhere in sight. When the question is "what is the smallest X that works?", search the space of answers rather than the input — and this is the single highest-leverage pattern for medium and hard problems.

The pattern

This is the same algorithm as the previous chapter applied to a space that does not exist in memory — you search over possible answers rather than over an array. The recognition signals are unusually reliable.

   THE RECOGNITION SIGNAL:

     "MINIMISE the maximum ..."
     "MAXIMISE the minimum ..."
     "the SMALLEST capacity / speed / size such that ..."
     "can we do it within K ...?"

   plus a MONOTONIC feasibility: if an answer of X works,
   then every answer larger than X also works (or every
   smaller one, for a maximise problem).

   THAT MONOTONICITY IS THE SORTED ARRAY. You never
   materialise it — you just binary search over it.

     candidate answers:  1  2  3  4  5  6  7  8  9
     feasible(x):        N  N  N  N  Y  Y  Y  Y  Y
                                     ^
                                     the answer

   THE RECIPE, four steps:

     1. GUESS the answer x.
     2. Write feasible(x): "can the task be done with x?"
        This is usually a SIMPLE GREEDY SCAN, O(n).
     3. Verify MONOTONICITY — argue why feasible is false
        then true (never alternating).
     4. Binary search the boundary with template B from
        chapter 09.

   THE TEMPLATE:

     let lo = <smallest conceivable answer>;
     let hi = <largest conceivable answer>;
     while (lo < hi) {
         const mid = lo + Math.floor((hi - lo) / 2);
         if (feasible(mid)) hi = mid;      // might be it
         else               lo = mid + 1;  // definitely not
     }
     return lo;

   PICKING THE BOUNDS IS HALF THE PROBLEM:
     lo = the answer that is trivially too small
          (often max(a), or 1)
     hi = the answer that trivially always works
          (often sum(a), or max value)
     GETTING lo TOO HIGH SILENTLY CUTS OFF VALID ANSWERS.
     When in doubt, make the range wider — it costs one
     extra iteration per doubling.

   COST: O(n · log(range)). The log of a numeric range is
   tiny — searching 10^9 values is 30 iterations — so this
   turns "try every capacity" into something linear-ish.

When to reach for it

"Minimum largest / maximum smallest"

Split array largest sum, ship packages, allocate books, painters partition.

A rate or capacity to choose

Koko eating bananas, minimum speed to arrive on time.

"Within D days / K groups"

Feasibility is a greedy sweep counting groups.

Maximise the minimum distance

Aggressive cows, magnetic force between balls. Note the flipped monotonicity.

Real-valued answers

Iterate a fixed 100 times, or until hi − lo < 1e-9, instead of using integer bounds.

Kth smallest in a structured set

Binary search the value; feasibility counts how many are ≤ it.

    // feasible(x) is TRUE for small x and FALSE for large x
    while (lo < hi) {

        for (const w of weights) {
            if (w > cap) return false;   // impossible at all
            if (load + w > cap) { groups++; load = 0; }
