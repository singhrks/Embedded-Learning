Arrays: the two-pointer pattern

Two indices walking the array under an invariant, turning an O(n²) pair search into a single O(n) pass. The first pattern to learn, and the one that appears most often.

The pattern

Two pointers is really three distinct techniques wearing one name, and telling them apart is most of the battle — each has its own precondition and its own reason for being linear.

   THREE VARIANTS. Learn to tell them apart.

   1. OPPOSITE ENDS - converging
        lo = 0, hi = n-1
        while (lo < hi) {
            evaluate(a[lo], a[hi])
            move ONE pointer inward, based on a rule
        }

        [ 1, 3, 5, 8, 11, 14 ]   target 16
          ^              ^        1+14=15 < 16 -> lo++
             ^           ^        3+14=17 > 16 -> hi--
             ^        ^           3+11=14 < 16 -> lo++
                ^     ^           5+11=16  FOUND

        REQUIRES A SORTED (or otherwise ordered) INPUT. The
        ordering is what makes "move which pointer?"
        decidable: if the sum is too small, only increasing
        the left value can help.

   2. SAME DIRECTION - fast and slow (read/write)
        write = 0
        for (read = 0; read < n; read++)
            if (keep(a[read]))
                a[write++] = a[read]

        THE INVARIANT: everything before `write` is the
        answer so far. Used for IN-PLACE FILTERING -
        removing duplicates, moving zeroes, partitioning.

   3. TWO SEQUENCES - one pointer in each
        i = 0, j = 0
        while (i < n && j < m)
            compare a[i] with b[j], advance the smaller

        Merging, intersection, subsequence checking.

   WHY IT WORKS - THE ARGUMENT YOU MUST BE ABLE TO GIVE:

     Each step ELIMINATES a whole set of candidates.
     In variant 1, when a[lo]+a[hi] < target, no pair
     (lo, k) for any k <= hi can reach the target, because
     a[hi] is the largest remaining partner. So the entire
     row for `lo` is eliminated in one step, and lo can
     advance permanently.

     n candidates, each pointer moves at most n times, never
     backwards -> O(n) total.

   THE COST: O(n) time, O(1) EXTRA SPACE. That O(1) is
   frequently the reason the interviewer asks for it.

When to reach for it

Sorted array + find a pair/triplet

Two Sum II, 3Sum, 4Sum. Sort first if the input is not sorted and indices do not matter.

"In place" + "O(1) extra space"

Read/write pointers. Remove duplicates, move zeroes, remove element.

Palindrome or symmetry

Converge from both ends comparing as you go.

Maximise something between two indices

Container with most water, trapping rain water. Move the pointer that limits the result.

Partition by a predicate

Dutch national flag, sort colours, segregate even/odd.

Merge or intersect two sorted lists

One pointer per sequence, advance the smaller.

/* THE TEMPLATE, converging variant */
function twoPointer(a, target) {
    let lo = 0, hi = a.length - 1;
    while (lo < hi) {
        const sum = a[lo] + a[hi];
        if (sum === target) return [lo, hi];
        if (sum < target) lo++;      // need a BIGGER value
        else              hi--;      // need a SMALLER value
    }
    return [-1, -1];
}

/* THE TEMPLATE, read/write variant */
function filterInPlace(a, keep) {
    let write = 0;
    for (let read = 0; read < a.length; read++)
        if (keep(a[read])) a[write++] = a[read];
    return write;                    // new logical length
}

/* THE FOUR THINGS THAT GO WRONG, every time:
     · `lo < hi` versus `lo <= hi`. Use `<` when the two
       pointers must be DIFFERENT elements (a pair), `<=`
       when a single middle element is still a valid state.
     · forgetting to SKIP DUPLICATES when the problem wants
       unique tuples
     · moving BOTH pointers when only one should move
     · assuming sorted input when it is not              */
